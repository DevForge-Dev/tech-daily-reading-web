Concise出力・/design・セルフホスト — Claude Codeが「CLIの外」へ広がる、Microsoftは実測PR+24%を裏づけ

派手な新機能より働き方の周辺を固めた一週間。結論先出しのConcise出力、アイデアからUIを起こす/design、自社インフラで走らせるセルフホスト、そして分類器で危険を審査するauto modeの既定化。Microsoftの査読研究はマージ済PRが約24%増えると実測した。

📅 2026年8月25日 ⏱ 約3分 🔗 出典 5 件

今日のClaude Codeは「最上位モデルの追加」ではなく、使い方・運用・組織導入の三方向を同時に固めた一日だった。CLIの内側だけでなく、その外側の作業までカバーする方向に広がっているのが8月の一貫した流れだ。

何が新しいか

まず出力面で、結論から述べて前置きや作業実況を省く新スタイル Concise が加わった（v2.1.237 以降、/clear後または新セッションで有効）。応答は短くなるがエンジニアリングの丁寧さはDefault同等を保つ。設計面では8月17日に /design スキルがリサーチプレビュー公開され、アイデア・スクリーンショット・既存デザインを編集可能なUIアートボードに変換できる。運用面では8月6日、クラウドセッションを自社サーバーで動かすセルフホスト環境がパブリックベータ（Team/Enterprise、既定オフ、Ownerが有効化）。リポジトリやシークレット、生成物を社内に留められる一方、モデル推論はAnthropic側のままでゼロデータ保持との併用は不可。そして8月14日から Pro/Max/Team の新規セッションで auto mode が既定になった。

数字で見る効果と安全網

auto modeは繰り返しの承認を、各ツール呼び出しが不可逆・破壊的・範囲外でないかを別の分類器で審査する方式に置き換える。Anthropicの有料テスター調査では危険コマンド検出率が分類器89%に対し人手は約13.6%（50プロンプト後は約5%へ低下）。導入効果ではMicrosoft Researchの査読論文が、数万人規模のエンジニアでマージ済PRが約24%増え、4か月間持続したと実測した（一方でトークン支出は数百万ドル規模＝予算ガバナンスが課題）。

実務での使いどころ・注意点

自分が試すなら、長時間・ログが膨らむ作業では Concise を既定にしてトークンと視認性を稼ぎ、UIの初期案は /design でコードと同じ画面から起こす。委譲はサブエージェント（専用プロンプト・限定ツール・独立コンテキスト）で境界を明確にしてから並列化するのが定石だ。注意点は二つ。ひとつは8月16日にClaude.ai/Code/Coworkが同時障害を起こした件で、開発フローを深く組み込むほど単一障害点リスクが顕在化する——ローカル完結の代替経路を用意しておきたい。もうひとつはauto modeは万能ではなくブロックが続けば手動承認へフォールバックする点（分類器用の追加トークンは非課金）。

ひとこと

「短く返し、UIを起こし、自社で走らせ、安全に自動化する」——モデルの世代交代が一段落し、周辺の運用体験を固める局面に入った。
