2026ロードマップ実行フェーズ — Impeller一本化とAOTシェーダーでjankゼロへ

テーマは「Finishing the Job（既存機能の完成）」。Android 10+でSkiaを撤去しImpellerへ一本化、WASM既定化を前進、状態管理は新規Riverpod 3・監査Bloc 9。

📅 2026年8月22日 ⏱ 約3分 🔗 出典 4 件

Flutter & Dartの2026ロードマップが実行フェーズに入った。掲げるのは「Finishing the Job」——新機能の乱造より、長年の宿題だった機能を仕上げる方針だ。現行安定版は Flutter 3.47 / Dart 3.13。material_ui/cupertino_ui 1.0 のstandalone化（移行は dart fix --apply --code=migrate_design_widgets）、Impellerがデスクトップでも既定、Widget Previewsがstableに、といった「完成」寄りの変化が並ぶ。

何が新しいか

レンダリングではImpellerへの一本化が核心。Android 10以上で legacy Skia backend を撤去し、iOS＋モダンAndroid（API 29+）で既定レンダラになる。Webは flutter build web --wasm の WasmGC を既定ターゲットへ前進させ、起動高速化・JSブリッジ縮小を狙う。Dart言語は Primary Constructors（コンストラクタとインスタンス変数をヘッダでまとめて宣言）と Augmentations（独立出荷、クラス定義の複数ファイル分割）を投入。Apple側は最低要件を iOS 15 / macOS 12 に引き上げ、Xcode 27で UIScene ライフサイクルが必須になる。

仕組み — なぜjankが消えるか

Flutter最大の歴史的痛点は shader compilation jank（初回描画時にシェーダーをコンパイルしてカクつく）だった。2026のImpellerはAOT（ahead-of-time）シェーダーコンパイルで、アプリが要する全シェーダーをビルド時にprecompileする。結果、初回jankゼロ・一貫したフレームタイミング・複雑シーンで raster約50%短縮。計測は profile モードで DevTools の flame chart を使い、16ms超のフレームを起こした関数を特定するのが定石だ。

状態管理とアニメの選定（2026）

状態管理は新規はRiverpod 3.3.1＋codegenを既定に。unified Ref・失敗時のautomatic retry・実験的offline persistenceが入り、ref.watch(provider.select(...)) で最小スライス購読ができる。監査証跡が要る規制業界（fintech/healthcare）や複雑並行は Bloc 9.0（on<Event> ハンドラ、完全なevent traceability）。GetXは退潮で長期プロジェクトでは回避推奨。アニメは micro（50–200ms）はimplicit、component（200–400ms）はexplicit、Hero（300–600ms）は flightShuttleBuilder、重い演出はRive/Lottieへオフロード、と時間帯で使い分ける。

ひとこと

「速くする新技」より「歴史的な遅さを構造で消す」年。まずは flutter --version で3.47系を確認し、Impeller前提でRepaintBoundaryとconstを効かせた再ビルド削減から着手したい。
