WebGLフラグメントシェーダー背景 — 生WebGL島 と R3F、CSSでは届かない"有機的な動き"

Stripe風メッシュグラデや流体ノイズはGPUのフラグメントシェーダー(GLSL)の領域。全画面クアッド＋u_time/u_resolution/u_mouse の3 uniformが骨格。背景1枚は生WebGL（数KB・依存ゼロ）、3D連携はR3F+drei shaderMaterial。SSR不可・DPR上限・毎フレームsetState禁止が鉄則。

📅 2026年8月7日 ⏱ 約4分 🔗 出典 5 件

「ぬるぬる動くメッシュグラデ」「オーロラ状の流体ノイズ」「ホバーで歪む画像」——アワード系サイト定番の"質感のある動き"は、DOMの transform/opacity や @property グラデでは到達できない。担うのは GPU上で走るフラグメントシェーダー（GLSL）だ。フラグメントシェーダーは「1ピクセルにつき1回、色を返す関数」を数千並列でGPUが実行するため、CPUを焼かずに全画面グラデを毎フレーム塗り替えられる。既存の 3D/WebGL 系メモは react-three-fiber と CSS 3D までで、GLSL そのものは空白だった——今日はその穴を埋める。

描画モデル（最小構成）。背景用途では頂点シェーダーはただの全画面クアッド（-1..1のクリップ空間に板2枚）で、表現はすべてフラグメントシェーダーが担う。gl_FragCoord を resolution で割って 0..1 の UV を作り、色 vec4(r,g,b,a) を返す。JS↔GPU の橋は uniform だけで、最小セットは3つ：アニメの駆動源 u_time、アスペクト/DPR 補正の u_resolution、ポインタ追従の u_mouse（0..1）。メッシュグラデの核は Simplex/Perlin ノイズ関数を1つ貼るだけ（依存ゼロ・約20行）で、数レイヤ重ねて mix() で2〜4色を補間すれば"ゆっくり流れる面"になる。3レイヤの simplex noise でモバイル60fps が定番の落としどころだ。

precision highp float;
uniform float u_time; uniform vec2 u_resolution, u_mouse;
float noise(vec2 p){ /* simplex を貼る（依存ゼロ） */ return 0.0; }
void main(){
  vec2 uv = (gl_FragCoord.xy - 0.5*u_resolution)/u_resolution.y;
  float n = 0.6*noise(uv*1.5 + u_time*0.05) + 0.4*noise(uv*3.0 - u_time*0.08);
  n += 0.3*smoothstep(0.6, 0.0, distance(uv, (u_mouse-0.5)*2.0));
  gl_FragColor = vec4(mix(vec3(0.13,0.16,0.55), vec3(0.9,0.35,0.55), clamp(n,0.,1.)), 1.0);
}

Next.js（App Router）での組み込み。WebGL は window/canvas 依存で SSR不可なので、'use client' の島に隔離し useEffect 内でだけ触る（JS前は背面のCSSグラデが見える＝プログレッシブエンハンスメント）。layout.tsx にこの島を1つ差し、children（RSC）を上に重ねればページはサーバー描画のまま背景だけクライアントで動く。R3F なら Canvas を積む wrapper を dynamic(..., {ssr:false}) で読む。

落とし穴。Retina(dpr=3)で全画面フラグメントは3倍のピクセル数——Math.min(devicePixelRatio, 2) で上限を掛ける（R3Fは dpr={[1,2]}）。時間・マウスは 毎フレーム setState で回さない（再レンダー地獄でINPが死ぬ）。useRef＋useFrame または生rAF内で uniform を直接書き換える。R3F の uniforms は useMemo で固定しないと再生成で値が飛ぶ。アンマウントで cancelAnimationFrame＋WEBGL_lose_context の cleanup 必須——Safari/iOS は同時WebGLコンテキスト数に上限があり、SPA遷移でCanvasを積むと「Too many active WebGL contexts」で真っ黒になる。動きに敏感な層には prefers-reduced-motion でrAFを回さず1フレームだけ描いて止める。

ひとことまとめ。「全画面クアッド＋3 uniform、背景は生WebGL・3DはR3F」。まずCSSで足りるか（@property/conic）を先に検討し、有機的に揺れる・ポインタに反応する要件が出てからシェーダーへ。
