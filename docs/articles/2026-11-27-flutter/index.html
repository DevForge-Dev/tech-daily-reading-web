Flutter は stable 3.50.1 据え置き7日目 — 12/2 の CocoaPods 期限と、Riverpod 3.0『統合』移行・Hero 共有要素遷移を押さえる

stable 3.50.1／Dart 3.14.0 は据え置き7日目で版番号は不動。次の節目は Dart 3.15 を載せた 3.51.0 の stable 昇格。一方で CocoaPods 中央 Specs(trunk) の read-only 化（12/2・残り5日）が実務デッドライン。技法面では Riverpod 3.0 の unified 移行（AutoDispose 削除・Family 融合・Ref<T> 廃止＋自動リトライ/Mutation）と、標準 Hero の共有要素遷移・RepaintBoundary を整理する。

📅 2026年11月27日 ⏱ 約4分 🔗 出典 4 件

リリース状況から。stable は 3.50.1／Dart 3.14.0 で据え置き7日目、beta は 3.51.0-0.2.pre（Dart 3.15.0）。版番号は動かず、次の節目は Dart 3.15 を載せた 3.51.0 の stable 昇格だ。実務上は stable 3.50.1 の継続 pin が妥当。ただし迫る期限がひとつ——CocoaPods 中央 Specs（trunk）が 12/2 に read-only 化（残り5日）。既存ビルドは動くが新規 pod の追加が止まり、iOS/macOS の既定依存マネージャは SwiftPM へ移る。依存プラグインの SwiftPM 対応棚卸しは今週中が実務デッドラインだ。

今日の技法①：Riverpod 3.0 は「統合（unified）」への移行期

状態管理の主役は Riverpod 3.0。公式は「よりシンプルな統合 Riverpod への移行期」と位置づけ、ライフサイクル変更があるため慎重な移行を促す。破壊的変更の核は“統合”だ。AutoDispose 系インタフェースは削除され Notifier に一本化、FamilyNotifier と Notifier も融合して family 引数はコンストラクタ渡しになる。Ref<T> の型引数は廃止（example(Ref ref) へ）、エラーは ProviderException でラップされる。StateProvider 等の旧 API は非推奨ではなく package:riverpod/legacy.dart へ移設され、後方互換は保たれる。

今日の技法②：Hero＝共有要素遷移 と RepaintBoundary

アニメーションは標準の Hero。2画面に同じ tag の Hero を置くと push/pop で要素が飛ぶ共有要素遷移（shared element transition）になる。飛行中の矩形は createRectTween で補間し、既定は MaterialRectArcTween（対角を弧で移動）、円⇄矩形の radial では MaterialRectCenterArcTween に差し替えるとアスペクト比が保たれる。パフォーマンス面では RepaintBoundary が子に専用 Layer を割り当て、再描画を部分木へ封じ込める——周囲と違うタイミングで再描画される部分木を囲むと無駄な paint を遮断でき、debugRepaintRainbowEnabled で効果を計測してから“適所”に置くのが鉄則だ。

ひとこと

stable は 3.50.1 継続で慌てる必要はないが、今日の手当ては2つ——12/2 の CocoaPods 期限に向けた SwiftPM 対応の棚卸しと、Riverpod を使うなら 3.0 の「AutoDispose 削除・family 融合・Ref<T> 廃止」を踏まえた慎重なアップグレードだ。どちらも“今すぐ全面対応”ではなく、期限と移行ガイドを見ながら段階的に進めるのが安全だ。
