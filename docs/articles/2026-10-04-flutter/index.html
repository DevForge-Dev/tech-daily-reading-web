Flutter “Great Thread Merge” と Riverpod 3 — 2026安定ラインの土台が固まる

UIスレッドがネイティブへ統合され同期FFIが可能に。Riverpod 3 の AsyncNotifier と animations パッケージで実装の定石も更新。

📅 2026年10月4日 ⏱ 約3分 🔗 出典 4 件

Next.App DevCon 2026（10/7–9・FlutterCon と Droidcon が合流）を3日後に控え、ロードマップ『Finishing the Job』の締め——WasmGC 既定化・Impeller 一本化・Material/Cupertino 分離——が現実になりつつある。現行安定版は Flutter 3.47.5 / Dart 3.13.4、11月の 3.50 で Web の --wasm 既定化と Android の Impeller 一本化（legacy Skia 撤去・API29+）が入る見込み。

いちばん大きい変化：UI Thread Merge（“Great Thread Merge”）。Dart の実行が専用 UI スレッドからネイティブのプラットフォームスレッドへ統合された。最大の効果は、platform channel の非同期往復なしに同期 FFI で Swift/Kotlin API を直接呼べること。シリアライズ/レイテンシが消えて起動・ネイティブ連携が速くなる。opt-out は撤去済みで2026安定ラインでは既定。

状態管理の定石：Riverpod 3 の AsyncNotifier + codegen。@riverpod を付けた関数/クラスの build() から provider を自動生成（build_runner）。非同期は build() が Future/Stream を返し AsyncValue<T> を公開、loading/error/data を型安全に分岐できる。Riverpod 3 では Mutations API・失敗時の自動リトライ（指数バックオフ）・stale-while-revalidate のオフライン永続化が内蔵。購読は ref.watch(provider.select(...)) で最小化、autoDispose 既定でリーク防止。テストは ProviderContainer + overrideWith でレンダリング起動なしに検証できる。

注意点。スレッド統合後も UI スレッドを塞げば即ジャンクなので、重い計算は従来どおり Isolate.run()/compute() で逃がす原則は不変。計測は必ず profile モードで（debug は JIT+assertion で無意味）。DevTools の Draw Call Batching / Texture Memory View で Impeller の GPU 挙動を監視する。

まとめ：土台（Impeller + Thread Merge）が速度を底上げし、実装は Riverpod 3 ＋ animations パッケージで“手書き AnimationController なし”へ。新規は Riverpod 3 既定、監査が要る領域は Bloc 9.2、細粒度は signals、という選び分けは据え置き。
