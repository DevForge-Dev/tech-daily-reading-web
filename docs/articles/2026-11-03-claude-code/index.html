Claude Code

11/3のClaude Code — Opus 4.8『fast mode』が10/30非推奨・11/30削除、作業ディレクトリ外の書込みを全モードで止める新設定、企業ゲートウェイの共有予算/レイヤードポリシー

公式changelogはv2.1.316(10/31)で止まったまま。11月第1週(v2.1.312〜316)の実質的な変更と、企業ゲートウェイ運用・Agent SDKの新仕様をまとめて深掘りする。

📅 2026年11月3日 ⏱ 約3分 🔗 出典 3 件

背景・なぜ今これか。 公式changelogの最新は依然 v2.1.316(10/31)で止まっているが、11月第1週は v2.1.312〜316 の4リリースが出ており、無人で長時間走らせる自分の運用に直接効く変更が複数入った。読み飛ばすと痛い順に整理する。

何が変わったか。 最大の破壊的変更は Opus 4.8 の高速モード（fast mode）が2026-10-30付で非推奨となり、11-30に削除予定であること。削除後はフォールバックせずエラーになるため、速度重視の設定は Opus 5.5 への移行が要る。あわせて v2.1.314 では、200Kトークン超の放置会話を自動要約する idle compaction が端末だけでなく VS Code / Claude Desktop のコードタブへ拡大し、v2.1.316 では CLAUDE_CODE_DISABLE_ULTRATHINK（ultrathink無効化）と CLAUDE_CODE_SUBAGENT_EFFORT（サブエージェント既定effort）が追加された。

仕組み：作業ディレクトリ外の書込み禁止。 v2.1.314 で追加された permissions.blockWritesOutsideWorkingDirectories は、Write/Edit/NotebookEdit を全権限モードで作業ディレクトリ外に書かせない設定で、既存の read 版と対になる。bypass 系で無人タスクを回すときの「想定外の場所への書込み」事故を物理的に止められる。

// .claude/settings.json
{
  "permissions": {
    "blockWritesOutsideWorkingDirectories": true,
    "blockReadsOutsideWorkingDirectories": true
  }
}

実務での使いどころ。 企業ゲートウェイでClaude Codeを束ねる運用なら、各メンバー上限に加えグループ全体で共有する月次予算 pooled_budget、複数ポリシーを下位から上書きマージする managed.policy_mode: layered（既定は最初の一致のみ適用）、Bedrock側でプロンプトを自動タグ囲いする guardrail.input_tagging が効く。1人×多数定期タスク運用でも、書込み禁止＋サブエージェントeffort既定化は「暴走しても被害が出ない箱」を作る実用設定だ。

注意点。 fast mode は削除後フォールバックしない＝放置設定が11/30に突然エラー化する。Team/Enterpriseではサーバ管理設定が承認プロンプト無しで適用される変更（v2.1.312）も入ったため、管理者ポリシーが黙って効く前提で自分の設定を書く。Agent SDK 側は省略時 permissionMode の既定がバージョンで変わるため明示指定が無難だ。

ひとことまとめ。 今週の自分向け実行項目は2つ——「11/30までにfast modeを捨ててOpus 5.5へ」「作業ディレクトリ外書込みを全モードで塞ぐ」。
