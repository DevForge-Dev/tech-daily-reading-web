11/7の話題リポジトリ — AI飽和の谷間で“非AI・軽量・ローカル”3本(player/kiri/rune)

生成AIではなく、ブラウザ/ネイティブで軽く動く道具が急上昇。重量依存・Docker/Electron疲れへの揺り戻しが共通テーマ。

📅 2026年11月7日 ⏱ 約3分 🔗 出典 3 件

本日も GitHub は AI 一色の飽和局面。その谷間で急上昇した3本は、偶然そろって「生成 AI ではなく、ローカル/ネイティブで軽量に動く道具」だった。重い依存・クラウド前提・Electron/Docker 疲れへの揺り戻しが共通テーマ。各リポジトリの「解決したい課題」と「提供する機能」を押さえる。

livliv-dev/player（TypeScript・⭐約949）

解決したい課題：VTuber/配信アバターを動かすのに、重いネイティブアプリや多数の依存を入れるのが面倒という“ツール疲れ”。提供する機能：WebGL2 だけで動く軽量な 2.5D キャラクター・プレイヤー。VRM/PNGTuber に対応し、リップシンクと Web カメラのフェイストラッキングをブラウザ単体・ローカルで実行する。AI 生成ではなく“再生エンジン”である点が新規で、公開約3日で約949★/forks100（日平均約316★/日・当日計測組で最高率の約33%）。Apache-2.0。

libracoder/kiri（Rust・⭐約545）

解決したい課題：Docker Desktop など重量級デーモンに依存するコンテナ実行の重さ・遅さ。提供する機能：macOS/Windows/Linux で動く、小さく高速なコンテナ・ランタイム。重いデーモンなしで軽量にコンテナを起動できる。AI 飽和局面では希少な純・非AI のシステム/DX 新星で、公開約5日で約545★/forks43（日平均約109★/日・率約20%）。Apache-2.0。

anomalyco/rune（Rust・⭐約2.5k）

解決したい課題：デスクトップ GUI が Electron/WebView 前提になり、バンドルが重く起動も遅いこと。提供する機能：WebView やバンドルランタイムに依存せずネイティブに描画する Rust 製 UI フレームワーク。公開約16日で約2,460★/forks58（日平均約154★/日）と総スター・日平均ともモメンタム上位、本日も push・open issues 63 で活発に開発中。MIT。

まとめ：自分が試すなら

いま一番“効く”のは kiri——Docker Desktop 依存を減らせれば CI/ローカル双方のコストに直結する。アバター UI を Web に載せたい実験には player、本気のネイティブ・デスクトップを狙うなら rune を watch。3本に共通するのは「クラウド/重量依存を外し、手元で軽く動かす」志向で、生成 AI 疲れの反動としてしばらく続きそうだ。
