Claude Code v2.1.225→226 — 支出上限の可視化とサブエージェント可観測性、暴走を止めるセッションキャップ

8/8の2連続リリース(v2.1.225/226)は派手な新機能より地固め。ゲートウェイ支出上限を利用警告に統合し上限値・リセット時刻を明示、--forward-subagent-textでサブエージェントの推論をstream-jsonへ転送、WebSearch/サブエージェント起動を各既定200でキャップして暴走ループを封じる。

📅 2026年8月9日 ⏱ 約2分 🔗 出典 3 件

8月8日に v2.1.225 と v2.1.226 が相次いで出た。目玉の新機能というより、直前の大型リリース群（セルフホスト実行・セッション間メッセージング）を安定運用に乗せるための地固めだ。長時間・並列でエージェントを回す運用ほど効いてくる回で、コストの見える化・可観測性・暴走防止という『事故らないための3点』が揃った。

何が新しいか

まず ゲートウェイ支出上限を利用警告に統合。上限到達メッセージが上限値・リセット時刻・運用者メッセージを明示するようになり（ゲートウェイ側も2.1.225が必要）、コスト超過時に『いつ・いくらで止まったか』が一目で分かる。次に公式changelog系の更新として、--forward-subagent-text フラグ（または CLAUDE_CODE_FORWARD_SUBAGENT_TEXT）でサブエージェントの内部テキスト・推論を stream-json 出力に転送できる。ログ基盤へのリアルタイム転送や、入れ子会話を見せるカスタムUI、デバッグ用の推論観測に使える。そして暴走対策として、1セッションあたり WebSearch とサブエージェント起動を各既定200回でキャップ（CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION / CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION で調整）。背景エージェントも結果を捏造せず、実完了後にのみステータスを報告するよう改善された。

実務での使いどころ

毎朝の定期タスクを多数並列で回す運用だと、支出上限の明示は『予算内で自動停止＋理由が残る』ので事後の原因究明が楽になる。サブエージェント転送は、深掘りリサーチを子エージェントに委譲したとき『子が何を考えて何を検索したか』をログに残せるのが大きい。自分なら定期タスクのログ基盤に --forward-subagent-text を噛ませて、失敗時のトレースに使う。

注意点

支出上限の表示にはゲートウェイ側も 2.1.225 以上が必要（片側だけ上げても効かない）。セッションキャップの既定200は深掘り系の重いタスクだと途中で頭打ちになりうるので、正当に多くの検索/委譲が要るタスクは環境変数で明示的に引き上げる。認証まわりも、保存済みログインの短命トークンが長命 CLAUDE_CODE_OAUTH_TOKEN を上書きしてヘッドレスを壊す401などが修正されたので、CI/ヘッドレス運用は更新推奨。

ひとことまとめ：新機能を足す回ではなく、既存の強力機能を『安全に長時間回す』ための回。並列・自動運用ほど恩恵が大きい。
