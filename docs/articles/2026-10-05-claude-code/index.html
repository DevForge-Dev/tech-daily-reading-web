Claude Code 2026-10-05 — 新機能なしの“地固め”: rmガード第2経路を封鎖、Claude Securityベータ、スキル/サブエージェント運用術

本体リリースなしの日こそ、権限ガード・安定版追従・スキル設計の基本を見直す。

📅 2026年10月5日 ⏱ 約3分 🔗 出典 6 件

本日(10/5)はClaude Code本体の新規リリースはなく、最新は10/3のv2.1.289のまま。派手な新機能のない日だが、だからこそ主題は「足回りの地固め」——権限ガードの封鎖、安定版の追従、スキル／サブエージェント運用の原則整理に目を向けたい。

何が動いたか。v2.1.289は、サンドボックス自動許可下で危険なrmを忍び込ませる第2の回避経路を封鎖した。TZ="$HOME" rm -rf build のように環境変数プレフィックスを付けてBashのdeny/askルールを素通りさせる手口で、前回のbash -cラッパー回避修正に続く第2弾。ただしCVE割当はなく、効くのはサンドボックス自動許可時のみ。注意したいのは、最新が日次でv2.1.286→289と出た一方、stableチャネルはv2.1.285(9/29)のまま最新から4ビルド遅れている点だ。基盤を共有するCowork(デスクトップ)はv2.19675.0で、Claude作成のスケジュールタスクが(許可組織では)既定で“自動承認”に変わり、動画のインライン再生も追加された。

仕組みを噛み砕く。スキルは段階的開示(progressive disclosure)で動く。name＋description(~100トークン)は常時読み込まれ、本体(~5K)はプロンプトがトリガ記述に合致したときだけ起動する。だから最重要原則は「descriptionが読み込み判断に使う“唯一の信号”」で、「use when…」型で具体的に書くこと。使い分けは、外部アクセスが要るならMCP(常時~55K)、独立作業ならサブエージェント(別コンテキスト)、繰り返し手順ならSkills(待機~100トークン)。サブエージェントは.claude/agents/にYAML定義を置き、model(haiku/sonnet/opus)とtoolsのallowlistで役割特化する。制約は入れ子不可・毎回新規起動・作業ディレクトリ非永続。

自分が試すなら。まずstable運用なら4ビルド遅れを認識し、サンドボックス自動許可で回しているならrmガード更新を取り込む。スケジュールタスクの既定“自動承認”は便利だが権限範囲を一度点検する。スキルはdescriptionを「use when」で磨き、1スキル1責務、芯は~500トークンに絞って詳細は参照ファイルへ逃がす。関連して、Anthropicは脆弱性スキャナ『Claude Security』を企業ベータ公開(10/3)——コードベースを走査し、データフロー追跡＋深刻度で優先順位付け、スケジュール実行対応で、/security-reviewとは別立ての製品だ。

落とし穴。サンドボックス修正はいずれも“自動許可時のみ”効く＝非自動運用では別の注意が要る。スキル側は4000トークン級に肥大したSKILL.mdや曖昧なトリガが逆効果になる。

ひとこと。新機能のない日ほど、安定版の追従・権限の既定・スキル設計の基本を見直す好機だ。
