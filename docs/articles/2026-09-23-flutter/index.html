CustomPainterでcanvas駆動アニメ — repaint:controllerでrebuildを飛ばす（3.47系/MVVM/コールドスタートも）

標準widgetで描けない有機的な曲線・進捗リング・path追従は最終手段のCustomPainterへ。AnimationControllerをrepaintに渡してpaintだけ走らせる勘所と、3.47系・MVVM・起動最適化の要点。

📅 2026年9月23日 ⏱ 約4分 🔗 出典 5 件

Flutter のアニメーションは、implicit / explicit の標準 widget で大半が足りる。だがスピードメーター、進捗リング、有機的な曲線、リアルタイムの path 追従など標準 widget では描けない領域に来ると、最終手段が CustomPainter による canvas 駆動アニメーションになる。今日はこの CustomPainter を主役に、あわせて 3.47 系リリース・公式 MVVM・コールドスタート最適化の要点を整理する。

何が要点か — repaint:controller で rebuild を飛ばす

CustomPainter アニメの勘所は、AnimationController を CustomPainter(repaint: controller) に渡すこと。こうすると paint フェーズだけが走り、widget rebuild をスキップして無駄を省ける。さらに shouldRepaint(oldDelegate) は視覚変化が無ければ false を返して再描画自体を回避する。path 追従は Path.computeMetrics() ＋ getTangentForOffset(distance) で path 上の座標と接線角を取得し、ベジェ曲線に沿って要素を滑らかに動かす（重い数式は不要）。path metrics は path が変わらない限りキャッシュし、paint() 内で毎フレーム再計算しないのが鉄則だ。

アニメーション技法の使い分け

粒度で道具を選ぶ。小さな変化は implicit、多段は flutter_animate、コンポーネント単位は explicit、画面間の共有要素は Hero、その先の完全カスタム描画が CustomPainter という段階だ。

足回り：3.47 系リリースと MVVM・起動最適化

現行安定版は Flutter 3.47.4 / Dart 3.13.3。3.47 系は Impeller が全デスクトップ既定、Widget Previews stable、material_ui/cupertino_ui 1.0 standalone、最低 iOS 15 が到達点で、パッチは PowerVR GPU の Impeller 不具合修正なども積み上げた。Dart 3.13 では primary constructors と dot shorthands（.start のように先頭ドット省略）が stable に。設計は公式アーキテクチャガイドの MVVM が軸で、UI 層（View＋ViewModel）と Data 層（Repository＋Service）に分け、Repository を single source of truth に据える。実装は Riverpod 3.3.x の Notifier/AsyncNotifier か Bloc 9.2.x が定番だ。

実務での使いどころ・注意点

コールドスタートは "do less at startup" が原則。独立初期化は Future.wait() で並列化、重い JSON parse や画像処理は compute() / Isolate.spawn() で背景 isolate に逃がし UI スレッドを空ける。CustomPainter 側の注意は、canvas 変換を save()/restore() で局所化し、描画領域を RepaintBoundary で外側の再描画から隔離すること。shouldRepaint を安易に true 固定にすると毎フレーム全再描画になり、せっかくの省コストが台無しになる。計測は flutter run --profile --trace-startup ＋ DevTools Timeline で。

ひとことまとめ

CustomPainter は「自由の代わりにコスト」を払う最終手段。repaint:controller・shouldRepaint・path metrics キャッシュ・RepaintBoundary の 4 点を押さえれば、120fps を保ったまま標準 widget の外側を描ける。
