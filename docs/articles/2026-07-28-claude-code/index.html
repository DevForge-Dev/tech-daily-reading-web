v2.1.220 で /fork がバックグラウンド化・自律コマンドは手動起動へ — 「賢さ」より暴走させない設計

直近の Claude Code は /fork を独立バックグラウンドセッション化し、旧来のインライン子を /subtask に分離。加えて /verify・/code-review・/deep-research を手動起動のみに改め、WebSearch にセッション200回の上限を導入するなど、自律実行の安全弁を一気に締めた。

📅 2026年7月28日 ⏱ 約3分 🔗 出典 3 件

なぜ今これが話題か

エージェント型コーディングが日常運用に入り、関心は「モデルの賢さ」から「無人でどこまで安全に走らせられるか」へ移ってきた。7/24 系のリリース v2.1.220 は、まさにその統制まわりを一度に締め直した回で、コマンドの役割整理・長時間セッションのメモリリーク一掃・自律実行の抑制がセットで入った。

何が新しいか

目玉は /fork の刷新だ。これまで /fork はインラインのサブエージェントを起動していたが、今回から会話を丸ごとコピーして独立したバックグラウンドセッション（claude agents に自分の行を持つ）として走らせ、本体の作業を止めずに続けられるようになった。旧来のインライン子は /subtask という別コマンドに分離され、「別文脈で長く走らせる＝/fork」「その場で短く委譲＝/subtask」と用途が明確になった。あわせて長時間セッションで問題化していた複数のメモリリーク——MCP stdio サーバの stderr が最大64MBまで肥大、LSP ドキュメントが開きっぱなし、バックグラウンド後もフック出力を保持、ヘッドレス/SDK で大きなツール結果が無制限に増加——を一括修正している。

仕組み・ポイント

安全弁側の変更も実務に効く。/verify・/code-review・/deep-research はこれまで Claude が自律的に走らせていたが、「手動で呼んだときだけ実行」に改められ、意図しない自動起動が止まった。さらに検索ループの暴走を抑えるため、WebSearch のセッション全体の呼び出しに既定200回の上限（CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION で調整可）が入った。サンドボックス実行では sandbox.network.strictAllowlist が許可リスト外ホストへの接続を無確認で拒否する。

自分が試すなら

長時間の調査タスクは /fork でバックグラウンドに逃がし、本体では別作業を進める運用を試したい。CI やスケジュール実行など無人の文脈では、strictAllowlist と WebSearch 上限を明示設定して「勝手にどこかへ繋ぎに行く」余地を潰しておくと安心だ。

注意点

/verify や /code-review が自動で走らなくなった分、品質ゲートは自分で明示的に叩く運用へ切り替える必要がある。「昔は勝手にレビューしてくれた」前提のワークフローは取りこぼしが出るので、コミット前チェックを手順に組み込むこと。

ひとことまとめ

今回は派手な新機能というより、自律エージェントを安心して無人運用するための土台固め。/fork とバックグラウンド化、手動起動化と各種上限は、そのまま日々の運用テンプレに落とし込む価値がある。
