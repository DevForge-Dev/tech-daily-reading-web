Flutter 3.47 — Material/Cupertino が 1.0 スタンドアロン化、Impeller が全デスクトップ既定に

3.47 の目玉は design system のコアSDKからの分離。Material/Cupertino が独立した1.0パッケージになり更新が速く届き、未使用UIを外してapp sizeも削減。Impellerは全デスクトップで既定、Widget Previewsも安定化。

📅 2026年9月11日 ⏱ 約3分 🔗 出典 3 件

現行安定版は Flutter 3.47.x／Dart 3.13.x（3.47.0 は 2026-08-12）。今日の主役は material_ui／cupertino_ui 1.0 の standalone 化だ。Material／Cupertino がコア SDK から独立した 1.0 パッケージへ分離し、design system が四半期の SDK リリースサイクルから decouple された。

何が変わるか

分離の狙いは二つ。第一に Material 3 の更新が SDK を待たずに速く届くこと。第二に、使っていない UI をバイナリから外せるので app size を削減できること。移行は当面 opt-in で既存 import は互換維持されるため、いきなり壊れる心配はない。もう一つの柱が Impeller が macOS／Windows／Linux の全デスクトップで既定になったこと（iOS=Metal／Android=Vulkan は従来どおり）。Widget Previews が stable になり、ローカルビルドキャッシュで起動が速く、リアルタイム検索/フィルタも付いた。最低 iOS 15、Web は WebAssembly が前進。

状態管理・パフォーマンスの現在地

新規プロジェクトの既定は Riverpod 3.3.1 ＋ code generation：@riverpod codegen で compile-time safety／context-free reads／first-class async を低ボイラープレートで。unified Ref・自動リトライ・experimental offline persistence・Mutations API も入る。監査証跡が要る規制業界や複雑並行は Bloc 9.1.1（bloc 9.2.x）が本線。パフォーマンスは不要な rebuild が遅延の約7割という実測が軸で、const・build()分割・ref.watch(provider.select(...))／BlocSelector での最小スライス購読・RepaintBoundary 隔離が効く。重い計算は Isolate.run()／compute() で背景 isolate へ逃がす。

実務での使いどころ・注意点

3.47 へ上げても design system 移行は急がなくてよい（opt-in）。まずは Impeller 既定化で desktop の描画が変わるので、profile モード＋DevTools でフレーム予算（60fps=16ms／90fps=11ms／120fps=8.3ms）を実測し回帰が無いか確認する。Rive は Impeller で稀に視覚/性能バグがあり、切り分けは --no-enable-impeller で Skia に落として比較。次の機能リリースは年4回サイクルで 2026年11月見込み。

ひとことまとめ

「UI レイヤをSDKから切り離す」構造改革の号。更新速度とアプリサイズの両取りが狙いで、当面は opt-in なので落ち着いて追随できる。土台の Impeller 全面化で描画は安定側へ、状態管理は Riverpod 3.3 既定が定着。
