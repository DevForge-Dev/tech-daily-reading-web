material_ui 分離と Impeller 既定化 — Flutter 3.44 が進める「モジュール化と高速化」

3.44 で material.dart/cupertino.dart がコアに凍結、将来は material_ui/cupertino_ui として独立配信（M3更新が四半期SDKを待たず届く）。Impeller は iOS＋Android API29+ の既定で、AOTシェーダーによりraster約50%短縮・バッテリー約17%削減・120fps維持。

📅 2026年8月6日 ⏱ 約3分 🔗 出典 4 件

今日の Flutter は「モジュール化」と「高速化」という二つの地殻変動が主役だった。SDK に長く同梱されてきた Material／Cupertino がコアから切り離され、レンダラは Impeller が既定に座る。どちらも"framework の形"を静かに変える変更で、いま把握しておく価値が高い。

何が新しいか（リリース）。Flutter 3.44 で material.dart／cupertino.dart がコアに凍結され、これがコアフレームワーク内の最終更新になった。将来は独立パッケージ material_ui／cupertino_ui として pub.dev から配信され、推奨 import は package:material_ui/material_ui.dart に変わる（現行 import も動くが deprecation 警告が出はじめる）。独立バージョニングで M3 更新が四半期 SDK を待たず届き、Material を使わなければ binary に含めずに済む。現行安定版は Flutter 3.44.7 / Dart 3.12、次の機能リリースは 2026年8月の予定だ。

何が新しいか（性能）。Impeller はもはや experimental ではなく iOS＋モダン Android（API 29+）の既定レンダラだ。シェーダーを AOT（ビルド時）にコンパイルするため歴史的な shader compilation jank を排除し、複雑シーンで frame rasterization を約50%短縮、アニメ重ワークロードで Skia 比 約17%低いバッテリー消費、高リフレッシュ表示で 120fps を維持する。

使いどころ・注意点。状態管理は 2026 も三強で、新規の既定は Riverpod 3.0（compile-time safety・自動リトライ・Mutations）、監査証跡が要る規制業界や大規模は Bloc 9.0、GetX は移行予算のない保守のみ。重い演出は Rive 0.13.20 の events／state machine に逃がし、.riv は initState で事前ロードして build 内で読み込まない。Dart 3.12 の primary constructors は experimental なので本番は様子見が無難だ。

ひとことまとめ。「Material は外に出て速く更新、描画は Impeller で速く回る」。まずは material_ui への import 置換と、profile モードでの raster 計測から手をつけたい。
