今日のTrendshift上位New 2026の3本は「使い捨てにしない」で一貫する。ハーネス改善を自動探索するSoL-Pi、1つのTransformerで音声込み動画まで生むMiniMax-H3、都度検索RAGではなく永続Wikiに知識を育てるllm_wiki。効率・生成・蓄積の三方向で毛色が違う。

📅 2026年9月12日 ⏱ 約3分 🔗 出典 3 件

今日Trendshift日次で急上昇した3本は、いずれもNew 2026の新星でありながら射程が大きく異なる。共通するのは「一度の結果を使い捨てにせず、改善や知識として積み上げる」という発想だ。効率化（研究ループ）・生成（オムニモーダル）・蓄積（知識Wiki）の三方向から、それぞれ解こうとしている課題と提供する機能を見ていく。

NVlabs/SoL-Pi（Python・New 2026／Trendshift日次7位）

解決したい課題：コーディングエージェントの性能は「ハーネス」（プロンプトやツール実行の足場）に左右されるが、その改善はこれまで人手の試行錯誤に頼ってきた。提供する機能：NVIDIA Labs発のSoL-Piは、pi コーディングエージェント・ハーネスを土台に、ハーネス改善そのものを自動探索する研究ループを回す。複数の公開環境をまたいで転移可能な改善を探し、pi比で平均スコア約94%を保ちつつトークンを45〜49%削減・コストを約1/3という数字が話題化した。大手研究×New 2026で本日のモメンタム筆頭級。

MiniMax-AI/MiniMax-H3（Python・約8.1k⭐／+684/7d）

解決したい課題：テキスト・画像・動画・音声がモデルごとに分断され、モダリティ横断の生成が面倒だった。提供する機能：Hailuo 3.0系オープンウェイトのMiniMax-H3は、1つのTransformerで全モダリティを扱い、ネイティブ・ステレオ音声付きの動画を最大2K・15秒で生成する。ComfyUIワークフローやvLLM対応など周辺整備も進む。AIスキル一色のトレンドに対し、基盤モデル/AIメディアという毛色違いの多様性を足している。

nashsu/llm_wiki（New 2026／Trendshift日次10位）

解決したい課題：文書が増え続ける現場で、毎回ゼロから検索するRAGは非効率で知識が定着しない。提供する機能：llm_wikiは手元のドキュメント群を、LLMが逐次的に構築・維持する「相互リンクされた永続Wiki」に自動整理するクロスプラットフォーム・デスクトップアプリ。「都度検索」から「一度整理して育て続ける」への発想転換が、ナレッジ管理の実用ニーズに刺さった。

まとめ

自分が試すなら、まず llm_wiki をローカル文書の整理に当てて「育つ知識ベース」の使い勝手を測りたい。SoL-Piの「改善を自動探索する」発想は、毎朝の調査タスクの品質規律（収集→検索→統合→蓄積）を設計し直すヒントになる。3本に通底するのは、出力を蓄積・改善へ回す姿勢だ。
