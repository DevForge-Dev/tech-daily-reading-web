10/27の話題リポジトリ — 大手3社が別角度から出した「AIコーディングの次」（自己進化IDE・録画からスキル化・spec敵対レビュー）

JetBrains・Microsoft・Googleが同じ日にトレンド上位に。共通する問いは「AIに書かせる前後をどう設計するか」——入口（IDE）・知見の資産化（録画）・品質の担保（spec）の3点を3社が分担した格好だ。

📅 2026年10月27日 ⏱ 約4分 🔗 出典 3 件

この日のGitHub TrendingはAIコーディング・ツール一色。中でも大手3社の新顔が別々の角度から急上昇したのが目を引く。共通するのは「LLMにコードを書かせること」自体ではなく、その前後——入口・知見の再利用・品質担保——をどう設計するかという問いだ。momentum枠のJetBrains/thinkrail、DevForge適合枠のmicrosoft/skill-recorderとgoogle/elephant-goldfish-modelを、「解決したい課題」と「提供する機能」の2点で読む。

JetBrains/thinkrail（TypeScript・⭐約2.8k）

解決したい課題：既存IDEは多機能ゆえ設定と学習コストが重く、AIで速く書きたい開発者の体感に追いつかない。提供する機能：AIコーディングツール「pi」でバイブコーディングしつつ、使い方に合わせてIDE自身がUI/挙動を自己カスタマイズする軽量な“実”IDE。JetBrains公式・Apache-2.0。なぜ今急上昇：本日+約1,156、実測約2,838★で率約41%＝当日トップ級。大型が居並ぶ中、総スターが小さいまま急伸した純モメンタムの新星で、「JetBrainsがバイブコーディング専用IDEを出した」こと自体が話題の軸。

microsoft/skill-recorder（TypeScript・⭐約5.2k）

解決したい課題：STATUS更新・デプロイ手順・定型チェックのような繰り返し作業が頭の中にしか無く、他人・他PJへ移せない。提供する機能：画面上の作業セッションを録画し、GitHub Copilot SDKで「意図＋手順」として再構成、再利用可能なスキル/自動化に変える。録画はAnalyze実行までローカル保持＝機微データと相性良し。Microsoft公式・MIT。なぜ今急上昇：本日Qiita日報にFirst Timerとして+約257で初登場。「反復作業を録画からスキル化」という発想が、1人で多PJを横断する開発の資産化の起点になりうる。

google/elephant-goldfish-model（Python・⭐約1.7k）

解決したい課題：specが曖昧なまま実装に入ると、仕様漏れや手戻りが後工程で噴出する。提供する機能：深い文脈を持つ「Elephant」がspecを起草し、文脈ゼロの独立サブエージェント「Goldfish」群が実装前にそのspecを敵対的にストレステストする、スペック駆動開発プラグイン。Claude Code/Codex/Antigravity/Claude Cowork対応、/egm-brainstorm→/egm-draft→/egm-reviewのループ。Google公式・Apache-2.0。なぜ今急上昇：Trendshift日次New掲載のGoogle公式新顔。「書く前にspecを多段レビューで潰す」設計が、Yes-man禁止・設計正本運用といった規律志向に刺さっている。

自分が試すなら

3本は導入の重さが違う。最も軽いのはskill-recorder——個人の繰り返し作業を1本だけ録画→スキル化して効果を測る。設計規律を上げたいならelephant-goldfish-modelを1PJの新機能でdraft→reviewだけ試運転（Apache-2.0で業務利用も問題なし）。thinkrailはApache-2.0のモメンタム枠だが、自己進化IDEはまだ観察対象——本採用より“どんなUIが自己調整されるか”を眺める段階だ。

ひとことまとめ

「速く書く（thinkrail）」「知見を残す（skill-recorder）」「仕様を潰す（elephant-goldfish）」。AIに書かせる時代の勝負どころが、コード生成そのものからその前後の設計へ移っていることを、大手3社が同じ日に示した。
