スクロール連動テキストハイライト — 読み進めに合わせ単語が“光る”。純CSS animation-timeline が2026-10にBaseline入り、JSゼロで実装

Apple/Stripe系LPで定番の read-along ハイライトを、GSAP/Motionなしの純CSSで。animation-timeline・scroll()/view()・animation-range が三大エンジン横断で動くようになり、Server Componentのまま'use client'不要で組める。

📅 2026年11月14日 ⏱ 約4分 🔗 出典 4 件

長文のナラティブを「読ませる」ための定番演出に、本文をスクロールすると文章が1語ずつ暗→明に点灯していく read-along（読み進め）ハイライトがある。これまでは GSAP ScrollTrigger や Motion の useScroll でJS実装するのが普通だったが、今回の主眼は純CSSのスクロール連動アニメーションで完全にJSゼロにできる段階に来たこと。

なぜ“いま”か：対応状況が節目を越えた

CSSスクロール連動アニメーション（animation-timeline / scroll() / view() / animation-range）が 2026年10月に Baseline “Newly available” 入り。Firefox 159 が既定で有効化し、Chrome/Edge 115+・Safari 26+ と合わせて三大エンジン横断で動く。「scroll-timeline はまだ実験的」という長年の但し書きが外れ、スクロールリスナーのJSを本当に捨てられる。ただし “Newly available” は旧端末には無いため、1〜2年は段階的強化（PE）での縮退設計が無難だ。

仕組み：タイムラインの「出所」と「区間」を分けて考える

核は2プロパティ。animation-timeline が進捗の出所を決め、animation-range がどの区間で流すかを決める。view() は対象要素がスクロールポートを横切る可視進捗（「要素が入ってきた分だけ」）、scroll() は最寄りスクローラのスクロール量そのもの。読み進めの本命は、背の高いセクションを作って中身を position: sticky で画面に留め、そのスクロール量を名前付きタイムラインにして各語spanへ割り当てる方式だ。語ごとに animation-range を --i（語インデックス）/ --n（総数）から calc() でずらすと、左上から右下へ読み進むように順次点灯する。

Next.js（App Router）での組み込み

うれしいのは Server Component のまま完結する点。語分割はサーバ側で text.split(/(\s+)/) して <span style={{'--i': i}}> を書き出すだけで、JSバンドル増ゼロ・ハイドレーションmismatchなし・CLS0（色変化はレイアウトに影響しない）。点灯CSSは globals.css に置く。PPR/ISR/SSG と無干渉で、'use client' 境界やハイドレーションコストを増やさないのが Motion/GSAP版との最大の差だ。

/* 名前付きタイムラインを各語へ割り当て */
.read-scroller { scroll-timeline-name: --read; scroll-timeline-axis: block; }
.word { color: oklch(60% 0 0 / 0.22); }            /* 未読=暗 */
@supports (animation-timeline: scroll()) {
  @media (prefers-reduced-motion: no-preference) {
    .word {
      animation: lightup linear both;
      animation-timeline: --read;                  /* ← ショートハンドの“後”に個別宣言 */
      animation-range: calc(var(--i)/var(--n)*100%)
                       calc((var(--i)+1)/var(--n)*100%);
    }
  }
}
@keyframes lightup { to { color: oklch(96% 0 0 / 1); } }  /* 既読=明 */

落とし穴（重要）

最も事故るのが animation ショートハンドが animation-timeline をリセットする点（MDN明記）。必ずショートハンドの後に timeline/range を個別宣言する。非対応ブラウザでは既定のドキュメントタイムラインで「1回だけ」再生されてしまうので、キーフレームの終了状態＝可読（明）にし、薄色とアニメ付与を @supports (animation-timeline: scroll()) で囲うと非対応時は最初から明で安全。background-clip: text を使う見出しスイープ版は -webkit- 前置必須。アクセシビリティ面は「点灯だけで情報を伝えない／未読部分も読める最低限のコントラストを確保する」が原則だ。

ひとことまとめ

read-along はサーバsplit＋純CSSでJSゼロ実装できる時代に。自分で試すなら、まず見出し1行の view() スイープから入れて、段落の順次点灯（名前付き scroll()）へ広げるのが堅い。
