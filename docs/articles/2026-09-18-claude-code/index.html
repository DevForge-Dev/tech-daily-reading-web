v2.1.273でRemoteセッションをローカルへfork — UIを手放しても作業は続く

Remote-controlセッションを状態保持のままバックグラウンドのローカルへforkしUIを解放。MCP切断通知＋/mcp診断、早期auto-compact修正も。9/8の--plugin-dirフォルダ受理とclaude plugin evalで、配布と品質検証まで数値で回せるようになった。

📅 2026年9月18日 ⏱ 約2分 🔗 出典 4 件

Claude Code の 9 月は「無人・自動・全社」の三点で実務化が進んでいる。9/15 公開の v2.1.273 は 64 件の CLI 変更を含む大型更新で、目玉は Remote-control セッションを状態を保ったままバックグラウンドのローカルセッションへ fork できる機能だ。これまで Remote で走らせるとその UI を占有し続けたが、fork すれば作業状態を引き継いだまま画面を解放でき、別の作業へ移れる。長時間の自律タスクを「投げっぱなしにできる」実感が一段強まった。

何が変わったか

fork 以外にも、MCP サーバがセッション途中で切断し自動再接続も諦めた場合に通知し、/mcp 診断へ誘導する挙動が入った。沈黙して壊れるのではなく、どのサーバが落ちたかが分かる。加えて 早すぎる auto-compact 発火バグの修正、permission 周りのセキュリティ修正、LLM ゲートウェイ向けのリクエストヘッダ追加も同梱。無人運用でいちばん怖い「気づかないうちに文脈が縮む／権限が緩む」箇所が着実に潰されている。

配布と品質を数値で回す（9/8 の更新）

少し前の 9/8 リリースでは配布・評価が強化された。--plugin-dir がプラグインを束ねたフォルダをまとめて受理し、ディスク保存するツール結果には 1GB の上限が付いた。新コマンド claude plugin eval はプラグインの eval 一式を実行しスコア付きの JSON / HTML レポートを出力するので、プロンプトの当たり外れではなく数値でプラグイン品質を検証できる。/output-style [name] の一覧・切替も headless / Remote Control で使えるようになった。

自分が試すなら・注意点

試すなら、まず長時間タスクを Remote で開始し、頃合いで fork して UI を解放する運用を一度体験するとよい。自作プラグインがあるなら claude plugin eval でスコアを取り、回帰の目安にする。注意点は、fork や auto モードで手を離すほど権限とネットワーク境界の設計が効いてくること。permission と（コマンド単位の）到達ドメイン制限を先に固めておく。背景として、日本でも楽天（市場投入の大幅短縮）・みずほ FG（3 万人規模）・NEC・日立と全社展開が相次ぎ、Copilot を売る Microsoft 自身が社内で広く採用、AI エージェント常用開発者の 71% が Claude Code を使うとの統計もある。ひとことで言えば、道具から「監査と権限のある運用基盤」へ——今日の更新はその地固めだ。
