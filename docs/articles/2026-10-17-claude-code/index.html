Claude Code v2.1.302 — forkサブエージェント既定ONと、Vals AIが突きつけた「多エージェントは高くつく」

forkが既定ON・auto mode分類器のモデル指定・バグ43件修正。一方でマルチエージェントは単体の1.8〜5.1倍のコストで品質ほぼ横ばい、という冷や水の検証も。

📅 2026年10月17日 ⏱ 約3分 🔗 出典 5 件

10/15のv2.1.301に続き、10/16にv2.1.302が出た。土曜なので派手な新機能ではなく運用面の調整が中心だが、一つだけ性格を変える変更がある——forkサブエージェントが既定ONになった（claude -p・Agent SDK・デスクトップ・VS Codeすべて。無効化はCLAUDE_CODE_FORK_SUBAGENT=0）。これまで「わざわざ並列化する」ものだったサブエージェントが、黙っていても走る前提になった。

v2.1.302の変更点

追加は、クライアント側auto mode分類器のモデルを選ぶCLAUDE_CODE_AUTO_MODE_MODEL（サーバ側のauto modeは不変）、/configのアイドル圧縮トグル、そして/design-sync・/design-loginへの「単体版Claude Design（claude.ai/design）は2026年12月14日に終了しClaude本体へ統合」という告知。変更では、権限モード未指定のclaude -p/SDKがサードパーティ上でdefault開始（autoを保つなら--permission-mode auto）、1イベントで同時に走るフックは最大12件に制限。バグ修正は43件で、128MB超画像の読込拒否、ToolSearch経由や圧縮後ツールのプロンプトキャッシュミス、MCPが新プロトコル2026-07-28をresultType等なしでネゴシエートした際のツール非表示などを含む。

「並列が既定」の直後に出た、冷や水のデータ

同じ週、評価機関Vals AIがマルチエージェントvibe codingベンチを公開した。GPT-6 SolとClaude Opus 5.5に、50本のWebアプリを「単体」と「チーム」の2通りで作らせて比較したところ、チーム構成は単体の1.8〜5.1倍のコストがかかった一方、品質スコアはほとんど上がらなかった。forkが既定ONになったからといって、むやみに多重化すればトークン代だけが膨らむということだ。

では並列はいつ効くのか — 『7つのTips』の読み方

実践ガイド『Claude Codeを使いこなす7つのTips』は、subagentの使いどころを「テスト実行やログ調査などノイズの多い作業を別会話にオフロードし、結論だけ受け取る」と位置づける。つまり並列化は品質を上げるためではなく、本線の文脈を汚さないための道具だ。他の勘所も実務的で、(1)着手前に目的・要件・現状・受け入れ基準の4点を「新しい同僚」に渡すように明確化、(2)CLAUDE.mdは絶対ルール/出力先/応答フォーマットだけに絞る、(3)繰り返す指示は/plan・/build・/commit等のスキルへ、(4)NOW.md中心のメモリで文脈復元、(5)破壊的コマンド前のPreToolUse確認などhooksで自動化、(6)Design→Plan→Build→手動受け入れ。

自分が試すなら

forkは既定ONのまま、まず「テスト/lint/ログ grep」のような使い捨て調査だけサブエージェントに投げ、設計や実装の本線は単体で握る。Vals AIの数字を踏まえ、委譲はノイズ隔離に限定してコストを監視する。そしてclaude.ai/designに資産がある人は、12/14の終了前に移行先を確認しておく。

注意点

サードパーティプロバイダでautoを前提にしたスクリプトは、v2.1.302以降default開始に倒れる点に注意（明示的に--permission-mode auto）。フックを多用している場合、1イベント同時12件の上限で残りは待機になる。

ひとこと：「forkが既定ON」と「多エージェントは割に合わない」が同じ週に並んだのは示唆的だ。並列は“速く賢くなる魔法”ではなく、文脈を汚さずノイズを隔離する配管——そう割り切るほどコストは読める。
