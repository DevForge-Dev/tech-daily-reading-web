App Router のグローバル・ルート遷移プログレスバー — router.events 無き世界での開始/完了検知

YouTube風トップローディングバーを App Router で正しく作る鍵は、URLコミットでなく"描画準備完了"を捉えること。React Transition の isPending が完了シグナルになる。

📅 2026年10月10日 ⏱ 約4分 🔗 出典 3 件

背景。画面上端を左→右に走る細い読み込みバーは、遷移が一瞬で終わらない時でも「いま遷移中」を即座に伝える定番UIだ。Pages Router 時代はRouter.events（routeChangeStart/Complete/Error）を購読すれば数行で作れた。ところがApp Router はこのrouter.eventsを持たない。さらにrouter.push()の戻り値はvoidで「遷移完了」をawaitでも取れない。加えて prefetch＋loading.tsxで多くの遷移が"ほぼ瞬間"になり、素朴なバーは一瞬チラついて消えるだけの邪魔者になる。「開始をどう捕まえ／完了をどう知り／速い遷移でチラつかせない」の3点が本題だ。

開始シグナル。起点は<Link onNavigate>（Next 15.3+）。同一オリジンのSPA遷移時だけ発火し、Cmd/Ctrl+クリック（新規タブ）・外部URL・download付きリンクでは発火しない——バーを出すべきでない遷移で勝手に黙ってくれるので都合がよい。プログラム遷移はonNavigateが効かないので、start()＋startTransition(() => router.push(href))でラップした薄いwrapperを使う。

完了シグナル（本丸）。App Routerの遷移はReact Transitionとして走り、router.pushは新しいRSCツリー（＋データ）が準備できるまで"サスペンド"する。だからstartTransitionで包むと、useTransition()のisPending が新ページを実際に描画できるまで trueのまま → false に落ちた瞬間が「完了」になる。URLコミットでなく"描画準備完了"を捉えるので、streaming下でも破綻しにくい。これがVercel公式例react-transition-progressやbuilduiの「Global progress」記事の肝だ。

擬似進捗。"本当の進捗%"は取れないので、NProgress流のトリクルで"それらしく"見せる。開始で8%へジャンプ→pending中は90%あたりへ漸近的にincrement→完了で一気に100%→フェードアウト。芯は value = value >= 90 ? value : value + (90 - value) * 0.1 + 0.5 の一行だ。

ドロップイン・ライブラリ。最速はnextjs-toploader（root layoutに<NextTopLoader />を置くだけ）。設定したいなら@bprogress/next（ProgressProviderでchildrenをラップ、height/color/showSpinnerなど）。準公式はVercelのreact-transition-progress。いずれも内部でLink/routerをパッチして全遷移を自動検知する。

アクセシビリティとCLS。擬似進捗は実進捗を持たない装飾なので、純装飾ならaria-hidden="true"にしてスクリーンリーダーに誤った%を読ませない。ルート変更自体はNext内蔵のRoute Announcerが読むので二重に読ませない。バーはposition:fixed; top:0でレイアウトフローから外しCLSゼロ、変化はtransform: scaleX()でコンポジタ合成し60fps。prefers-reduced-motionではシマー等を止め「出る→消える」の2状態に寄せる。

自分が試すなら。まずnextjs-toploaderで体感を掴み、挙動を細かく制御したくなったらゼロ依存の方式①（カスタムLink＋startTransitionでisPendingを観測）に置き換える。戻る/進む（popstate）でも出したいならusePathname側でも拾う二段構えにする。
