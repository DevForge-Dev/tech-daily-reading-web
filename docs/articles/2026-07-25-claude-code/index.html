v2.1.218 — MCP接続失敗にHTTPステータスを表示、フロントマターbool柔軟化。公開Artifactが閲覧者ごとのライブデータに

7/25の v2.1.218 は37変更の大きめリリース。目玉は MCP サーバ接続に失敗したとき claude mcp list と /mcp に HTTPステータス＋エラーテキストを出すようになったこと。原因切り分けが一気に楽になった。同じ週、公開Artifactが「開くたびに閲覧者自身のMCPコネクタ」を呼べるようになり、スナップショットではなくライブなダッシュボードを配れる。

📅 2026年7月25日 ⏱ 約2分 🔗 出典 2 件

背景から。MCPサーバを複数ぶら下げて運用する構成が当たり前になり、「接続できない」トラブルの原因切り分けが日々の運用課題になっていた。従来はエラーが抽象的で、認証なのか URL なのか TLS なのか分かりづらかった。v2.1.218（37変更）はその不透明さに手を入れた回だ。

何が新しいか

核心は、MCP接続に失敗した際に claude mcp list と /mcp がHTTPステータスコードとエラーテキストを表示するようになったこと。401なら認証、404ならURL、5xxならサーバ側、と一目で当たりが付く。加えて skill/plugin のフロントマターの真偽値が yes/no/on/off/1/0（大文字小文字問わず）を受理して記述が柔軟化。設定値に紛れた先頭・末尾の不可視空白に警告を出す改善、/config model=<x> やリモート操作でモデルを切り替えたとき fast モードの変化を通知する挙動も入った。「N個のMCPサーバが認証を必要としています」という起動通知が claude.ai コネクタを過剰カウントしていた不具合や、プロンプト履歴の欠落・重複も修正されている。

もう一つの動き：公開Artifactがライブデータに

同じ週（Week29）、公開したArtifactが閲覧されるたびに閲覧者自身のMCPコネクタを呼び出せるようになった。作成時点のスナップショットではなく、開くたびに最新データを取得して必要ならアクションもする「配れるダッシュボード」が作れる。各呼び出しは閲覧アカウント自身の接続を経由し、初回のコネクタ呼び出し前に閲覧者が明示的にアクセスを承認する。見えるのは本人の権限内データだけ。Pro/Max/Team/Enterprise で使え、一般公開（publicly-shared）のArtifactでは無効だ。

実務での使いどころ・注意点

自分ならまず、詰まりがちな社内MCPの接続チェックを /mcp でやり直して、ステータスで一発切り分けする運用に変える。Artifact のライブデータ化は、この読み物置き場のような自分用ダッシュボードを「作者が毎回セッションを回さなくても最新化される」形にできて相性が良い。注意は、ライブArtifactは閲覧者の承認と接続前提なので、権限のない相手には空に見えること。ひとことで言えば「エラーは可視化、Artifactは生モノ化」の回だ。
