静かな週末のClaude Code — v2.1.319の運用要点と、skills→hooks→subagentsの使い分け

週末に新リリースは無く最新は11/6のv2.1.319のまま。/loopの終了挙動やtrust-workspaceといった“止める仕組み”と、3レイヤー拡張の順序を整理する。

📅 2026年11月9日 ⏱ 約3分 🔗 出典 3 件

週末（11/7〜9早朝）に確定した新リリースは無く、Claude Code の最新は引き続き 11/6 公開の v2.1.319（集計サイト gradually.ai が 11/8 に公式 CHANGELOG と照合済みと表示。一次は未照合）。新機能が乏しい日なので、ここでは v2.1.319 で入った運用に効く変更と、周辺記事で整理された skills / hooks / subagents の使い分けを読み物として再構成する。

v2.1.319 の運用ポイント

自己ペースの /loop は1ターンが終わると自動で再スケジュールせず終了するよう変わった（従来どおり回し続けたいなら CLAUDE_CODE_LOOP_KEEPALIVE=1）。セルフホストランナー向けに --trust-workspace false が、リポジトリ設定由来の hooks・skills もまとめて無効化するようになった。セキュリティ面では worktree 作成時のサンドボックス脱出を塞ぎ、Bash の権限判定（環境変数プレフィックスでの回避の修正・広い deny が個別 ask を上書き）も強化。エンタープライズ運用者は、Claude Desktop が 11/10 に会話保持期間（chatSessionRetentionDays）の挙動を変更予定（gateway 起動時警告で予告）な点も要確認だ。

3レイヤーの使い分け

DEV/ofox.ai の完全ガイド（2026-11-07更新）が示す結論は明快だ。まず skills から始め、決定論的な強制が要る所に hooks を足し、並列作業や文脈隔離が要る時に subagents を使う。skills の本体は呼び出し時だけロードされ、常駐する CLAUDE.md と違って「使うまで無コスト」。hooks は PreToolUse を“主要なセキュリティ関門”と位置づけ、matcher: Bash ＋条件で rm * を止めたり、PostToolUse で編集後に linter を走らせる。subagent は親の skill を継承しないので、必要なら skills: で事前ロードする（※ガイドは hook 発火点の数え方などに食い違いがあり、コピー前に要検証）。

現場での効き所

事例面では、GoDaddy が Claude Code を全エンジニア2,000人に Amazon Bedrock 経由で展開しスプリントを約半減（二次報道・測定基準は不明）、PwC×Anthropic は3万人訓練と全社展開を進める（5月付でやや旧聞）。規模の数字は割り引くとして、skills/hooks は自分・プロジェクト用、plugins はチーム横断の共有用という線引きは実務の指針になる。

ひとことまとめ

更新が静かな日は“止める仕組み”を締め直す好機。/loop の終了挙動と --trust-workspace を押さえ、skills→hooks→subagents の順で拡張を組むのが堅い。
