Claude Code

Claude Codeがセルフホストに対応 — 自社インフラでセッションを回し、Opus 5とプラグインzip配布で足回りも刷新

v2.1.224でセルフホスト環境がパブリックベータに。Web/モバイル/定期実行から始めたセッションも自社ネットワーク内のrunnerで動き、内部DBやレジストリへ直結できる。既定OpusはOpus 5（1Mコンテキスト・Opus 4.8と同額）、プラグインはzipのHTTPS配布＋SHA-256ピン留めに対応した回。

📅 2026年8月15日 ⏱ 約3分 🔗 出典 4 件

この数日のClaude Codeは「どこで実行するか」を自社側に引き寄せる方向へ大きく動いた。Anthropicは v2.1.224 でセルフホスト環境をパブリックベータとして公開。Web・モバイル・デスクトップ・定期実行のいずれから開始したセッションも、Anthropicのホスト基盤ではなく自社ネットワーク内で動作し、内部サービス・データベース・レジストリに直接アクセスできる。閉じた環境でエージェントを回したいエンタープライズにとって、これは待望の一歩だ。

何が新しいか。仕組みの中心は runner と呼ぶ常駐プロセスで、これを固定台数（Fixed）またはオンデマンド（On-demand）で配置する。各セッションは個別のチェックアウトで分離され、ソースコードやビルド成果物は自社管理下に留まる。提供はTeam/Enterpriseプラン向けで既定オフ、ZDR（ゼロデータ保持）組織は現時点で非対応という統制寄りの設計だ。あわせてモデル面では v2.1.219 でOpus 5が既定のOpusモデルになり、1Mトークンのコンテキストに対応しつつ価格はOpus 4.8と据え置き。配布面ではアーカイブ・プラグインソースが加わり、zipをHTTPSで取得するだけでgit/npm不要でプラグインを導入でき、任意でSHA-256ピン留めにより内容の同一性を担保できる。

仕組みのポイントは、実行の場所（runner）・分離単位（チェックアウト）・配布経路（zip＋SHA-256）という三層をすべて自社側に寄せたこと。runnerをFixedにすれば常時待機で起動が速く、On-demandにすればコストを抑えられる。プラグインは再現性のあるピン留めで「誰が入れても同じ中身」を保証できる。実務ガイド側でも「Skillがやり方を教え、Hookがルールを強制し、Subagentが作業を隔離する」という役割分担が定番化しており、セルフホストはこの構成を閉域で回すための土台になる。

自分が試すなら、まず小さな内部リポジトリでOn-demand runnerを1本立て、社内DBに触れる定型調査（ログ集計・スキーマ確認）をセッション化して、egressを閉じたまま完結するかを見たい。プラグインはzip＋SHA-256で配布し、チーム全員が同一ハッシュを取得できる運用を試す。Opus 5の1Mコンテキストは、複数ファイル横断のリファクタで効果を測るのに向く。

注意点。セルフホストは既定オフでZDR組織は非対応、runnerの台数設計を誤ると待ち時間かコストのどちらかに跳ねる。/verify・/code-review・/deep-research の自律実行は段階的に廃止されており、これらに依存したワークフローは手動起動やSubagentへの委譲へ組み替えが要る。閉域でも権限・Hookによる破壊的操作の歯止めは省略しない。

ひとことまとめ：今回は「実行の場所・分離・配布」を自社側へ寄せる回。Opus 5とzipピン留めで足回りを固めつつ、エンタープライズが閉域でエージェントを安心して回すための地固めが主眼だ。
