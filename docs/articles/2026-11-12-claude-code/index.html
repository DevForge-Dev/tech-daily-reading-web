Claude Code

Claude Code — v2.1.321でFable 5.2が既定に（値下げ）、cp/mvの保護強化とプラグインskills非ロード

小粒リリースに見えて中身は世代交代。既定Fableが5.2（$8/$40・1M据え置き）へ、cp/mvの宛先ディレクトリにもdeny適用、mod自動有効化と.claude/skills非ロードの破壊的変更が同居する。

📅 2026年11月12日 ⏱ 約3分 🔗 出典 3 件

Claude Code は 11/9 に v2.1.321 をリリースし、11/12 時点でその詳報が出そろった。小粒な機能追加のリリースに見えて、中身は「既定モデルの世代交代（＋値下げ）」「権限・サンドボックスの締め直し」「プラグイン/mod 周りの破壊的変更」と、日々の運用に効く変更がまとまっている。※価格・ベンチ数値は classmethod（英語・機械翻訳）等の二次情報で、一次 CHANGELOG はこのセッション時点で v2.1.311 までしか反映されていない点に注意。

最大の目玉は Claude Fable 5.2（claude-fable-5-2）が既定の Fable モデルになったこと。コンテキストは 1M（100万トークン）を維持したまま、価格が 入力 $8 / 出力 $40 per Mtok・キャッシュ読取 $0.20 へ下がった。旧 Fable 5.1（$10 / $50、$0.25）より素直に安い。記事は「約20%安・最大30%高速」とするが、この数字自体は未検証。

仕組み・運用面で見るべきは権限とサンドボックスのセキュリティ修正だ。(1) cp/mv の宛先にディレクトリを指定して書き込まれるファイルにも、これまで素通りだった deny ルールと保護ファイル確認が効くようになった（/bin/cp のようにフルパス指定しても同じパス検査の対象）。(2) MCP サーバのリダイレクト時にリフレッシュトークン等の秘密が別ホストへ漏れる不具合を修正。(3) 読み取り専用 Bash がサンドボックス外で確認なしに走るケース、権限判定が誤ったフォルダ基準になるケースも修正。無人・自動運用で Claude にコマンドを任せるほど効いてくる守りの変更だ。

いっぽうで破壊的変更は、黙って挙動が変わる類なので把握が必要：保存済みの Fable 5.1 選択は自動的に fable へ移行、Claude が作成した mod は auto/bypass モードでは確認なしに有効化されるようになり、~/.claude/plugins 配下の .claude/skills は読み込まれなくなった。プラグインでスキルを配っている場合、スキルが突然消えたように見えるので要確認。

あわせて公式の「Claude Code パワーユーザーのヒント」も読みどころ。最重要#1は“検証”＝Claude に自分の作業を確かめる手段（フロントエンドなら Chrome 拡張、変更後の /simplify 等）を渡すこと。ほかに claude --worktree で 3〜5 並列、/effort は low〜max（複雑作業は xhigh）、claude -p --bare は約10倍速く起動（代わりに CLAUDE.md・設定・MCP を自動ロードしない）、/loop・/schedule での定期実行。

自分が試すなら：まず既定モデルが 5.2 になった前提でコスト感を測り直す。次に無人ループ（/loop//schedule）を回しているなら、今回の deny/サンドボックス強化が自分のワークフローを壊していないか一度流して確認。プラグインでスキルを配布しているプロジェクトは、.claude/skills 非ロード化の影響を今日中にチェックしておきたい。

ひとことまとめ：「既定モデルが安く速くなった」話より、無人運用の安全弁が一段締まったこととプラグイン/mod の黙示的挙動変更が本題。恩恵と副作用が同居するので、自動化している人ほど一読の価値あり。
