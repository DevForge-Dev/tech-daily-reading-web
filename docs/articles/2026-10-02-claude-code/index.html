Claude Code v2.1.288 — 落ちないエージェントへ、そして『どう社内に配るか』の3軸

派手な新機能より安定性修正に振れた回。部分応答からの継続・自動コンパクトと、5社事例が示す配布の3軸、Claude for Government の一般提供まで。

📅 2026年10月2日 ⏱ 約3分 🔗 出典 6 件

10月2日に公開された v2.1.288 は、派手な新機能より「落ちない・取りこぼさない」方向に振れたリリースだ。同じ10/2には Claude for Government が米政府機関に一般提供開始となり、Claude Code の CLI も FedRAMP High 環境で早期アクセス入りした。毎朝このダイジェストを自動で回している自分には、機能追加より安定性修正と「社内にどう配るか」の知見の方がむしろ本命だ。

何が新しいか（v2.1.288）

信頼性の修正が厚い回だ。応答の途中で API がタイムアウトしてもターン全体を失敗させず、非対話セッションとサブエージェントは受信済みの部分応答から処理を継続する。長い会話で出ていた『Prompt is too long』は自動コンパクトで回避され、--resume のファイル取りこぼしやターン末応答の消失も解消。機能面では、mod 開発向けに最後に選択したテキストを返す $.ui.selection()、GitHub CLI 不在のクラウドセッションへ gh api 内蔵、Ctrl+C で消したプロンプトを空の状態で↑キー復元、/code-review の --max-findings <n>|all、agents 画面の Ctrl+F 検索と Alt+↑/↓ グループ移動が加わった。

使い分けと上級テクニック

今日の技術記事が共通して言うのは「役割で道具を分けろ」だ。CLAUDE.md は毎回読まれる常設ルール向きだが、長いセッションでは初期指示が埋もれるコンテキストドリフトに弱い。スラッシュコマンドは実行タイミングを自分で握る手動トリガー、Skills は説明文から自動検出され条件が合えば発火する（不発もある）能力単位。そして調査・検索・統合が多いタスクはサブエージェントを既定に——別コンテキストで走るので本体スレッドが膨張しない。上級編では、機密ファイルへの書込みを Hooks（PreToolUse/PostToolUse で exit code 2）で遮断し、権限は deny→ask→allow の評価順を使って機密ファイルを deny で「見えなく」する方が Hooks より安全、という原則が刺さった。同じ問題で2連続失敗したら粘らず /clear で汚染リセット、というのも実感に近い。

社内に配るときの3軸

日本 IT 5社（メルカリ/楽天/ZOZO/GMO/Gemcook）の事例から抽出された判断軸は、配布範囲（エンジニアのみ/全社）・自律実行の許容度（承認重視/サンドボックス回避の Auto Mode）・コンテキスト供給の設計（CLAUDE.md・MCP・Plugins・Skills）の3つ。メルカリは MDM で全社配布し非エンジニアが月10〜15時間削減、楽天は並列実行＋チャット連携で機能納期を24日→5日（79%短縮）、ZOZO は Plugins＋Atlassian MCP で準拠チェックを自動化。段階的アクセスを伴う Auto Mode が、二択の許可/拒否に代わる新標準になりつつある。

自分が試すなら

まず /code-review --max-findings all で一度すべて出させて指摘の母数を把握する。次に Explore 系サブエージェントへ調査を委譲する運用を標準化し、CLAUDE.md は『この行を消すと間違えるか？』で各行を精査して短く保つ。落とし穴は Skills の不発——危険操作の Skill は disable-model-invocation: true で手動限定にしておくと事故りにくい。

ひとこと：派手さはないが「長く回しても落ちない」土台が固まった回。社内展開は機能より運用設計（3軸）が勝負どころ。
