Claude Code

v2.1.251でモデル切替フック＋前景サブエージェントのライブ配信、v2.1.248でrestricted mode — /usageに支出上限バー・/costにprompt-cache行

新モデルではなく「切替・実行・支出」を見張る足回りを固める更新。Pre/PostModelSwitchフックで切替を遮断・確認・注記、前景サブエージェントの実行はRemote Controlへライブ配信。restricted modeが破壊的操作を一括ブロックし、/usageの支出上限バーと/costのprompt-cache行で使いすぎに気づける。査読論文はマージPR約24%増、30人組織で35%向上が4か月持続と報告。

📅 2026年8月31日 ⏱ 約4分 🔗 出典 5 件

今日のClaude Codeは新モデルの発表ではなく、「切替・実行・支出」を見張って制御する足回りを固める一日だった。最新の v2.1.251（8月28日）では、モデルを切り替える前後で発火する PreModelSwitch / PostModelSwitch フックが加わり、切替を遮断・確認・注記できるようになった。前景で走るサブエージェントのツール呼び出しと結果を Remote Control クライアントへライブ配信できるようにもなり、遠隔からの進捗把握がしやすい。SessionStart の resume フックはセッションの陳腐化度と再キャッシュ推定コストを受け取れるようになり、再開時の判断材料が増えた。

何が新しいか

直前の v2.1.248（8月27日）でrestricted mode（制限モード）が導入され、破壊的コマンドやリポジトリ外への書き込みといった高リスク操作をまとめて遮断できるようになった。あわせてエージェント型ワークフロー向けの新しいキャッシュ設定が入り、繰り返し実行の効率が上がる。さらに v2.1.247 では問題発生時にClaude自身がフィードバック報告を自動下書きする機能も追加された。可観測性の面では、支出上限のあるゲートウェイ利用者向けに /usage へ「Spend limit バー」が付き、ステータスライン用の rate_limits.spend_limit フィールドも用意された。/cost にはセッション単位の prompt-cache 行が加わり、ヒット率・ミス・再キャッシュ量・warm/cold を確認できる。新設の環境変数 ANTHROPIC_DEFAULT_MODEL で新規セッションの開始モデルを固定でき、SendMessage の notify_when_idle で別セッションのアイドル通知も頼める。

仕組みのポイント

モデル切替フックは UserPromptSubmit や PreToolUse と同じイベント駆動の系譜で、PreModelSwitch が発火した時点で切替をブロック（非ゼロ終了）したり、切替理由をログへ注記したりできる。restricted mode は「許可の網羅列挙」ではなく「危険カテゴリを既定で閉じる」発想で、ホワイトリスト運用の初期コストを下げる。/cost の prompt-cache 行は、長いセッションでどれだけキャッシュが効いた（warm）か・再キャッシュ（cold）でトークンを食ったかを可視化し、支出の内訳を掴ませる。これは /usage の Spend limit バーと対になって「使いすぎる前に気づく」導線になっている。

実務での使いどころ・自分が試すなら

まず CI や共有環境では restricted mode を既定にして、破壊的コマンドとリポジトリ外書き込みを塞いでおきたい。PreModelSwitch で「高コストモデルへの切替時に確認を挟む」フックを書けば、無自覚なモデル格上げによる支出増を抑えられる。長時間タスクは /cost の prompt-cache 行を見て、cold が多い箇所（コンテキストの積み過ぎ）をCLAUDE.mdの短文化やスキルのオンデマンド読込で削るのが効く。事例面では、Microsoft Researchの査読付き実地調査が導入チームでマージPR約24%増を報告し、30人規模の組織では共有スキル22本・フック11本を整えて35%の生産性向上が4か月持続したとされる。効くのは「配布」ではなく運用の型づくりで、まず1チームでCLAUDE.mdとフックを磨いてから横展開するのが定石だ。

注意点・落とし穴

更新頻度が非常に速く、フック名・タブ・環境変数が短期間で増える。破壊的変更の有無を確認しつつこまめに追従する前提で運用したい。restricted mode は安全側に倒す反面、正当な操作まで塞ぐことがあるので、遮断が起きたら「なぜ塞がれたか」を確認してから緩める。査読論文が示す通り、生産性向上の裏でトークン支出が膨らむため、Spend limit バーと予算ガバナンスの整備は導入とセットで考える。

ひとこと

モデルが一段落し、Claude Codeは「毎日安全に、支出を見ながら使い倒す」ための制御レイヤを着実に厚くしている。派手さはないが、道具としての信頼性が上がる更新だ。
