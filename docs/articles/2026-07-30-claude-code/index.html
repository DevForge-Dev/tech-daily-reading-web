Claude Code

拡張の役割分担を決める — Hooks・Skills・Subagents・MCP の使い分けと自律コマンドの手動化

SmartScope/Tembo/Totalum の実践ガイドが揃って示す結論は「強制はHooks、知識はSkills、分離はSubagents、常時指針はCLAUDE.mdに短く」。あわせて /verify・/code-review・/deep-research が手動起動へ、EndConversation も追加された。

📅 2026年7月30日 ⏱ 約2分 🔗 出典 4 件

エージェント型コーディングが日常運用に入り、関心は「どんな機能があるか」より「どれをどこで使い分けるか」へ移った。今日は上級ベストプラクティスの記事が3本そろい（SmartScope／Tembo／Totalum）、拡張機構の役割分担という指針が固まった。

核心はシンプルだ。ルールを強制したいならHooks／permissions（決定論的にライフサイクルを制御し品質ゲートを敷く）、知識・手順はSkills（YAML＋MarkdownのSKILL.mdで、呼ばれるまで本文をロードしないコスト小の再利用プロンプト。メイン会話の文脈で動く）、作業の分離はSubagents（専用システムプロンプト・限定ツール・独立権限・固有コンテキストで隔離実行）、外部連携はMCP、そして常時参照するCLAUDE.mdは短く保つ。Subagentはname／description／tools／modelの4フィールドで挙動が決まり、とりわけdescriptionが自動起動のトリガーになる。

あわせて安全側の既定も動いた。Claudeは/verify・/code-review を自発的に実行しなくなり、使いたいときだけ手動起動する方式へ。/deep-research も手動のみになり、極端に虐待的なセッションを閉じるEndConversationツールが加わった。WebSearch・サブエージェント生成・Bash実行のセーフガードも強化されている。7/24のv2.1.220は新機能を足さずバグ修正に専念した安定化リリースで、直前の大型変更（/fork刷新等）を均す位置づけだ。

自分が試すなら：副次タスクはSubagentの隔離コンテキストへ逃がし、本体の文脈を汚さない。コミット前チェックはHooks＋permissionsで固定する。注意点：/verify・/code-reviewが自動で走らなくなった分、品質ゲートは自分で明示的に叩く運用へ切り替える。descriptionが曖昧だとSubagentが「呼ばれない／呼ばれ過ぎる」ので一文で用途を絞ること。ひとことまとめ：機能を足すより、Hooks／Skills／Subagents／MCPとCLAUDE.mdの役割を決めることが、いまの生産性を左右する。
