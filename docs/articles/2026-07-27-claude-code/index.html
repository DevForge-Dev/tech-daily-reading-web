v2.1.219 で Opus 5 が既定Opusに — strictAllowlist・DirectoryAddedフックと自走の安全弁

7/24 リリースの v2.1.219 が既定Opusを 1M文脈の Claude Opus 5 に切り替え、あわせて27件のCLI変更を投入。許可リスト外ホストを無確認で拒否する sandbox.network.strictAllowlist、作業ディレクトリ追加時に発火する DirectoryAdded フック、Dynamic workflow のサイズ指針 workflowSizeGuideline が加わった。「賢いモデル」と「安全に自走させる土台」が同じ回で進んだ。

📅 2026年7月27日 ⏱ 約2分 🔗 出典 3 件

なぜ今これが話題か

エージェント型コーディングが日常運用に入り、焦点はモデルの賢さと無人でも安全に回す統制の二つに割れてきた。7/24 の v2.1.219 はその両輪を同じ回で進めた大型アップデートで、既定Opusを刷新しつつサンドボックス・フック・ワークフロー周りの締め直しを一度に入れた。

何が新しいか

核心は既定Opusの切り替えだ。Claude Opus 5（claude-opus-5）が1Mトークン文脈を既定として載り、あわせて27件のCLI変更が入った。安全面では sandbox.network.strictAllowlist が許可リスト外ホストへの接続を確認プロンプトなしで拒否する。運用面では、セッション途中に /add-dir やSDKの register_repo_root で作業ディレクトリが増えたときに発火する DirectoryAdded フック、Dynamic workflow のサイズ指針を任意の設定から指定する workflowSizeGuideline キーが追加。Fast モードは2倍コストで約2.5倍速という位置づけも明示された。直前後の changelog では、サブエージェントのテキストストリーミング（途中経過のリアルタイム表示）に対応し、/code-review がバックグラウンドのサブエージェント実行へ、ネスト深さは既定3まで緩和された。

実務での使いどころ

自分なら Opus 5 を日常の既定に据えつつ、無人サンドボックス実行では strictAllowlist をオンにして外部到達を封じる。長時間の自動処理では DirectoryAdded フックで作業ディレクトリ追加を検知し、監査ログやフォーマッタ起動につなげる。/code-review はそのまま回せばバックグラウンド実行でメイン会話ログを汚さない。

注意点・落とし穴

1M文脈・Fastモードはトークンとコストが増える方向。軽い作業では文脈や速度を欲張らない。strictAllowlist は正当な外部依存（パッケージ取得等）まで止めうるので、許可リストの初期設計が要る。ネスト深さ3の緩和は便利だが、多段委譲は暴走fan-outの温床になりやすく、同時実行数の把握は引き続き重要。

ひとことまとめ

v2.1.219 は「既定を強く、実行を安全に、運用を可視化」の回。Opus 5 を既定に置きつつ strictAllowlist と DirectoryAdded で自走の安全弁を締めるのが今日の実践だ。
