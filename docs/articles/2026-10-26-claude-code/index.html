10/26のClaude Code — 新規版なしでも効く「強制はフックへ」の設計術と、採用で初逆転した市場データ

本日時点の最新はv2.1.310（10/23）で24〜26日の新規リリースは未確認。だがこの日の読みどころは版番号ではなく、CLAUDE.mdを“文脈”、permissions/フックを“強制”と割り切る運用術と、法人採用でAnthropicがOpenAIを初めて上回ったRampの数字だ。

📅 2026年10月26日 ⏱ 約4分 🔗 出典 6 件

2.1系は10月に入ってからも小刻みなパッチが続いている。2026/10/26(JST)時点の最新は v2.1.310（10/23） のままで、10/24〜26付の新規版は確認できない。新機能を追う日ではないが、直近の積み重ねは「何を制御に使うか」の思想がはっきりしてきた点で読む価値がある。

v2.1.309（10/22） は claude ultrareview にワークスペースの信頼を必須化した。スクリプトからは --trust-workspace 指定か CLAUDE_CODE_DISABLE_ULTRAREVIEW_TRUST_CHECK=1 が要る。併せて sed -i を通常のBashコマンド扱いに変更。v2.1.307（10/21） はCode Reviewに @claude review stop を追加し、OpenTelemetryに claude_code.safety_event イベントを増やした。v2.1.304（10/19） は /auto-mode-setup と /claude-api managed-agents-secure を追加。MCPでは、非対話セッションでサーバーのelicitationが未応答のままツール呼び出しがタイムアウトした場合、「応答が来なかったので同じ呼び出しを繰り返すな」とClaudeに伝える挙動も入った。

何が新しいか：「文脈」と「強制」を混ぜない

SmartScopeの上級ガイド（10/13更新）が整理する要点がこの日いちばん効く。CLAUDE.md は“共有される文脈”であって、強制可能なアクセス境界ではない。実行を本当に止めたいなら、その制御は permissions とフック に置く。フックはイベントペイロード・判定・終了挙動という契約に従って初めて“制御”として働くので、いきなり何本も書かず、まず検証フックを1本 作り、「許可される操作1件」「ブロックされる操作1件」が正しく動くか確かめてから広げる。これは実装の鉄則で、WindowsでGit Bash不在かつ引用符だけのフックコマンド時にフックがツール呼び出しをすり抜けていた不具合（v2.1.310で修正）のような“静かな素通り”を自分で検知できる体制につながる。

実務での使いどころ・試すなら

まず既存の雑多なCLAUDE.mdから「守らせたいルール」を1つだけ抜き出し、PreToolUse系のフックに移してテストする。サブエージェントは、実装コンテキストを圧迫する調査（大量ファイルの横断確認など）の委譲に使い、対象ファイル・問い・編集権限・返すべき証拠 を明示する。コンテキストは、残す設計/テスト詳細を指示した /compact、無関係作業は新規会話、/clear 前に未解決の問いと再現手順を記録、で回す。

市場データ：採用でAnthropicが初めて前に出た

事業面も節目だ。RampのAI指標（2026年8月データ・9月公表）で、観測対象企業のうち Anthropicに支払った法人が43.8%、OpenAIが39.8% で約4ポイント差。これは“法人の購買シェア”であって、エンタープライズAI売上全体のシェアではない点に注意だが、コーディング用途でのClaude定着が背景にある。資金面ではシリーズGで300億ドルを調達、評価額3800億ドル、Claude Codeの年換算売上は25億ドル超（2026年初から倍増）と報じられている。

ひとことまとめ

版が止まっていても“運用の質”は上げられる。CLAUDE.mdに期待しすぎず、止めたい操作はフックへ。検証は1本ずつ。採用面の追い風は、この使い分けを社内標準にする後押しになる。
