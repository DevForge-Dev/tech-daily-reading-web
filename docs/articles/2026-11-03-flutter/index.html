11/3のFlutter — signals_flutter 7.1で『読んだ.valueだけ』を再描画する細粒度リアクティビティ（＋Dart 3.14で Isolate.runSync が消える注意）

Provider/Riverpodのプロバイダ単位rebuildに対し、値単位で再描画を絞るsignalsの3プリミティブを深掘り。あわせてDart 3.14 betaの同期Isolate撤回という実務注意も押さえる。

📅 2026年11月3日 ⏱ 約3分 🔗 出典 4 件

背景・なぜ今これか。 Provider/Riverpodは「プロバイダ単位」で再描画するため、1つの値変更が広めのwidget再構築を誘発しがち。SolidJS/Preact由来の signals（umbrella signals / Flutterは signals_flutter、current 7.1.0）は、読んだ .value を自動追跡しその値を読んだwidgetだけをdirty化する細粒度リアクティビティで、BuildContextもcodegenも要らない。

3つのプリミティブ。 signal(0)（書込可能・.valueで読み書き）、computed(() => count.value * 2)（遅延＋memo化＝読まれた時だけ計算しキャッシュ）、effect(() => print(count.value))（読んだsignalを自動購読し変化で再実行、戻り値のdispose関数で解除）。依存は実行時に読んだものだけ登録される（pullベース＝書いた瞬間でなく次に読まれた時に再計算）。

final count = signal(0);
final doubled = computed(() => count.value * 2);

// Flutter接続：builder内で読んだsignalだけ再構築
SignalBuilder(builder: (context) => Text(count.value.toString()))

バッチと非追跡。 batch(() { a.value = 1; b.value = 2; }) で複数更新を1トランザクションにまとめ途中の再計算/再描画を抑制、untracked(() => a.value) や signal.peek() で依存登録せず値だけ覗ける（effect内で読みたいが購読したくない時）。旧 Watch((context) => …) は deprecated で、SignalBuilder への移行が推奨される。

勘所。 rebuildを絞るため SignalBuilder は木の深い位置に置く（高位で全体を包むと利点が消える）。computed は副作用禁止の純粋関数、effect のdispose忘れはリーク源。既存資産とは ValueNotifier↔signal 変換で段階導入できる。

あわせて注意：Dart 3.14。 beta（3.50系同梱）のDart 3.14では、3.13で実験的に入った同期Isolate API（Isolate.runSync 等）が撤回（unship）される。少し前に「今すぐ使える」と紹介された runSync は3.14で消えるので本番採用は見送りが無難。重い処理の退避は従来どおり Isolate.run / compute（ただしWebはisolate非対応でメインスレッド実行）に寄せる。新ツール dart migrate も入り、各依存のSDK制約下限を1マイナーずつ段階的に引き上げられる。

ひとことまとめ。 「再描画を値単位まで絞りたいならsignals」「Dart 3.14でrunSyncは消えるのでisolateはIsolate.runに寄せる」。
