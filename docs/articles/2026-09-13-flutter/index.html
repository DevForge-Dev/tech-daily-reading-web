Flutter 2026『Finishing the Job』— Android legacy Skia撤去でImpeller一本化、Web WasmGCへ

既存機能を『完成させる』実行フェーズ。Android 10+でlegacy Skiaを撤去しImpeller(Vulkan)へ一本化、WebはWasmGCを既定ターゲットへ前進。ラスタライズがボトルネックでなくなった今、最適化の軸はbuild/layoutへ移る。

📅 2026年9月13日 ⏱ 約3分 🔗 出典 5 件

2026年のFlutterは新機能の乱発でなく「Finishing the Job（やりかけを完成させる）」を掲げる実行フェーズにある。今日の主役はレンダリング基盤の一本化だ。Android 10+（API 29+）で legacy Skia backend を撤去して Impeller(Vulkan) に集約し、WebAssembly(WasmGC) を Flutter Web の既定コンパイルターゲットへ前進させる。地味だが、日々のパフォーマンスの前提が変わる更新だ。

何が新しい/重要か

Androidは中間抽象を挟まずネイティブGPUを直接叩き、全shaderをbuild時にAOT precompileして first-run jank（初回のカクつき）を排除する。Webは flutter build web --wasm（WasmGC）でopt-in、dart:html→package:web 移行を前提に起動高速化とJSブリッジ縮小を狙う。ロードマップの4本柱は Performance(Impeller)・Tooling/DX・Web/Accessibility・Stability＋AI（GenUI SDK / Dart-Flutter MCP Server）。2026は年4回（2/5/8/11月）のstableをコミットする。現行安定版は Flutter 3.47.x / Dart 3.13.x、次の機能リリースは2026年11月見込みで 3.48 / Dart 3.14 が beta。

仕組みのポイント（最適化の軸が移った）

Impellerが全shaderをAOTでコンパイルした結果、frame rasterization はもはや主要ボトルネックでない。今しばしば効くのは widget build と layout computation だ。DevTools Performance では rebuild count と layout pass duration を主要指標にする。最も多い根因は不要な rebuild で、対策は const 徹底・大きな build() の分割・最小スライス購読（ref.watch(provider.select(...)) / BlocSelector）・アニメ領域の RepaintBoundary 隔離。重い計算は Isolate.run()/compute() で背景isolateへ逃がす。計測は必ずprofileモードで（debugはJIT/assertで歪む）。

アーキテクチャの定番

状態管理と画面遷移も棚卸ししておく。ルーティングは go_router が公式標準（月間128万DL超、deep link・browser history・auth redirect・tab shell を自動処理）。新規プロジェクトの既定は Riverpod 3.3.1＋@riverpod codegen、監査証跡が要る規制業界（fintech/healthcare）や複雑並行は Bloc 9.1.1（hydrated_bloc で永続化）。両者は ProviderScope と MultiBlocProvider で共存できる。アニメは micro=implicit → 宣言的多段=flutter_animate → component=explicit → 共有要素=Hero と用途で使い分け、重いアートは Rive にオフロードして事前ロードする。

ひとことまとめ

基盤を「完成」に寄せる年。Android Skia撤去でImpeller一本化、WebはWasmGCへ。ラスタは片付いたので、次に削るのは rebuild と layout。profileモードで rebuild count を見るのが今日からの基本動作だ。
