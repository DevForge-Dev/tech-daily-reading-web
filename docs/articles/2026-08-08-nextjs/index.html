dnd-kit 新アーキ（@dnd-kit/react v0.5.0）— App Routerで並び替えを「{ref}一発」に

掴んで並び替えを最小配線で。旧@dnd-kit/coreのattributes/listeners/transform手配線が、新@dnd-kit/reactでは{ref}を刺すだけに。moveヘルパ・PointerSensor統合・アクセシビリティ既定ON・prefers-reduced-motion自動対応。0.xゆえ本番はバージョン厳密固定で。

📅 2026年8月8日 ⏱ 約4分 🔗 出典 3 件

ドラッグ&ドロップと並び替え（sortable / Kanban / リスト整列）は、Reactが最も苦手にしてきたインタラクションの一つ。デファクトの dnd-kit がここ1年でゼロから作り直され、旧 @dnd-kit/core 系（v6・安定）とは別物の新パッケージ @dnd-kit/react（現行 v0.5.0・2026年6月） が実用段階に入った。旧版の「useSortable が返す attributes/listeners/setNodeRef/transform/transition を全部自分で配線する」冗長さが、新版では {ref} を要素に刺すだけに激減する。

何が新しいか

層構造は、FW非依存コア @dnd-kit/abstract → DOM実装 @dnd-kit/dom → 薄いReactアダプタ @dnd-kit/react。インストールは @dnd-kit/react と sortable用の @dnd-kit/helpers の2つで足りる。API は DragDropProvider（旧 DndContext）で包み、useSortable({id, index}) が返す {ref} を刺すだけ。SortableContext ラッパは不要。並び替え結果は move(prev, event) ヘルパが計算する（旧 arrayMove 相当）。PointerSensor がマウス・タッチ・ペンを Pointer Events で統合し、KeyboardSensor と共に自動登録される＝無設定でキーボード操作可。アクセシビリティプラグインが既定で有効で、ライブリージョン読み上げ込みで WCAG 2.1 AA を満たす。prefers-reduced-motion も v0.2.4 で全アニメ自動尊重。

    App Routerでの組み込み

    方針は「掴む島」だけ Client、データ取得とページ本体は RSC のまま。初期順序は RSC で取得して Client島に props で渡す。SSRハイドレーションは、items state をサーバー由来の順序で初期化し描画順と一致させれば mismatch は出ない。永続化は onDragEnd でまず setItems(move(...)) の楽観更新 → Server Action で新順序をDB保存 → revalidateTag。保存失敗時は前配列にロールバック。認可・バリデーションは必ずサーバー側で行い、クライアントの並び順を鵜呑みにしない。

    落とし穴

    touch-action: none を付けないとモバイルでスクロールと競合。key に配列 index は禁止（安定idを使う。index だと並び替えが破綻）。useSortable の index が描画順とズレると同種の事故。センサはインライン配列で毎回生成せず安定参照に。そして 0.x は実験版でマイナーに破壊的変更があり得るため package.json は厳密固定し、堅実運用なら旧安定版（core）も選択肢。Tailwind v4 併用時は @layer dnd-kit 対応済みの新しめのバージョンに上げる。

    ひとことまとめ：並び替えの「操作そのもの」を、最小配線・a11y既定・reduced-motion自動で。実験版ゆえバージョン固定は必須。
