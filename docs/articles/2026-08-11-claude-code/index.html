セッション制御が一段強化 — /fork がバックグラウンド化・/subtask 独立・WebSearch 200回上限、支出上限警告も

Opus 5 が既定になった裏で、長時間・並列運用を安定させるセッション制御とコスト暴走対策が相次いで入った。

📅 2026年8月11日 ⏱ 約2分 🔗 出典 3 件

大きな話題は Claude Opus 5 が CLI v2.1.219 で Claude Code の既定モデルになったこと（入力 $5／出力 $25・Opus 4.8 据え置き、約8割のエンジニアリング作業をカバー、MCP 2026-07-28 仕様対応）だが、日々のパッチで地味に効いているのはセッション運用まわりの整理だ。エージェントを何時間も走らせる使い方が普通になり、暴走やコスト膨張をどう抑えるかが実務課題になっている。

変更の中心は3つ。第一に /fork が、会話を新しいバックグラウンドセッションへコピーして並行実行する挙動に変わった。元の作業を止めずに別方針を試せる。第二に、従来 /fork が兼ねていた「セッション内サブエージェント」は /subtask として独立し、役割が明確化した。第三に、検索ループの暴走を止めるため WebSearch にセッション全体で既定200回の上限が付き、CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION で調整できる。さらに v2.1.225 では使用量警告にゲートウェイの支出上限が加わり、上限額・リセット時刻・運用者メッセージを明示。未信頼ディレクトリへのワークスペース信頼プロンプトも claude 側と統一された。

使いどころ。長い調査を回しながら別ブランチの検証を試したいときは /fork で分岐し、本筋を止めない。逆に、無関係な副次作業でメインの文脈を汚したくないときは /subtask に投げてコンテキストを隔離する。検索を多用するエージェントには200回上限が保険になり、支出上限警告はチームの予算管理を見通しやすくする。

落とし穴。/fork と /subtask は名前が近いが役割が逆方向（並行 vs 隔離）。混同すると、意図せず作業が別セッションに分裂したり、共有したい文脈が切れたりする。検索上限に達すると調査が途中で止まるので、大規模リサーチ時は環境変数を先に引き上げておくとよい。

まとめ：Opus 5 で「賢さ×コスト」を底上げしつつ、/fork・/subtask・検索上限・支出上限で「長時間・並列でも暴走させない」土台が整った回。まず自分のワークフローで fork と subtask の使い分けを言語化しておきたい。
