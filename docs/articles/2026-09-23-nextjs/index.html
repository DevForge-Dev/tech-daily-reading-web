SVGだけで作る円形プログレス／リングUI — stroke-dashoffsetのdeterminateと、conic-gradient・<progress>の使い分け

KPIやアップロード進捗の「円で見せる」UIは、ライブラリ無しでSVGの円＋stroke-dashoffset一本で軽量に作れる。3方式の使い分けと、App RouterでのRSC/Client切り分けを整理する。

📅 2026年9月23日 ⏱ 約4分 🔗 出典 3 件

ダッシュボードの KPI、アップロード進捗、スコア、ポモドーロ、読了率——「円で進捗を見せる」UI は頻出だが、ライブラリを入れなくても SVG の円＋stroke-dasharray/stroke-dashoffset だけで依存ゼロ・軽量に作れる。線を描くアニメ全般ではなく、本稿は 0〜100% の determinate な進捗に絞り、(1) SVG ストローク、(2) conic-gradient＋@property、(3) ネイティブ <progress> の 3 系統をどう選ぶかまで整理する。

仕組み：破線を「どこまで見せるか」で進捗にする

<circle> の輪郭線を 1 本の破線に見立て、実線長＝円周にして「実線をどこまで見せるか」を stroke-dashoffset でずらす。円周は 2 × π × r（r=45 なら約 282.74）。stroke-dasharray＝円周、stroke-dashoffset＝円周 ×(1 - progress/100)。円弧は 3 時方向始まりなので、上(12 時)始まりにするには CSS で transform: rotate(-90deg)（transform-box: fill-box 併用）。丸端は stroke-linecap: round。アニメは stroke-dashoffset を CSS transition で補間するのが軽い。

3方式の使い分け

SVG ストローク＝最も柔軟で既定。丸端・多重リング・目盛り・アイコン合成・細かな a11y に強い。conic-gradient＋@property＝DOM 1 要素で「塗り」進捗（パイ）に向くが、丸端が作りにくく、アニメには @property 登録が必須（未登録のカスタムプロパティは補間できない）。<progress>＝直線バーなら a11y 無料だが円形にはできない。indeterminate（不定スピナー）は短い弧を作り @keyframes spin で回すのが定番。

// progress(0-100) → stroke-dashoffset
const r = 45, c = 2 * Math.PI * r;      // 円周 ≈ 282.74
el.style.strokeDasharray  = String(c);
el.style.strokeDashoffset = String(c * (1 - p / 100));

Next.js（App Router）での切り分け

静的な determinate リング（初期表示だけ動かさない）は Server Component のままでよい。progress を props で受け、stroke-dashoffset をサーバ側で計算して属性に埋めるだけ——'use client' 不要・JS 0KB。値がクライアントで動く（アップロード・カウントダウン・スコア加算）ときは、そのリング描画だけを小さな Client 島に切り出し、ページ本体は RSC のまま。indeterminate スピナーは純 CSS 回転なので loading.tsx/<Suspense fallback> にそのまま置ける。読了率リングは animation-timeline: scroll() のスクロール駆動で --p を 0→100 に補間すれば JS ゼロで作れる。

注意点

<circle> の線幅は中心線基準なので、線の半分が viewBox 外に切れることがある——余白を持たせるか r を線幅ぶん小さく。a11y はラッパーに role="progressbar"＋aria-valuemin/max/now を付け、SVG 本体は aria-hidden="true"。indeterminate には aria-valuenow を付けない（誤読の元）。prefers-reduced-motion: reduce では回転を止め、determinate も transition: none で最終値へ即スナップ（情報は失わない）。

ひとことまとめ

「円の進捗」は stroke-dashoffset 一本で足りる。App Router では静的＝RSC、動く部分だけ Client 島に切るのがきれいな設計。
