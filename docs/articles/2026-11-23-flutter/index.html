描画エンジン Impeller — SkSL warm-up 時代の終わり

Impeller は Skia に代わる新レンダリング runtime で、設計の肝はシェーダをエンジンビルド時に事前コンパイルすること。従来 Skia は実行時にシェーダをコンパイルし初回表示で jank（カクつき）を生みがちだったが、Impeller は事前コンパイル済みで描画が予測可能になる。既定状況は、iOS/Android(API 29+) が 3.27 から既定、iOS は Skia に戻せない唯一エンジン、Vulkan 非対応や API<29 の Android は legacy OpenGL へ自動退避、macOS/Linux/Windows は 3.47 で既定（将来 opt-out 廃止予定）、web はまだ Skia。実務インパクトは、Skia 時代に初回 jank を手当てした --bundle-sksl-path などの SkSL warm-up が役目を終えること。残るコストは raster thread 側＝saveLayer・過剰な半透明・ブラー・AA で、計測は DevTools の Performance view で続ける。

不変モデル freezed 4.0 — primary constructors 対応

状態管理で載せる immutable モデルの定番 freezed（Riverpod と同じ Remi Rousselet 作）は、@freezed abstract class X with _$X ＋ factory から copyWith/==/hashCode/toString/fromJson を自動生成する。バージョン史が要点で、3.0.0 で map/when を削除して Dart 3 の switch パターンマッチへ寄せた後、移行緩和で 3.1.0 に復活、4.0.0(2026-08) で primary constructors に対応。4.0.0 の breaking は「コンストラクタ引数内の final キーワード廃止」（Dart 3.13 が構文を許可しなくなったため）。sealed union は各 factory がサブクラス化し、ネイティブ switch/if-case で網羅分岐できる。

再生専用 lottie と、Rive との対比

アニメーションでは lottie 3.8.2（After Effects 由来の JSON を純 Dart で“再生”する player）。前回扱った Rive が入力で分岐する state machine なのに対し、Lottie は決め打ち再生（分岐なし）。描画コストの要は v3.0 の renderCache（RenderCache.raster でフレームをビットマップ化＝同一アニメ多数で CPU/GPU 削減・メモリ増）と frameRate の間引き。実行時の色/位置差し替えは LottieDelegates/ValueDelegate、3.7.0 で slots 対応。最低 SDK は Flutter 3.47 / Dart 3.13 へ引き上げ。

ひとことまとめ

新機能ゼロの日は“土台”を確認する日。iOS は Impeller 固定で SkSL warm-up は過去、状態モデルは freezed 4.0、再生専用アニメは lottie の renderCache。そして tracker ではなく配布物を信じる。
