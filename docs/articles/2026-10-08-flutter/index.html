DevCon 2026 Day2 — Dart Primary Constructors でボイラープレート撲滅（＋Augmentations）

クラスヘッダに引数を直接書く新記法で、フィールド宣言・初期化・引数の三重定義が1行に。macros停滞の穴はAugmentationsが埋める。

📅 2026年10月8日 ⏱ 約3分 🔗 出典 4 件

DevCon 2026 の Day 2（10/8）言語トラックで、Dart の次の目玉「Primary Constructors」が実演された。無期限ポーズ中の macros に代わり、ボイラープレート削減を言語機能側から進める動きで、Flutter の data class や @riverpod の Notifier まわりの「同じ名前を何度も書く」苦痛に効く。

何が新しいか。クラスヘッダに引数を直接書けるようになる。class Point(final int x, final int y); と書くだけで、フィールド宣言・this.x 初期化・initializer list の三重定義が1行に畳まれる。const、named（class User({required final String id})）、先頭 _ の private named parameter にも対応する。

仕組み。ヘッダのパラメータが、暗黙のフィールド宣言＋初期化として展開される。従来との差は次の通り。

// 従来：id / name を実質3回記述
class User {
  final String id;
  final String name;
  const User({required this.id, required this.name});
}

// Primary Constructor：ヘッダ1行
class User({required final String id, required final String name});

合わせて Augmentations（augment class / augment 宣言）も要注目。既存クラスにメンバーを後付けで「追記」でき、生成コードを本体から分離できる。これが止まっている macros の穴を部分的に埋める。codegen 自体は引き続き build_runner ＋ source_gen が担う。

自分が試すなら。まずボイラープレートが最も多いモデル層（API レスポンスの data class）で素振りし、次に @riverpod の Notifier サブクラスへ。既存コードの一括移行は急がず、新規ファイルから少しずつ。

注意点。現行の安定版は Flutter 3.47.5 / Dart 3.13.4、beta が 3.49 系 / Dart 3.14.0 で、Primary Constructors はまだ固まりきっていないプレビュー段階。private named の _ 規則など記法が変わる余地があるため、本番コードの全面書き換えは時期尚早。

まとめ。「同じ名前を3回書く」Dart の宿痾に、ついに言語側のメスが入った。次期 stable 3.50（11月）の WasmGC 既定化・Impeller 一本化と並んで、2026 後半の Flutter/Dart は「書く量を減らす」方向に明確に舵を切っている。
