Claude Code

10/29のClaude Code — v2.1.312が固める「無人で安全に長く走る」地固めと、成熟したエコシステム

oidc.user_id_claimによる企業ID名寄せ、巨大CLAUDE.mdの先頭読み上書き修正、VS Code管理設定の取得漏れ修正。派手さより信頼性。あわせて拡張4機構の使い分けと採用統計(職場39%)を読む。

📅 2026年10月29日 ⏱ 約3分 🔗 出典 4 件

この日の焦点は最新版 v2.1.312（10/27公開、10/29 JST時点で最新。10/28の新規リリースは未確認）だ。いずれも「見ていなくても安全に、長く走らせる」ための地固めで、新機能の華やかさよりも運用の信頼性に寄った週である。

追加されたのは2点。企業の認証基盤に合わせ、Claude appsゲートウェイで sub 以外のクレームからユーザーを識別できる oidc.user_id_claim（ID基盤に沿った名寄せが可能に）と、フルスクリーン表示でキューに積んだメッセージをクリックして送信する操作。修正は地味だが効く2件で、非常に大きいCLAUDE.mdやルールファイルを「先頭だけ読んだ状態で上書き」してしまう不具合と、VS Code拡張からサインインした後に managed settings が取得されない不具合が潰れた。長文ルールを運用する身には前者が特に重要だ。

補足として前日枠で未掲載だった v2.1.310（10/23〜25）も読んでおきたい。Monitorツール／プラグインMonitorが Amazon Bedrock・Google Vertex・Microsoft Foundry 経由でも使えるようになり（マルチプロバイダ対応）、Claude Enterprise のカスタムロールに「クラウドセッション」権限が加わった。さらにタイムアウトしたMCPツール呼び出しを同じ内容で再実行しないようClaudeに伝える変更が入っており、無人運用での暴発を抑える方向だ。

技術記事側では、4拡張機構の実務的な使い分け（上図）が刺さる。要は「skill.md本体は短く保ち、例や雛形は別ファイルへ」「Subagentには狭い仕事を与え構造化した要約だけ返させる」。hookify プラグインを使えば /hookify で会話形式のままHookを作れる、並列作業は /fork やgit worktreeで競合を避ける、といった小ネタも効率に直結する。

ニュースの目玉はJetBrains調査（15,000人超、5〜7月）で、Claude Codeを「職場で使う」開発者は39%（1月の18%から倍増）、主要ツール比率は夏期31%・米国では47%に達した。Copilotは21%（-8pt）、Codexは16%（+13pt）、Cursorは12%（-6pt）という勢力図だ。npm累計は約5.63億DL、GitHub約15万star。※39%は「利用率」でありシェアそのものではない点、Anthropic社内の「コミット約5倍」は因果の生産性向上を示すものではない点に注意したい。

自分が試すなら：巨大CLAUDE.mdの上書き修正が入ったので、まずローカルを v2.1.312 に上げ、長文ルールの編集が壊れないか確認。並行して「譲れないルールはHookへ」の原則で、.env 読取ブロックとコメント投稿前承認を会話形式の hookify で1本ずつ作ってみる。落とし穴はMCPの入れすぎ（有効10未満の目安を超えるとツール選択がぶれる）と、Subagentに広い仕事を渡してレビューがノイズまみれになること。
