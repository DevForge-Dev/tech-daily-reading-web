alibaba/open-code-review（— ・ ⭐急上昇）

解きたい課題：コードレビューが手動で、CIに自動アプリセキュリティ検査（SAST）が無いという空白。レビュー品質が人依存で、NPEやスレッド安全、XSS/SQLインジェクションのような定番リスクを機械的に拾えていない。提供する機能：決定論パイプラインとLLMエージェントのハイブリッドで、行レベルの精緻な指摘と多言語ルールセット（NPE/スレッド安全/XSS/SQLi）を機械可読に出す。Alibabaの実運用規模で鍛えられ、OpenAI/Anthropic互換。Trendshift日次23位・New 2026で急上昇。DevForge適合→ §0のSAST空白に直撃し §4 reviewerエージェントの補完にもなる。まず1PJのCIに試験導入し findings を Tier B で回す価値がある。

google-research/timesfm（Python ・ ⭐約31k / +3.1k・7d）

解きたい課題：需要・トラフィック・金額系列の予測に、系列ごとの追加学習コストがかかること。提供する機能：時系列版の事前学習済み基盤モデルで、追加学習なしのゼロショットでも将来値を予測できる。findarepoで +3.1k/7d（率約10%）と継続急伸。DevForge適合→ §1 soemo の資金繰り可視化(money-loop)の予測強化や、careport/Aiselly の問い合わせ量・商談パイプライン予測に効く。追加学習なしで試せるので、まず soemo の入金/資金繰り予測 PoC として評価したい。

melgarafael/DeskcommCRM（— ・ ⭐New）

解きたい課題：「チャットで売る」ビジネスで、AI営業の会話・リード・商談管理がツール間で分断されていること。SaaS依存だとデータ主権やコストも気になる。提供する機能：ネイティブAIエージェント＋WhatsApp(WAHA)を備えたセルフホスト型のオープンソースAI営業OS/CRM。MCP対応・マルチテナントで、Kommo/Octadesk/Intercomのオープン代替。Trendshift日次18位・New 2026。DevForge適合→ §1 Aiselly のAI営業自動化（リード→アウトリーチ→商談管理）の設計・機能参照として直球。careport/soemo のチャット起点CRM設計の比較対象にもなる。まず Aiselly の商談カンバン/シーケンス設計の参照として評価したい。
