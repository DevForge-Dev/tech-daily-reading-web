11/6のFlutter — 3.50 stableの昇格が再始動、待機中はflutter_bloc 9.1.1の4ウィジェットを固める

beta 0.4.preでpreが再進。合間にBlocBuilder/Listener/Selectorとread/watch/selectを整理し土台を作る。

📅 2026年11月6日 ⏱ 約4分 🔗 出典 5 件

なぜ今これが話題か——beta 3.50.0-0.4.pre が11/4に到着し、約6日ぶりにpreが進んだ＝3.50 stableの昇格作業が再始動した。stableは依然 3.47.9（Dart 3.13.7） 据え置きで、release-tracker #195830は11/2起票のままopen・未公開。3.50が出れば Dart 3.14がstable初到達し、Web WasmGC既定化・Android Impeller一本化・material_ui/cupertino_ui の正式deprecationが一般化する。

実務の構えは明快だ。本番は 3.47.9 をpin のまま、別ジョブで 0.4.pre を緑化（build web --wasm と appbundle を今のうちに通す）。preが再び動き出した＝stable公開は近い可能性があり、昇格直前は個別hashよりチャネル追従が安全。

この待機期間に足場を固めるなら、状態管理の定番 flutter_bloc 9.1.1 のウィジェット使い分けを押さえておきたい。最小は Cubit（公開メソッド内で emit(新state)）、イベント駆動が要るときに Bloc へ昇格（on<E> は bloc_concurrency の sequential/droppable/restartable/concurrent を transformer に取り、同型イベントの並行性を制御できる）。肝はUI側の4ウィジェットの役割分担だ。

stateは Equatable で値等価にして無駄なrebuildを抑え、Repositoryは RepositoryProvider をbloc群の上に置き context.read<Repo>() で注入する（bloc同士を直接stream購読せず、共有はrepository経由にする）のが定石だ。

試すなら——アニメは Rive 0.14 でランタイムがDart→C++（rive_native）に刷新された点に注意。世のtutorialの多くは0.14未満でそのままではコンパイル不可だ。RiveAnimation.asset→RiveWidget、StateMachineController.fromArtboard→RiveWidgetController、SMIBool/SMITrigger/SMINumber→stateMachine.boolean/trigger/number に置き換わり、main() で await RiveNative.init() が要る。メモリ点検は leak_tracker：not-disposed（dispose漏れ）/not-GCed（参照を断て）/GCed-late の3種を、testWidgetsWithLeakTracking でテスト失敗として検出し、DevTools > Memory > Leaks で詳細を見る。真因（culprit）を直せば巻き添え（victim）は自然に消える。

注意点：3.50は"近い可能性"だが未公開＝flutter upgrade 差分とrelease notesを見てから昇格すること。Riveはdocs内でも版表記が ^0.14.11/^0.15.0-dev と不統一なので、pin前にpub.devで安定版を確認。leak_trackerはWeb非対応・公式docは現在"建設中"。

ひとことまとめ：本番はpin維持で3.50を緑化待機。合間に、Blocの4ウィジェット＋read/watch/select の使い分けという"土台"を固めるのが9.1.1でも最良の投資だ。
