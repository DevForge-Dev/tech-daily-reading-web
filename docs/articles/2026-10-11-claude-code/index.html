Claude Code

Claude Code v2.1.296 を棚卸し — サブエージェントの autoCompactWindow、Read の allow_large、そして Shift-JIS 編集拒否という破壊的変更

週末は新バージョンなし。最新は v2.1.296 のまま。だが中身は地味に効く——日本語プロジェクトを直撃する「非UTF-8編集の拒否」を含む。

📅 2026年10月11日 ⏱ 約3分 🔗 出典 4 件

背景。Claude Codeの公式changelogは週末に更新が止まり、10/10・10/11は新バージョンの追加がない。最新は10/9公開のv2.1.296のままだ。派手な新機能がない時期こそ、直近版の"地味だが効く"変更を棚卸ししておきたい。とくにv2.1.296には、日本語プロジェクトを直撃しうる破壊的変更が紛れている。

何が新しいか。v2.1.296（変更79件＝修正47・セキュリティ8ほか）の開発者向け要点は3つ。(1) サブエージェントのフロントマターや--agents定義にautoCompactWindowを指定でき、メイン会話より早く自動コンパクトを効かせられる。(2) Readツールにallow_largeが加わり、通常のサイズ上限を超えるテキストも必要時に一括取得できる。(3) 破壊的変更として、Edit/NotebookEditが非UTF-8ファイル（Shift-JISなど）への編集を、従来の「非ASCII文字を黙って置換」から「拒否」へ変えた。

噛み砕くと。autoCompactWindowは、長い調査を任せるサブエージェントほど早めに履歴を畳みたい、という要求への答え。メイン会話の閾値とは独立に、エージェント単位でコンパクトのタイミングを決められる。allow_largeは検証が分かりやすく、3,000行のファイルを無指定で読むとトークン上限で732行に切り詰められたが、allow_large:trueなら全行取得できた。巨大なログや生成物を"端まで"読ませたいときの明示スイッチだ。

実務での使いどころ・注意点。最大の注意はShift-JIS拒否。これまではEdit時に非ASCIIが黙って置換され気づきにくかったが、今後は編集自体が弾かれる。データ破壊を防ぐ正しい方向の変更だが、Shift-JISのレガシーファイルを扱う現場では、事前にUTF-8へ変換するかエンコーディングを明示する運用に切り替える必要がある。セキュリティ面ではBASH_ARGV0経由のBash権限バイパスや秘密情報マスクの漏れも塞がれているので、未アップデートなら上げておきたい。

あわせて、週次まとめ（9/25〜10/1）ではUltracodeがeffortから独立して切替可能になり（オフは/effort ultracode off）、/doctor prompt-auditがCLAUDE.mdやスキルの古い指示・無効参照・矛盾を点検して修正案を返すようになった。指示ファイルが太ってきたプロジェクトの健康診断に使える。

ひとこと。新バージョンが出ない週末は、既存版の破壊的変更を取りこぼさない好機。まずは手元のプロジェクトにShift-JISファイルが残っていないか確認しておこう。
