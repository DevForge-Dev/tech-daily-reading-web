テキストスクランブル & タイプライター — GSAP無償化で実務投入、a11yの型（aria-label/aria-hidden＋reduced-motion）とRSCのままの土台

「文字が乱れて解読される／1文字ずつ打たれる」定番テキスト演出。2025年のGSAP完全無償化で ScrambleTextPlugin が無料化。最大の論点はスクリーンリーダーが1字ずつ読む問題と reduced-motion。純CSSタイプライターはServer Componentのまま置け、スクランブルは小さなClient島に隔離してプログレッシブエンハンスメントで組む。

📅 2026年8月5日 ⏱ 約3分 🔗 出典 5 件

Web演出で定番の「テキストスクランブル（decode/decrypt）」は、最終文字列に落ち着くまでランダムな記号を高速に差し替え、徐々に正しい文字へ確定させる。並走する古典が1文字ずつ打鍵する「タイプライター」効果だ。07-31のSplit Text（透明→表示で「出す」）とは別物で、スクランブルは「化ける→確定する」、タイプライターは「文字数を増やす」。注目理由は3つ：①2025年のGSAP完全無償化で有料だった ScrambleTextPlugin が無料・商用可になり実務採用のハードルが消えた、②a11yの正解が固まった、③依存ゼロでも約40行で書ける。

スクランブルの仕組み。各文字に開始フレーム start と終了フレーム end をランダムに割り当て、requestAnimationFrame のフレームカウンタを回す。frame<start は元の文字、start≤frame<end はランダム記号を確率的に引き直して「ちらつき」、frame≥end で確定文字。全文字が end を超えたら終了する。文字ごとに確定タイミングがずれることで「解読が波及する」見え方になる。

タイプライターは純CSSで完結する。white-space:nowrap; overflow:hidden; で1行固定し、width:0→N ch を steps(N) で刻む。ch は「0の字幅」なので等幅フォントなら文字数とほぼ一致し1字ずつ現れる。キャレットは border-right を別keyframesで点滅。純CSSなので Server Componentのまま置け、hydrationゼロ・INP/CLS有利だ。

Next.js（App Router）での型。スクランブルの動き本体は requestAnimationFrame と matchMedia を使うため、'use client' の小さな島に隔離する。初期HTMLには「確定テキスト」を出し（JS到達前・SSRでも読めてSEO/SRに強く、hydration mismatchも起きない）、useEffect が乗ったら化けさせるプログレッシブエンハンスメントにする。毎フレームの setState は厳禁で、el.innerHTML/textContent を直接書いてReactの再レンダーを回さない（INP対策）。return () => cancelAnimationFrame(raf) でcleanupも必須。

落とし穴：毎フレーム textContent を書き換えるとSRが途中経過を読む→親aria-label＋内側aria-hiddenで回避。プロポーショナルフォントでは ch と実文字数がズレて末尾が欠ける→等幅推奨。空→全文で幅が変わるとCLS→領域を先に確保。長文・多数同時はINP悪化→同時発火数を絞りビューポート外は IntersectionObserver で停止。自分が試すなら：ヒーロー見出しだけスクランブル、ラベル群はCSSタイプライターにして依存ゼロで組む。まとめ：トリガと確定テキストはHTML/RSC、動きはClient島、守りは aria-label/aria-hidden＋reduced-motion——この分業でSEOもa11yも崩さず「化ける」見出しが作れる。
