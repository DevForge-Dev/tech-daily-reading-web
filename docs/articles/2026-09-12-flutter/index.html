iOS/macOSの依存管理がSwiftPM既定へ（3.44〜）— 併用移行と、typed go_router・Hero・ListView最適化

Flutter 3.44以降、新規プロジェクトのiOS/macOS依存管理の既定がCocoaPodsからSwiftPMへ。解決・ビルドが高速化しXcode統合も向上、既存はPodfileを検出して段階移行できる。あわせて今日の実践トピック（typed go_router×Riverpod、Heroの共有要素遷移、ListView.builderのlazy build）も整理する。

📅 2026年9月12日 ⏱ 約3分 🔗 出典 4 件

今日の主役はSwift Package Manager（SwiftPM）がiOS/macOSの依存管理の既定になったこと。Flutter 3.44 以降、新規プロジェクトの既定が CocoaPods から SwiftPM へ移行した。パッケージ解決・ビルドが高速化し、native Xcodeプロジェクトとの統合が向上、SwiftPMスキームの早期除外などでビルド時間も最適化される。現行安定版は Flutter 3.47.x / Dart 3.13.x、次の安定機能リリースは年4回サイクルで2026年11月見込みだ。

既存アプリはどう動くか

いきなり全面切替ではない。既存アプリは flutter コマンドが Podfile を検出し、CocoaPodsと併用しつつ段階的にSwiftPMへ移行できる。新規は最初からSwiftPM前提。Webは WebAssembly（WasmGC） 移行を継続中で、flutter build web --wasm でopt-in（dart:html → package:web 移行が前提）、初期ロード短縮・描画高速化を狙い既定化へ前進している。

今日の実践トピック

アーキテクチャ：go_router の type-safe（typed）routes × Riverpod は、@TypedGoRoute のcode generationでルート/パラメータをcompile-timeに検証し、runtime errorをcompile errorに倒す。deep link/queryも型安全になり、redirectをprovider（auth状態）で駆動して未認証を /login へ動的リダイレクトできる。2026の既定はRiverpod 3.3系＋@riverpod codegen（監査/規制はBloc 9系）。アニメーション：Hero＝共有要素遷移はsource/destinationに同一で一意な tag を付け、両画面でaspect ratioとalignmentを揃えて飛行中の歪みを防ぐ。飛行の見た目は flightShuttleBuilder、Hero内のsubtreeは最小化する。

パフォーマンスと注意点

長リストは ListView.builder / SliverList のlazy buildで、1万件でも可視の約15個のみbuildされる。itemBuilder はスクロール中に頻繁に呼ばれるので重い計算を置かない（事前にデータ整形）。要素高さが一定なら itemExtent 指定でlayout計算を削減、cacheExtent は500〜800pxから調整する（大きいほど滑らかだがメモリを食う）。最も多い根因は不要なrebuildで、const 徹底・ref.watch(provider.select(...)) で最小スライス購読・重い計算は compute() で背景isolateへ逃がす。計測は必ずprofileモードでDevTools Performance、フレーム予算は60fps=16ms / 90fps=11ms / 120fps=8.3ms。SwiftPMは足回りの高速化なので、まずCIのビルド時間で効果を測るのが分かりやすい。

ひとことまとめ

iOS/macOSの土台がSwiftPMへ。新規は即恩恵、既存は焦らずPodfile併用で段階移行。上物はtyped go_router＋Riverpod、Heroの一意tag、ListViewのlazy buildとフレーム予算という定番を守れば、速さと安全を両取りできる。
