v2.1.260 — /diff で会話横にフルスクリーンDiffパネル、prompt_cache にキャッシュミスの推定原因、ヘッドレスへ /reload-plugins。Bash巻き添えブロックは撤回

編集中の未コミット変更を会話の横でリアルタイムに眺められる Diff パネルが目玉。/cost と prompt_cache にはキャッシュミスの推定原因が出てコスト最適化の手がかりに。ヘッドレスにも /reload-plugins が入り、無人環境でプラグインを再読込できる。前版で入った“Read denyルールをBash引数にも適用”は build/grep を巻き添えにする回帰だったため撤回された。

📅 2026年9月5日 ⏱ 約2分 🔗 出典 3 件

9月3日リリースの v2.1.260 は、単発の派手さより「見えづらかったものを見えるようにする」更新が並ぶ。Claude が触っている未コミットの変更をその場で確認でき、コストのブラックボックスにも光が入る回だ。

何が新しいか

最大の追加は フルスクリーンDiffパネル。フルスクリーン時に会話の横へ開き、Claude が編集中の未コミット変更をリアルタイム表示する。/diff で開閉できる。あわせて /cost とステータスラインの prompt_cache にキャッシュミスの推定原因（ツール定義やシステムプロンプトの変更、TTL超過のアイドルなど）が出るようになり、「なぜキャッシュが効かなかったか」を後追いできる。ヘッドレスセッションには /reload-plugins が加わり、無人環境でもプラグインを再読込できる。

撤回された変更に注目

もう一つの読みどころは回帰の撤回だ。前版 v2.1.259 で入った「Read系の deny ルールを Bash の引数にも適用する」変更は、auto モードでも一般的な build や grep の複合コマンドを巻き添えでブロックしてしまっていた。実運用の使い勝手を優先して元に戻された。セキュリティ強化と日常の使い勝手のバランスを、リリースをまたいで調整している様子が見える。

使いどころ・自分が試すなら

大きめのリファクタを任せるときこそ /diff を開いておくと、生成の途中経過を目で追いながら軌道修正できる。コストが読めないプロジェクトでは prompt_cache の推定原因を見て、システムプロンプトやツール定義の変更頻度を抑えるチューニングに繋げたい。スケジュール実行でプラグインを更新する運用なら、ヘッドレスの /reload-plugins で再起動なしに反映できる。

まとめ：可視化（/diff・prompt_cache 原因）と足回りの安定化（Bash巻き添え撤回・各種Fix）の両輪。派手さはないが“毎日の信頼性”を底上げする堅実な回だ。
