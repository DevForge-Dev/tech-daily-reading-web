Claude Code

Mods が正式リリース — TypeScript で Claude Code 自体を拡張、v2.1.287 以降は既定で有効

フックの一歩先。シェルを叩いて終わるのでなく、TS関数を常駐させて状態を持ち、UIまで足せる。"何を自動化するか"から"どう操るか"へ軸が動いた版。

📅 2026年10月10日 ⏱ 約3分 🔗 出典 3 件

背景。Claude Codeは「フックやスキルを自然言語で書いて挙動を縛る」運用がすっかり定着した。その拡張の決定版として、Anthropicが2026/10/1に発表したModsが正式リリースされ、v2.1.287 以降は既定で有効になった。追加設定は不要で、CLI・デスクトップ両対応。本日10/10の公式changelogに新バージョンの追加はなく最新はv2.1.296（10/9）のままだが、"今の運用で何が効くか"という視点ではこのMods解禁が一番大きい。

何が新しいか。ModsはTypeScriptで書いた「mod」でClaude Codeの動作とUIを拡張する仕組み。プロンプトの書き換え、ツールのblock/再試行、権限要求の自動承認・拒否、さらにボタン・入力フォーム・ペインなどのUI追加、組み込み機能の置き換えまで行える。Hooksとの決定的な違いは、シェルコマンドを実行して終わるのではなく、TS関数を登録してセッション内で状態を保持できること。配布は/pluginで入れるプラグイン形式で、マーケットプレイス共有やClaudeディレクトリ掲載申請もできる。

どう使い分けるか。同週に出たAnthropic公式の指針が明快だ。「指示は助言でありガードレールではない。絶対に起きてはならない事はHooks・権限・管理者設定で強制せよ」。常に必要な事実はCLAUDE.md（短く・目安200行未満）、特定ファイルに触れた時だけの制約はrulesのpaths:、反復手続きはskills、中間出力が不要な副作業はsubagents（最終要約だけ戻る）。そして「状態やUIを足す対話的な拡張」こそがModsの持ち場になる。

落とし穴。modは非サンドボックスで利用中のPCにアクセスできる。信頼できる提供元のmodだけを入れること。あわせて直近の素振りも押さえておきたい：2.1.295（10/8）でフックにonFailure:"block"が入り、起動失敗・タイムアウト・異常終了で操作をブロックできる。Program Status Protocol（OSC 7501）対応で対応ターミナルが「作業中/入力待ち/完了」を表示、ツール検索経由で読むツール説明の上限は16,384字へ拡張された。

自分が試すなら。まず「1スキル＋1コマンド」程度の小さなプラグインを作り、そこにModsを1つ足す。最初の一撃は"lint/test/git statusの権限を自動承認して承認疲れを消す"か"進捗を出すステータスペイン"あたりが、効果が見えやすく安全。claude plugin validateで検証してから配布する。
