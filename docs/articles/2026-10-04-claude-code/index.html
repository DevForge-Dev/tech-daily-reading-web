Claude Code v2.1.289 — Mod/プラグインを“落ちない”土台へ、制御は『ハーネス設計』の時代

Mod機構の権限の抜けを塞ぎ、agent.spawnで連携を広げる安定化リリース。併せて公式が示す挙動制御7手法は『うまく指示する』から『仕組みで囲う』へ発想を移す。

📅 2026年10月4日 ⏱ 約3分 🔗 出典 4 件

直前にMod/プラグイン機構を載せたばかりのClaude Codeにとって、今いちばん必要なのは新機能ではなく「落ちない・漏れない」土台づくりだ。10/3のv2.1.289は、その穴を集中的に塞いだ安定化リリースになった。

何が重要か。まず権限制御の抜け。サンドボックスの自動許可下で TZ="$HOME" rm -rf build のような環境変数プレフィックス付きコマンドや、コマンド前の素の変数代入があるとBashのdeny/askルールが素通りしていた不具合を修正。シンボリックリンク経由で@メンション／変更／IDE選択されたファイルにReadのdenyが効かない穴も塞いだ。描画面では、modの ui.render が例外を投げてもセッション全体は落とさず単体失敗(ui.fault)に切り替わる。さらにteammates向けに agent.spawn が追加され、$.agent.list() が各エージェントの idle/waiting 状態を返すようになり、modからサブエージェントを起動して稼働監視する作り込みがしやすくなった。

制御の発想が変わってきた。公式ブログ『Steering Claude Code』は、挙動を制御する7手法を「消費するコンテキスト量」対「指示の強制力」で整理する。CLAUDE.mdは常時オンのプロジェクト文脈で肥大を避け200行以下が目安、Rulesは paths フロントマターでディレクトリ限定の制約に、Skillsは呼び出し時だけ起動する手順書、サブエージェントは別コンテキストで中間結果を隠蔽、Hooksはlint実行・通知・コマンド遮断をコードで決定論的に効かせるためコスト最小。「常にXせよ」はHooksで機械化し、再利用しない中間作業はサブエージェントに回すのが定石だ。5万スターのTips集が繰り返す核心も同じ2点——CLAUDE.mdを最小限に保ち、残りは検証手段・Hooks・権限で囲う『ハーネスエンジニアリング』。自己検証できる環境を与えると最終成果物の質が2〜3倍になるという。

自分が試すなら。セキュリティ修正を含むので即アップデート。その上でCLAUDE.mdを200行以下にダイエットし、ドメイン固有ルールは .claude/rules/ に paths: で必要時ロード、「常にlint」などの定型はHooks化する。なお自動許可(auto mode)はdeny/askと併用が前提で、サンドボックスを過信しないこと。要は「モデルを賢く指示する」から「失敗しにくく囲う」への移行だ。
