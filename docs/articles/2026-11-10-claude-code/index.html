Claude Code v2.1.321 — モデル別名の再割り当てと、cp/mvまで広げた書き込み保護

best→opus・fable→Fable 5.2 の別名変更に加え、cp/mv の書き込み先にも deny と保護ファイル確認を適用。派手さはないが権限判定を一段固める回。

📅 2026年11月10日 ⏱ 約3分 🔗 出典 3 件

前日まで最新だった v2.1.319 に続き、v2.1.321 が 11/9 付の変更追跡 issue（melodic-software/claude-code-plugins #14843、bot 起票）で確認できた。範囲は 2.1.321 単独で、要点を言い換えで示す二次情報（一次の CHANGELOG 本文は本セッション未照合）。それでも中身は「静かだが運用に効く」回で、読みどころはモデル別名の再割り当てと権限判定の底上げの二つだ。

何が変わったか

まずモデル別名。best が opus と同じモデルに解決され、fable は Fable 5.2 を指すようになった。運用系では、managed な marketplace の take-over で退避された保存データが cleanupPeriodDays の間だけ保持され、claude plugin restore-set-aside で復元できる。1,000 文字を超える background コマンドは通知や TaskStop 結果で先頭と末尾だけ表示に短縮。クラウドセッションのサービス中断後に、バックグラウンドエージェントを“ユーザーが停止した”と誤報告する不具合も直った。

権限・セキュリティの底上げ

今回いちばん効くのはファイル操作の保護拡張だ。cp/mv が書き込む先のファイルにも deny ルールと保護ファイル確認プロンプトが及ぶようになり、パス指定の cp/mv も対象に入った。「読み取りは許すが特定ファイルへの上書きは拒否」といったルールが、コピー・移動の宛先でも守られる。加えて、サンドボックス外で読み取り専用の Bash が無確認で走る不具合を修正。mods まわりは、Claude が書いた mod を auto/bypass モードで無確認有効化でき、mod の $.tool.call/$.mcp.call は ask を省略する（ただし deny ルールと組織ポリシーは引き続き適用）。~/.claude/plugins 配下の .claude/skills は、そのディレクトリ上で作業するとき自動ロードしなくなった。

試すなら・注意点

別名運用をしているなら、CI やエイリアス設定で best/fable の実解決先を一度確認しておくとよい。cp/mv 保護は、既存の deny ルールが宛先で“急に”効き始めるので、バッチ処理が確認待ちで止まる場合がある点に注意。なお本稿は #14843 の言い換えに基づく二次情報で、一次リリースノートは未照合——挙動は公式 CHANGELOG で裏取りしてから本番適用したい。ひとこと：派手な新機能より、“宛先ファイルまで守る”“別名の解決を揃える”という地味な整合性の底上げが中心。エージェントに広い権限を与えるほど効いてくる回だ。
