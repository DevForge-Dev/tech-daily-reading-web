Claude Code

Claude Code の“運用に効く”実務更新 — Organization policy 行・128K 出力上限・1M コンテキスト標準・自動セッション再開

9/6 の v2.1.263 が最新で 9/7 以降の新規公式リリースは未確認。空白日は派手な新機能でなく、v2.1.261 前後で積み上がった運用向けの地味な改善（組織ポリシー可視化・出力上限拡大・Concise 出力・利用枠倍増）を棚卸しするのに向く。

📅 2026年9月9日 ⏱ 約3分 🔗 出典 4 件

9月9日時点でも公式 changelog の最新は v2.1.263（9/6）のままで、9/7 以降の新規リリースは確認できなかった。派手な機能追加が無い日こそ、直近で積み上がった運用向けの地味な改善を振り返る価値がある。モデル/プランの土台も動いているので、あわせて整理する。

何が新しい/重要か

v2.1.261（9/4）は運用色の濃い更新だった。/status と claude doctor に 「Organization policy」行が加わり、組織ポリシーの適用状況を一目で確認できる。bashOutputMaxChars と taskOutputMaxChars で、コマンド出力とバックグラウンドタスク出力の上限を最大 128K 文字まで引き上げられるようになり、長いログやテスト結果の途中切れを防げる。さらに --append-subagent-system-prompt-file でサブエージェントのシステムプロンプトをファイル指定できる。周辺の対話改善として、冗長さを抑える Concise 出力スタイル、利用上限リセット後の自動セッション再開、作業中に /permissions・/add-dir を開ける点、MCP 設定でのフォルダ信頼（folder trust）必須化が入っている。

モデルとプランの土台

v2.1.261 は Opus 5・Fable 5.1・Sonnet 5 に対応し、いずれも 1M コンテキストが標準になった。複数エージェントを束ねる Agent Teams は実験的機能として利用でき、Pro/Max/Team/Enterprise の 5 時間の利用ウィンドウ上限が倍増して連続作業のスループットが上がった。リリースペースは週 1〜2 本、累計 380 版超という開発速度も相変わらず。

実務での使いどころ・自分が試すなら

まず bashOutputMaxChars を引き上げて、テスト/ビルドの長いログが途中で切れて原因を見失う事故を潰す。次に --append-subagent-system-prompt-file で「調査用」「検証用」サブエージェントの役割定義を Git 管理のファイルに切り出し、複数プロジェクトで再利用する。事例では楽天が新機能導入時間を 80% 削減し、7 時間の自律リファクタも報告される一方、地に足の付いた数字は PR 自動レビュー＋テスト自動生成でレビュー工数 50〜70% 削減あたり。ここから小さく始めるのが現実的だ。

注意点

1M コンテキストは「詰め込めば賢くなる」わけではない。Subagents の独立コンテキストで調査・実装・検証を分離してノイズを減らす設計は依然として有効で、コンテキスト長の増加はその代替にならない。Concise スタイルは短くなる反面、判断根拠が省かれるので、重要判断のログは別途残す運用にする。

ひとことまとめ

空白日の Claude Code は「新機能」より「運用の摩擦を減らす更新」で進んでいる。組織ポリシー可視化・128K 出力・自動再開といった地味な改善こそ、毎日回す定期タスクの安定性に直結する。
