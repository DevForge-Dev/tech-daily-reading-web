iOS 26 / Xcode 26 対応と UIScene ライフサイクル必須化 — Impeller全既定時代の移行チェック

Flutter 3.47がApple義務化のUISceneベース・ライフサイクルに追従。旧UIApplicationDelegateからの移行でmulti-window/state restorationが整う。現行安定は3.47.4/Dart 3.13.3、Impellerは全デスクトップで既定。アクセシビリティdocsも全面刷新。beta 3.48/Dart 3.14（WasmGC既定化）、次の安定は11月見込み。

📅 2026年9月20日 ⏱ 約3分 🔗 出典 4 件

今日の主役は iOS 26 / Xcode 26 / macOS 26 フル対応と、UIScene ベース・ライフサイクルの必須化だ。Apple が義務化した UIScene ライフサイクルに Flutter 3.47 が追従し、旧 UIApplicationDelegate ベースからの移行で multi-window / state restoration がきれいに整う。現行の安定版は Flutter 3.47.4 / Dart 3.13.3（2026-09-11 patch）で、Impeller は全デスクトップで既定、最低 iOS 15 / macOS 12、material_ui / cupertino_ui は 1.0 standalone、Widget Previews は stable に達している。

何が新しいか

Xcode 26 でビルドするなら UIScene 対応は実質必須で、ここが移行の詰まりどころになりやすい。あわせてアクセシビリティ docs が全面刷新され、Semantics やスクリーンリーダー対応の指針が再構成された。言語側は Dart 3.12（Flutter 3.44 同梱）が private named parameters を導入し、Dart 3.13 で primary constructors / dot shorthands が stable 化。beta は Flutter 3.48 / Dart 3.14 で WasmGC 既定化と Android の Impeller 一本化を継続し、次の安定機能リリースは 2026年11月見込みだ。

仕組みのポイント — Impeller と描画予算

レンダラは Impeller が全プラットフォームの既定になった。Skia を置き換え iOS=Metal / Android=Vulkan で GPU を直接叩き、全 shader を build 時に precompile することで runtime shader compilation jank を根絶する。フレーム予算は 60fps=16ms / 90fps=11ms / 120fps=8.3ms。パフォーマンス最適化の勘所は変わらず、DevTools で Impeller の draw call batching を見てlayer tree を平坦化し総 draw call を削減、不要な Opacity/ClipRRect レイヤーを整理、動くアニメ領域は RepaintBoundary で隔離、重い計算は Isolate.run()/compute() で背景 isolate へ逃がす。計測は必ず profile モードで。

実務での使いどころ・注意点

自分が移行するなら、検証ブランチで Xcode 26 ビルドを通し、UIScene 対応（AppDelegate/Scene の分離）を最初に確認する。状態管理の基本線は据え置きで、新規は Riverpod 3.3.1＋@riverpod codegen（Provider 比メモリ 20–25%減の実測）、監査/規制業界は Bloc 9.2.x（audit trail 生成・blocTest 検証）。アニメは micro=implicit →多段=flutter_animate → component=explicit → 共有要素=Hero と用途で使い分ける。落とし穴は、UIScene 未対応のプラグインが混在するとビルド/復帰まわりで事故りやすい点だ。

ひとことまとめ

レンダラは Impeller 前提、iOS/macOS は UIScene 前提——2026 秋の Flutter はこの2つを外すとビルドが通らない。移行の窓は今だ。
