Claude Code

v2.1.306→307→308 — 停止/承認を記録する safety_event と、26件の事故潰し

3日で3版。芯は「止めた・承認した・差し戻した」を各ツール呼び出し単位でOpenTelemetryに刻む可観測性と、スリープ/中断/キーチェーン由来の事故を1つずつ塞ぐ安定化。

📅 2026年10月23日 ⏱ 約3分 🔗 出典 3 件

レビュー律速の時代に自動化を増やすほど、「誰が・何を・なぜ止めたか」を後から追えることが効いてくる。Barclaysが2026年末までに開発者の半数をClaude Codeへ移すといった組織規模の導入が進む今、ガバナンスと可観測性は実務上の必須要件だ。10/21〜22にかけて v2.1.306 → 307 → 308 と小刻みに更新され、その芯がまさにここにある。

何が新しいか — claude_code.safety_event（OpenTelemetry）

大型の v2.1.307（10/21） の目玉が新OTelイベント claude_code.safety_event。権限ルール・auto mode・セーフティチェック・フック・サンドボックスのいずれかがツール呼び出しを停止／承認要求／差し戻ししたとき、その呼び出しごとに発火する。あわせて Code Review に @claude review stop（off/pauseも）が入り、always 購読を新規レビューを起こさず終了できる。セルフホストランナーの checkout フックは既定30分でタイムアウト（--checkout-hook-timeout-minで調整）。/claude-api api-version で API を 2026-10-21 へ移行可能。

前後の2版 — 地ならしと安定化

v2.1.306（10/21）は2件の誤り修正。クラウドセッションで環境変数なしに起動した claude -p が誤って「Not logged in」と出る問題と、MCPツールを多数登録した環境でAPIエラーが「prompt is too long」と誤表示され不要なコンテキスト圧縮が走る問題を解消した。翌日の307は26件の修正を含み、キーチェーンロック中の認証失敗、スリープ復帰後のMCPタイムアウト固着、中断後のHTTPツール二重送信（読取/冪等のみ再送）、大きなツール結果での誤「Autocompact is thrashing」などを潰した。v2.1.308（10/22）はその後の安定化リリースで、目立つ新機能の記載はない。

実務での使いどころ

SmartScopeの上級ベストプラクティスが言う通り「強制はCLAUDE.mdでなく権限／フックに置く」のが筋で、safety_event はその強制が実際にどこで効いているかをCollector経由でダッシュボード化できる。どの権限ルールやフックが開発を止めているかが数字で見えるので、締めすぎ・緩すぎの調整が勘から計測へ変わる。多数MCP環境の「prompt is too long」誤判定が消えた点も効く——以前これで圧縮が多発してMCPを削っていたなら、構成を戻して再評価する価値がある。

注意点とまとめ

safety_event は「止めた／承認要求した／差し戻した」呼び出しのみ発火し、素通りした呼び出しは出ない点に注意（＝通過率の分母は別途取る）。api-version の 2026-10-21 移行とセットで挙動を確認したい。ひとことで言えば今回の路線は「自動化を増やし、増やした分を測る」。止まった理由がテレメトリに残るのが最大の実利だ。
