Flutter 3.47 / Dart 3.13の現在地 — AIネイティブ開発の定着とImpellerで120fps、状態管理は『新規Riverpod3・監査Bloc9』

現行安定版はFlutter 3.47 / Dart 3.13。年4回サイクルの積み上げに加え、Flutter MCP Server・Agent Skills・Agentic Hot Reload・GenUIといったAIネイティブ開発ツールが定着した。状態管理は新規=Riverpod 3、監査/規制=Bloc 9、細粒度=Signals 6、GetXは回避が2026の選定図。描画はImpellerで全シェーダーをAOTし、複雑シーンでraster約50%短縮・安定120fps。

📅 2026年8月20日 ⏱ 約3分 🔗 出典 5 件

今日の主役はAIネイティブ開発ツールの定着だ。現行安定版はFlutter 3.47 / Dart 3.13。Google I/O 2026の3.44/Dart 3.12公開後、2/5/8/11月の年4回サイクルで3.47に到達し、2026ロードマップは最低4回のstableをコミットしている。バージョンを上げるだけでなく、開発の「回し方」そのものが変わりつつある回だ。

何が新しいか。Flutter MCP ServerとFlutter Agent Skillsで、エディタやAIエージェントがFlutterプロジェクトを直接操作できる。Agentic Hot ReloadはAIのコード変更を自動hot reloadで即反映して反復を高速化。GenUIはAIがwidgetレイアウトをその場で合成し、Genkit for Dartが生成AIアプリ構築をDartで標準化する。言語側のDart 3.13はprimary constructorsの正式化、private named parameters、.valueを省略できるdot shorthands、no_raw_types/no_dynamic_casts lintを備える（利用はlanguage versionを^3.13.0に）。

Riverpod 3.0/3.3.xはcompile-time safety・unified Ref・失敗providerの自動リトライ（指数バックオフ）・@mutationによる副作用のIdle/Pending/Success/Error反映・experimentalなoffline persistence（riverpod_sqflite）を備え、新規の既定。性能重視の細粒度反応性はSignals 6.0、監査/規制業界や複雑並行はBloc 9.0/9.2.xが向く。ref.watch(provider.select(...))で最小スライス購読するのが再ビルド削減の基本だ。

描画はImpellerで一段安定した。iOS＋Android(API 29+)＋3.47でデスクトップ3OSの既定になり、全シェーダーをビルド時にAOTで事前コンパイルしてshader compilation jankを解消。複雑シーンでraster約50%短縮、アニメ重負荷でSkia比約17%省電力、高リフレッシュで安定120fpsを出す。

自分が試すなら：新規appはRiverpod 3＋@riverpod codegenで組み、計測は必ずprofileモードでDevTools Performanceからtimeline traceを取る（debug VMは大幅に遅い）。最頻出の性能問題は不要なwidget rebuild——constを付けたwidgetは再ビルドを完全スキップし、大きなbuild()は分割、アニメ領域はRepaintBoundaryで隔離する。落とし穴：AIネイティブ系（MCP Server/GenUI/Agentic Hot Reload）は強力だが発展途上で、GenUIの生成レイアウトはそのまま本番投入せずレビュー前提で。まとめ：3.47/Dart 3.13でAI開発が回しやすくなり、状態管理は用途別に割り切り、Impellerでフレーム予算を守れば120fpsが現実的な一日だ。
