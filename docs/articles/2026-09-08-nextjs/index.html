テーマ切替の円形リビール — 同一ドキュメント View Transitions が Baseline 入り、数十行で全画面クロスフェード超え

同一ドキュメント View Transitions が 2025-10-14 に Baseline Newly available へ。document.startViewTransition＋clip-path: circle() で、クリック点から新テーマが円状に広がる演出を依存ゼロ・数十行で。

📅 2026年9月8日 ⏱ 約3分 🔗 出典 4 件

クリックしたトグルを中心に、新テーマ（暗↔明）が円形にじわっと広がって全画面を塗り替える——2025〜26 に定番化した「シネマティックなテーマ切替」。ライブラリ無し・数十行で作れるうえ、未対応環境でも即フリップに落ちて壊れない、費用対効果の高い演出だ。

何が新しいか

同一ドキュメント View Transitions が 2025-10-14 に Baseline "Newly available" に到達（Firefox 144 対応で主要3エンジン揃い）。document.startViewTransition() レベルはもう実験ではなく通常運用してよい段階だ。単なる background-color の transition では、テキスト色・画像・SVG・影まで一括で滑らかに変える術がない。View Transitions は旧ページ全体と新ページのスナップショットを撮り、その2枚をコンポジタで合成することでこれを一撃で解決する。

仕組みのポイント

デフォルトのクロスフェードを止め、新テーマのスナップショット ::view-transition-new(root) をクリック点中心の円 clip-path で 0→全画面に広げるだけ。半径は四隅までの最大距離 Math.hypot(Math.max(x, innerWidth-x), Math.max(y, innerHeight-y))。CSS で ::view-transition-old/new(root) { animation:none; } により既定フェードを無効化するのが肝だ。

const t = document.startViewTransition(() => flushSync(() => setTheme(next)));
await t.ready;
document.documentElement.animate(
  { clipPath: [`circle(0px at ${x}px ${y}px)`, `circle(${r}px at ${x}px ${y}px)`] },
  { duration: 450, easing: 'ease-in-out', pseudoElement: '::view-transition-new(root)' }
);

実務での使いどころ・落とし穴

App Router では window/flushSync に触るトグルの島だけ 'use client'、テーマは next-themes に任せ <html suppressHydrationWarning> を付ける。React state 経由なら callback 内の flushSync が必須（同期コミットしないとスナップショットが旧DOMのまま撮られる）。素の classList.toggle なら不要。animation:none 忘れで既定フェードと二重に走り濁るのが最頻出ミス。全画面モーションは prefers-reduced-motion を JS で gate し即フリップに落とす。

ひとことまとめ

ほぼ全サイトが持つテーマ切替 UI に、依存ゼロで「作品感」を足せる。Next.js の experimental ViewTransition（ルート遷移用）とは別物で、ここは生 API を直接叩くのが正解。
