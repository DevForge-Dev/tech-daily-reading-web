Vaul（ドロワー/ボトムシート）を App Router で — iOS級のドラッグ体験と『Vaul実質メンテ停止→shadcnはBase UIへ』の現況

モバイルの“掴んで動かすシート”を自前で作ると地雷だらけ（60fps維持・スクロール競合・キーボード追従・a11y）。VaulはRadix Dialog上にiOS由来のイージングで組み、ドラッグで閉じる・スナップ・背景スケールを最初から備える。2026年の要点は現況——Vaulは1.1.2で実質メンテ停止、shadcn/uiはDrawerの依存をBase UIへ移行した。新規はどちらを選ぶかの判断が要る。

📅 2026年9月4日 ⏱ 約3分 🔗 出典 4 件

Apple Maps のボトムシートのような“掴んで動かせるシート”をWebで再現する定番が Vaul（Sonner作者 Emil Kowalski 製）。shadcn/ui の Drawer の実装母体としても広く使われ、週数百万DL規模だ。自前実装はスクロールとドラッグの競合・慣性・マルチタッチ・仮想キーボード追従・a11yと地雷だらけで、そこをiOS由来の作法でまとめてあるのが価値。

仕組み（要点）

土台は Radix Dialogで、フォーカストラップ・Escで閉じる・ARIA・bodyスクロールロックといったa11y配線を継承する。ドラッグは再レンダーを避けるため 対象要素の style.transform を命令的に直接更新（当初のCSS変数方式は子要素が増えると全子孫のstyle再計算で重くなった）。速度が閾値を超えたら閉じる“慣性”、上端での“ダンピング”、中身が最上部の時だけ引ける shouldDrag、そして仮想キーボードは Visual Viewport API でドロワー高さを追従させる。iOS由来のカーブ cubic-bezier(0.32,0.72,0,1) と 500ms で“あの感触”を模す。

App Router での組み込み

'use client' 必須の完全クライアント部品なので、ドロワーの島だけClient Componentに隔離し、ページ本体・データ取得はRSCのまま。中身はRSCで生成してpropsで渡す。閉じた初期状態はサーバー/クライアントで一致するので hydration mismatchは起きない。フォームは <form action={serverAction}> をドロワー内に置けてServer Actionsと素直に噛む。背景スケールを使うならルート直下ラッパに vaul-drawer-wrapper 属性を付ける。a11yでは Drawer.Title が事実上必須（無いと警告＝SRにダイアログ名が伝わらない。見せたくなければ sr-only）。

注意点・自分が試すなら

最大の判断は VaulのままかBase UI版か。既存プロジェクトでVaulが安定動作なら1.1.2で機能は揃っており急いで剥がす必要はない。新規で長期メンテ重視ならBase UI版Drawerが今の推奨線で、移行は direction→swipeDirection と依存パッケージの置換が中心。落とし穴は中身スクロールとの競合（handleOnly でハンドル限定にすると誤操作減）、iOS PWA standalone でのポインタ分離不具合報告、背景スケールの vaul-drawer-wrapper 付け忘れ。

まとめ：“iOS級のシート”は自作せずVaul/Base UIに任せる。新規はBase UI版Drawerを基本線に、a11yの Title だけは必ず入れる。
