Flutter — 3.50の機能面を総覧：Direct native interopがstable、iOSタッチ即時配信、material_ui既定化

platform channelを外す同期ネイティブ呼び出し（FFIgen/JNIgen stable）、iOSタッチが最大16ms短縮、Web WasmがJS比2倍超、そしてmaterial_ui/cupertino_uiが新規既定に。

📅 2026年11月13日 ⏱ 約3分 🔗 出典 3 件

11/12 のダイジェストが Flutter 3.50 の「リリース手続き面」を扱ったので、今日は中身——公式 whats-new blog が総覧する機能面を読む。3.50 は Dart 3.14 と同梱で（Emma Twersky・2026-11-11）、現時点の最新 stable は 3.50（3.51 は未登場）。目玉は Direct native interop の stable 化、iOS タッチの即時配信、Web Wasm の高速化、そして新プロジェクト既定パッケージの刷新だ。

Direct native interop が stable：platform channel を外す

Objective-C 向けの FFIgen が既存の C 対応に加えて stable になり、Java/Kotlin 向けの JNIgen も stable 入りした（Pigeon の native interop モードは preview）。要点は platform channel のメッセージ受け渡し無しで同期呼び出しができ、バックグラウンド isolate からも呼べること。ネイティブ連携の定番ボトルネックだった「チャンネル越しの非同期シリアライズ」を外せるのが大きい。

体感性能と Web、そして既定パッケージの刷新

体感面では iOS のタッチイベントが即時配信になり、公式ベンチで 60Hz なら 16ms・120Hz ProMotion なら 8ms 速くなった。Web Wasm は重い widget ベンチで JS の2倍超のフレームレート（Safari 26.2+／Firefox 147+ は opt-in、Chrome/Edge 137+ は既定）、WebParagraph（experimental）で CanvasKit のダウンロードが 5.46MB→約3.75MB に縮んだ。さらに大きいのが material_ui／cupertino_ui が新規プロジェクトの既定になった点——flutter create が package:material_ui を import し、従来の package:flutter/material.dart 系は正式 deprecation。移行は dart fix --apply --code=migrate_design_widgets で進められる。

実務での使いどころ・自分が試すなら

既存アプリで platform channel 越しにネイティブ SDK を叩いている箇所は、FFIgen/JNIgen への置き換え候補。特にバックグラウンド isolate で重い処理をしたいケースは効果が出やすい。新規は AGP 9.3.1・Gradle 9.5.0・compile/target SDK 36・minSdk API 24 が既定になるので、CI のツールチェーンも合わせる。試すなら、まず検証用に flutter create した 3.50 プロジェクトで material_ui 既定の差分を確認し、既存プロジェクトは dart fix のドライラン的に影響範囲を見てから移行するのが安全。描画最適化では公式 perf ベストプラクティス（saveLayer/Opacity/clip を避ける・ListView.builder・Widget に operator== を書かない）も併せて効く。

注意点・ひとことまとめ

既定パッケージ刷新は影響範囲が広く、従来 import の deprecation は既存コードの地雷になりうるので dart fix で計画的に。Wasm は一部ブラウザで opt-in、HCPP は Android 14+・Vulkan 上の Impeller が前提と、適用条件に幅がある。まとめると、3.50 は「ネイティブ連携の同期化」と「既定パッケージの世代交代」が二本柱で、どちらも“今の配管”を見直す good な契機になる。
