Next.js — useLinkStatusでリンク単位のペンディングUI（15.3+）

クリックから画面が変わるまでの"空白"を、リンクごとの小さなインジケータで埋めるクライアントフック。prefetch無効のリンクやloading.jsの無い動的ルートが主戦場。

📅 2026年11月11日 ⏱ 約2分 🔗 出典 3 件

背景：App Router の <Link> をクリックしても、Next.js はまず RSC ペイロード（?_rsc=）を取りに行き、それが届くまで loading.js フォールバックすら表示しない。プリフェッチ済みなら一瞬だが、prefetch 無効・プリフェッチ進行中・loading.js の無い動的ルートでは"固まった？"という空白が生まれる。

何が新しいか：useLinkStatus（Next.js 15.3.0）は、React の useFormStatus を踏襲したクライアントフック。<Link> の子孫コンポーネントに置くだけで、そのリンクの遷移中かを pending ブール値で受け取れる。API は const { pending } = useLinkStatus() の一行だけ・引数なし。同じ 15.3 では遷移を横取りできる onNavigate も入った。

仕組みと勘所：import { useLinkStatus } from 'next/link'（'use client' 必須）。必ず <Link> の子孫に置く——外や兄弟では効かない。プリフェッチ済みなら pending 段階はスキップされるので prefetch={false} のときに最も有用。連打時は最後に押したリンクの pending だけが出る。Pages Router では常に false を返す。

二つの落とし穴：(1) インジケータを条件付きで DOM 出し入れするとレイアウトシフト（CLS）が出る→常に描画し、サイズ固定で opacity/visibility だけ切り替える。(2) 速い遷移で一瞬光ってチラつく→初期を透明にし animation-delay: 100ms を与え、100ms を超えたときだけ見せる（CSS だけで解決・JS デバウンス不要）。

使いどころ・まとめ：あくまで"遅い遷移の応急処置"で、根本は loading.js とプリフェッチで instant navigation を狙うこと。自分で入れるなら prefetch={false} のナビ項目と loading.js の無い動的ルートに1個ずつ。prefers-reduced-motion での無限アニメ停止も添える。
