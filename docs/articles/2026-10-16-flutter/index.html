Flutter 3.50（11月）前の環境対応チェックリストと、レイヤ別テスト戦略

3.50はコードより足回り。Java 17・16KB・UIScene・Dart 3.14への備えを今月中に。あわせてunit→widget→integration＋goldenのテストピラミッドを整理。

📅 2026年10月16日 ⏱ 約3分 🔗 出典 5 件

次の安定版Flutter 3.50は11月。WasmGC既定・Impeller一本化・material_ui/cupertino_ui分離が揃う節目だが、今回は「コード変更」より環境・ビルド基盤の対応の比重が大きい。だからこそ、足回りは今月のうちに固めておきたい。現行安定は3.47.7 / Dart 3.13.5、betaは3.49.0-0.2.pre / Dart 3.14.0。

3.50前にやる環境対応チェックリスト

AndroidはJava 17必須と16KBページサイズ対応（大ページ端末でクラッシュしないようNDK・ネイティブ依存を16KB整列ビルドへ）。ImpellerはAPI29+で既定、opt-outは3.38でdeprecated済み。AppleはUISceneライフサイクル移行が必須化の流れで、AppDelegate単独構成は将来ビルド不可。SwiftPM既定化もロードマップ入り（CocoaPodsはメンテナンスモード）。Dart 3.14はmacrosが無期限ポーズ継続で、メタプログラミングはAugmentations（2026予定）へ一本化、当面のcodegenはbuild_runner + source_gen。

前倒し移行の実務は、安定ラインを3.47.7にpin、flutter channel betaをCIに1本足して3.50回帰を検知、design widget分離はdart fix --apply --code=migrate_design_widgets、flutter build web --wasmとflutter build appbundleを今のうちに緑にしておく、の4点。

あわせて整える — レイヤ別テスト戦略

原則は「捕まえたい失敗を最も安く捕まえるテストを書く」。テスト数やカバレッジ数値の最大化が目的ではない。公式アーキ（UI層／データ層・MVVM）を下から厚く・上を薄く積むピラミッドで考える。

具体には、Unitは純ロジックをmocktail/fakeで（実タイマー・実ネットワークは使わない）、WidgetはtestWidgets＋pump/pumpAndSettleで、状態層はRiverpodならProviderContainer＋overrides・Blocならbloc_test。Integrationはintegration_testでサインインやチェックアウト等を数本（flutter_driverは3.13以降非推奨）。GoldenはmatchesGoldenFileをフォント・環境を固定して範囲を絞り、設計段階は@Previewで反復してから敷く。

ひとことまとめ

3.50はコードより足回り——Java 17・16KB・UIScene・Dart 3.14を今月中に。テストは数を競わず「最も安く失敗を捕まえる層」へ寄せる。ついでにパフォはOpacity→AnimatedOpacity、クリップよりborderRadiusでsaveLayerを避け、画像はcacheWidth/Heightで表示サイズデコードが効く。
