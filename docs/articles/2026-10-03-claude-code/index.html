Claude Code

Claude Code『Mods』が正式導入 — TS/JSでツール呼び出しにミドルウェアを挿す

v2.1.287でHooksの上に“状態を持つTS/JS層”が乗り、プロンプト書き換え・ツール遮断・UI改変まで踏み込めるようになった転換点。

📅 2026年10月3日 ⏱ 約2分 🔗 出典 4 件

10月1日公開の v2.1.287 で、Claude Code の挙動を深部までいじれる Mods が正式導入された。Boris Cherny の「全員が同一の Claude 体験を持つべき理由はない」という言葉どおり、設定や従来 Hooks を越えて“自分の働き方に合わせる”ための仕組みだ。関連で $.ui.selection()（選択テキスト取得）が v2.1.288 で追加され、見落としを指摘する内蔵サイドエージェント『You should know』も同時に入った。

何が新しいか。Mods は Hooks に TypeScript/JS 関数を登録する仕組みだが、従来 Hooks と違い セッション中ロードされ続けて状態を保持し、UI 要素の追加・更新までできる。モデルに渡る前のプロンプト書き換え、ツール呼び出しの遮断・改変、権限要求の制御、インターフェース再設計、新機能追加——が同じ土俵で行える。

実務での使いどころ。導入48時間レビューで最も実用的とされたのは、Edit/Write が .env や秘密ファイルに触れる前に遮断するセキュリティガード。次いでコンテキスト残量・ファイル変更・ターン別タイムラインを出すライブ監視ペイン、過去セッションを Claude に振り返らせて“繰り返す問題”向け mod を提案させる自己監査。MIT の mod 50種が claude plugin marketplace add whyashthakker/awesome-claude-code-mods で1分弱で試せる（Context Meter / Task Board / Staged Review が入門向け）。

自分なら、まず「.env 書込み遮断」と「Token Weather（消費率可視化）」を既存 Hooks と並走させて検証から入る。

落とし穴。mod はサンドボックス無し＝マシンへフルアクセスで動く。Read-only Mode のような助言的ガードは真のセキュリティ境界ではなく、本物の制御はネイティブ権限と企業向けの deny 上書き禁止ガードで担保する。第三者コードは必ずソースを読んでから入れること。

まとめ：Hooks が「点」なら Mods は「常駐するレイヤ」。まず自分用の安全ガードと可視化から始めて、効くパターンを mod 化していくのが現実的な入口。
