Claude Code v2.1.317〜319 — 「止まらない自動運用」へ既定を締め直す。Autoモードのフォールバック廃止・denyInsteadOfPrompting・MCPタスク背景化

人が張り付かないheadless/scheduled実行を主語に据えたリリース群。サーバ判定不能時に内蔵分類器へ逃げず確認/拒否へ、MCPツールは背景実行、そしてclaude -p は安全判定不能の拒否で終了コード1を返すようになった。

📅 2026年11月14日 ⏱ 約4分 🔗 出典 2 件

最新版は依然 v2.1.319（npmリリース11/6）のままで、11/14時点で v2.1.320 以降は出ていない（npmのstableタグも v2.1.311 据え置き）。一次CHANGELOGは本セッションの可読範囲で v2.1.312（10/27）までしか見えないため、以下の数値・挙動は dev.to の週次まとめ（英語）と labmemo（日本語）という二次情報2本に基づく。それでも輪郭は一貫している——このサイクルの主題は「人が見ていない自動実行で、確認待ちや暗黙フォールバックに足を取られない」ことだ。

何が変わったか：Autoモードの「黙ってフォールバック」をやめた

最大の破壊的変更は Autoモード。テレメトリやfeature flagを無効化した環境（LLMゲートウェイの背後を含む）で、サーバ側が安全判定を返せない呼び出しに対し、従来は内蔵分類器へフォールバックしていた。v2.1.319 からはフォールバックせず「確認または拒否」に倒す。維持したい場合は CLAUDE_CODE_AUTO_MODE_SERVER=0、ゲートウェイ背後でサーバ判定を使うなら =1（Bedrock/Vertex/Foundry は挙動不変）。プロジェクト設定やプラグインからの再有効化は不可で、組織の managed settings 側で締める設計だ。あわせて /status が、サーバ側レビューが実際にはセッションに届いていないのに「Auto mode server: Enabled」と誤表示していた問題も直った。

非対話運用の新しい道具立て

関連して増えた設定・変数が、いずれも「人がいない前提」を向いている。permissions.denyInsteadOfPrompting は、本来なら確認プロンプトで待つツール呼び出しを、待たずに拒否してターンを続行する（terminal/subagent/teammate で有効）。CLAUDE_CODE_DISABLE_FEATURE_FLAGS はテレメトリを切らずにflag取得だけ止め各flagは内蔵既定値を使うが、アイドル圧縮（idle compaction）もflag取得可能が発火条件のため同時に止まる点に注意。MCP面では、MCPツール呼び出しがターミナルで背景実行され完了時に結果をClaudeへ返すようになった（CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND で呼び出し内待機に戻す／CLAUDE_CODE_DISABLE_MCP_TASKS=1 で機能自体を無効）。さらに claude -p が安全判定不能による拒否で終了コード1を返すよう修正（従来0・text/JSON両方）——CIやスクリプトが「黙って成功扱い」しなくなるので、既存パイプラインの戻り値チェックは要見直しだ。

# 無人実行で「待ちぼうけ」を作らない例
export CLAUDE_CODE_AUTO_MODE_SERVER=1          # ゲートウェイ背後でサーバ判定を使う
# permissions.denyInsteadOfPrompting: true     # 確認待ちせず拒否して続行
claude -p "…"; echo "exit=$?"                   # 判定不能拒否なら exit=1

運用での使いどころ・落とし穴

自分の用途（1人×スケジュール実行×複数PJ）では、まず claude -p を使う全ジョブで終了コードの解釈を見直すのが先。これまで0で素通りしていた「判定不能の拒否」が1になるので、CIの成功条件が緩いと今後は赤くなる。次に、ゲートウェイ/フラグ無効環境を使っているなら CLAUDE_CODE_AUTO_MODE_SERVER を明示設定しないと、無言フォールバックが消えた結果として確認待ちで止まるか拒否される。v2.1.318 ではサインイン期限が claude auth status の loginExpiresAt と claude -p JSON の credential_expires_at で見えるようになり、期限10日前からstderr警告が出る——長期の無人運用では認証切れの事前検知に効く。セキュリティ修正も多数（worktreeのサンドボックス脱出、環境変数プレフィクスやsedによるBash権限回避、引用符付きコマンドが deny/ask にマッチしない問題など）で、公式一覧は146項目とされる。

ひとことまとめ

「便利に黙って進める」より「読めない自動実行はしない」へ既定が寄った。無人運用者ほど、終了コード・Autoモードのサーバ変数・denyInsteadOfPrompting の3点を先に点検しておきたい。※全てバージョン依存の二次情報であり、挙動は公式CHANGELOGでの再確認を要する。
