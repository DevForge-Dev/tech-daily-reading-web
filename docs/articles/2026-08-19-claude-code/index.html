セルフホスト実行環境がパブリックベータ公開 — claude self-hosted-runnerで自社インフラ上にセッション実行、v2.1.233は@マルチセッション連携も

8/19はTeam/Enterprise向けセルフホスト実行環境のパブリックベータが目玉。claude self-hosted-runner一つで自社マシン/コンテナを実行基盤化し、Fixed/On-demandの2モードで金融・医療・防衛など規制業種の導入障壁を解消する。v2.1.233はGitLab MR URL対応、@で他セッションをメンションするマルチセッション、Bashのメモリcgroup上限を追加。サブエージェントは既定3階層・並列20という最新仕様も押さえておきたい回。

📅 2026年8月19日 ⏱ 約3分 🔗 出典 5 件

今日の目玉はセルフホスト実行環境のパブリックベータ公開だ。これまでClaude CodeのWeb・モバイル・デスクトップ・スケジュール実行のセッションはAnthropic管理のクラウドで走っており、データ所在地やネットワーク分離の要件がある金融・医療・防衛系のチームは採用に踏み切りづらかった。ここに正面から応えるアップデートだ。

新しいのは、claude self-hosted-runnerコマンド一つで自社のマシンやコンテナを実行レイヤーに変えられる点。Team/Enterpriseプラン向けで、エージェント実行を自社の内部ネットワーク内、既存のセキュリティ統制のすぐそばで動かせる。既定はオフ、ZDR（ゼロデータ保持）組織は対象外。実行方式は用途で選べる2モードを用意する。

Fixedモードは固定台数のランナーを常時維持し、待ち時間を最小化したい定常運用向け。On-demandモードはキューを監視して必要なときだけランナーを起動し、終了後に停止する——コストを抑えたい間欠運用向けだ。

CLI側も8月14日のv2.1.233で前進した。GitHub/BitbucketのPR URLと同様にGitLabのMR（マージリクエスト）URLを--worktreeフラグとagentsビューで扱えるようになり、MRは!N形式で表示される。加えて@で他のClaudeセッションを名前でメンションして連携するマルチセッション、LinuxでBashツール実行にメモリcgroup上限をかけるCLAUDE_CODE_TOOL_MEMORY_LIMIT、WebFetchのキャッシュTTLを決めるCLAUDE_CODE_WEBFETCH_CACHE_TTL_MS（既定15分）も追加された。

設計の指針も更新された。サブエージェントは既定で3階層までネスト可能・並列実行上限20が最新仕様。委譲すべきかはGoogle論文の「45%ルール」（隔離コンテキストに切り出すオーバーヘッドが見合うかの目安）で線引きすると整理しやすい。単一エージェントで全部やるか、別コンテキストへ委譲するかの判断軸になる。

自分が試すなら：手元の常時起動マシンをOn-demandランナーにして、毎朝のスケジュールタスクを自宅インフラで回す構成が面白い。GitLab運用なら@マルチセッションで「調査担当」と「実装担当」のセッションを分けて連携させたい。落とし穴：セルフホストは実行環境を自社に置くだけで、モデル推論自体はAnthropic API経由という点は変わらない。パブリックベータ・既定オフ・ZDR組織は対象外という前提も忘れずに。

まとめ：実行基盤を自社へ寄せられるセルフホストで規制業種に道が開け、v2.1.233の@マルチセッションとGitLab対応で並列運用が一段回しやすくなった回だ。
