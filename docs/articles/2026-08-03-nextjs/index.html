Invoker Commands API（command / commandfor）— popover・dialog をJSなし宣言的に開閉、App RouterではServer Componentのまま動く

「ボタンを押したらモーダル/ポップオーバーを開く」を2つのHTML属性 command / commandfor だけで宣言的に書ける。2025年12月にBaseline『Newly available』入り。show-modal / close / *-popover は純HTMLで動くため RSC のまま 'use client' 不要で、hydration前から開閉が効く。カスタムコマンド（--接頭辞）だけ command イベントで拡張。

📅 2026年8月3日 ⏱ 約4分 🔗 出典 4 件

Webで最頻出のUIは「ボタンを押したらポップオーバーやモーダルを開く」だ。これまでは <button> に addEventListener('click', …) を書いて showModal() / showPopover() を呼ぶJS実装が定番だった。Invoker Commands API は、これを2つのHTML属性 command / commandfor だけで宣言的に書けるようにする。2025年12月にBaseline『Newly available』入りし（Chrome/Edge 135・Opera 120・Safari・Firefox が出揃った）、いま実務投入を検討できる段階に来た。

<button command="show-modal" commandfor="dlg">開く</button>
<dialog id="dlg">
  <button command="close" commandfor="dlg">閉じる</button>
</dialog>

何が新しいか。既存の popovertarget は popover 専用で dialog を開けなかった。Invoker Commands はpopover と dialog を同じ語彙で扱え、さらに -- で始まるカスタムコマンドで任意操作に拡張できる。組み込みコマンドは下図の6つ。

Next.js（App Router）でうまい理由。show-modal / close / *-popover は純粋にHTMLだけで動くため、Server Component がそのままボタンと dialog を出力すればよい。'use client' 不要＝クライアントJSゼロで hydration 負荷なし、INP/CLS に有利、しかもJS到達前から開閉が動くプログレッシブエンハンスメントになる。command / commandfor は小文字のプレーンHTML属性で、React 19 は未知の小文字属性をそのまま出力するので JSX にそのまま書ける（camelCaseにしない＝綴りは commandfor）。SSRで window に触れないので hydration mismatch も起きない。

カスタムはClient島に隔離：--rotate-left のような独自操作は対象要素に飛ぶ command イベント（event.command / event.source）をJSで拾う。Reactに onCommand 合成イベントは無いので、その部分だけ 'use client' にして useRef＋useEffect で addEventListener('command', …) を手動登録し、cleanupで解除する。ページ本体とデータ取得はRSCのまま、動く島だけ切り出す。

落とし穴：属性が効くのは本物の <button>（button系input）だけで、<div role=button> では効かない。古いブラウザは属性を無視してボタンが無反応になるため、必須操作なら "command" in HTMLButtonElement.prototype で機能検出してJSフォールバックを用意する。id は一意に。開閉の見た目アニメは Invoker の役割外で、@starting-style / transition-behavior: allow-discrete / ::backdrop など純CSS側で付け、prefers-reduced-motion では transition: none にして動きだけ消す。まとめ：トリガはHTML、演出はCSS、拡張だけJS——という素直な分業で、モーダル開閉から 'use client' を消せる。
