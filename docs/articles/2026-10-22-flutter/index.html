Flutter 3.50 直前のチャネル戦略 — Rive データバインディング・bloc_signals・leak_tracker

本番は 3.47.7 pin＋別ジョブで beta。Wasm/Impeller 既定化の緑化を進めつつ、Rive は宣言的結線、状態は computed の自動デタッチ、品質は leak_tracker のCIゲート。

📅 2026年10月22日 ⏱ 約4分 🔗 出典 4 件

今日のFlutterは「11月の 3.50 stable を前にチャネル戦略をどう組むか」と、Rive・状態管理・計測の実務ネタが並んだ。安定は 3.47.7 / Dart 3.13.5 で据え置き、beta は 3.50.0-0.1.pre / Dart 3.14.0。本番は 3.47.7 に pin（fvm か CI の SDK 固定）し、別ジョブで beta を回す二本立てが基本線だ。

チャネル戦略と 3.50 の破壊的変更

10/21 時点で dev チャネルが再稼働し main 相当が流れている。最先端APIは dev、昇格候補の実検証は beta、本番は stable pin——と役割を分ける（dev は無警告の破壊的変更が入るのでCI/本番には絶対に使わない）。3.50 で確定の破壊的変更は、Web の WasmGC 既定化、Android の Impeller 一本化完了（legacy Skia 引退）、Wasm 遅延ロードの stable 昇格、Android 17 day-zero。昇格前の緑化対象は flutter build web --wasm と flutter build appbundle。material_ui/cupertino_ui は正式 deprecation で、移行は dart fix --apply --code=migrate_design_widgets（import 元のみ変更・シンボル名は不変）。

Rive：データバインディングで状態→アニメを宣言的に

新ランタイム（rive 0.14.11 / 0.15.x dev）は RiveWidgetBuilder が RiveLoading / RiveLoaded / RiveFailed の3状態を sealed で分岐し、FileLoader は複数ビルダーで共有しても実ファイルは一度しか読まれない。新定番は controller.dataBind(DataBind.auto()) が返す viewModelInstance に Flutter 側の状態（Bloc/Riverpod）を流す方式で、SMIBool/SMITrigger の手動トリガより保守しやすい。多数同時表示は RivePanel 配下の useSharedTexture: true で1テクスチャに集約する（Web は各 widget が WebGL コンテキストを1つ消費するため必須級）。dispose は生成の逆順だが、RiveWidgetBuilder 利用時は fileLoader だけ破棄すればよい。

状態管理：bloc_signals で Bloc の規律×signals の速度

bloc_signals 系は、Bloc の構造・イベント規律を保ったまま signals の同期的・細粒度リアクティビティを得る狙い。Domain は純 Dart の不変エンティティ＋AsyncState<T> で、値が変わらなければ rebuild しないのが核。Application 層は computed() で小計/税/合計を派生し、購読者が0になると上流から自動デタッチするため dispose 不要という設計。直接メソッド駆動は CubitSignal、イベント駆動は BlocSignal（droppable()/restartable() など）と使い分け、Widget は signal.watch(context) で細粒度 rebuild する。ただし「O(1) de-dup・zero leak」は著者主張でベンチ未提示——既存 Bloc/Riverpod 資産には追加経路として慎重に。

計測：leak_tracker でリークを自動検出

リークは notDisposed（GC されたが dispose 未呼び）/notGCed（dispose 済だが参照残存）/gcedLate（dispose 後に遅れてGC＝一時的な過剰保持）の3分類で可視化できる。leak_tracker は flutter_test に統合済みで、testWidgets に LeakTesting.settings を効かせれば CI の回帰ゲートになる。自作クラスは dispatchObjectCreated/dispatchObjectDisposed を仕込めば追跡対象に入る。計測の大前提は profile ビルド（debug は hot-reload 分で誤差）で、実測オーバーヘッドは追加メモリ約400KB（総量の約0.5%）・オブジェクト毎約0.05ms と軽量だ。

ひとことまとめ

3.50 は「Wasm と Impeller の既定化」が本丸。pin＋betaの二本立てで緑化を進めつつ、Rive はデータバインディング、状態は computed の自動デタッチ、品質は leak_tracker のCIゲート——が今日の持ち帰りだ。
