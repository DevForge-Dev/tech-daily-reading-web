Claude Code v2.1.301とCode Review GA — 「7つの制御手段」で主文脈を守る設計

小コンテキスト切替時の自動要約と37件の修正、そしてCode Reviewの一般提供。あわせて読みたいのがCLAUDE.md/skills/subagents/hooks/pluginsの使い分け。

📅 2026年10月16日 ⏱ 約4分 🔗 出典 4 件

公式更新は10/14のv2.1.299/300に続いて10/15にv2.1.301へ。さらに同日、Claude Codeのマルチエージェント型PRレビュー機能Code ReviewがTeam/Enterprise向けに一般提供(GA)入りした。設定・運用まわりが一段落したので、あわせて読みたい『制御手段の使い分け』ガイド2本と一緒に整理しておく。

何が新しいか — v2.1.301とCode Review GA

v2.1.301の実務的な目玉は、小コンテキストモデルへ切り替える際に旧モデルが長い会話を要約してから移行する挙動（しかも無断でクレジットを消費しないよう修正済み）と、長時間サブエージェント実行中の進捗描画を毎回再処理せず増分更新で高速化した点。可観測性では OpenTelemetry の tool_decision イベントに classifier_verdict / permission_mode / classifier_category が加わり、Auto Modeの分類器判定と権限ルールを切り分けて追えるようになった。バグ修正は37件で、PreToolUse(Edit/Write)フック下でもArtifact更新が拒否されない、Readが.xlsm/.parquet/.epub/.heic等のバイナリをテキストとして読まない、などが含まれる。

Code Reviewはプレビュー比約3倍速で通常6〜10分（従来約20分）。並列エージェントが差分と周辺コードをレビュー→検証ステップで誤検知を除去→重複排除・重大度順にインラインコメント＋サマリ＋「Claude Code Review」チェックとして投稿する。既定はスタイルやテスト網羅より正当性バグ重視で、REVIEW.md / CLAUDE.md で調整。PRオープン時・各push後・@claude reviewで起動し、チェックは失敗させずマージ可否の判断は人に残す。要件はTeam/Enterprise＋GitHubホスト型で、ZDR/HIPAA/BAA/CMEKは未対応。

仕組み — 7つの制御手段を3軸で見る

技術記事2本が共通して言うのは「Claudeの挙動を縛る手段は複数あり、いつ読み込まれ・コンテキスト圧縮に耐え・トークンをいくら食うかで使い分ける」こと。CLAUDE.mdは直下が起動時読込でいちばん高価、skillsは名前と説明だけ起動時に読み本体は呼び出し時、subagentsは別窓で最終要約だけ返し、hooksはライフサイクルイベントで発火して圧縮されず主文脈の外に居続ける。よく使う4つを並べるとこうなる。

自分が試すなら

判断則はシンプルに割り切れる。「YのあとXを常に」ならhook化、「Zは絶対禁止」ならhook／権限ガード、長い手続きフローはskills、ディレクトリ固有の制約はパススコープrules、重い読み込みはsubagentへ委譲して主文脈を節約。CLAUDE.mdは50〜150行・500トークン未満に抑え/initで雛形生成し、オーナーを置いてコードと同様にレビューする。チームへ配るときはskills/subagents/hooks/MCPをpluginsに束ねて1手で配布。

注意点

Code Reviewのチェックはあくまで補助で、落とすのは人の責任——「緑だから安全」ではない。ZDR/HIPAA構成では使えない点も要確認。設定側は、CLAUDE.mdを盛りすぎると起動時トークンを食い、圧縮で古い文脈から落ちる悪循環になるので、/contextで窓を見ながら痩せさせる。hookは確定実行ゆえに副作用も確定——.env編集のPreToolUseブロックのような「保証したい動作」に限定する。

ひとことまとめ

v2.1.301は「切替時に旧モデルが要約してから渡す」で長時間セッションのムダ消費をさらに抑える方向。制御手段は読込タイミング×圧縮耐性×費用の3軸で選べば迷わない。常時の規約はhook、重い知識はsubagent、配布はplugin。
