SDK内蔵 `material.dart`/`cupertino.dart` の正式 deprecation が目前 — `material_ui`/`cupertino_ui` 独立パッケージへの import スワップ移行ガイド

stableは3.47.9、次期 stable 3.50 の確定事項の一つが『SDK内蔵のMaterial/Cupertinoを正式 deprecation し、独立パッケージ(1.0.0は公開済み)へ切り出す』こと。変わるのは原則 import 行だけ——クラス名は不変で、`dart fix` の自動移行と互換ブリッジ、localizations再配線まで押さえておく。

📅 2026年11月2日 ⏱ 約4分 🔗 出典 3 件

背景・なぜ今これか。現況は stable 3.47.9 / Dart 3.13.7、beta 3.50.0-0.3.pre(共に10/29)で、11月 stable 3.50 はまだ未公開。その3.50の確定事項の一つが、SDK内蔵の material.dart / cupertino.dart の正式 deprecation＝デザインライブラリを独立パッケージ material_ui / cupertino_ui(1.0.0は3.47でpub.dev公開済み、今からopt-in可)へ切り出す動きだ。毎日複数PJを横断する運用では、各アプリの import を機械的に差し替える『段取り』を今のうちに握っておきたい。

何が変わるか＝原則 import 行だけ。package:flutter/material.dart → package:material_ui/material_ui.dart、package:flutter/cupertino.dart → package:cupertino_ui/cupertino_ui.dart。クラス名・シンボル名は不変(1.0.0は凍結済みフレームワークコードと一致＝API再設計ではなくseamlessな移行が狙い)。ただし公開パッケージを移行すると、未更新のconsumerには破壊的変更＝メジャーバンプ扱いになる点は忘れないこと。

// before
import 'package:flutter/material.dart';
// after
import 'package:material_ui/material_ui.dart';

// 自動移行
dart fix --apply --code=migrate_design_widgets
// 依存が追記されない時は手動で
flutter pub add material_ui   // 使う方だけ

仕組み・localizations の再配線。flutter_localizations からデザイン系デリゲートが unbundle され、Material/Cupertinoのデリゲートと文字列は新パッケージ側へ移動する。これに伴い localizationsDelegates は、旧来の GlobalCupertinoLocalizations.delegate / GlobalMaterialLocalizations.delegate / GlobalWidgetsLocalizations.delegate の3行を GlobalMaterialLocalizations.delegates の1本に短縮できる(Cupertino/Widgetsのデリゲートも内包)。

互換ブリッジと限界。未移行の依存が legacy ライブラリを import し続ける場合、MaterialApp.builder で MaterialUiCompatibilityBridge(child: child!) をかぶせるとテーマ/localizationが木を下り、Theme.of(context) / MaterialLocalizations.of(context) を読む未移行の子が動く。ただし公開APIの型不一致は解決不能——package:flutter の ColorScheme/TextTheme/FloatingActionButtonLocation を material_ui 型の引数には渡せない。つまりAPIが型で結合した依存は先に移行必須だ。

自分が試すなら・落とし穴。横断運用の現実解は『葉から順に』——型でAPI結合しているパッケージ(共有UIライブラリ等)を依存グラフの下流から先に移行し、アプリ側は dart fix --apply --code=migrate_design_widgets で import を一括書き換え→必要な方だけ pub add→再度 dart fix で lint整列、の順。移行途中のアプリは MaterialUiCompatibilityBridge で延命できるが、型不一致が出たらそのconsumerは延命不可＝先に上げる合図と捉える。3.50が降ってくる前に、まず1つのPJでドライランして差分の手触りを掴んでおくのが安全だ。
