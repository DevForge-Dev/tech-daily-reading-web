Flutter 3.50 直前 — WasmGC既定化に向けたWeb移行(dart:html→package:web)プレイブック

11月stableの3.50でWebはWasmGC既定化。真の関門はflutter build web --wasmを緑にすること。import差し替え・型名リネーム・interopの定石と、cross-origin isolationという最大の落とし穴を一枚に。

📅 2026年10月21日 ⏱ 約4分 🔗 出典 3 件

バージョンの現況を固定しておく。安定は 3.47.7 / Dart 3.13.5（10/8 patch）、beta は 3.50.0-0.1.pre / Dart 3.14.0（10/14）で据え置き。11月のstable 3.50 で Web は WasmGC 既定化（flutter build web --wasm が skwasm を選択）、Android は Impeller 一本化完了、Wasm 遅延ロードが stable 昇格となる。つまり「来月の本番」を今から緑にしておく話だ。

真の関門は flutter build web --wasm を通すこと

dart2wasm のコンパイルエラーはimport チェーンを出力してくれるので、grepでは見逃す依存まで特定できる。これを緑にするのが3.50準備の本丸で、dart2jsビルドは本番据え置きのまま Wasm 側を先に通す。移行の実務は3段だ。(1) import差し替え：dart:html→package:web（flutter pub add web＝web: ^1.1.1）、dart:js_util/package:js→dart:js_interop。prefix無し取り込みはFlutterのElement/Image/Textと衝突するので必ずas webで受ける。(2) 型名リネーム：dart fix --applyでHtmlElement→HTMLElement等に自動変換、ただしCheckboxInputElementは未変換なのでHTMLInputElement()..type='checkbox'へ手当て。(3) interopの定石：Dart→JSは.toJS、JS Promise→Dartは.toDart、isチェックは効かずel.isA<HTMLInputElement>()、条件importはdart.library.html→dart.library.js_interop（旧条件はdart2wasmがstubを黙って選び実行時に落ちる）。

最大の落とし穴 — cross-origin isolation

性能面の実像も押さえたい。--wasm は実行時に skwasm（約1.1MB・SharedArrayBufferがあればworkerで別スレッド描画）を選び、非対応ブラウザは skwasm→canvaskit（約1.5MB）→JSビルドへ自動フォールバックするので全ブラウザで動く。非公式ベンチではスクロール平均約41%高速・フレーム描画最大2倍・99パーセンタイル最悪値最大3倍改善と報告されるが、効果はグラフィック/アニメ重の画面ほど大きく、単純ページはほぼ差がない。

対応ブラウザ(WasmGC)はChrome/Edge 119+・Firefox 120+・Safari 18+で、2026時点でシェア90%超。ただしFlutter webはcanvas描画でクローラに可読HTMLがほぼ無いため、マーケ/ブログはHTML(CMS/SSG)、ログイン後SaaS・データ重PWAは--wasm、検索要件ありはハイブリッド、と使い分ける。

ひとこと：3.50対応は「新機能の学習」ではなく「--wasmを緑にする移行作業」。import・型名・interop・COOP/COEPの4点を潰せば、来月のstableは実質ノーイベントで迎えられる。
