Claude Code

/fork がバックグラウンド分岐に刷新・旧来の分岐は /subtask へ改名 — 暴走を止めるWebSearch/サブエージェント各200上限、2分超MCPは自動バックグラウンド化

v2.1.212で /fork は会話をバックグラウンドセッションへ丸ごとコピーして並行実行、従来のセッション内分岐は /subtask に改名。WebSearch(既定200)とサブエージェント生成(既定200)の上限で暴走ループを抑止し、2分超のMCP呼び出しは自動でバックグラウンドへ退避。企業導入研究ではマージPRが約24%増、年換算売上は約$2.5B規模。

📅 2026年8月3日 ⏱ 約3分 🔗 出典 5 件

7月中旬、AnthropicはClaude Codeを v2.1.207 から v2.1.218 まで矢継ぎ早に出し、v2.1.212 で /fork の意味を作り替えた。背景にあるのは「長時間エージェントを本体の作業を止めずに、暴走させずに回したい」という運用側の要求だ。これまで一つのセッションに何でも詰め込むと、深い検索やサブ委譲が膨らんで本流が固まる問題があった。今回の更新はそこへ効く。

何が新しいか。/fork は従来セッション内サブエージェントを起動していたが、新仕様では会話を新しいバックグラウンドセッション（claude agents の独立した行）へ丸ごとコピーし、本体を止めずに並行実行する。これまでの「セッション内フォーク」は /subtask に改名して住み分けた。名前の意味が入れ替わった点に注意が要る。

暴走対策のガードレールも同時に入った。WebSearch のセッション全体の呼び出し上限（既定200、CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION で調整）と、サブエージェント生成の上限（既定200）を追加し、検索・委譲の無限ループを止める。さらに2分を超えるMCPツール呼び出しは自動でバックグラウンドへ移り、セッションが固まらない。7月22日前後の更新では /code-review もバックグラウンド実行できるようになり、レビュー中も対話を続けられる。既定OpusはOpus 5に切り替わっている。

自分が試すなら：長い調査を投げるときは /fork でBGへ逃がし、本体では別の実装を進める二正面運用を試す。逆に「この会話の派生で軽く分岐したい」だけなら /subtask。深い検索やログ解析など後で参照しない中間作業はサブエージェントへ切り出し、上限200を頼りに暴走を気にせず回す。注意点：名前の意味が反転したので、既存の手順書やエイリアスに /fork と書いてある箇所は挙動が変わる。事業文脈としては、Microsoft Researchの7/1論文で導入者のマージPRが約24%増、年換算売上は約$2.5B規模と報じられ、週次枠+50%プロモも8月19日まで延長。生産性の実証とトークン支出の統制が同時に問われる局面だ。まとめ：8月のClaude Codeは「並行させる自由」と「暴走させない既定」を同じリリースで手に入れた。
