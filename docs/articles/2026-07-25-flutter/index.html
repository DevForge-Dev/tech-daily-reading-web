Flutter 3.44 が「ネイティブに感じる」理由 — Impeller が Android 既定へ、描画・構造・AIの3方向転換

安定版は Flutter 3.44.0 / Dart 3.12（2026-05-18・Google I/O 2026）。増分アップデートではなく、描画（Android Impeller-only）・構造（Material/Cupertinoデカップリング）・作り方（agentic/GenUI）の3方向転換だ。約2年のプレビューを経て Impeller が Android の既定レンダラに昇格し、シェーダーをAOTで事前コンパイルして shader jank をゼロにした。

📅 2026年7月25日 ⏱ 約3分 🔗 出典 3 件

背景から。Flutter は「速いが、初回アニメで一瞬カクつく」問題を長く抱えていた。原因は実行時のシェーダーコンパイル（shader jank）。3.44.0 / Dart 3.12（2026-05-18・Google I/O 2026）はこの描画基盤を含む3方向を同時に切り替えた回で、単なる増分ではない。

何が新しいか

描画：Skia backend を Android 10 以上で撤去し Pure Impeller（Vulkan）が既定に。シェーダーをAOTでバイナリ事前コンパイルすることで初回描画のジャンクが消え、予測可能なアニメ性能と起動→操作の高速化を実現（iOS=Metal / Android=Vulkan でGPU直結）。円のレンダリングは signed-distance function（SDF）ベースでエイリアス解消、perspective matrix 補正で影と射影変換が正確に。構造：Material/Cupertino をコアから完全デカップリングし material_ui / cupertino_ui 独立パッケージへ。M3の新機能がSDKリリースを待たず独自 cadence で届く。言語：Dart 3.12 は private named parameters（先頭 _ 自動省略）・primary constructors（experimental）・dot shorthands。次の機能リリースは2026年8月（年4回 2/5/8/11月）。

状態管理の指針（2026）

本番向けの意思決定はシンプルに保てる。新規プロジェクトは Riverpod 3.0 を既定——compile-time safety・組込みオフライン永続化・async取得＋自動エラー回復・BuildContext 不要・override でテスト容易、と揃う。監査証跡が要る規制業界（fintech/healthcare）や10人超の大規模は Bloc 9.0——全状態遷移のログ化＋replay と厳格レビューに向く。鉄則は「1つ選んで一貫し、テストを書く」。現行版は Riverpod 3.3.x / bloc 9.2.x / flutter_bloc 9.1.x。上に feature 単位の Clean Architecture＋go_router、移行は screen-by-screen で共存可。

実務での使いどころ・注意点

自分なら Android 実機で profile モードの DevTools Timeline を開き、raster スレッドのスパイクが消えたかを確認する。アニメは用途で使い分け——まず implicit（AnimatedContainer）、pre-built 連鎖は flutter_animate、精密 choreography は explicit（AnimationController はdispose必須、忘れるとリーク）、重い演出は Rive。フレーム予算は 60fps=16ms / 90fps=11ms / 120fps=8.3ms。再ビルド削減は const 徹底・build分割・最小スライス watch・RepaintBoundary 戦略配置が軸。ひとことで言えば「初回ジャンクが消えて、やっと"ネイティブに感じる"」回だ。
