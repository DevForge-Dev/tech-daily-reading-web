純CSSだけのグリッチ／RGBずれテキスト — Server Component のまま動く「数少ない全部盛り」と、光過敏性(PSE)という本題

見出しを信号ノイズのように震わせるサイバーパンク定番。依存ゼロ・'use client' 不要で App Router と相性抜群だが、WCAG 2.3.1「3回点滅」に正面衝突しうる唯一クラスの装飾。閾値を知っているかで差が出る。

📅 2026年11月23日 ⏱ 約4分 🔗 出典 6 件

同じ文字を複数レイヤーに複製し、色と位置をずらして「信号が乱れたように震える」グリッチ表現。SplitText やスクランブルのような“文字を動かす系”とは別軸で、構造はシンプルだ。純CSSで書けるため Server Component のまま動き、'use client' もハイドレーションも不要——INP/CLS を汚さず Next.js App Router と相性が良い“数少ない安全な全部盛り”。ただし本題は見た目ではなく、点滅＝光過敏性発作(PSE)のリスク制御にある。

仕組み（3レイヤー＋スライス帯）

王道実装は3ステップ。(1) data-text 属性に本文と同じ値を持たせ、::before/::after の content: attr(data-text) で同じ文字を2枚複製。(2) 2枚に別色を与える（::before=シアン #0ff、::after=マゼンタ #f0f、本体は白）。暗背景なら mix-blend-mode: screen で色収差らしく発光する。(3) 各コピーを clip-path: inset() で横帯に切り、transform: translate() で小刻みにずらす。ここで animation: ... steps(2) とコマ送りにするのが“デジタルノイズ”感の正体で、滑らかに補間してはいけない。2枚を別周期・別 steps にすると非同期に暴れてリッチになる。

対応状況

clip-path・mix-blend-mode・content: attr()・steps()・prefers-reduced-motion はいずれも全モダンブラウザで Baseline。検出もフォールバックも不要で、色を滑らかに補間したいとき“だけ” @property を併用する。

本題：光過敏性(PSE)と WCAG の閾値

装飾グリッチは容易に「点滅」になり、WCAG 2.3.1（3回点滅以下）に触れる。覚えておく数値は、(a) 毎秒3回超(>3Hz)が危険域（Section 508 は 3〜55Hz を禁止、発作誘発は 5〜30Hz が多い）、(b) 相対輝度が最大の10%以上変化する点滅、とくに飽和赤への遷移は輝度に関係なく危険、(c) 点滅面積が画面の約25%（中心視野約10度）を超えると危険度が跳ねる。つまり「小さく・低コントラスト・飽和赤を避ける」ほど安全。

Next.js での組み込みと a11y

純CSSグリッチは RSC のまま、CSS クラスを当てるだけ。data-text はSSRでそのまま出力されるのでハイドレーション不一致も起きず、use cache/ISR にも無干渉。安全側の設計は既定オフ——[data-motion="on"] .glitch::before{ animation:... } のようにオプトインで初めて動かし、小さな 'use client' 島でトグルする。OS の低モーション設定は必ず尊重する：

@media (prefers-reduced-motion: reduce){
  .glitch::before,.glitch::after{ animation:none !important; }
}

落とし穴とまとめ

擬似要素はスクリーンリーダーに読まれず選択もできないが、本体テキストが DOM に実在するので情報は伝わる（装飾を唯一の伝達手段にしない原則を自然に満たす）。0.2〜0.4s の常時ループは“カクつき点滅”になりやすいので、ホバー時だけ・短時間1回に寄せ、公開前に PEAT で点滅チェック。見た目はド派手でも、設計の8割は「どこまで激しくしてよいか」の線引きだ。
