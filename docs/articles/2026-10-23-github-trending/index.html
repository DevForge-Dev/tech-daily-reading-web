deepseek-ai/deepseek-recipe（Rust/Python・⭐約2.2k）

解決したい課題：Messages／Chat Completions／Responses と各社のAPI形式が乱立し、DeepSeek V4/V4.1向けのプロンプト整形・トークンID化・応答の逆変換を使う側が毎回再実装している低レイヤの手間。提供する機能：各API形式と共通のConversation形式を相互変換し、V4/V4.1向けプロンプト生成・トークン化・逆変換まで行うRustライブラリ＋Pythonバインディング。推論・ツール実行・HTTP転送は呼び出し側に委ね、“前処理だけ”を部品化した。なぜ急上昇：DeepSeek公式orgが自社の前処理パイプラインを切り出した新規性＝わずか4コミットで実測約2.2k(gh-trends週間>3x Tier1)、MIT。

WhiteTowerAI/ohmygame（デスクトップ・⭐約931）

解決したい課題：ゲーム制作は設計書・アート・3D・動画・コードと工程が分断され、個人が“1人スタジオ”として最後まで通すのが難しい。提供する機能：共有キャンバス上で設計書／アート／3D／動画／コードをAI生成し、ライブプレビュー→プレイテスト→共有リンク公開まで1アプリで回すmacOS/Windowsデスクトップ環境(ベータ)。40+プロバイダをBYOキーで利用、Apache-2.0。なぜ急上昇：10-09時点は約37★でfloor未達だったが本日約931へ急伸した“再評価”枠。

jddevtime/open-lakehouse-compute-fabric（Python・⭐約236）

解決したい課題：データ基盤(レイクハウス/Spark)はクラウド前提でコストとデータ機微度が課題になり、手元マシンの遊休計算を束ねて使えない。提供する機能：手元の複数マシンをSparkクラスタ化し、ワークスペース／SQL／ノートブック／パイプラインをWebコンソール・REST・CLI・Python SDKで管理。Microsoft Fabricの計算拡張としてFabricノートブックのジョブをオンプレSparkへオフロードでき、MCPでカタログ問い合わせも可(Apache-2.0・0.1.0ベータ)。なぜ急上昇：gh-trends週間>3xの🔥メイン枠に入った非AIデータ基盤の新星。

まとめ：エージェント一色の中で抽象度が三者三様なのが面白い。自分ならまず deepseek-recipe の Conversation 正規化を、複数モデルAPIを叩く自作ツールの共通前処理層として検証したい。
