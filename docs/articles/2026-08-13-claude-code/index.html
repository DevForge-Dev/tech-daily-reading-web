Claude Code

セルフホスト・ランナーとOpus 5デフォルト化 — コードを外に出さず、既定の地力を上げる回

v2.1.224でセッションを自社インフラで実行できるようになり、v2.1.219でOpus 5が新デフォルトに。派手な新機能というより、規制環境でも安全に・速く回すための土台強化がまとまって届いた。

📅 2026年8月13日 ⏱ 約2分 🔗 出典 4 件

この数日のClaude Codeは、機能の見た目を派手にするより「どこで・どのモデルで・どれだけ安全に回すか」という運用の土台を固める更新が続いた。背景には企業導入の実データがある。Microsoft社内を対象にした査読研究では、Claude Code採用者のマージ済みPRが24%増加し効果は4か月持続した一方、トークン支出は数百万規模に達しコストと予算ガバナンスが導入の要点になると指摘されている。「効くが、統制しないと高い」——今回の更新群はまさにその統制側を厚くする。

何が新しいか。8月7日リリースの v2.1.224 で claude self-hosted-runner が追加され、自社のマシンやコンテナをClaude Codeセッションの実行基盤にできるようになった。コードやシークレットをAnthropicのサーバーに出さず、社内ネットワークアクセス・独自ツール・コンプライアンス制御を効かせたまま運用できる（Team/Enterprise向けパブリックベータ）。あわせて v2.1.219 で Claude Opus 5 が新デフォルトモデルに。価格はOpus 4.8据え置き（入力$5／出力$25 per 1Mトークン）で1Mコンテキスト対応、2.5倍の Fast Mode も用意された。8月上旬（v2.1.220〜227）の変更では、Writeツールが未読ファイルの上書きに対応、git/npm不要でZIP over HTTPS からプラグインを導入できるArchive Pluginソース（SHA-256ピン留め）が加わり、スラッシュメニューの視認性も改善された。

自分が試すなら、まず開発マシンで claude self-hosted-runner をベータ登録し、社内ネットワークの内部APIやプライベート依存を触るタスク（ログ解析・社内リポジトリ横断）を隔離実行してコスト計測とあわせて評価する。Opus 5は1Mコンテキストが効くので、大規模リポジトリの設計レビューを一気読みさせる用途で真価を試したい。

注意点。セルフホストはパブリックベータで、実行基盤の可用性・シークレット管理・監査ログは自前責任になる。Opus 5への切り替えは価格据え置きとはいえトークン消費が増えやすく、Microsoftの事例どおり予算ガバナンスとセットで入れるのが安全。Writeツールの未読ファイル上書き対応は便利な反面、意図しない上書きに注意し差分レビューを挟むとよい。

ひとことまとめ：今回は「速く・賢く（Opus 5）」と「安全に・自社内で（self-hosted-runner）」を同時に底上げする地固めの回。派手さより、長時間・本番で回すための堅牢化が主眼だ。
