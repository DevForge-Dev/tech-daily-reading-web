v2.1.267 — maxEffortLevel で努力度に上限、--system-prompt-snapshot off で毎回再描画。週次上限は9/14から恒久+25%

派手な新機能より『制御とコスト』の週。全プロバイダの努力度に上限をかける maxEffortLevel、プロンプト再描画オプション、そして9/14からの週次上限恒久+25%と Fable/Mythos 5.1 のキャッシュ75%値下げを棚卸しする。

📅 2026年9月11日 ⏱ 約3分 🔗 出典 3 件

9月9日公開の v2.1.267 は、エージェント運用の『制御』を強める地味だが効く更新だ。暴走的な高コスト推論を組織として抑える仕組みと、プロンプト調整をやりやすくする仕掛けが中心。あわせて 9/14 から始まる週次上限の恒久+25%、9/1 の Fable 5.1／Mythos 5.1 のコスト改善まで、この時期に効いてくる変更をまとめて押さえ直す。

何が新しい/重要か

新設の maxEffortLevel は努力度（effort level）に上限をかける設定で、トップレベルにも modelSettings 配下のモデル単位にも書ける。効く範囲は Bedrock・Vertex・Foundry を含む全プロバイダ。利用者はより低い水準を選べるが上限を超える指定はできないため、チームとして高コスト推論の暴走を防げる。もう一つの --system-prompt-snapshot off は、会話に記録済みのプロンプトを再利用せず毎リクエストでシステムプロンプトを新規描画する。プロンプト文言を詰める反復検証がやりやすくなる。

設定の型

{
  "maxEffortLevel": "medium",
  "modelSettings": {
    "claude-opus": { "maxEffortLevel": "high" }
  }
}

週次上限は、期間限定の +50% プロモが 9/13(PT) まで4度目の延長、そして 9/14 から Pro・Max・Team・シート課金 Enterprise の標準週次上限が恒久的に +25%になる。プロモ終了後も従来比で実効上限が底上げされる形だ。価格面では 9/1 の Fable 5.1／Mythos 5.1 が単価据え置き（$10／$50 per 1M）のままキャッシュ読み込みを75%値下げ（$0.25/100万）し、典型ワークロードで約25%・エージェント型で最大45%のコスト削減につながる。

実務での使いどころ

複数人でモデルを共有するチームは、既定を medium に絞りつつ Opus 等の高価モデルだけ high を許すといったモデル別ガードが組める。CI や自動化で走らせる箇所は特に上限を低く固定して事故的な高コスト実行を封じたい。プロンプト調整期は --system-prompt-snapshot off を付けて、system prompt の文言変更が即座に反映される状態で回すと検証が速い。

注意点・落とし穴

maxEffortLevel はあくまで上限であって固定値ではない。実際の努力度はモデル/呼び出し側の指定との低い方に丸められる点を理解して設計する。snapshot off は毎回プロンプトを描き直すためキャッシュ効率とのトレードオフがあり、調整が終わったら外すのが基本。プロモ由来の +50% と恒久 +25% は別物なので、9/14 以降の恒常的な水準で運用計画を立てる。

ひとことまとめ

『どこまで頑張らせるか』を組織で締められる週。maxEffortLevel でコスト暴走を封じ、キャッシュ75%減で下地のコストも下がり、週次上限も底上げ。毎日回すエージェント運用の“財布”まわりが一段固くなった。
