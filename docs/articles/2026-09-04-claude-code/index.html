v2.1.259 — 組織のHTTP/SSE MCPを全ユーザーへ配る managedMcpServers、無人向け --permission-prompts none、Linuxバイナリ約75MBへ

派手な新機能というより「組織で・無人で・軽く回す」ための地固めの回。管理者設定 managedMcpServers で社内コネクタ（HTTP/SSE）を全ユーザーへ一括配布でき、ヘッドレス向けに --permission-prompts none が追加。glab のMR操作が『MR !N』表示になり、claude plugin validate --json で機械可読レポートも。直近の安定化でLinux x64バイナリは約340MB→約75MBへ。

📅 2026年9月4日 ⏱ 約3分 🔗 出典 3 件

9月2日リリースの v2.1.259 は、個人の便利さより『組織運用・無人実行・起動の軽さ』を一段引き上げる更新だ。単発の目玉ではなく、CIやスケジュール実行、社内配布といった“毎日の足回り”が静かに堅くなる。

何が新しいか

管理者設定 managedMcpServers が加わった。.mcp.json と同じ記述で HTTP/SSE のMCPサーバーを全ユーザーへ一括配布でき、各開発者が設定を編集しなくても社内コネクタが行き渡る（command を指定するローカル起動エントリはスキップ）。あわせて無人のヘッドレス環境向けに --permission-prompts none が追加され、プロンプトが出る操作は自動的に拒否しつつ、auto など有効な権限モードの判定は維持する。人待ちで止まらず、確定的に処理が進む。

仕組みと使いどころ

managedMcpServers は、これまで各自の .mcp.json 頼みだった社内コネクタ配布を、管理者が面で管理できるようにする。GitLab中心のチームには glab mr create/merge/close などが折りたたみ要約で MR !N と見えるのが地味に効く（GitHub の PR 表示に並んだ）。claude plugin validate --json はCIでのプラグイン検証をスクリプトに組み込みやすい。無人運用なら --permission-prompts none をスケジュールタスクに付けておくと、想定外の許可要求で固まらず確実に落ちる/進む。

注意点・自分が試すなら

自動化パイプラインを持つなら、まず --permission-prompts none を無人ジョブに導入して“人待ち停止”を潰したい。ただし自動拒否ゆえ、承認が要る操作を含む手順はヘッドレスでは通らないので、事前に権限モードや許可設計を詰めておく。managedMcpServers は組織管理者権限が前提で、配布対象はHTTP/SSEに限る点に注意。Linuxバイナリの縮小（zstd圧縮で約75MB）は初回セットアップやコンテナイメージの軽量化に効く。

まとめ：組織配布（managedMcpServers）・無人実行（--permission-prompts none）・可視性（glab MR / plugin validate --json）・軽量化（75MB）。派手さより“毎日の足回り”を締める堅実なリリースだ。
