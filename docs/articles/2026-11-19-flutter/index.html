Flutter 3.50.1 hotfix tracker が起票（未出荷）＋ AnimatedBuilder の child 最適化・ListView.builder・Riverpod code-gen

3.50.1 の release-tracker issue #196743 が 11/17 起票（OPEN・assignee justinmc）だが cherry-pick は空で stable 表に 3.50.1 行は無く未出荷。技法は「Listenable で最小再描画」を軸に、AnimatedBuilder の child 再利用、ListView.builder の遅延生成、Riverpod 3 の code generation を一本で捉える。

📅 2026年11月19日 ⏱ 約4分 🔗 出典 5 件

今日の Flutter は、リリースの“枠”が立ったというニュースから。GitHub の release-tracker issue #196743「[stable] [hotfix] Flutter Release Version 3.50.1」が 11/17 に bot で起票され、状態 OPEN・assignee は justinmc・tag 3.50.1・candidate flutter-3.50-candidate.0。ただし flutterreleases.com（releases.json は 11/18 生成）の stable 履歴は全197本で先頭は依然 3.50.0（11/11）——3.50.1 行はまだ無く、未出荷だ。

何が確定して、何がまだか

issue 本文は個別 PR を列挙せず、チェックリストの『Merge outstanding cherry-picks』が label:"cp: review" の動的クエリへリンクするだけ。Dart 版も未記入（空の Dart Hash: テンプレ）で、具体的な修正内容はこの時点では未確定。チェックリスト（cherry-pick マージ→Dart 版更新→engine hash pin→changelog→postsubmit→push→Archive 確認→告知）は全項目未チェックで、tag と branch は名前が立っただけ。公式ポリシーは『最新版だけ hotfix する』なので、実務は引き続き 3.50.0 を pin 基準にしつつ #196743 を watchし、cp: review の PR がマージされ始めたら 3.50.1 が近い合図だ。

仕組み — 『最小再描画』で一本につながる3つの道具

技法面は、Listenable を購読して必要な所だけ作り直すという一本の思想で読むと腑に落ちる。AnimatedBuilder は『Listenable（通常は Animation）が notify するたび builder だけ再実行』する汎用リビルダ。肝は child: 最適化——builder 内にアニメへ依存しない subtree があるなら、それを child に渡して一度だけ構築し、builder の第2引数で受け取って再利用する（公式も good practice と明言）。再利用可能な独立アニメ widget を作るなら AnimatedWidget、大きい build() の一部に織り込むなら AnimatedBuilder、という住み分け。名前に反して AnimatedBuilder は Animation 専用ではなく、ChangeNotifier/ValueNotifier でも rebuild できる（その場合は可読性のため ListenableBuilder 推奨）。

長大リストと状態管理

パフォーマンスの定石は ListView.builder。既定の ListView(children:) は『表示されうる全要素』を構築するため小リスト専用で、builder は itemBuilder で可視の子だけを作り、スクロールで画面外へ出た子は element/state/RenderObject ごと破棄する（1万件でも軽い）。高さが一定なら itemExtent、ひな形があれば prototypeItem で各子の測定を省ける（両方同時指定は不可）。なお off-screen キャッシュ量の cacheExtent は 3.41 以降非推奨で、scrollCacheExtent に置き換わった点に注意。状態管理は Riverpod 3（riverpod 3.4.3・MIT）の code generation が現行推奨——@riverpod Future<T> foo(Ref ref) と関数に注釈するだけで fooProvider が生成され、consumer は ref.watch(fooProvider) で得た AsyncValue を AsyncData/AsyncError/loading に分岐する。loading・error を“状態として”既定で面倒を見てくれるのが要点だ。

ひとこと：3.50.1 は枠が立っただけで中身は空——慌てず 3.50.0 で pin し #196743 を watch。技法は『Listenable で最小再描画』の一本槍で AnimatedBuilder と ListView.builder を同じ目で見ると設計がぶれない。
