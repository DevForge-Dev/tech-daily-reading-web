Flutter stable 3.50.1 据え置き8日目 — 12/2 の CocoaPods 期限は“今週末が最後”、技法は flutter_animate のメソッドチェーン

stable 3.50.1／Dart 3.14.0 は据え置き8日目で版は不動、次の節目は Dart 3.15 を載せた 3.51.0。実務デッドラインは CocoaPods 中央Specs(trunk) の read-only 化（12/2・残り4日）で、今日からが移行前の最後の週末。SwiftPM が iOS/macOS 既定へ。技法は flutter_animate——AnimationController/StatefulWidget 無しで .animate() にエフェクトをメソッドチェーンし、.then() で直列ステガー、AnimateList でリストを時間差再生する宣言的エフェクト合成を整理する。

リリース状況から。stable は 3.50.1／Dart 3.14.0（11/20 出荷）で据え置き8日目、beta は 3.51.0-0.2.pre（Dart 3.15.0）。版番号は動かず、次の節目は Dart 3.15 を載せた 3.51.0 の stable 昇格だ。実務は stable 3.50.1 の継続 pin が妥当。ただし迫る期限がひとつ——CocoaPods 中央 Specs（trunk）が 12/2 に read-only 化（残り4日）。この日以降「新しい version や pod は trunk に追加されない」ため既存ビルドは動くが新規 pod 追加が止まり、SwiftPM が iOS/macOS の既定依存マネージャへ昇格する（top 100 iOS プラグインは 61% 移行済み）。依存プラグインの Package.swift 対応棚卸しは、実質この週末がデッドラインだ。

今日の技法：flutter_animate の宣言的エフェクト合成

アニメーションの技法は flutter_animate（gskinner・4.5.2・BSD-3・Flutter Favorite）。売りは README いわく「AnimationController と StatefulWidget を触らずに」ビューティフルなエフェクトを足せる統一 API だ。明示形 Animate(effects:[FadeEffect(), ScaleEffect()], child: ...) と短縮形 Text("Hello").animate().fade().scale() は両形で全機能が使える。組み込みエフェクトは fade/scale/slide/blur/shake/shimmer/shadows/crossfades/follow path ＋ color 系。タイミングは各エフェクトに delay/duration/curve を持ち、既定は全エフェクト並行。未指定値は直前エフェクトから継承し、num 拡張で 300.ms／2.seconds と書ける。

直列のステガーは .then()（ThenEffect）が担う——「前エフェクトの終了時刻＋自身の delay」を新しい基準時刻にするので、.fadeIn(duration:600.ms).then(delay:200.ms).slide() なら slide の基準は 800ms になる。リストは AnimateList(interval:400.ms, …) で子を時間差入場させる。既出の Rive/Lottie（素材再生）や標準の implicit/explicit アニメと違い、flutter_animate の主戦場は宣言的なエフェクト合成だ。

補足：公式アーキと Memory view

設計の土台は公式「Guide to app architecture」の MVVM 二層——UI 層＝View（ロジックを持たない widget）＋ViewModel（UI State を管理し commands を公開）、Data 層＝Repository（唯一の source of truth・domain model 化）＋Service（API ラップ・状態無し）で、state は data→UI、event は UI→data の単方向に流す。Riverpod/Bloc/get_it はこの層構成の中で ViewModel と DI をどう実装するかの選択肢だ。パフォーマンスでは DevTools の Memory view が、Diff Snapshots（操作前後のスナップショット差分）でリークを特定できる。AnimationController/StreamSubscription/TextEditingController の dispose 漏れか、dispose 済みでも GC されない参照残りが主因——flutter_animate のように dispose を内包する API は、この種の事故を機械的に減らしてくれる。

ひとこと

stable は 3.50.1 継続で慌てる必要はないが、今日やる価値があるのは 12/2 の CocoaPods 期限に向けた SwiftPM 対応の棚卸し——“今週末が最後”というのが効く一手だ。アニメは flutter_animate で 並行が既定、直列は .then() と覚えておけば、Controller 地獄に落ちずに宣言的に積める。
