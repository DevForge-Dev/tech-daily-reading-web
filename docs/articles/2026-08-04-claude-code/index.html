Claude Code

Claude Code、既定Opusが Opus 5 に — /deep-research は手動起動のみ、DirectoryAddedフックとworkflowSizeGuidelineで「自律実行を絞る」設計転換

既定Opusが Opus 5（claude-opus-5・1Mコンテキスト）へ。/deep-research は手動呼び出しのみ、DirectoryAddedフックとworkflowSizeGuidelineを新設し、暴走とコストを抑える方向に舵。既定エージェントは Sonnet 5（1M、8/31まで$2/$10）。

📅 2026年8月4日 ⏱ 約3分 🔗 出典 4 件

Claude Code は個人開発者からチーム・大企業へ一気に広がり、$1M超を支出する企業顧客が1,000社超、週次アクティブは年初から倍増、年換算売上は約$2.5B規模と報じられる局面にある。規模が大きくなるほど焦点になるのが「エージェントをどこまで自律的に走らせ、トークン支出をどう統制するか」だ。今回の一連のリリースは、既定モデルの引き上げと同時に、まさにその自律実行にブレーキをかける設計変更を束ねている。

何が新しいか。既定Opusが Opus 5（claude-opus-5、1Mコンテキスト、Fastモード$10/$50・100万トークン）に切り替わった。既定エージェントモデルは Sonnet 5（1Mコンテキスト、通常$3/$15だが2026年8月31日まで紹介価格$2/$10）。あわせて /deep-research は手動で呼び出したときだけ起動し、Claudeが自発的に立ち上げなくなった。開発体験面では、/add-dir やSDKの register_repo_root で作業ディレクトリが増えたときに発火する DirectoryAdded フックを新設。任意の設定ファイルから作業粒度の指針を渡せる workflowSizeGuideline キーも加わった。

仕組みのポイント。DirectoryAdded はライフサイクルフックで、ディレクトリが追加された瞬間に規約チェックや依存の読み込みを自動化できる。workflowSizeGuideline は「どのくらいの粒度で作業を刻むか」の指針を設定ファイルから注入するもので、暴走的に大きな変更を一気に進める挙動を抑える。プラン＋autoモードも見直され、静的解析で読み取り専用と証明できないBashコマンドを都度確認せず、auto分類器の判断に委ねる挙動に変わった。判断を分類器へ移すことで確認ダイアログの摩擦を減らしつつ、危険な書き込みは止める狙いだ。

自分が試すなら：大規模モノレポで /add-dir するときに DirectoryAdded で lint/規約の読み込みを自動注入し、追加ディレクトリでも品質を揃える。プラグインは導入前に『Will install』セクション（v2.1.145+）で追加されるコマンド・エージェント・スキル・フック・サーバーを必ず確認してから入れる。注意点：外部由来プラグインは .claude/settings.json で有効化しても、各メンバーが claude plugin install を実行するまで読み込まれない安全側の挙動（v2.1.195+）。Sonnet 5 の$2/$10は8/31までの紹介価格である点も見落としやすい。まとめ：8月のClaude Codeは「モデルは1Mクラスへ引き上げ、自律実行は既定で締める」を同じ更新でやってのけた。
