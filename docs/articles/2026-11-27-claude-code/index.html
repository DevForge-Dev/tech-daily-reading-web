11/27は新バージョンなし — MCP公開2周年の『Skills over MCP』ベータで、サーバーが“指示”まで配る時代に

npm latest=next=v2.1.332 据え置き（stable=v2.1.326）で本体の新リリースは無い日。話題は 2026-11-24 の MCP 公開2周年にぶつけた一連の発表に集中する。目玉は『Skills over MCP』のパブリックベータ——MCPサーバーがツール/データに加え再利用可能なスキルを配布でき、Claude Code では `/` メニューに server:skill 形式で並ぶ。Tasks・Elicitation は GA、File Uploads は実験的に近日。『サーバー承認＝その指示の承認』へと重みが変わった。

📅 2026年11月27日 ⏱ 約4分 🔗 出典 4 件

今日（JST 11/27）は Claude Code 本体の新バージョンが無い日だ。npm view @anthropic-ai/claude-code dist-tags の一次確認で latest＝next＝v2.1.332（2026-11-24 公開）据え置き、stable＝v2.1.326。リリース面の新事実は乏しく、話題の中心は 2026-11-24 の MCP 公開2周年にぶつけられた一連の発表にある。中でも効いてくるのが『Skills over MCP』のパブリックベータ化だ。

何が新しいか：MCPサーバーが「スキル」まで配れるようになった

これまで MCP サーバーが配れるのはツールとデータだった。Skills over MCP では、そこに再利用可能なエージェント指示（スキル）が加わる。スキルは SKILL.md と補助ファイルを持つディレクトリで、サーバー接続時に検出され、必要になった時だけ全文が読み込まれる（常時コンテキストを食わない）。Claude Code では / メニューに server:skill 形式で並び、/docs:pdf report.pdf のように起動する。提供は Pro/Max/Ultra が既定ON、Team は管理者が有効化、Enterprise は近日。同じ発表で Tasks（長時間ジョブを裏で実行）と Elicitation（実行中にサーバーがユーザーへ情報要求）が GA となり、File Uploads（モデルのコンテキストを介さずサーバーへ送信）は実験的に近日とされる。

仕組みと、見落とせないセキュリティ前提

肝は「MCPサーバーを承認すること＝そのサーバーがエージェントに与える指示を承認すること」になった点だ。サーバー提供スキルはプロンプトインジェクションのリスクとして明示され、ローカルコード実行の前には毎回ユーザー承認が要る。承認済みスキルのファイルが変われば再確認が求められる。Classmethod（石川覚）の v2.1.332 解説は、deny ルール Skill(mcp__docs__*) でブロックできること、クラウドプロバイダ接続・claude -p・Agent SDK では使えないこと、新フック PreSkillShellCommand が公式 hooks ドキュメント未掲載であることまで補足している。

エコシステムと周辺の修正

配布は Claude/Claude Code に閉じない。Microsoft も VS Code 1.147 以降で Skills over MCP に対応し（独自のセットアップ・承認制御付き）、スキル配布がクライアント横断の標準になりつつある。あわせて v2.1.332 では、第三者プロバイダ利用者向けのモデル解決が多数修正された——とくに Bedrock Mantle の sonnet が Haiku 4.5 に化ける不具合を修正し Sonnet 5 を指すように（Sonnet 5 未有効のアカウントはエラーになるため事前有効化が必要）。Foundry は管理者がブロックした版について、同ファミリーの許可された最新版へフォールバックするよう直された。

実務での使いどころ・落とし穴・ひとこと

自分の運用に引きつけると、便利な MCP サーバーを足すほど「そのサーバー発のスキルが黙って指示を持ち込む」経路が増える。接続前に提供元を確かめ、重要リポでは deny ルールで握っておくのが安全だ。新バージョンが無い日の要点は「機能より“承認の意味”が変わった」こと——MCP を1つ承認する重みが上がったと捉え、既存接続を一度棚卸ししておきたい。
