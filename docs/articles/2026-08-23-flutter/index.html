material_ui / cupertino_ui が1.0スタンドアロンに — 四半期SDKを待たずM3更新

Flutter 3.47 / Dart 3.13。material.dart は3.44で凍結、独立パッケージへ。M3更新がpub.dev経由でweekly到達し、未使用UIを外してアプリサイズも削れる。

📅 2026年8月23日 ⏱ 約3分 🔗 出典 4 件

今日の主役はMaterial / Cupertino デザインシステムの分離が実務フェーズへ入ったこと。3.44から進んでいた material_ui / cupertino_ui への切り出しが、3.47で 1.0 standalone に到達し、pub.dev から weekly でリリースされるようになった。現行安定版は Flutter 3.47 / Dart 3.13。

何が変わったか

旧 material.dart / cupertino.dart は3.44で凍結（新機能追加なし）。UIが独立バージョニングになったことで、Material 3 の更新が四半期ごとのSDKを待たずに届く。さらに、使っていないUIパッケージをバイナリから外せるのでアプリサイズの削減にもなる。あわせて Impeller がデスクトップ3OS（macOS/Windows/Linux）で既定に、Widget Previews が stable、最低要件は iOS 15 / macOS 12、Xcode 27 では UIScene ライフサイクルが必須になった。

移行のやり方

importの置換は自動化されている：dart fix --apply --code=migrate_design_widgets でOK。失敗する場合は flutter pub add material_ui cupertino_ui してから再実行する。旧importは2026年秋（11月 stable）に正式 deprecated 予定なので、まだ猶予はあるが、weekly更新のメリット（M3を早く受け取れる・サイズ削減）を取りに行くなら早めに移すのが得だ。

# import自動置換
dart fix --apply --code=migrate_design_widgets
# 失敗したら依存を追加してから再実行
flutter pub add material_ui cupertino_ui
flutter --version   # 3.47 / Dart 3.13 を確認

実務での使いどころ・注意点

自分が試すなら、検証ブランチで dart fix を回し、CIのアプリサイズ計測で削減幅を見てから本線に入れる。Xcode 27 では UIScene ライフサイクル必須なので、iOS/macOSビルドはここで詰まりやすい——移行と同時に AppDelegate/Scene 対応を確認する。デスクトップは Impeller 既定化で初回jankが消える一方、旧レンダラー前提の描画ワークアラウンドは不要になる場合がある。周辺の定番（新規は Riverpod 3.3.1、監査/規制は Bloc 9、フレーム予算は90/120Hzで8–11ms）は据え置き。

ひとこと

「フレームワークのコアからUIが外れる」大きな構造変化。移行コスト自体は dart fix 一発で小さいので、秋の非推奨を待たず今動くのが賢い。
