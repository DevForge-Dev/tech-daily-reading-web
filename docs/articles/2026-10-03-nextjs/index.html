CSS `:has()` で“JS不要”のインタラクティブUI — App Router / RSC と相性抜群

2026年に Widely available 入りした唯一の関係擬似クラス。小さなUI島を Server Component のまま・追加JS 0 で書ける。

📅 2026年10月3日 ⏱ 約3分 🔗 出典 3 件

:has() は「子孫や兄弟に条件がマッチする親（＝主語）」を選べる唯一の関係擬似クラス。長年 CSS に無かった“親セレクタ”と“前の兄弟セレクタ”を同時に実現する。2026年に Baseline Widely available へ到達し、querySelector/matches からも使える安定機能になったので、いま改めて実戦投入の価値が高い。

App Router での価値。これまで useState + 'use client' が要った小さなUI島——選択ハイライト・ドロワー開閉・空状態・フォーム検証表示・タブ装飾——を Server Component のまま・追加JS 0・hydration 0 で書ける。状態をネイティブ部品（checkbox / radio / <details>）の DOM 状態に持たせるので SSR の HTML にそのまま乗り、React state を介さないため hydration mismatch が原理的に起きない。結果 INP / CLS / TBT に効く。

仕組みの要点。主語は :has() が付いた要素そのもの（figure:has(figcaption) は figure を選ぶ）。相対セレクタで :has(> .x)（直下）/ :has(+ .x)（直後の兄弟）/ :has(~ .x)（後続）を書き分け、:checked/:user-invalid など動的擬似クラスと組むと状態変化で再評価されて“疑似リアクティブ”になる。

/* ラジオカードの選択ハイライト（RSCのまま） */
.card:has(input[type="radio"]:checked){
  outline:2px solid var(--accent);
}
/* 操作後だけ検証色：:invalid より実務的な :user-invalid */
.field:has(input:user-invalid){ --ring:crimson; }
/* 空状態 */
.list:not(:has(> li))::after{ content:"まだ項目がありません"; }

落とし穴。①非寛容セレクタ——引数に1つでも無効なものがあると全体が無効化する。寛容にしたいなら内側を :is() で包む。②:has() の中に :has() はネスト不可、擬似要素も引数に取れない。③詳細度は“最も強い引数”と同じで :has(#id) は事故の元 → :has(:where(#id)) で0に。④パフォーマンスは 主語をコンポーネント根に絞るのが鉄則（body:has(...) を高頻度トグルしない）。Tailwind v4 なら has-[:checked]:ring-2 等のバリアントで同じことが書ける。

まとめ：:has() は「見た目だけで完結する局所インタラクション」専用の道具。ルーティングや他コンポーネントへの波及が要る所だけ Client に残す、という線引きが App Router では一番きれい。
