AnimatedList — 項目の出入りをアニメで見せる（データListとの手動同期が肝）

3.50 stable 待ちの間に。insertItem/removeItemでリストの挿入・削除を演出。削除は順序とkey固定が事故らない型。

📅 2026年11月8日 ⏱ 約3分 🔗 出典 4 件

現況から：stable は 3.47.9 / Dart 3.13.7、beta は 3.50.0-0.4.pre / Dart 3.14.0（11/4）で、11/8 時点でも 3.50 stable は未公開。11/4 の 0.4.pre 以降 新しい pre が出ず実質4日の据え置き、release-tracker #195830 は open のまま人間のコメントなし、Dart Hash 欄もプレースホルダ——昇格の最終ゲートで足踏みが続く。本番は 3.47.9 を pin しつつ 0.4.pre を別ジョブで緑化しておくのが安全。今日は“待ちの間”に効く UI 技法、AnimatedList を掘る。

項目の出入りをアニメで見せる

ListView.builder は件数変化を黙って差し替えるだけで、追加・削除を演出しない。AnimatedList（スリバー版 SliverAnimatedList、グリッドは AnimatedGrid）は挿入・削除を明示的にアニメさせる。大原則はバッキングのデータ List と AnimatedList を手動で同期すること。データを足す/消すのと同時に state の insertItem/removeItem を呼ぶ。

操作は final _listKey = GlobalKey<AnimatedListState>(); 経由。削除の肝は、消した項目がもうデータに無いため、removeItem の builder:(context, animation) に「消える最中に描く中身」（削除前 widget を SizeTransition＋FadeTransition で畳む退場専用ビルダ）を渡すこと。比較的新しい AnimatedList.separated なら separatorBuilder／removedSeparatorBuilder で区切り線もアニメ対応になる。

あわせて：keepAlive と offline-first

遅延 viewport（ListView.builder/PageView/TabBarView）は画面外の子を dispose するので、スクロール位置や入力が消える。子の State に AutomaticKeepAliveClientMixin を付け wantKeepAlive=>true＋build 冒頭で super.build(context) を呼べば維持できるが、全項目に付けると遅延リストの省メモリ効果が消えるので「失うと困る子だけ」に絞る。アーキテクチャ面では、ローカル DB を single source of truth にし UI は Stream 購読、書き込みは outbox にキューして復帰時に flush する offline-first が定石だ。

ひとことまとめ

AnimatedList は「データとリストの二重管理」を受け入れる代わりに出入りを演出できる。削除は“先にデータ除去→index を removeItem→退場ビルダで畳む”の順序、key は固定、が事故らない型。
