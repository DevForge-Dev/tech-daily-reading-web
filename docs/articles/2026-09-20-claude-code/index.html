auto modeがサーバサイド分類器へ（v2.1.278）— 分類オーバーヘッド非課金と、AGENTS.mdフォールバックの正しい理解

v2.1.278でauto mode（モデル自動選択）の分類がサーバサイドの分類器ルーティング既定に。API/Enterpriseでは分類オーバーヘッドが非課金になり、/statusに『Auto mode server』行が追加。前版v2.1.277はCLAUDE.md不在時にAGENTS.mdを読むフォールバック対応（マージではない）と、壊れた~/.claude.jsonによるクラッシュ多数を修正。堅牢化と運用フェーズの回だ。

📅 2026年9月20日 ⏱ 約3分 🔗 出典 4 件

直近のClaude Codeは派手な新機能より運用の足回りを整える方向が続く。今日の軸は2つ——9/19の v2.1.278 による auto mode のサーバサイド化と、9/18の v2.1.277 による AGENTS.md フォールバックおよびクラッシュ修正だ。どちらも「毎日エージェントを回すチーム」に効く実務寄りの変更である。

何が新しいか（v2.1.278）

auto mode はタスクに応じてモデルを自動選択する仕組みだが、その分類処理がこれまでクライアント側で走っていた。v2.1.278 では Claude API・Enterprise ユーザー向けにサーバサイドの分類器ルーティングが既定となり、従来クライアントで発生していた分類オーバーヘッドが課金対象外になった。auto mode を多用するほどコスト効率が効いてくる。あわせて /status に 「Auto mode server」の行が加わり、今どちらの分類経路で動いているかを確認できる。

AGENTS.md は『フォールバック』であって『マージ』ではない（v2.1.277）

v2.1.277 は、CLAUDE.md が存在しないプロジェクトでのみ AGENTS.md を代わりに読むフォールバックを追加した。ここを誤解しやすいが、両ファイルの内容を統合（マージ）するわけではない。CLAUDE.md を持つ既存プロジェクトでは従来通り CLAUDE.md が優先され、AGENTS.md は無視される。切替は /config の「Project instructions」から可能で、Bedrock/Vertex/Foundry は未対応。加えて、壊れた ~/.claude.json——不正な theme 値で起動時クラッシュ、不正な claudeAiMcpEverConnected 値で /mcp や /plugin manage がクラッシュ——を回避する堅牢化が入っている。

実務での使いどころ・注意点

試すなら、まず /status で自分のセッションが「Auto mode server」経路かを確認し、auto mode 主体のワークフローでコスト挙動を観察するとよい。他ツールと規約を揃えたくて AGENTS.md へ寄せたいなら、CLAUDE.md を残したままだと読まれない点に注意——移行時は明示的に切替える。拡張機能の使い分け（強制=Hooks/権限、知識=Skills、委譲境界=Subagents、常時指針=CLAUDE.md）という判断軸は引き続き有効で、まず Skills から始め、決定論的な強制が要れば Hooks を足し、並列・文脈分離が要れば Subagents を使う段階導入が定石だ。国内では PC Watch が Projects 刷新（「あとはよろしく」でスコープ設定〜委譲〜統合まで自動）を報じ、実務導入も個人試用→部署PoC→全社標準へと広がっている。

ひとことまとめ

コスト（auto mode 非課金化）と堅牢性（クラッシュ修正）を静かに底上げしつつ、AGENTS.md 対応で他ツールとの相互運用に一歩——今日はそういう地固めの回だった。
