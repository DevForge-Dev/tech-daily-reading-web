v2.1.270で権限回帰を修正 — Fable 5.1・1M文脈を土台に『強制/知識/委譲』の使い分けが定石化

9/14時点の最新はv2.1.270。読み取り専用gitコマンドが不意に権限を求める回帰（v2.1.269起因）を潰した安定化リリース。既定はFable 5.1・1M文脈・128K出力で、Hooks=強制/Skills=知識/Subagents=委譲の決定フレームと、マーケット>プラグイン>スキルの配布階層が実務の定石になりつつある。

📅 2026年9月14日 ⏱ 約3分 🔗 出典 4 件

9月のClaude Codeは派手な新機能より「基盤を固めて運用に組み込む」更新が続く。9/14時点の最新は9/12公開の v2.1.270——長時間セッションで git status/git log といった読み取り専用gitコマンドが不意に権限確認を求める回帰（前版 v2.1.269 で混入）を修正した累積リリースだ。plugin evalや /output-style といった大型追加の直後に出た副作用を素早く潰した格好で、9月は v2.1.257 のFable 5.1既定化以降、週1〜2本ペースで機能と修正が積み上がっている。

何が新しい/重要か

土台の既定モデルは Claude Fable 5.1。1Mトークンのコンテキストを標準で備え、最大128,000トークンの出力に対応する。Opus 5 / Sonnet 5 も1M文脈で選べるので、大規模コードベースを一度に読み込ませる長文脈ワークフローが現実的になった。この基盤の上に、カスタマイズの3系統（Hooks・Subagents・Skills）をどう使い分けるかの「決定フレーム」が定着しつつある。

仕組み — 配布は3層で整理できる

チームで広げる段では「マーケットプレイス＞プラグイン＞スキル」の階層が効く。マーケットはプラグインのカタログ、プラグインはスキルの束、スキルは指示のフォルダ、という入れ子だ。導入は /plugin marketplace add owner/repo でマーケットを登録し /plugin install name@marketplace で入れる2コマンド。公式マーケットは自動登録され、コミュニティ版は anthropics/claude-plugins-community を追加する。個人のメモに溜めていた"やり方の意見"を、誰でも30秒で購読できるインストール単位に変える配布システムという位置づけだ。

実務での使いどころ・注意点

まずは自分の環境固有の知識（DBスキーマ・テスト規約・デプロイ手順）をSkillに落とし、強制したいルールはHooksか権限へ、重い探索はSubagentsへ逃がす、という型を作りたい。数字も追い風で、Claude Codeのラン率売上は2026年2月に $2.5B超、ビジネス購読は2026年で 4倍。Deloitteは 47万人超に展開し、日本企業の事例では実装時間を 平均40〜60%削減と報告される。注意点は、成功パターンが「少数のパワーユーザーが実績を作って横展開」であること——単発利用でなくHooks/Skillsでワークフロー化して初めて定着する。

ひとことまとめ

「基盤を固める」回。Fable 5.1・1M文脈を土台に、強制/知識/委譲/常時指針の置き場所を決め、プラグインで配る。毎日回すエージェント運用の再現性が一段上がった。
