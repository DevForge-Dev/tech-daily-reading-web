Dart 3.13でprimary constructors正式化 — 定型が激減、Impellerは120fps既定に

Flutter 3.44.7 / Dart 3.13。クラスヘッダでコンストラクタとフィールドをまとめて宣言できる primary constructors が正式化。no_raw_types / no_dynamic_casts lintで型チェックも一貫化。描画はImpeller既定でネイティブ120fps、状態管理の既定はRiverpod 3.0。

📅 2026年8月16日 ⏱ 約3分 🔗 出典 3 件

背景。Flutterの現行安定版は Flutter 3.44.7 / Dart 3.13（Dartは2026-08-12リリース）。今回の主役は Dart 3.13 で正式化された primary constructorsだ。ViewModelやデータクラスで繰り返し書いていた「フィールド宣言＋同名の代入コンストラクタ」の定型を、クラスヘッダ1箇所に集約できる。

何が新しいか。従来はフィールドと this.x コンストラクタを二重に書いていたが、primary constructors はクラス宣言部でコンストラクタとインスタンス変数を同時に宣言する。利用にはlanguage version 3.13以上が必要で、pubspec.yaml の environment: sdk を ^3.13.0 へ上げる。あわせて解析lintに no_raw_types（旧 strict-raw-types）と no_dynamic_casts（旧 strict-casts）が入り、型チェックの挙動が明確化した。

描画と状態管理。レンダリング基盤の Impeller は iOS＋Android(API 29+) で既定となり experimental を卒業。AOTでシェーダーをビルド時コンパイルし Metal/Vulkan をネイティブ利用、frame rasterizationを約50%短縮・高リフレッシュで安定120fps・アニメ重負荷で約17%省電力。フレーム予算は 60fps=16ms / 90fps=11ms / 120fps=8.3ms を目安に profile モードのDevToolsで計測する。状態管理は新規はRiverpod 3.0＋codegen（自動リトライ・画面外providerのpause/resume省電力・実験的offline persistence）を既定、監査/規制業界はイベント追跡性の高い Bloc 9.0 という住み分けだ。

自分が試すなら、まず flutter upgrade 後に dart fix / flutter analyze で警告を潰し、language versionを3.13へ。手元のデータクラス数個を primary constructors に書き換えて差分を測る。analysis_options.yaml の strict-* を新lintへ移行し、Impellerは実機のprofileモードでrasterizationを確認する。

注意点。primary constructors はSDK 3.13以上が前提でチーム全体のバージョンを揃える必要がある。lint移行は既存コードで新規警告が出ることがあるので段階的に。パフォーマンスは必ずprofileモードで測る（debugは遅い）。最大の犯人は不要な再ビルドで、const 徹底・select/Selector・RepaintBoundary が効く。

ひとことまとめ：Dart 3.13は「書く量を減らす」primary constructors と型lintで足元を固め、Impeller既定＋Riverpod 3.0で描画と状態管理の現代化が既定路線になった回。
