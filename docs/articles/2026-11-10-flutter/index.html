Flutter 3.50は最終ゲートで足踏み — 待つ間に効くTweenAnimationBuilderとRepaintBoundary

stableは3.47.9のまま、beta 3.50.0-0.4.preが据え置き6日目。昇格待ちの今こそ、Controller不要の暗黙アニメと再描画の封じ込めを手に馴染ませる。

📅 2026年11月10日 ⏱ 約3分 🔗 出典 3 件

リリース面はこう着が続く。stable チャネルは依然 3.47 系（公開タグ最新 3.47.9）、beta は flutter-3.50-candidate.0 に乗りつつ 3.50.0-0.4.pre（11/4）で据え置き 6 日目——新 pre も stable 3.50 も 11/10 時点で未公開だ。release tracker #195830 は 11/2 起票のままコメント数ゼロ（動いているのは bot の相互参照だけ）で、11/9 に購読者は増えたが作業は進んでいない。最終ゲートで足踏みの構図は起票以来そのまま。実務は本番を 3.47.9 に pin 継続が安全で、別ジョブで beta を緑化して 3.50 の確定内容（WasmGC 既定・Android Impeller 一本化・material_ui/cupertino_ui の正式 deprecation・出れば Dart 3.14）を先取り検証しておくとよい。昇格待ちの今は、派手な新機能より“手に馴染ませておくと効く”標準部品を 2 つ。

TweenAnimationBuilder — Controller 無しで差分アニメ

ImplicitlyAnimatedWidget のサブクラスで、公式いわく「animated 版 widget が存在しない任意のプロパティを目標値まで animate する」のに便利。AnimationController を自分で持たずに、角度・係数・double・Color などを動かせる。肝は「新しい end を持つ tween を渡すと、現在値から新 end へ自動で差分アニメが走る」こと——状態変数を更新して rebuild するだけでよい。注意は、この widget が渡した tween の所有権を取得して内部で mutate する点で、渡した後の tween にアクセスしたりインスタンス変数に保持してはいけない。begin は初回のみ有効だ。

TweenAnimationBuilder<double>(
  tween: Tween(begin: 0, end: score.toDouble()), // score が変わると自動補間
  duration: const Duration(milliseconds: 400),
  curve: Curves.easeOut,
  builder: (_, v, __) => Text(v.toInt().toString()), // タップで 10→42 をカウントアップ
)

RepaintBoundary — 再描画を1レイヤで封じ込める

「子に対して別個の display list（専用 Layer）を作る widget」。再描画は最も近い祖先の repaint boundary まで伝播し、その内側を全部描き直す——だから常時アニメするスピナーやカウンタを包むと、外側の静的なリストやヘッダが巻き込まれなくなる。逆に「頻繁に変わるツリーの中の重く静的なサブツリー」を包めば、エンジンが一度ラスタライズしてキャッシュし高速化することもある。どこが無駄に再描画されているかは debugRepaintRainbowEnabled = true で枠色がチカチカする領域として観測できる。ただし Layer 追加は合成コスト・メモリがタダではないので、実測して効く境界に 1 枚だけが鉄則だ。

設計の土台としては、公式の App Architecture 推奨（UI 層＝View＋ViewModel／データ層＝Repository＋Service、MVVM で“widget を dumb に”、単方向データフロー、DI は provider、ルーティングは go_router）が引き続き基準線。ひとこと：バージョンが止まっている時間は、標準部品の手札を増やす好機だ。
