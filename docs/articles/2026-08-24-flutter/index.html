Dart 3.13 primary constructors 正式化とImpellerデスクトップ既定 — 状態管理は4択時代へ

クラスヘッダで field と constructor を1行宣言。Dart 3.13 で primary constructors が stable になり定型が激減。Impeller はデスクトップ3 OSで既定になりraster約50%短縮、状態管理は Riverpod/Signals/Bloc の使い分けが軸に。

📅 2026年8月24日 ⏱ 約3分 🔗 出典 4 件

今日のFlutterは「言語の定型削減」「描画の底上げ」「状態管理の選択肢拡張」が同時に動いた日。現行安定版は Flutter 3.47 / Dart 3.13（3.47.0 stable が Dart 3.13.0 を同梱）だ。

何が新しいか

primary constructors が 3.12 の experimental preview を経て Dart 3.13 で正式化。クラスヘッダで field と constructor を1行宣言でき、定型コードを大きく削減する。new / factory で簡潔な constructor 構文が書け、空の宣言本体は ; で終了可能。利用には language version を ^3.13.0 に上げる。あわせて Flutter 3.47 では Wasmアプリを小さな lazy-load モジュールへ分割する Wasm deferred loading（main channel の flag下・experimental）で初期ロードを最適化、multi-window改善・desktop flavors も実験導入された。

描画とアニメーション

Impeller が macOS / Windows / Linux の3 OSで既定レンダラに。SDF（Signed Distance Function）でデスクトップのテキストとベクター曲線がシャープになり、複雑シーンで raster時間を約50%短縮、ページ遷移や複雑なHeroも安定フレームで動く。軽い演出は flutter_animate の .animate().fadeIn().slide().scale() 連鎖、単なるfadeは AnimatedOpacity 等のimplicitで AnimationController を省く。時間設計の目安は micro 50〜200 / component 200〜400 / Hero 300〜600ms。

状態管理は4択時代へ

エコシステムは Riverpod 3.0 / Bloc 9.0 / GetX（退潮）の3強に Signals 6.0 が加わった。基本線は新規は Riverpod 3.0 を既定（unified Ref・automatic retry・experimental offline persistence、ref.watch(provider.select(...)) で最小スライス購読）、性能特化は Signals 6.0（surgicalなUI更新でリビルド範囲を最小化）、監査/規制業界は Bloc 9.0（on<Event> に統一、完全な event traceability と blocTest）。「どれが最良か」でなくチームの規模・リスク・性能要件でパラダイムを選ぶのが要点だ。

パフォーマンスとひとこと

最も多い性能問題は不要なwidget rebuild。プロパティ不変なら const で再ビルドを完全スキップ、アニメ領域は RepaintBoundary で隔離、大きな build() は分割、select で局所再描画。フレーム予算は 60fps=16 / 90fps=11 / 120fps=8.3ms、計測は必ずprofileモードで。言語・描画・状態管理が同時に底上げされた今は、まず primary constructors で定型を削り、Impeller前提でアニメを攻める好機だ。
