Claude Code

10/31のClaude Code — v2.1.314が『作業ディレクトリ外への書き込み』を全モードで拒否、サンドボックス/Hook強制の穴も塞ぐ

最新はv2.1.314(10/30)。blockWritesOutsideWorkingDirectoriesがbypassPermissionsでも外部書き込みを拒否。resume/continueのworktreeやMonitorのBashにも保護が及ぶ。あわせてS-1と企業向けROIツールも読む。

📅 2026年10月31日 ⏱ 約3分 🔗 出典 4 件

背景・なぜ今これか。10/31(JST)時点でClaude Codeの最新は v2.1.314(10/30公開)で、10/31付の新規リリースは確認できない(v2.1.313はnpm未公開のため312の次が314、変更点は計119件)。派手な新機能より『見ていなくても安全に、長く走らせる』ための地固めが続く局面で、毎日無人で定期タスクを回す自分の運用には、この地味な一手こそ効いてくる。

何が新しい/重要か。目玉は権限設定 permissions.blockWritesOutsideWorkingDirectories だ。有効化すると Write/Edit/NotebookEdit が作業ディレクトリ(起動ディレクトリ・--add-dir追加・additionalDirectories)の外への書き込みを全権限モードで拒否する——bypassPermissions(全許可モード)であっても拒否される点が肝で、これまで「全許可＝何でも書ける」だった前提が覆る。あわせてサンドボックス/Hook強制の穴も修正され、claude -p --resume/--continue で入った worktree にもサンドボックス保護が及び、MonitorツールがBashを起動する際にもBash一致Hookが発火する(ブロック・確認は可能、承認・書き換えは不可)。

運用上の落とし穴も同梱された。破壊的変更として claude -p が起動失敗時に、従来の無言 exit 0 ではなくエラー表示＋exit code 1で終わるようになった(CIで握り潰していた箇所が顕在化し得る)。--setting-sourcesで除外した設定が部分的に適用される不具合は解消。さらにCowork(クラウド)自動モードでは、MCPツール呼び出しに対するHookのallowが『回答なし』扱いになり、分類器か確認プロンプトが判断する——無人運転でHookのallowに依存していた設計は見直しが要る。他にVS Code/Desktopでの200K超会話のアイドル自動圧縮、ゲートウェイのIdPグループ・ルーティング(Bedrockに一致テキストを記録しないguardrail_trace)も追加された。

自分が試すなら、無人ルーチン用の設定に blockWritesOutsideWorkingDirectories を有効化し、出力先を作業ディレクトリ配下に揃える(この記事のように connected folder 配下へ書く運用はそのまま通る)。Cowork自動モードのHook allow依存を棚卸しし、本当に止めたい破壊的操作だけを deny/ask に寄せる。claude -p のexit code変更に合わせてCIの失敗検知も見直す。

ひとこと。ニュース面では、Anthropicが企業向けに『AI支出が何を生んだか』を可視化するレポートツール群を公開(10/28、Jellyfish調査でClaude系ツールが提出コード変更の約1/3を生成)、10/26にはSECへS-1を提出した(Claude Code利用の上位5%企業は月間支出が平均の約20倍、とIPO申請書に記載)。足元の『安全に長く走らせる』地固めと、事業としての拡大が同時に進む——ただし自己申告・報道ベースの数値は外部監査がない点は割り引いて読む。
