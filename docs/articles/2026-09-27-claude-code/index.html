Claude Code

静かな週末に運用の型を締める — claude plugin evalと「助言 vs 強制」の設計思想

新リリースはなくても、eval・Hook強制・Skill厳選・stable運用という“守られる仕組み”が出そろった一日。

📅 2026年9月27日 ⏱ 約3分 🔗 出典 7 件

週末（9/26〜27）は新バージョンのリリースがなく、最新安定版は9/25の v2.1.283 のまま。派手な更新がない代わりに、この週末は「Claude Code をどう運用するか」の型が出そろった。ひとつ前の v2.1.282 では、広い端末で本文の行幅だけを抑える maxProseWidth、Chrome連携と管理MCPを併用する allowClaudeInChromeWithManagedMcp、初回リクエストの低遅延化などが入り、セッション再送の変形や compaction 失敗といった地味だが効く不具合も潰されている。

公式『What's New』の目玉は claude plugin eval。作ったプラグインを一連のテストケースで実行してスコア化し、プラグイン無し（ベースライン）と比較できる。claude plugin eval init が評価ケースとグレーダーの下書きまで生成するので、「そのプラグインが本当に効いているか」を勘ではなく数字で検証できるようになった。

チュートリアル群で一貫していたのは「助言」と「強制」を分ける思想だ。CLAUDE.md の指示は約80%しか守られない一方、終了コード2を返す bash フックは確定実行で、破壊的な git 操作のブロックや編集後の自動 lint を100%強制できる。CLAUDE.md は150〜200行を超えると遵守率が目に見えて落ちるため、ビルドコマンド・アーキテクチャ・必須ワークフローに絞り、@path インポートで本体を肥大化させないのが定石。Skill も同じ発想で「8〜12個に厳選」が鉄則——増やすほどコンテキストを食い、性能は上がらない。Subagent は役割別（reviewer / test-writer）に作り、読み取りは Haiku・バランス作業は Sonnet とモデルを使い分け、独立コンテキストで並列実行させる。

自分が試すなら、まず破壊的操作を止める Hook を1本（exit 2）入れ、CLAUDE.md を200行以内に削り、Skill を棚卸しして未使用を落とす。運用ガイドは「即更新」より stable チャンネルで約1週間遅れの安定版を勧めており、デフォルトモデルが Sonnet→Opus 系へ段階変更されているので更新後は必ず /model で確認。新型モデルでは Todo 系ツールが既定オフになり CLAUDE_CODE_ENABLE_TODO_TOOLS=1 で戻せる点も落とし穴だ。

事例では、Coder が Agent Relay に Claude Code を統合し、顧客のクラウド／VPC／オンプレで自己ホスト実行＋完全監査を可能にして、金融など規制業界の導入障壁を外した。市場面では2026年5月に企業AI採用シェアで Anthropic 34.4%が OpenAI 32.3%を初逆転、年換算売上$30B超、Claude Code 単体でも$2.5B——牽引役はまさにこの自律コーディングだ。

ひとこと：静かな週末こそ運用の型を締める好機。eval で効果を測り、Hook で強制し、CLAUDE.md と Skill を絞る——「守られる仕組み」に投資した分だけ、日々の事故が減る。
