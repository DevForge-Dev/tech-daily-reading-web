Claude Code — Vertexでfast mode対応、MCP呼び出しの背景化と権限の締め直し

v2.1.322はVertexのfast mode対応という小粒。だが読みどころは直近v2.1.319の「MCPのバックグラウンド化」「denyInsteadOfPrompting」「auto modeの検証不能時ask/deny」で、権限と待ち時間の設計が一段固まった。

📅 2026年11月11日 ⏱ 約3分 🔗 出典 3 件

11/11時点の最新は v2.1.322（11/10付）。変更は実質1件で、Vertex（Google Cloud）上で fast mode（高速モード）が global/us/eu の各リージョンで使えるようになり、Vertex 側が拒否すれば標準速度へ自動フォールバックする。※Havoptic 版ページ＋変更追跡 issue #14951 の二次情報で、一次 CHANGELOG は未照合。公式 fast-mode ドキュメントは依然 Vertex/Agent Platform を"非対応"と記載しており、機能と表記が一時的にズレている点も指摘されている。

ただし"読み物"としての本題は、直近 v2.1.319（11/6）で入った権限・実行まわりの3点だ。

① MCP ツール呼び出しのバックグラウンドタスク化——呼び出しをターミナルで即バックグラウンドに移し、完了時に結果を Claude へ報告する。長い MCP を待つ間に手を止めずに済む。待機挙動へ戻すには CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND、完全無効化は CLAUDE_CODE_DISABLE_MCP_TASKS=1。

② permissions.denyInsteadOfPrompting——これまで"確認待ち"で止まっていた呼び出しを、プロンプトを出さず拒否してターンを継続する設定（ターミナル/subagent/teammate で有効）。無人実行で「人の承認待ちのまま固まる」事故を避けられる。

③ auto mode の判定整理——安全判定はサーバ側チェックに依存するため、テレメトリ無効や LLM ゲートウェイ下では判定が届かず、検証できない呼び出しは ask または deny に倒れる。内蔵分類器を使い続けたいなら CLAUDE_CODE_AUTO_MODE_SERVER=0（Bedrock/Vertex/Foundry は従来通り）。

自分が試すなら：無人の定期タスクに denyInsteadOfPrompting を入れて"承認待ちハング"を潰し、重い MCP を使うワークフローで背景タスク化の効きを /context 込みで確認する。落とし穴：ゲートウェイ経由だと auto mode が意図せず ask/deny に倒れるので、挙動が変わったらまず CLAUDE_CODE_AUTO_MODE_SERVER を疑う。まとめ：派手さは無いが「待たせない・止めない・緩めない」の三方向で運用が一段固まった回だ。
