Claude Code

8月のClaude Codeを総ざらい — v2.1.235スペルチェック、利用上限リセット後の自動継続、そしてMicrosoft調査『マージPR+24%』

8月はv2.1.229〜235がほぼ日次でリリースされ、細かな安定性・セキュリティ・エディタ体験の改善が積み上がった。235はプロンプト入力のスペルチェック、234は利用上限リセット後のセッション自動継続と資格情報漏洩対策。裏づけとしてMicrosoft社内の数万人規模調査が『Claude Code採用でマージPRが約24%増、効果は4か月持続』を示し、法人30万社超・ラン率売上25億ドル超という市場規模と、公式101プラグインのエコシステムが並ぶ回。

📅 2026年8月20日 ⏱ 約2分 🔗 出典 5 件

今日は特定の新機能というより、8月に積み上がった日次改善の総ざらいが主題だ。Claude Codeはこの月、v2.1.229〜235をほぼ毎日刻むペースでリリースし、派手さはないが安定性・セキュリティ・エディタ体験を着実に底上げしてきた。点を線にすると流れが見えてくる。

直近の目玉を2つ。v2.1.234（8/17）は、利用上限に達したセッションが上限リセット後に自動で継続するようになり、長時間の作業が途中で止まらなくなった。あわせて資格情報の漏洩に対するセキュリティ保護を強化。v2.1.235（8/18）はプロンプト入力欄にスペルチェック（任意）を追加し、インストール済みのaspell/hunspell/ispellでミス単語に下線を引く。加えて言語サーバ再接続時のキャッシュ失効、ネストMarkdownリストのズレ、Shift+Tab誤承認などUIの細かな不具合を多数修正した。

こうした改善が実務でどれだけ効くかを裏づけるのが、Microsoft Researchの査読付き調査だ。数万人規模のエンジニアを対象に、Claude Code採用者は未採用時よりマージされたPRが約24%多く、効果は4か月の観測期間を通じて持続したという。ただし生産性の裏でトークン支出が数百万規模に達する点も指摘され、予算ガバナンスの必要性が説かれている。

足回りの知見も更新された。設定ファイルCLAUDE.mdは公式鉄則「200行以内・削れる行は全部削る」が軸で、長いほどトークンが増え指示が競合して精度が落ちる——短いほど守られる。.claude/rules/の正式機能化やauto memoryも押さえたい。エコシステム面では公式マーケットにAnthropic製33＋パートナー製68の計101プラグインが並び、Skills・Subagents・Hooks・MCPを束ねて/pluginで導入できる。

自分が試すなら：手元のCLAUDE.mdを200行に圧縮し、削った規約を.claude/rules/へ分離してトークンを軽くする。CIにはヘッドレスモードで自動レビューを噛ませたい。落とし穴：日次リリースは便利だが、スペルチェックはaspell等の外部辞書が前提で、入っていなければ動かない。まとめ：小さな改善の連打が「マージPR+24%」という実効に結実し、101プラグインの土台が広がった——数字で振り返るのに良い一日だった。
