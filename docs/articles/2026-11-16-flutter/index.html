Flutterは今日もstable静か（3.50.0を実質pin）。深掘りはAnimatedSwitcher — 差し替えアニメが「動かない」最大の罠は一意のKey

stableは3.50.0（11/11）据え置きでhotfix 3.50.1も約5日未登場、四半期ケイデンスでは次feature stableは2027 Q1が目安。今日の技法はAnimatedSwitcher——別widgetへの差し替えを自動クロスフェードするが、childに一意のKeyを与えないと遷移しない。

Flutterのstableは今日も静かだ。flutterreleases.comのreleases.jsonは11/15生成に更新されたが、中身はstable 3.50.0 / Dart 3.14.0（11/11）が据え置き——公開から約5日経ってもhotfix 3.50.1は未登場で、公式docsのwhats-newも「reflects Flutter 3.50」のままだ。公式ポリシーは「最新版だけをhotfix」で、過去例では3.47.1が3.47.0の約1週間後に出ているため3.50.1はまだ出得る時間帯だが、回帰hotfix連発は起きていない＝初動は安定。2026は番号+3ずつのほぼ四半期リズム（3.41→3.44→3.47→3.50）なので、次のfeature stableは2027 Q1・番号は3.53相当が観測からの目安。それまで3.50.xが実質のpin基準だ（ケイデンスは二次情報ベースなので版依存の確定値はroadmap要確認）。

今日の技法：AnimatedSwitcher と「動かない」最大の罠

AnimatedSwitcherは別々のwidget間の入れ替えを暗黙アニメするStatefulWidgetだ。AnimatedContainer（同一widgetのプロパティ補間）や自前ControllerのSlideTransitionと違い、「古いchildを退場・新しいchildを入場」という差し替えそのものを補間する（ロゴ切替・カウンタ・ローディング→結果の切替など）。必須引数はdurationのみで、既定はクロスフェード。

最大の罠は、childが「変わった」判定が型＋Keyで行われること。新childが旧childと同じruntimeTypeかつ同じkeyだと、パラメータが違っても「同一widgetの更新」とみなされ遷移が起きない（frameworkがin-place更新する）。発火させるには新childに毎回ユニークなKey（通例ValueKey(識別データ)）を付ける。

AnimatedSwitcher(
  duration: const Duration(milliseconds: 300),
  transitionBuilder: (child, anim) =>
      ScaleTransition(scale: anim, child: child),
  child: Text('C', key: ValueKey(count)), // ← Keyが肝
)

挙動とカスタム

旧childがswitchOutCurveでフェードアウトしつつ、新childがswitchInCurveでフェードインを同時進行する（ともにduration）。transitionBuilderは新childがセットされた時だけ呼ばれ、layoutBuilderは毎build呼ばれて入退場childをまとめてラップする（どちらもnull返却不可）。ScaleTransition／SlideTransition／RotationTransitionに差し替えれば任意のエフェクトになる。使い分けは、候補が不定・多数ならAnimatedSwitcher（keyで差し替え）、ちょうど2つの既知widget間ならAnimatedCrossFade（crossFadeStateで切替・両方を常にbuild）。

今日のもう2つのメモ

provider（6.1.5+1）はInheritedWidgetの薄いラッパでRiverpodの前身。ChangeNotifierProvider＋context.watch/read/selectが基本で、新規生成は自動disposeされるcreate:、既存オブジェクトは.value（既存のChangeNotifierをcreateで渡さない）。アダプティブUIは「responsive＝空間に収める／adaptive＝空間で使える」で、公式唯一の数値閾値は600論理px（未満はbottom nav、以上はnav rail）。計測はMediaQuery.sizeOf＋LayoutBuilder。なお公式プリセットflutter_adaptive_scaffoldはDISCONTINUEDなので新規依存は避け、M3ガイド＋自前分岐に寄せるのが現行の推奨だ。

ひとこと

AnimatedSwitcherは「Keyを付け忘れて動かない」で一度は必ずハマる。ValueKey(識別データ)をセットで覚えておけば、カウンタやローディング→結果の切替が数行でクロスフェードになる。stableは3.50.xでpinしたまま、別ジョブでbeta 3.51.0-0.1.pre（Dart 3.15）を緑化して次サイクルを先取りしておくのが堅い。
