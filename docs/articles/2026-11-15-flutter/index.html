Flutter 3.50 リリースノートを棚卸し — windowing APIの改名・新Sliver/Dialog API・最低AGP 9.1.1、そしてRiverpod 3のMutations

stable は 3.50.0 据え置き（hotfix 3.50.1 は公開約4日でも未登場＝初動は安定）。今日はリリースノート実体を読み解く。multi-window の API 改名、新API群、design library の正式deprecation。あわせて Riverpod 3 の experimental「Mutations」で送信中状態を型にする。

📅 2026年11月15日 ⏱ 約3分 🔗 出典 3 件

リリース状況から。stable は 3.50.0 / Dart 3.14.0（11/11）が現在も最新で、公開直後の最初の hotfix 3.50.1 はまだ出ていない（公開から約4日）。過去の「公開直後に回帰修正が連発」パターンは今回は起きておらず、初動は安定している。beta は同日に 3.51.0-0.1.pre（Dart 3.15.0）。本番は 3.50.0 を新たな pin 基準に、別ジョブで 3.51 beta を緑化しておくのが定石だ。

3.50 で入った実体：API改名と新API

multi-window 周りが名前ごと整理された。RegularWindow*→Window* 改名、sizedToContent→shrinkWrap 改名（PR #189363）、Win32 の satellite windows 実装、macOS の size-to-content window 実装。旧 RegularWindow 参照のコードは改名追従が必要。新APIも多い：sliver を矩形/角丸でクリップする SliverClipRect/SliverClipRRect、RawImage/RenderImage に blendMode、showDialog にバリアを自前widgetで描ける barrierBuilder、ListView.separated に itemExtentBuilder（可変extent）、MediaQuery が reduceMotion アクセシビリティ対応、など。

Riverpod 3 の Mutations（experimental）で「進行状態」を型にする

「送信中スピナー」等の進行状態を provider の state に持たせると UI 懸念が混ざる。Mutations はその loading/error/success の面倒を肩代わりする（codegen 無しの plain object）。宣言は final addTodo = Mutation<Todo>();、起動は addTodo.run(ref, (tsx) async { … })、購読は ref.watch(addTodo)。状態は MutationIdle / MutationPending / MutationError / MutationSuccess の4種で、UI は switch で分岐する。完了または全listener除去で自動的に Idle へ戻る。

自分が試すなら・注意点

まず flutter upgrade→flutter analyze で改名漏れを洗い、dart fix --apply で design library import を寄せる。AGP 9.1.1 未満はビルドが通らないので CI の Gradle/AGP を先に上げること。Mutations はexperimental でメジャー無しに破壊的変更があり得るため本番採用前に import を確認。hotfix 3.50.1 が出たら即追従で。
