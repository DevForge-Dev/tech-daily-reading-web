Claude Code

Claude Opus 5 が既定に — 1Mコンテキストと運用回りの地ならし

既定Opusが Opus 5 へ更新。最大100万トークンの文脈と fast モード、/doctor の自動修復やサブエージェント3階層まで、開発フロー全体が静かに底上げされた。

📅 2026年7月29日 ⏱ 約2分 🔗 出典 4 件

この数週間、Claude Code は派手な単発機能よりも「土台の底上げ」に寄っている。今日の目玉は、既定の Opus モデルが Claude Opus 5（claude-opus-5） に切り替わったこと。単なるモデル更新に見えて、扱えるコンテキストが最大100万トークンへ拡張されたのが効く。大規模コードベースや長時間の会話を、要約で削らずに丸ごと載せて考えさせられるようになった。

価格面では応答優先の fast モードが用意され、入力$10／出力$50（100万トークンあたり）が案内されている。深い推論が要る場面は通常、即応が欲しい対話は fast、と使い分ける前提だ。

運用回りも整った。/doctor はセットアップを点検し、見つけた問題をその場で修復まで試す。サブエージェントは既定で深さ3までネストでき、委譲フローを多段に組める。/code-review はバックグラウンドのサブエージェントとして走るので、レビュー出力が本体の会話を埋め尽くさない。デスクトップ版には内蔵ブラウザが加わり、ドキュメントや任意サイトを Claude Code 内で開いて操作できる。

効果は数字にも出ている。Microsoft Research の査読論文（7/1）では、Claude Code 導入者はマージPRが約24%増え、4か月の観測期間を通じて持続したという。市場側でも 2026年2月時点でラン率売上$2.5B超、エンタープライズ契約は年初から4倍と、CLIエージェントが主流化しつつある。

自分が試すなら、まず 1M 文脈を活かして「リポジトリまるごと読ませての設計レビュー」を深いモデルで、日常の反復は fast で、と役割を分ける。落とし穴はコスト。エンタープライズ規模ではトークン消費が数百万ドル規模に達しうるので、上限設定と可視化（予算ガバナンス）を先に敷くのが成功条件だ。ひとことまとめ：機能追加というより「広く扱い、静かに回す」ための地ならしの一週間。
