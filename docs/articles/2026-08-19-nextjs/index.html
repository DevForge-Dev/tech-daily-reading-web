Next.js

next/formの<Form>で検索・フィルタを1コンポーネントに — プリフェッチ＋ソフト遷移＋PEを標準装備、actionの型で2分岐

検索/フィルタUIの定型（'use client'＋useRouter().push＋useSearchParams＋form onSubmit）を、next/formの<Form>が1コンポーネントに畳み込む。actionの型で挙動が2分岐し、文字列ならGET検索ナビゲーション（プリフェッチ＋クライアント遷移＋JS無効でも動く）、関数ならServer Actionミューテーション。Next.js 16ではsearchParamsがPromiseでawait必須になった点も要注意。

📅 2026年8月19日 ⏱ 約4分 🔗 出典 4 件

検索ボックスやフィルタUIは入力をURLのクエリパラメータに載せて結果ページへ遷移するのが定石だ。URLが共有可能で、戻る/進むで復元でき、SEOにも強く、サーバー側でsearchParamsを読んで取得できるからだ。だが素朴に書くと'use client'＋useRouter().push()＋useSearchParams()＋<form onSubmit>の定型コードが毎回膨らみ、遷移先のプリフェッチやJS無効時のフォールバックまで自前で面倒を見ることになる。

これを1コンポーネントに畳み込むのがnext/formの<Form>だ（Next.js 15でGA導入、現行は16.3）。HTMLの<form>を拡張し、(1)ビューポート進入時に遷移先の共有UI（layout.js・loading.js）をプリフェッチ、(2)送信時はフルリロードでなくソフトナビゲーションで共有UIとクライアント状態を保持、(3)中身は素のGETフォームなのでJS未ロード/無効でも動くプログレッシブエンハンスメント——の3つを標準装備する。

そして最重要はactionの型で挙動が2分岐することだ。

action が文字列（URL/相対パス）ならGET検索ナビゲーション。フォームデータがURLの検索paramにエンコードされ、そのURLへ遷移する。<input name="query">にabcを入れて送信すれば/search?query=abcだ。空文字action=""は同じルートにparamだけ更新して遷移する（フィルタUIの定番）。一方action が関数ならServer Action（ミューテーション）で、遷移先が実行時まで不明なので自動プリフェッチは効かず、replace/scroll propも無視される。

// 検索: 別ページへGETナビゲーション（'use client'不要）
import Form from 'next/form'
<Form action="/search">
  <input name="query" />
  <button>Search</button>
</Form>

文字列actionモードのpropsは実務で効く。replace（既定false）で履歴をpushでなくreplaceにしフィルタ操作で履歴を汚さない、scroll（既定true）はフィルタではscroll={false}にして現在位置を維持、prefetch（既定true）で可視時にプリフェッチ。だから同ルートのフィルタは<Form action="" scroll={false} replace>が定番形になる。サーバーで現在のsearchParamsを読みdefaultValueへ流せば選択状態が復元する。

落とし穴：onSubmitでevent.preventDefault()を呼ぶと<Form>の遷移が止まる。method/encType/targetは非対応（必要なら素の<form>を使う）。<input type="file">は文字列actionだとファイル名だけ送信されるのでアップロードは関数action（Server Action）で。key propは文字列actionに渡せない。そしてNext.js 16ではsearchParamsがPromiseでawait必須、読むページは動的レンダリングになる点にも注意。

使い分け：別ページ検索はaction="/search"、同ルートフィルタはaction="" scroll={false} replace。入力ごとに即URL反映するライブ検索/デバウンスは<Form>の担当外で、useRouter()＋useSearchParams()＋useDebouncedCallbackの'use client'島でやる。型安全なparam状態が欲しければnuqsのuseQueryStateと併用する（<Form>で確定・nuqsで読み書き）。

まとめ：検索は<Form action="/search">、フィルタはaction=""＋scroll={false}＋replace。プリフェッチとプログレッシブエンハンスメント込みの「送信で確定」型ナビゲーションを、RSCのまま最小コードで置けるのが<Form>の価値だ。
