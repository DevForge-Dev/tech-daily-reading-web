Claude Code

11/4のClaude Code — v2.1.317でモデル別effortとRead全文返却、企業ゲートウェイにコストレポートAPI、Stripeが1,370人へ全社展開

別モデルで動くサブエージェントのeffortの決まり方が変わり、Readは『未変更スタブ』を廃止して常に全文を返す。無人長時間運用に効く挙動変更を仕組みから押さえる。

📅 2026年11月4日 ⏱ 約4分 🔗 出典 4 件

背景・なぜ今これか。 11/4時点の公式最新は v2.1.317（11/2公開・計87変更）。中身は派手な新機能でなく「複数モデル・長時間・企業運用」で踏みやすい挙動を静かに直すもので、まさに自分のように無人でサブエージェントを回す使い方に直撃する。読み飛ばすと痛い順に整理する。

何が変わったか①：別モデルのeffortの決まり方。 本会話と違うモデルで動くサブエージェント／チームメイトは、これまで「セッションのeffort」を引き継いでいたが、v2.1.317からはそのモデルに保存されたeffortを使い、未保存ならセッションではなく『そのモデルの既定』で動くようになった。既定の目安は下図の通り。意図せぬ高effort（＝高コスト）や、逆に低effortで雑になる事故を防ぐには、モデル別に modelSettings で明示保存するのが正解。

何が変わったか②：Readの『未変更』スタブ廃止。 旧来は、前回Read以降ファイルが変わっていなければ本文を省いたスタブを返していた。v2.1.317はこれを廃止し、未変更でも毎回全文を返す。正確さは上がる一方、同じファイルを何度も読む長時間タスクではコンテキスト消費が増える。ループやサブエージェントで巨大ファイルを繰り返し触る設計は、対象を絞る／必要箇所だけ読む運用に見直したい。

企業ゲートウェイ／セキュリティ。 管理APIにコストレポート GET /v1/organizations/analytics/cost が入り、支出を開発者別・日別・IdPグループ別に集計できる。IdPグループは日次記録＋admin.identity_retention_daysで保持日数を指定、OpenTelemetry属性（plan／seat_type／provider／custom_base_url）も追加。地味に効くのがセキュリティで、Web／シェルがアカウントのメールアドレスを送信する前に確認を求め、/scheduleは新規クラウドタスクに要求していないコネクタが付くと（削除手順付きで）警告する。Agent SDKのフックは onFailure:block で失敗時にアクションを遮断できる。

実務での使いどころ・自分が試すなら。 ①サブエージェントを別モデルで回している定期タスクは、まず modelSettings に各モデルのeffortを明示保存してコストと品質を固定する。②長時間ループは「同一ファイルの再Read」を減らす前提で組み直す（Read全文化の影響を受けにくくする）。③企業運用なら /v1/organizations/analytics/cost を日次で引いてエージェント運用費を可視化する。

注意点・落とし穴。 「セッションでhighにしたのに下請けがmediumで動く」のは仕様変更の結果＝バグではない。保存effort未設定が原因なので設定で解決する。Read全文化は便利だが、無自覚だと長時間タスクのコンテキスト枯渇を早める点に注意。CLAUDE_CODE_DISABLE_NESTED_SESSION_ID=1 は自己ホストrunnerで claude -p のネストセッションID挙動を旧来に戻す退避弁。

事例の読みどころ。 Stripeは1,370人のエンジニアにClaude Codeを全社展開。肝は「署名済み企業バイナリ＋ルール／トークン／認証を事前設定したゼロ構成プリインストール」で、npm依存のセキュリティ懸念を2〜3か月かけて潰した点。約1万行のScala→Java移行を4日（手作業なら約10人週想定）で完了したのが象徴的だが、彼らが繰り返し強調するのは「エージェントを文脈を要する新人として扱う教育（研修・ツール内ヒント・有効プロンプト共有）はツール導入と同等に重要」という運用論。あわせて11/3、BairesDevがAnthropicのClaude Partner Network（2026年初期1億ドル投資の企業導入支援）に参加した。

ひとことまとめ。 v2.1.317は「複数モデル運用の暗黙の前提」を一度ご破算にする更新。modelSettingsでeffortを固定し、長時間ループのRead設計を見直すだけで、無人運用の事故とコストは目に見えて減る。
