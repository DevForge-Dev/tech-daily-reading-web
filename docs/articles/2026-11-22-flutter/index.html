Flutter の今日の軸は「配布は先行・tracker は未更新」の beta hotfix と、Rive 0.14 のネイティブ化 — Dart ランタイム全廃で API も刷新

stable は 3.50.1／Dart 3.14.0 据え置き。今日の news は beta 側のホットフィックス手続き——tracker #196929「3.51.0-0.1.pre」が cherry-pick 全マージ済みなのに publish 系は全未チェック、一方で配布物は既に 3.51.0-0.2.pre（Dart 3.15.0）が出現、という“配布先行・tracker stale”の再演。技法面では rive 0.14.0 が Dart ランタイムを全廃し C++ ネイティブ（rive_native）へ全面移行、ウィジェット API も RiveWidget 系へ刷新された。

まずリリース状況。stable は 3.50.1／Dart 3.14.0（11/20）据え置きで昨日から変化なし。今日の動きは beta チャネルのホットフィックス手続きにある。GitHub の flutter/flutter #196929「[beta][hotfix] 3.51.0-0.1.pre」が release-tracker として OPEN で、cherry-pick はすべてマージ済み、Dart ハッシュ（3b174b7…）と engine ハッシュ（e98d27d…）も pin 済み。ところが「Validate and publish release」節——postsubmit 検証／MPA push／SDK Archive 確認／告知——は全項目が未チェックだ。にもかかわらず flutterreleases には既に 3.51.0-0.2.pre（Dart 3.15.0・11/19）が出現している。stable の #196743 と同じ「配布物は出ているが tracker は未更新」というねじれが、beta 側でも再演された格好だ。

今日の技法：Rive が Dart ランタイムを捨てた

アニメーションの主役は rive パッケージの大転換だ。Rive は Lottie（After Effects 由来 JSON の“再生”）と違い、入力で分岐する state machine（インタラクティブ実行時アニメ）が主戦場。その rive 0.14.0 が、ランタイムに使っていた Dart コードを完全撤去し、下層の C++ Runtime（rive_native）へ全面移行した。changelog いわく純 Dart 実装はこの版で廃され、prebuilt ネイティブライブラリをビルド時に取得する方式になった（純 Dart の最終版は 0.13.20、legacy repo 側に残る）。対応は iOS／Android／macOS／Windows／Linux／web。現行は rive 0.14.11（verified publisher rive.app・MIT・依存に rive_native 0.1.11）。

仕組みのポイント：描画エンジンを選べる＋ API 刷新

ネイティブ化の副産物として、各 File が描画エンジンを選択できるようになった——Factory.rive（Rive 独自ベクタ描画＝Rive Renderer）か Factory.flutter（Flutter の Skia／Impeller 経由）だ。0.14 系で Rive Renderer・data binding・layouts・scrolling・N-slicing・vector feathering が加わり、0.14.1 で Rive Scripting、0.14.2 で observable view model に valueStream が入った。ウィジェット API も刷新され、旧来の RiveAnimation.asset/.network ＋ StateMachineController ＋ SMIBool/SMINumber/SMITrigger という組み立てから、RiveWidget ＋ RiveWidgetController（active で state machine の稼働を制御）＋ File.asset へ変わった。公式 example もこの新 API 基準だ。

移行の落とし穴：input/text run は data binding へ、switch は網羅破綻に注意

破壊的変更が重いので要注意だ。0.14.0-dev.14 で「state machine input と text run へアクセスするメソッドが deprecated」となり、data binding が推奨になった（example も Inputs/Text Runs を「Legacy Features [Use data binding instead]」に分類）。旧 findInput／findSMI 系で input を直接叩いていたコードは data binding へ書き換える前提で臨む。さらに 0.14.7 で audio events が sealed Event に追加され、網羅的な switch に新しい arm が必要になる（＝アップグレードで switch が非網羅になりコンパイルが落ち得る）。0.14.11 では web で ancestor transform を加味する RenderResolution が入った。ネイティブライブラリの再生成は dart run rive_native:setup --clean --build --platform <os>。

あわせて：hooks と CPU profiler

状態管理では flutter_hooks 0.21.3+1（Riverpod と同じ Remi Rousselet 製）が React Hooks の Flutter 実装として安定。HookWidget を継承し build() 内で useAnimationController 等を呼ぶと initState/dispose の定型が消える。肝は hook state が Element 上の List<Hook> に呼び出し順で格納される点——だから use* は条件分岐で囲まず無条件に呼ぶのが鉄則だ。パフォーマンス面では DevTools の CPU profiler は profile モード必須（flutter run --profile）で、Bottom up（self time 大のメソッド探し）／Call tree（高コスト経路）／Method table／Flame chart の4ビューを使い分ける。sampling rate 既定 medium は 1 sample/250μs だ。

ひとこと

stable は 3.50.1 継続で慌てて動く必要はない。むしろ今日見るべきは Rive の 0.14 ネイティブ化で、既存 Rive 統合を持つプロジェクトは「data binding 必須・switch 網羅の破綻・描画エンジン選択」の3点を踏まえてから上げるのが安全だ。state machine を多用しているほど移行コストは実在するので、移行ガイド（rive.app/docs/runtimes/flutter/migration-guide）を先に読んでおきたい。
