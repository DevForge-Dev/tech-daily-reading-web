<Activity>（React 19.2）で「状態を保ったまま隠す」— タブ/ルートのkeep-alive・先読み・選択的ハイドレーション、Next.js 16の自動bfcacheの土台に

条件付きレンダーは非表示でアンマウントしstateを破棄するが、<Activity mode="hidden">はdisplay:noneで隠しつつstate/DOMを保持し、visible復帰で前状態を復元する。App Routerではデータ取得をRSCに残し表示制御だけを薄いClient島に置くのが定石で、hydration mismatchも起きない。Next.js 16のcacheComponentsが内部でこれを使い、戻る/進むを状態付きで高速復元する。

📅 2026年8月31日 ⏱ 約5分 🔗 出典 5 件

React 19.2（2025-10-01リリース）で <Activity> が安定APIになった。従来の条件付きレンダー {cond && <Page/>} は、非表示にした瞬間にコンポーネントをアンマウントし、内部stateもDOM state（入力途中のテキスト、スクロール位置、<video>の再生位置など）も破棄してしまう。<Activity> はこれを置き換え、mode="hidden" の間は display:none で視覚的に隠しつつ state と DOM を保持し、mode="visible" に戻すと前の状態のまま復元する。なぜ今かというと、これが Next.js 16 の Cache Components（cacheComponents:true）がクライアント遷移の「戻る/進む」を高速化する土台になっているからだ。

何が新しいか

19.2時点のmodeは2つ。hidden は子を display:none で隠し、Effectをクリーンアップ（概念的にアンマウント）、更新は「他にやることが無くなるまで後回し（低優先度）」——ただし state / DOM は保持する。visible は表示＋Effect再マウント＋通常優先度で、省略時のデフォルト。主な使いどころは3つで、(1) タブ/サイドバーを閉じても入力が残る状態保持（keep-alive）、(2) 初回から hidden で置き低優先度で裏レンダーする先読み（pre-render）、(3) 境界でツリーを分割する選択的ハイドレーションの高速化だ。関連機能に useEffectEvent、RSC専用の cacheSignal、react-dom の Partial Pre-rendering（prerender+resume）がある。

仕組みのポイント

App Routerではデータ取得はRSCのままにし、表示制御を持つ薄いClient島だけ 'use client' にするのが定石だ。home/posts を Server Component として page.tsx から props で流し込み、島側で <Activity mode={tab==='home'?'visible':'hidden'}> を切り替える。初回SSRのHTMLは条件付きレンダー版と同じ見た目なので hydration mismatch は起きない。先読みは、子が use(fetchPosts()) のようにSuspenseを発火する取得を持つときだけ効く（useEffect内fetchは対象外）。

実務での使いどころ・自分が試すなら

まず既存のタブUIで {cond && <X/>} を <Activity mode={cond?'visible':'hidden'}> に置換し、入力途中フォームやスクロール位置が消えないか確認したい。次に開きそうな重いタブは初回から hidden で置いて先読みし、実タップ時にフォールバックを出さない。Next.js 16 では cacheComponents:true を有効化すれば <Activity> を直書きせずとも自動bfcacheが効き、必要なら router.bfcacheId で「新規遷移か復元か」を分岐（復元時はアナリティクスの重複計測を避ける等）できる。

注意点・落とし穴

<video>/<audio>/<iframe> は隠してもDOMが残るため再生が鳴り続ける。useLayoutEffect のクリーンアップで videoRef.pause() する（視覚的に隠れるタイミングに同期させるため useEffect ではなく useLayoutEffect）。hiddenの間はEffectが動かないので、購読やタイマーはcleanup側で止める設計に直す。<StrictMode> を使うと未クリーンアップのEffectを炙り出せる。テキストだけを返す子はhiddenでも何も描かない（適用先のDOM要素が無いため）。hidden中もツリーは生きてメモリを使うので無制限に積まない（Nextのbfcacheは直近N件に制限）。<ViewTransition> と組むと visible/hidden で enter/exit アニメが発火するが、@media (prefers-reduced-motion: reduce) で動きだけ止め、状態切替は残す。

ひとこと

「隠す＝壊す」だった条件付きレンダーを、「隠す＝取っておく」へ変える地味だが効く一手。App Routerの島設計と噛み合い、Next.js 16では書かずとも恩恵を受けられる。
