Scroll Snap Events で『どこにスナップしたか』をJSで正確に拾う — scrollsnapchanging と scrollsnapchange

CSS scroll-snap は気持ちよく止まるまではCSSで完結するが、『今どこに着地したか』をJSで正確に知る手段が長らく無かった。先行の scrollsnapchanging と確定の scrollsnapchange がそれを解決する。App Router での島化まで。

📅 2026年9月11日 ⏱ 約3分 🔗 出典 3 件

CSS scroll-snap（scroll-snap-type／scroll-snap-align）は「気持ちよく止まる」までは CSS だけで完結する。しかし『今どのアイテムにスナップしたか／これから何にスナップしようとしているか』を JS で正確に知る手段が長らく無かった。従来は IntersectionObserver で「ポートの大半を占める要素＝スナップ対象だろう」と推測し scrollend を待つ回りくどい実装しかできず、フリック操作では取りこぼしが出ていた。

何が新しいか — 対になった2イベント

SnapEvent インターフェースの2イベントが性格の対になっている。scrollsnapchanging は先行・積極的：スクロール中（指を離す前）に「離したらここに着地する」と判定した瞬間に発火し、1ジェスチャで複数回出うる。フリックで複数を飛び越えても途中は飛ばして最終着地の1つだけ通知する。scrollsnapchange は遅延・確定：完全静止し、かつ対象が変わった時だけ scrollend の直前に発火する（対象が変わらなければ出ない）。

イベントオブジェクトと対応状況

event.snapTargetInline／event.snapTargetBlock にスナップした要素ノードが入る（横のみなら Block は null、縦のみなら Inline は null）。発火はスナップ・コンテナで、document／window でも受けられる。対応は 2026-09 時点で Chrome/Edge 129+のみで Firefox/Safari 未対応＝Baseline 未達。必ずプログレッシブ・エンハンスメント前提で使う。

App Router での組み込み

スクロールイベント購読はブラウザ専用なので 'use client' 必須。スクローラーを小さな Client Component（島）に隔離し、周囲は Server Component のまま。ギャラリー画像や見出しは RSC 側から children／props で渡し、イベント配線だけをクライアントに置く。初期アクティブは useState(0) で決め打ちし、マウント後にイベントで更新して hydration mismatch を避ける。未対応ブラウザは IntersectionObserver へフォールバックする。

落とし穴

scrollsnapchange は「対象が変わらない微スクロール」では発火しない＝常時ハンドラを載せない（それは scroll／scrollend の仕事）。scrollsnapchanging は高頻度で出るので中で DOM 大量更新をしない（クラス付替え程度に）。そもそも scroll-snap-align の付いた子が無いと発火しない。ピッカーとして使うならキーボード/スクリーンリーダー導線を別途用意する。

ひとことまとめ

「推測なし・正確・適切なタイミング」でスナップ状態を拾える素の API。カルーセルのドット同期や着地演出が依存ゼロで書ける。ただし Chrome 系限定なので、フォールバック込みで“進歩的強化”として仕込むのが正解。
