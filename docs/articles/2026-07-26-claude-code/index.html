Claude Opus 5 リリースと、暴走fan-outを止めるサブエージェント統制 — v2.1.217〜changelog

7/24に新フラッグシップ Claude Opus 5 が正式リリース。1Mトークン文脈・最大128k出力・思考(thinking)既定オン・新「xhigh」推論を備え、価格は据え置きの$5/$25のまま最上位 Fable 5 に迫る。同じ週、Claude Code 側は暴走的なサブエージェントの扇形展開(fan-out)を抑える統制を入れた。「強いモデル」と「安全に回す土台」が同時に来た回。

📅 2026年7月26日 ⏱ 約2分 🔗 出典 3 件

背景から。エージェント型コーディングが日常運用に入り、課題は二つに分かれてきた。ひとつはモデルの賢さ、もうひとつはエージェントを安全に回す統制だ。7月24日はその両輪が同じ週に動いた日で、Opus 5 のリリースと Claude Code 側のサブエージェント制御が重なった。

何が新しいか① — Claude Opus 5

新フラッグシップ Claude Opus 5 は 1Mトークンの文脈ウィンドウ（1Mが既定かつ最大）、最大 128kトークン出力、思考が既定オンで、新たな推論エフォート水準 「xhigh」 を持つ。価格は Opus 4.8 から据え置きで 入力100万トークン$5 / 出力$25。最上位 Fable 5 に迫る知能を約半額で出す位置づけで、Frontier-Bench や GDPval-AA などのコーディング・知識労働評価で社内の新最高水準を記録した。Claude Max の既定モデル、Claude Pro で使える最強モデルとして展開される。

何が新しいか② — サブエージェントの統制

v2.1.217 はサブエージェント制御を見直した回。既定ではサブエージェントが入れ子(ネスト)のサブエージェントを生成しないよう変更し、深いネストが要る時だけ CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH で明示許可する方式にした。あわせて同時実行サブエージェント数の上限(既定20)を CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS で新設し、1メッセージが無制限にバックグラウンドエージェントを扇形展開する事態を防ぐ。その後の changelog では、扇形展開の抑制と柔軟性のバランスを取りネスト深さ3が既定へ緩和され(=1で無効化)、/code-review がバックグラウンドのサブエージェント実行になってメイン会話ログを埋めなくなった。claude-api スキルの既定モデルも Opus 5 に更新された。

実務での使いどころ・注意点

自分なら Opus 5 を日常の既定に置きつつ、大量ファイル横断で並列サブエージェントを使う場面では同時実行上限(20)を意識してタスクを束ねる。レビューは /code-review をそのまま回せばログが汚れない。注意は、xhigh や 1M 文脈・思考既定オンはトークンとコストが増える方向なので、軽い作業では推論エフォートや思考を絞ること。深いサブエージェント階層は既定で抑えられているので、意図的な多段委譲は環境変数で明示的に開ける。ひとことで言えば「賢さは据え置き価格で底上げ、運用は統制で安全に」の回だ。
