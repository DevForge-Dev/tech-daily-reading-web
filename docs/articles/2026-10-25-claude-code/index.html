Claude Code

v2.1.310でMonitorを主要クラウドへ開放 — そして「フック/スキル/ルール/サブエージェント」の使い分け

小刻みパッチが続く2.1系はv2.1.310でMonitorをBedrock/Vertex/Foundryへ拡大。この日の読みどころは、指示を「いつ読まれ・圧縮に耐え・どれだけ文脈を食うか」で整理する公式の操縦術と、採用で初逆転した市場データだ。

📅 2026年10月25日 ⏱ 約4分 🔗 出典 6 件

2.1系は10月に入って権限・サンドボックス・MCP安定性まわりの小刻みパッチが続いてきた。本日2026/10/25(JST)時点の最新は v2.1.310（10/23） で、10/24・10/25付の新規版は確認できない。v2.1.310の芯はクラウド/エンタープライズ強化だ。MonitorツールとプラグインMonitorをAmazon Bedrock・Google Vertex・Microsoft Foundry、およびテレメトリ無効環境でも利用可能にし、これらの環境での長時間フォアグラウンドsleepもブロックする。クラウドセッションとリモートコントロールの可否をEnterpriseのカスタムロール権限として追加し、Ownerがロール単位で制御できる。改善6件・修正14件では、一部ゲートウェイが effort-2025-11-24 ベータ値や会話途中のsystemメッセージを拒否してリクエストが失敗する問題（外して再試行）、cleanupPeriodDaysを極端に大きくすると貼付画像など最近のファイルが消える問題、「Prompt is too long」後の圧縮がbase64/SVGを残しすぎて再失敗する問題を解消した。

この日の技術面の本命は、Anthropic公式ブログによる指示手段の使い分けだ。各手段を「いつ読み込まれるか／圧縮に耐えるか／文脈をどれだけ食うか」で整理する。毎回必ず実行したい処理（編集後のlint、特定コマンドのブロック）はCLAUDE.mdではなくフックへ——CLAUDE.mdは多くの場合従われるがフックは決定論的で、PreToolUseが終了コード2を返せばツール呼び出しを拒否できる。CLAUDE.mdは常時保持すべき事実（ビルド/構成/規約）に絞り200行以内でコードのようにレビューする。手順書やレビュー観点はスキル（呼び出し時のみ読込）、ファイル限定の制約はpaths:付きルール（例 src/api/**）、中間出力が大きい調査はサブエージェント（最終要約だけ戻す）に委譲する。PubNubの実践記事も、サブエージェントは単一責務・ツール権限最小化（tools省略時はMCP含む全継承に注意）・SubagentStopフックでの連鎖・フックのプロダクションコード化を説く。

市場データも大きく動いた。Ramp指標（2026年5月）でAnthropic 34.4% > OpenAI 32.3% と法人採用率が初逆転し、eWeekは主因をClaude Codeと分析。JetBrains 2026開発者調査ではClaude Codeの職場採用39%がCopilot 21%を上回った（米国47%、週次利用は約90%）。Tygart Mediaの合成事例では、30人のエンジニア組織が90日で内部監査スコア19→41、生産性35%向上を報告し、CLAUDE.mdを各リポジトリ400行以内に保ったチームほどスキル呼び出し率が高かった（800行超は約40%低下）。

自分が試すなら：まずCLAUDE.mdを棚卸しして200〜400行に圧縮し、「lint実行」「危険コマンド拒否」はフックへ移す。繰り返す手順はスキル化し、重いログ解析はサブエージェントに投げて本流の文脈を汚さない——この配分が採用事例の生産性差を生んでいる。

ひとこと：リリースは落ち着きフェーズだが、エコシステムの主役交代と「運用の作法」が固まりつつある転換点。
