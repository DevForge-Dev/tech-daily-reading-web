Claude Code

v2.1.234〜238は「地盤固め」— /designプレビューと4プリミティブの使い分け

この時期のリリースは派手な新機能より完成度重視。新スキル /design のプレビュー投入と、Hooks/Skills/Subagents/MCP の役割分担が今日の勘所。

📅 2026年8月22日 ⏱ 約3分 🔗 出典 5 件

今週のClaude Codeは、機能を足すより足元を固める方向のリリースが続いた。8/17の v2.1.234 は51件の変更を含む大型版で、直後の v2.1.238 は39件の修正中心。派手さはないが、日々のエージェント運用で取りこぼしていた不具合と、チーム導入で効いてくる細かな配慮がまとめて入ったのがポイントだ。

何が新しいか

v2.1.234 では、セッションごとに設定ディレクトリを割り当てるホスト向けに、トランスクリプト保存名を短く指定できる環境変数 CLAUDE_CODE_PROJECT_DIR_NAME が追加された。GitLabリモート＋glab認証があるとフッター/ステータスラインに MR番号バッジ（draft/pending/greenの状態色付き）が出るようになり、加えて利用上限に達したセッションがリセット後に自動継続する挙動が入った。v2.1.238 は安定性・セキュリティ寄りで、MCP v2接続と通知フックの不具合、LinuxのアイドルセッションでCPUが100%張り付く問題、Windowsのパス検証の脆弱性などを潰している。

もう一つの目玉が新スキル /design のリサーチプレビュー。Claude Designのアートボードワークフローをコーディング画面に取り込み、複数のUI案を生成→選択→そのままコード化まで一気通貫でできる。claude.ai/design に切り替えて貼り戻す往復が不要になる。

仕組み・考え方

複数の解説記事（AIXplore、Totalum、Firecrawl）が口を揃えるのは、これらは競合ではなく補完だということ。SkillはSKILL.mdを核にしたフォルダ単位の指示パックで、Claudeに能力を足す「Capability Uplift」型と、自社の手順を守らせる「Encoded Preference」型の2種類がある。決定的に縛りたいならHooks、隔離したいならSubagents、外部接続ならMCP——と、目的ごとにプリミティブを選ぶ意思決定フレームで考えると迷わない。

実務での使いどころ

自分が試すなら、まず /design でUI叩き台を数案出してから実装に入る流れを一度試したい。加えて、Linux上で常駐させているセッションがあるなら v2.1.238 以降へ上げてCPU張り付きを回避しておく。チーム導入の数字も出ていて、Microsoftの研究ではClaude Code採用者はマージ済みPRが約24%増え、その効果は4か月持続した一方、数百万ドル規模のトークン支出も観測された。生産性は伸びるがコストは効くので、トークン予算のガバナンス設計はセットで考えたい。

注意点

/design はリサーチプレビューで仕様変更・実コードベースへの見直しが前提。バッジやMR連携はGitLab＋glab認証が要る。自動継続やセキュリティ修正は嬉しいが、過信せず認証情報の扱いは引き続き慎重に。

ひとこと

「機能を増やす」フェーズから「取りこぼしを潰し、使い分けを整える」フェーズへ。派手さはないが、日常運用がいちばん軽くなる回だった。
