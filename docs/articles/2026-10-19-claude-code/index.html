fork既定ON×テレメトリ強化 — 「分岐を増やし、増えた分を測る」v2.1.302/300を腰を据えて読む

週末を挟み新リリースはなし（最新 v2.1.302）。直近2本のchangelogを通読すると、forkの既定ON（増やす）とOpenTelemetry/キャッシュTTL内訳（測る）が一本の線でつながる。

📅 2026年10月19日 ⏱ 約3分 🔗 出典 3 件

週末を挟んで新しいバージョンのリリースはなく（最新は10/16の v2.1.302）、今日は直近2本のchangelogを腰を据えて読む回。テーマは一本に貫かれている——「生成はもう速い。詰まっているのは分岐・観測・運用コストのほう」だ。v2.1.302でfork型サブエージェントが既定ONになり、v2.1.300でOpenTelemetryのGenAI属性とキャッシュ書込TTL内訳が入った。片やエージェントを"増やす"機能、片や増えたエージェントの挙動とコストを"測る"機能で、きれいに両輪になっている。

何が変わったか（v2.1.302）

fork型サブエージェント（subagent_type:"fork"）が既定で有効に。forkは親セッションの文脈をそのまま引き継いで作業を分岐させる仕組みで、ゼロから文脈を積み直す通常のサブエージェントと違い、"今の会話の続き"を別働隊に任せられる。claude -p・Agent SDK・デスクトップ・VS Codeの全面で既定ONになり、切りたい時は CLAUDE_CODE_FORK_SUBAGENT=0。あわせて CLAUDE_AUTO_MODE_MODEL でAuto mode分類器のモデルを指定できるようになった。10/15のチートシートが整理するとおり、対話セッションの既定権限モードはAuto（旧既定はManualに改称）、既定モデルはOpus 5.5（medium）だ。

観測性の底上げ（v2.1.300）

トレースに gen_ai.provider.name / gen_ai.conversation.id / gen_ai.tool.name / error.type などOpenTelemetry GenAIセマンティック規約の属性が付き、api_request イベントにはキャッシュ書込を cache_creation_5m_tokens と cache_creation_1h_tokens のTTL別に分けた内訳が入った。forkで並列作業が増えるほど「どのサブエージェントがどれだけキャッシュを焼いたか」が効いてくるので、この2つは同じ問題の表裏だ。トレースはベータで CLAUDE_CODE_ENABLE_TELEMETRY=1 + CLAUDE_CODE_ENHANCED_TELEMETRY_BETA=1 が必要。Claude Platform on AWSでは別モデルに相談する /advisor も使えるようになった（Bedrockは非対応、CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1で無効）。

実務での使いどころ・自分が試すなら

まず CLAUDE_CODE_ENABLE_TELEMETRY=1 + 拡張ベータを入れ、普段のタスクで cache_creation_1h_tokens がどれだけ出るか地の値を取る。次にforkを意識的に使って長い調査タスクを分岐させ、同じダッシュボードでトークン挙動を観察する。効くのは「分岐の前後でキャッシュ書込がどう動くか」を数字で握ること。落とし穴は既定ONを知らずにfork乱立 → TTL別キャッシュ書込がかさむパターンで、コストが跳ねたら CLAUDE_CODE_FORK_SUBAGENT=0 で一旦戻して比較するのが安全だ。

ひとこと

エコシステム側も『Claude for Startups』拡充やFDE1万人育成の『Frontier Academy』始動と外堀が埋まりつつあるが、日々の開発で効くのは「分岐を増やし、増えた分を測る」この地味な2本。forkを使うなら同時にテレメトリも入れる——セットで扱うのが今日の学びだ。
