animation-composition で複数アニメを「重ねて」合成する — transformの上書き合戦を1要素で解決（add／accumulate／replace）

1要素に複数の@keyframesを当て両方がtransformを触ると、素直に書けば後勝ちで前が丸ごと消える。animation-compositionは合成の「仕方」をreplace/add/accumulateで宣言するプロパティ。Baseline Widely available、App RouterではServer ComponentのままJSバンドル増ゼロで使える。

📅 2026年11月16日 ⏱ 約5分 🔗 出典 3 件

「常時ゆっくり上下するfloatループ」に「ホバーで少し持ち上げる」を足そうとすると、ホバー側のtransform: translateY(-8px)がfloat側のtransformを上書きし、浮遊が止まってカクッと跳ねる。1要素に複数のアニメを当て、両方がtransformを触ると後勝ちで前が丸ごと消える——CSSアニメの古典的な罠だ。従来はラッパーdivの二重ネストやJS合成、Motion/GSAPで逃げていた。

何が解決されるのか：合成の「仕方」を宣言する

animation-compositionは、キーフレームの効果値を下敷きの値（CSSルールの静的値や他アニメの寄与）とどう混ぜるかを切り替えるプロパティ。replace（既定・上書き＝従来の後勝ち）／add（下敷き値の後ろに積む＝リストへの連結）／accumulate（同種コンポーネントを1つに畳んで加算）の3値を取る。効くのはキーフレームが動かしているプロパティだけで、静的指定のプロパティは「混ざる側（underlying value）」になる。注目の理由は2つ——Baseline Widely available（2023-07〜）で実験的の但し書きが要らない成熟フェーズに入ったこと、そしてscroll-drivenやView Transitionsで「同じ要素のtransformを複数の駆動源で同時に動かしたい」需要が増えたことだ。

add と accumulate の覚え方

filter（blur）で見ると一貫する。下敷きblur(5px)＋キーフレームblur(10px)のとき、addはblur(5px) blur(10px)と関数を2つ連ねる（実質15px相当）、accumulateはblur(15px)と同じ関数を数値加算して1つに畳む。つまりaddは「リストに項目を増やす」、accumulateは「同種を1つに合算する」と覚えると全プロパティで通る。box-shadowのようなリスト値はaddで既存の影にレイヤーを重ねられる。animation-composition: replace, addのようにカンマ区切りでanimation-nameの並び順に位置対応し、数が合わなければ先頭からループして割り当てられる。

App Routerでの実装

純CSSで完結するので'use client'不要・Server Componentのまま置け、hydration mismatchゼロ、JSバンドル増ゼロ、INP/CLSに無害、PPR/ISR/SSGとも無干渉。ラッパーdivの二重ネストを1要素に畳めるので、RSCツリーに余計なclient境界やDOM階層を増やさずに済むのがApp Router的な利点だ。

.card {
  animation: float 3s ease-in-out infinite;
  animation-composition: add;   /* 上書きでなく積む */
}
@keyframes float { 50% { transform: translateY(-10px); } }
.card:hover {
  animation: float 3s ease-in-out infinite, lift .25s ease-out forwards;
  animation-composition: add, add;   /* animation-nameの順に対応 */
}
@keyframes lift { to { transform: translateY(-16px) scale(1.03); } }

落とし穴

addは「前キーフレーム」でなく「underlying」基準——キーフレーム間で累積移動したいならaccumulateかMotionの方が素直だ。rotate/scaleのadd vs accumulateの厳密な畳み方は公式ドキュメントに明記がなく、実機検証が必須。animationショートハンドはanimation-compositionを含まない（別に宣言する）。単なる:hover { transform: ... }には効かず、ホバー側も@keyframes＋animation（forwards）にして初めて合成が効く。浮遊ループは@media (prefers-reduced-motion: no-preference)の中だけで付与し、縮退時は中立状態に固定する（WCAG 2.3.3）。

ひとこと

「transformを複数の駆動源で同時に動かす」場面——scrollでparallaxしつつhoverでtilt、など——が増える中で、ラッパー二重化やJS合成を本当に捨てられる段階に来た。対応はChrome/Edge 112+・Firefox 115+・Safari 16+。まずはfloat×hoverの1要素化から試すのが入り口として手頃だ。
