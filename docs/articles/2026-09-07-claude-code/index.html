Claude Code

Claude Code が GitLab を一級市民に — glab MR認識と /code-review --comment 直接投稿

v2.1.263 で glab の MR 操作を認識し、/code-review --comment が GitLab マージリクエストにレビュー所見を直接投稿できるようになった。GitHub 偏重からの脱却。

📅 2026年9月7日 ⏱ 約2分 🔗 出典 3 件

これまで Claude Code のエージェント運用は GitHub（gh CLI）を軸に組まれてきたが、直近の連続リリースで GitLab 環境が一級市民に格上げされた。GitHub 以外でエージェント型開発を回したい層にとって、地味だが効く更新だ。

何が新しいか

v2.1.263（9/6）が本命。glab mr create/merge/close/reopen/note/update といったコマンドを認識し、折りたたみのツール概要に 「MR !N」と表示、フッターの MR バッジも更新する。さらに /code-review --comment が、これまで「対象がサポート外」と報告していたケースでも glab mr note 経由で GitLab の MR に直接レビュー所見を投稿できるようになった。土台は v2.1.259（9/2）の managedMcpServers（組織が HTTP/SSE 型 MCP を全ユーザーへ一括配布）と --permission-prompts none（無人ホスト向けに権限プロンプトを無効化）、v2.1.261（9/4）の --append-subagent-system-prompt-file（共通指示を外部ファイル化して Subagent 構成で再利用）だ。

実務での使いどころ

GitLab 運用なら CI から claude -p "/code-review --comment" を回して MR に自動所見を残せる。社内標準の MCP は managedMcpServers で一括配布し、バッチ実行のホストは --permission-prompts none で無人化。自分なら GitLab 側の 1 プロジェクトでまず /code-review --comment をパイプラインに差してみる。

注意点

managedMcpServers は command を実行する型の MCP はスキップし HTTP/SSE 型のみ配布する。--permission-prompts none は権限プロンプトを消すので、書き込み系を無防備に走らせない前提設計が必須。並行セッションが互いの設定を無言で巻き戻す不具合は v2.1.259 で修正済み。

ひとこと：「GitHub じゃないから」でエージェント運用を諦めていた現場に、そのまま刺さる更新。
