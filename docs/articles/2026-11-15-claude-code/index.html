Claude Code

Claude Code、latestが v2.1.319→v2.1.325 へ一気に前進 — サンドボックスBashを既定で権限フローへ、実験的Code Mode、既定Fableが5.2に

11/13リリースの v2.1.325 を筆頭に、v2.1.321〜325 を棚卸し。主題は「人が見ていない自動実行の安全側への締め直し」と「ツール呼び出しをコードで書くCode Mode」。数値は英語二次まとめ（havoptic）ベースで一次CHANGELOG未照合。

📅 2026年11月15日 ⏱ 約4分 🔗 出典 3 件

本セッションで npm view を確認したところ、Claude Code の latest タグが v2.1.319（11/6）から v2.1.325（11/13）へ一気に進んでいた（stable は v2.1.311 据え置き）。前日まで本読み物が追えていた範囲から数リリース飛んでいるため、v2.1.321〜325 をまとめて棚卸しする。なお一次 CHANGELOG は本セッションの可読範囲で v2.1.312（10/27）までしか見えず、以下は集約サイト havoptic（英語二次）に基づく＝綴り・細部は要確認。

何が変わったか：自動実行の「黙ったフォールバック」をやめる方向

最新 v2.1.325（約200項目）の軸はセキュリティと取り違え修正。zstd 圧縮応答のデコード処理のセキュリティ修正、opusplan/haiku 設定時にサブエージェントが plan 用モデルへ移されてしまう不具合、別モデルのサブエージェントがファイル読取/MCP 結果のサイズ見積りにメインセッションのモデルを誤用する不具合、そして多くのサードパーティゲートウェイ／Foundry で毎ターン context length エラーになりcompaction（圧縮）が走らない不具合の修正が目立つ。挙動変更として、サンドボックス内 Bash が既定で通常の権限フローを通るようになった（従来どおり無確認で走らせたいなら sandbox.autoAllowBashIfSandboxed: true）。

仕組み：Code Mode ＝「ツールを直接呼ぶ」から「JSを書いて呼ぶ」へ

v2.1.323 の目玉が実験的 Code Mode。従来は Claude が個々のツールを1つずつ呼ぶが、Code Mode では Claude が JavaScript を書き、その中から自前のツール群を呼び出す（code.claude.com/docs/en/code-mode でオプトイン、組織単位で無効化可）。多数のツール呼び出しをループや分岐でまとめられるのが利点で、権限ダイアログの「Yes」系の語が届かない不具合や、スクリプト実行中に終了したセッションの再開が勝手に走らない修正も同梱。あわせて未知モデルIDの想定コンテキストを200K→1Mへ変更（200K維持は /autocompact か CLAUDE_CODE_DISABLE_1M_CONTEXT=1）。プラグインには engines["claude-code"] の版レンジが入り、範囲外は導入/更新/ロードしない。

自分が試すなら

無人運用（scheduled/headless）を回している身としては、v2.1.325 のsandbox Bash 権限フロー化と compaction 不発修正が効く。前者はセキュリティ的に正しい締め直しだが、スケジュールタスクが Bash を自動実行する構成だと確認待ちで止まりかねないので、無人側は sandbox.autoAllowBashIfSandboxed: true か permissions.allow の整備が要る。既定 Fable が 5.2（1Mコンテキスト）に替わった点も、長文の digest を一気に食わせる用途では追い風。

注意点

これらは英語の第三者集約（havoptic）由来で一次 CHANGELOG 未照合。env 変数名はページ側でアンダースコアが欠落表示される既知のクセがあり、綴りは実機で要確認。Code Mode は experimental で破壊的変更があり得るため、無人パイプラインへの即投入は避け、別ブランチで検証してから。

ひとこと：このサイクルは「速く自動で動かす」より「人が見ていない実行を安全側に倒す」方向が通底している。sandbox Bash の権限フロー化はその象徴で、自動運用勢は権限設定の棚卸しを一度やっておくと安心。
