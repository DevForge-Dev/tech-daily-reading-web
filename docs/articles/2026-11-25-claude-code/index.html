Claude Ship ベータ公開 — PR の「レビュー・修正・承認」をAIに回す3本柱と /ship

コードレビューの“両側”にAIを。Code Review(GA)＋PR Steward(beta)＋Claude Approvals(beta)、そして Claude Code の /ship コマンド。

📅 2026年11月25日 ⏱ 約4分 🔗 出典 3 件

2026-11-24、Anthropic が PR のレビュー・修正・ポリシー承認を自動化するエージェント群「Claude Ship」をベータ公開した。狙いは一言でいえば「コードレビューの両側にAIを置く」こと——指摘をする側だけでなく、指摘に対応する側、そして定型変更を承認する側までを回す。あわせて Claude Code とデスクトップ版に /ship コマンドのロールアウトが始まった。1人で複数リポジトリを回す開発スタイルでは、PR の往復こそが地味に時間を食う工程なので、そこを自動化する動きは素直に効く。

何が新しいか — 3本柱

構成は3つ。(1) すでに一般提供(GA)の Code Review：PR をコードベースに照らして複数観点で検査→検証→分類し PR にコメントする。深さは Quick / Standard / Deep をリポジトリ単位で選べる。(2) 新規ベータの PR Steward：失敗した CI・マージ競合・レビュー指摘に対応し、push ごとに「何を変えたか／取り消す方法」をコメントする。操作は @claude ／ @claude stop。ただし承認・マージはしない。(3) 同じくベータの Claude Approvals：リポジトリ内のポリシーファイルに基づいて定型変更を承認し、特定条件は人手承認を要求する。まずは observe-only（観察のみ）運用が推奨されている。

仕組み — /ship の一気通貫

変更が整った状態で /ship を実行すると、Claude がコードを push し、PR を作成し、そのレビューを行い、レビュー指摘や失敗 CI への対応まで進める。マージ可否は開発者の権限＋リポジトリのブランチ保護ルールに従う（AIが勝手にマージするわけではない）。/ship の実行は通常の Claude Code 利用として課金される。管理者は /ship を使わせずとも、Code Review と PR Steward をリポジトリ単位で有効化し、PR 上でエージェントを自動稼働させる運用も選べる。

実務での使いどころ・自分が試すなら

提供は GitHub ホスト＋Team/Enterprise 限定で、課金はトークン量ベース。ZDR（ゼロデータ保持）／HIPAA 構成／顧客管理鍵(CMK)の組織は対象外なので、まず自分の組織区分を確認するのが先。自分で試すなら、いきなり承認まで任せず Claude Approvals は observe-only から、PR Steward は小さな CI 失敗の自動修正から入れて、コメントの質と誤爆率を数日眺めるのが安全。Anthropic 社内では Claude Code チームのマージ済み PR が6→9月で2倍超、revert 率が40%超低下したと主張しているが、これは広いレビュー工程の一部という但し書き付き。

注意点・落とし穴

今日の情報源は二次情報（Help Net Security, 2026-11-24）で、Anthropic 公式原典は未照合。数値や挙動は確定として扱わない方がよい。もう一点、npm 側の動き：本日 JST 07:06 頃に v2.1.332 が next タグで公開されたが、latest は依然 v2.1.331、stable は v2.1.325 のままで、公式 CHANGELOG に v2.1.332 の変更ノートはまだ載っていない。つまり「新版が npm に出た」事実だけで、中身は未掲載。実務の既定導入先は据え置きと見てよい。

ひとことまとめ

Claude Ship は「レビューする／直す／承認する」を分離した3エージェント構成。/ship はその入口で、最終的なマージ権は人間とブランチ保護ルールに残る。試すなら observe-only から、対象外組織(ZDR/HIPAA/CMK)かどうかの確認を最初に。
