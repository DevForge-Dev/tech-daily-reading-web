v2.1.325を一次で裏取り——自動実行を安全側へ締め直す

昨日まで本読み物は英語の二次まとめ（havoptic）ベースでv2.1.325を扱っていたが、公式リポジトリ anthropics/claude-code のCHANGELOG.md先頭もv2.1.325で、より新しい版（2.1.33x以降）は存在しないことを確認できた。主要点は、(1)zstd圧縮応答のデコード処理のセキュリティ修正、(2)サンドボックス内Bashを既定で通常の権限フローに通す（従来の無確認継続はsandbox.autoAllowBashIfSandboxed: trueで明示）、(3)非信頼リポジトリの読み取り専用gitコマンドも確認を要求（許可は--add-dir）、(4)スケジュールタスクや/loopがhooks/allowed-toolsを宣言するSkillの実行前に確認（無人実行はpermissions.allowにSkill(name)を追加）、(5)opusplan/haiku設定時に独自モデル指定のサブエージェントがplan用モデルへ取り違えられる不具合の修正。人が見ていない自動実行まわりを安全側に締め直す色が濃い。

技術記事3本の核：拡張手段の使い分け

今日の技術記事は、Claude Codeを「操る」手段の整理で揃った。Anthropic公式『Steering Claude Code』は、CLAUDE.md／rules／skills／subagents／hooks／output styles／システムプロンプト追記の7手段を「文脈コスト×強制力×いつ読み込まれるか」で使い分ける。dev.toの『Skills vs Hooks vs Subagents』はこれを一言に凝縮——「Skillsは教える／Subagentsは隔離する／Hooksは強制する／Pluginsは配布する」、判断軸は決定性→文脈隔離→起動モデル→配布の順。公式サポートの『power user tips』は最重要の実践として「検証ループを与える」（テスト・Chrome拡張・/simplifyでClaudeに自己確認の経路を用意）を挙げ、git worktreeでの並列、Planモード＋/effort、リポ直下の共有CLAUDE.mdに誤りの度に追記、を推す。

自分が試すなら

「絶対にやるな」系のルールはCLAUDE.mdの指示ではなくhooksかpermissionsに置く——PreToolUseフックが終了コード2で呼び出しをブロックできる、という公式の明言が実務の勘所だ。まずは共有CLAUDE.mdを200行以内に保ちつつ、整形・lint・危険コマンドのブロックをhooksへ移すところから。版の追跡はnpm view ... dist-tagsをメモに貼っておく。
