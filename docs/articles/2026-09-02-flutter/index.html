AIネイティブ開発がframeworkの中核へ（Agentic Hot Reload・GenUI・Genkit）——3.47.1時代の状態管理・Hero・パフォーマンスを一望

現行安定版はFlutter 3.47.1 / Dart 3.13.1、次の機能リリースは2026年11月。今日の主役はAIネイティブ開発のframework統合（Agentic Hot Reload／GenUI／Genkit for Dart）と、2026ロードマップ「Finishing the Job」（Impeller一本化・WasmGC既定化）。状態管理は50画面未満Riverpod 3.0／監査・大規模Bloc 9.0、HeroはflightShuttleBuilder、パフォーマンスはPerformanceOverlayの赤バー＝rendering complexity。

📅 2026年9月2日 ⏱ 約4分 🔗 出典 5 件

今日のFlutterはAIネイティブ開発がframeworkの中核へ据えられた点が大きい。Agentic Hot Reload（AIのコード変更をhot reloadで即検証）、GenUI（生成UI）とA2UI protocol、Genkit for Dart——AIは“コード上のレイヤー”ではなく開発ループそのものの中核に位置づけられた。現行安定版はFlutter 3.47.1 / Dart 3.13.1（3.47系）で、stableは年4回（2/5/8/11月）、次の機能リリースは2026年11月。確認はflutter --version、更新はflutter upgrade。2026ロードマップ「Finishing the Job」では、Android 10（API 29）以上でlegacy Skiaを撤去しImpeller(Vulkan)へ一本化、WebはWasmGCを既定コンパイルターゲットへ（flutter build web --wasm）。Material/Cupertinoのコア分離（material_ui/cupertino_uiのstandalone化）も継続で、M3更新が四半期SDKを待たず届き、app sizeも削減される（移行はdart fix）。

状態管理：2026の選定図

選定の基本線は50画面未満はRiverpod 3.0、複雑エンタープライズ＋監査要件はBloc 9.0。Riverpod 3.0はcompile-time safety・built-in offline persistence・最小boilerplateで多くの新規に最適（現行3.3.x＋codegen、unified Ref・automatic retry）。規制業界（fintech/healthcare）で完全なevent traceabilityや複雑並行が要るならBloc 9.0——flutter_bloc 9.xはmapEventToStateを廃しon<Event>に統一、blocTestで検証する。設計指針はderived/computed provider（Riverpod）やderived getters/selectors（Bloc）で冗長な再計算を避け、ref.watch(provider.select(...))で最小スライスを購読すること。

アニメーション：Heroの実践

今日の主役はHero。同一tagをsource/destinationに付与すると画面遷移で共有要素を滑らかに補間する。飛行中の歪みを防ぐコツは両画面でaspect ratioとcontent alignmentを一致させること。flightShuttleBuilderで飛行中の見た目をカスタム、HeroModeでグループの有効/無効、HeroControllerでtiming/durationを微調整できる（Hero/ページ振付は300–600ms）。時間帯別の使い分けは、micro（50–200ms）はimplicit（AnimatedOpacity等・controller不要）、component（200–400ms）はexplicit（AnimationController＋AnimatedBuilder・dispose必須）、複雑シーケンスはRive/Lottieへオフロード。

パフォーマンス：赤バーの読み方

PerformanceOverlayは16.7ms（60fps）予算を超えたフレームを可視化し、下段グラフの赤バーはrendering complexity（GPU/raster）を示す。典型原因はsaveLayerをトリガするnested Opacity・複雑なclipping path・重なる複数shadow・offscreenバッファへの反復描画。特定はDevToolsのtimelineで予算超過フレームを展開しbuild passを確認、計測は必ずprofileモードで行う（debug VMは遅い）。フラッグシップは90/120Hzで1フレーム8–11ms。最も多い問題は不要なwidget rebuildで、constで完全スキップ・大きなbuild()を分割・Selector/selectで局所再描画が効く。

ひとこと

AIが開発ループの中核に入り、描画はImpeller一本化・WebはWasmGCへ。土台が更新される時期こそ、状態管理は選定図どおり素直に、パフォーマンスは予算とrebuild削減という原則で足場を固めたい。
