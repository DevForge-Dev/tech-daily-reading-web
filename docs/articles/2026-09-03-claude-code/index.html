Fable 5.1が既定に（1Mコンテキスト）＋自動モードにContainment Escape、旧macOS起動不能も修正（v2.1.257/258）

派手な新機能よりも「賢さ・安全・安定」を一段ずつ底上げした数日。Fable 5.1が既定Fableモデルになり1Mトークン文脈へ拡張、自動モードはクラウド資格情報の取得やテナント越境を既定で自動承認しなくなった。macOS 12の起動不能リグレッションとスケジュール実行の権限再送エラーも解消。折しもMicrosoft Researchの査読論文はClaude Code採用でマージPRが約24%増と報告している。

📅 2026年9月3日 ⏱ 約2分 🔗 出典 4 件

この数日のClaude Codeは、モデルの賢さ・エージェント運用の安全境界・地味だが効く安定化が同時に進んだ。単発の目玉ではなく、日々の運用が静かに軽く・堅くなるタイプの更新だ。

何が新しいか

v2.1.257で Claude Fable 5.1（claude-fable-5-1）が既定のFableモデルに昇格した。1Mトークンの文脈に対応し、価格は入出力$10/$50 per Mtok、キャッシュ読み出しは$0.25/Mtokと安い。大きなリポジトリを丸ごと文脈に載せる運用でも、キャッシュを効かせればコストを抑えやすい。あわせて timeFormat/timeZone 設定が追加され、ターン終了時の時計やトランスクリプトのタイムスタンプを12/24時間制・UTC・任意のstrftimeパターンで表示できる。

安全境界が既定で厳しくなった

自動モードに Containment Escape（封じ込め回避）ルールが新設された。クラウドのメタデータ資格情報の取得、egress回避、クロステナントへの到達といった操作は、環境側が『想定内』と明示しない限り自動承認されない。CI/クラウド上でエージェントを回すときの事故を構造的に防ぐ変更だ。加えて CLAUDE_CODE_SUBAGENT_MODEL_FORCE で、全サブエージェントに主モデル（または指定モデル）を強制適用できるようになり、コスト・挙動のばらつきを抑えられる。

実務での使いどころ・注意点

自動化パイプラインを組んでいるなら、まず v2.1.258 まで上げて権限再送のスケジュール実行バグを回避したい。クラウド実行では『想定内』の明示（許可すべき操作の宣言）を先に設計しておかないと、Containment Escapeで意図した処理まで止まる可能性がある。Microsoft Researchの査読論文（4か月観測でマージPR約24%増）や『最も愛される46%』調査は導入の後押しになるが、記事群が口を揃えて指摘するのはトークン支出の予算ガバナンスだ。1M文脈は強力な反面、キャッシュ設計を怠るとコストが膨らむ。

まとめ：賢さ（Fable 5.1・1M文脈）と堅さ（安全境界・安定化）が同時に前進。上げるなら258まで、回すなら予算とキャッシュ設計をセットで。
