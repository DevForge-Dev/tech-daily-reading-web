Claude Code

Opus 5がClaude Codeの既定Opusに — 1Mコンテキストで価格据え置き、スキャンと自動継続で運用も堅牢化

既定モデルが黙って切り替わる日。Opus 5が1Mコンテキストを携えてClaude Codeの既定Opusになり、料金はOpus 4.8と同一。スキル/プラグインのマルウェアスキャンや上限リセット後の自動継続も揃い、運用の地盤が固まってきた。

📅 2026年8月24日 ⏱ 約2分 🔗 出典 4 件

今日のClaude Codeは「最上位モデルの世代交代」と「運用の安全網」がテーマだった。7/24に登場した Claude Opus 5 が既定のOpusモデルとして据えられ、あわせてスキル/プラグインのマルウェアスキャンや、利用上限リセット後の自動継続といった、派手さより実運用に効く更新が並んだ。

何が新しいか

Opus 5は 1Mトークンのコンテキストウィンドウ を備え、Frontier-BenchやGDPval-AAといったコーディング/知識労働のベンチで最高水準を更新しつつ、料金は Opus 4.8と同一の $5 / $25 per MTok に据え置かれた。設定を変えていなくても既定Opusが切り替わるのがポイントで、Maxプランでは既に既定選択、Proでは到達できる最強モデルという位置づけ。一方 Pro / Team Standard の全体既定は引き続き Sonnet 5 のままなので、用途とコストで Opus 5 / Sonnet 5 を意識的に使い分けたい。

運用の安全網

サプライチェーン対策として、サードパーティ製スキル/プラグインをマーケットプレイスへアップロード・編集した時点で自動スキャンが走り、結果を pass / warn / fail の3段階で返すセキュリティ機能がベータ提供された（まずEnterprise、Cowork等にも展開）。プラグイン共有が一般化するなかの最低限のガードレールだ。さらに v2.1.234 では利用上限（レート制限）リセット後にセッションを自動継続し、長時間作業を止めずに再開できる。資格情報の漏えい対策強化、GitLab MRのworktree/agentsビュー対応、暴走ビルドを抑えるメモリ上限、@メンションのセッション間コラボ改善も同週に入った。

実務での使いどころ・注意点

自分が試すなら、まず重いリファクタや大規模設計レビューだけ Opus 5 を指名し、日常は Sonnet 5 に寄せてコストを最適化する。プラグインは導入前にスキャン結果を確認する癖をつけたい。注意点として、既定が黙って変わるぶん /cost で実額を測り直すこと、スキャンは現状Enterprise中心のベータで万能ではないこと。市場面では Anthropic の年換算売上が7月末に約 650億ドル（1年で約7倍）、Claude Code単体でも約 150億ドル に迫り、収益の過半がエンタープライズ利用という追い風もある。

ひとこと

「最強を既定に、安全に、安く回す」——モデル世代交代とガードレール整備が同じ日に来たのは象徴的だ。
