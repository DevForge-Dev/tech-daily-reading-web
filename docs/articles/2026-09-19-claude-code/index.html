v2.1.276 緊急ホットフィックスとProjectsベータ刷新 — 回帰を即塞ぎ、並列エージェントを統括する

v2.1.275でプロキシ/ゲートウェイ経由が全て400になる回帰をv2.1.276が緊急修正。claude.aiのスキル/プラグインは端末へ自動同期。9/17にはProjectsをベータ刷新し、コーディネーターが並列スレッドを分解・委譲・統合。ただし既定Opus・並列で上限に早く到達する点に注意。

📅 2026年9月19日 ⏱ 約2分 🔗 出典 4 件

Claude Code の直近は「壊れた回帰を即座に塞ぐ」運用フェーズに入っている。9/18 の v2.1.276 は緊急ホットフィックスで、直前の v2.1.275 が抱えた回帰——ANTHROPIC_BASE_URL がプロキシや LLM ゲートウェイを指す構成で全リクエストが 400 エラーになる——を修正した。プロキシ/ゲートウェイ運用のチームは即アップデートが必須だ。あわせて v2.1.275 では、claude.ai で有効化したスキル/プラグインを同じアカウントの端末セッションへ自動同期する挙動が入った。ローカルで独自管理しているなら競合確認とオプトアウトを検討したい。

Projects ベータ刷新——並列エージェントの統括

9/17 には Claude Code Projects がベータで刷新された。コーディネーターがリクエストを分解して作業を委譲し、複数の並列エージェントスレッドを走らせて結果をレビュー・統合する。各スレッドは別ブランチ/リポジトリコピー上の独立したクラウドセッションで動き、プロジェクトメモリとアップロード済みファイル・生成成果物のライブラリを共有する。コーディネーターとワーカーでモデルと思考努力レベルを個別指定でき、まず一部の Pro/Max から提供が始まった。

強力さと消費のトレードオフ

実務の注意点は消費だ。並列フルセッションのため既定で Opus・高努力度が割り当てられ、同時に多数を回すと利用上限に早く到達する。対策は役割別の配分——コーディネーターには上位モデルと高努力度、テスト実行など定型ワーカーには標準モデルと低努力度、というように割り当てる。拡張の3手法（Hooks は決定論的だが仕込みすぎると DX を損なう／Skills はオンデマンド読み込みで粒度設計が肝／Subagents は文脈汚染を防ぐが乱用で調整コスト増）を目的で選び分ける判断軸も、この並列運用と地続きだ。

自分が試すなら・まとめ

試すなら、まず調査系タスクを1本 Projects のワーカーに委譲し、コーディネーターだけ Opus・ワーカーは標準モデルに落として上限消費を観察するとよい。導入は国内でも加速しており、NEC が日本初のグローバルパートナーとして約3万人へ展開＋CoE 設置、日立は約29万人規模で計画、GMO インターネットが戦略的提携、海外 Ramp はインシデント調査を80%短縮したと公式ベースで報じられている。ひとことで言えば、回帰を即塞ぎつつ「並列を統括する基盤」へ——今日の軸はこの二つだ。
