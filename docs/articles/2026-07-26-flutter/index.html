Flutter 3.44 で Native Asset Bundling が stable — C/C++/Rust を同梱、SwiftPMがCocoaPodsを置換

今日の主役は Native Asset Bundling の stable 昇格（安定版 Flutter 3.44 / Dart 3.12）。脆いプラットフォームチャネル回避策なしで、C/C++ や Rust ライブラリをアプリに直接同梱できる。Apple は依存管理を CocoaPods → Swift Package Manager へ移行、Android は Hybrid Composition++ で埋め込み描画を刷新。描画は Impeller 既定。

📅 2026年7月26日 ⏱ 約3分 🔗 出典 3 件

背景から。Flutter からネイティブライブラリ(C/C++/Rust)を使うのは長らく面倒で、プラットフォームチャネル越しの脆い回避策や手作業ビルドが要った。Flutter 3.44 / Dart 3.12 はここに正面から手を入れ、Native Asset Bundling を stable に昇格させた回だ。

何が新しいか

native asset bundling が安定化し、回避策なしで C/C++ や Rust ライブラリを Flutter アプリに直接同梱できる。Apple 側は依存管理を CocoaPods → Swift Package Manager(SwiftPM) へ移行して iOS/macOS を近代化。Android 側は Hybrid Composition++(HCPP) でネイティブビュー埋め込みの新しい描画パスを追加した。Web は stateful hot reload が既定になり、リロードでナビゲーションスタック・フォーム入力・スクロール位置を失わない（ロードマップは WebAssembly を Web の既定にコミット）。描画は Impeller が iOS/Android 既定で、Material/Cupertino はコアから独立バージョニングのパッケージへ移行を開始。Dart 3.12 は private named parameters・primary constructors(experimental)・dot shorthands。次の機能リリースは 2026年8月（年4回 2/5/8/11月）。

状態管理の指針(2026)

本番の意思決定はシンプルに保てる。新規プロジェクトは Riverpod 3.0 を既定（compile-time safety・組込みオフライン永続化・最小ボイラープレート、現行 flutter_riverpod 3.3.x ＋ @riverpod codegen）。監査証跡が要る規制業界(fintech/healthcare)や大規模は Bloc 9.0（全状態遷移が特定イベントに対応する audit trail、現行 bloc 9.2.x / flutter_bloc 9.1.x）。鉄則は「1つ選んで一貫し、テストを書く」。上に feature 単位 Clean Architecture ＋ go_router、移行は screen-by-screen。

実務での使いどころ・注意点

自分なら FFI ＋ native asset 同梱で、Rust 製の暗号処理や画像処理をアプリに取り込む構成を試す。iOS/macOS は SwiftPM 前提になるため、既存の CocoaPods 資産の移行可否を先に確認する。パフォは Impeller 既定でシェーダーを AOT 事前コンパイルし初回ジャンクを排除、フレーム予算は 60fps=16ms / 90fps=11ms / 120fps=8.3ms。再ビルド削減は const 徹底・build 分割・最小スライス watch・RepaintBoundary 戦略配置が軸。ひとことで言えば「ネイティブ資産とビルドの近代化で、Flutter が本当に地続きになった」回だ。
