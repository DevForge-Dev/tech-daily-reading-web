8月リリース直前チェックリスト — 3.44系で足場を固める：Impeller実機検証・Hero遷移・Riverpod3/Bloc9・120fpsシェーダー

次の機能リリースは2026年8月（3.45系は未リリース）。現行安定は3.44.6/Dart 3.12.2。移行前は flutter upgrade→Impellerを実機検証→Material/Cupertino分離に備え依存整理→dart fix/analyze。共有要素はHero、状態管理は新規Riverpod 3.3.x/監査はBloc 9、120fpsはシェーダー4–5msが軸。

📅 2026年8月2日 ⏱ 約5分 🔗 出典 5 件

Flutterは年4回（2/5/8/11月）の機能リリースで、次は2026年8月が目前（3.45系はまだ未リリース）。区切り前のいまは、現行安定版Flutter 3.44.6 / Dart 3.12.2（2026-07-09）で足場を固める好機だ。3.44の3本柱はImpellerがAndroidの既定になりSkiaがコアから撤去、Material・Cupertinoがコアから独立パッケージへ分離、そしてAIツーリング（Agentic Hot Reload・Agent Skills・GenUI・A2UI・Genkit Dart）の強化。Dart 3.12はprivate named parameters・primary constructors(experimental)・dot shorthandsで定型コードを削減する。

移行前チェックリスト：8月アップデート前に、①flutter upgradeで3.44最新パッチへ追随、②Impellerを実機（特にミッドレンジAndroid）で検証し、差が出たら--no-enable-impellerで切り分け、③Material/Cupertinoのパッケージ分離に備えて依存とimportを整理、④dart fix／flutter analyzeで警告を解消。ロードマップ『Finishing the Job』はAndroidのImpeller移行完遂（Android 10+でlegacy Skia backend撤去）とWebのWebAssembly（Wasm）既定化を掲げる。

アニメーション（Hero共有要素遷移）：Heroは2画面のwidgetを同じtagで包むと、size・position・appearanceを自動補間してオーバーレイ上を飛ばす共有要素遷移になる（円→四角の形状変化も可）。肝はsource/destinationでアスペクト比・整列・視覚アイデンティティを一貫させること。飛行中の外観はflightShuttleBuilder、グループ制御はHeroMode。黄金律は「まず implicit」——UIモーションの約80%（hover・state遷移・レイアウト変化）はAnimatedOpacity/AnimatedContainer、複雑なchoreographyやphysicsだけexplicit（AnimationController＋Tween）、重い演出はRive/flutter_animate/Lottieへオフロード。時間設計はmicro 50–200ms／component 200–400ms／Hero・page 300–600ms。

状態管理とパフォーマンス：BLoCとRiverpodは同じ問題を異なるメンタルモデルで解く。API差の暗記よりBLoCのCommand→Process→Stateの理解が重要。新規はRiverpod 3.3.x＋@riverpod codegen（unified Ref・@mutation・自動リトライ／backoff・opt-in offline persistence）が2026の最良の既定、監査証跡が要る規制業界（fintech/healthcare）や複雑並行はBloc 9.2.x（on<Event>ハンドラ）。移行はscreen-by-screenで、ProviderScopeを既存のMultiBlocProviderの脇に足せば競合なく共存できる。パフォーマンスはImpellerのAOTシェーダー事前コンパイルがjankを排除し、カスタムfragment shaderは重い分岐を避けmix()/smoothstep()/clamp()へ寄せ、実行を4–5ms以内に収めて8.33ms予算を守る。計測はDevTools Performanceをprofileモードで、GPU（raster）スレッドを監視。予算は60fps=16ms / 90fps=11ms / 120fps=8.3ms（60fpsはraster<4ms）。const徹底とアニメ区間のRepaintBoundary隔離、巨大リストはListView.builder＋addRepaintBoundaries:true＋固定itemExtentが効く。

自分が試すなら：この週末にflutter --versionで3.44.6を確認し、チェックリストの4手を回す。Hero遷移を1つ実装してアスペクト比の一貫を体感し、状態管理は新規画面をRiverpod 3.3で切ってみる。注意点：Material/Cupertinoが別パッケージ化されたので移行時はimportを点検。60Hz端末で120fps狙いの過剰最適化はバッテリーの無駄。ひとことまとめ：8月の新機能は3.44の地ならしの上に来る。今のうちにImpeller検証・const/RepaintBoundary・状態管理の基本線を固めておこう。
