いいね（ハート）ボタンのマイクロインタラクション — スプリング＋パーティクル・バーストをGPUだけで

派手に見えて実装コストが低い"いいね"の演出を、transform/opacityだけ・新API不要で堅牢に作る。

📅 2026年10月12日 ⏱ 約3分 🔗 出典 4 件

「いいね／お気に入り／ブックマーク」はほぼ全アプリにあるトグル操作だ。タップした瞬間にハートがスプリングでポンと弾み（overshoot）、周囲に小さな粒子が放射状にバーストする——X（Twitter）やInstagramで知られたこの演出は、「押した」という手応え（perceived responsiveness）を一気に高める。なぜ今あらためて取り上げるかというと、派手なのに実装コストが低く、GPUだけで完結できるという設計上の気持ちよさがあるからだ。

何が新しく・効くのか。アニメーションを transform と opacity だけに閉じれば、メインスレッド／レイアウト／ペイントを汚さずコンポジタ合成で走る。実験的APIは不要で、@keyframes ＋CSS変数、または Web Animations API（WAAPI）だけで全モダンブラウザで動く。バネの質感は linear() イージング（Chrome 113+／Firefox 112+／Safari 17.2+。2026年は広くベースライン）でJSライブラリなしに出せる。

仕組み。実体は本物の <button> にして aria-pressed で状態を支援技術へ伝える（div onClick では作らない）。塗りハートを scale(0)→(1) で出すと、色のクロスフェードより弾んで見える。粒子は固定数をあらかじめDOMに置き、各粒子に角度 --angle を持たせて translate で外へ飛ばす。連打で確実に再生させたいなら WAAPIの element.animate() が楽だ（CSSだと「クラス除去→強制リフロー→再付与」が要る）。

Next.js（App Router）での組み込み。ボタンはインタラクティブなので 'use client' 必須。初期の liked／いいね数は RSC でDBから取得し props で注入すると、SSRのチラつきが消える。ミューテーションは Server Action にし、useOptimistic ＋ useTransition で即時フィードバック、失敗時はReactが自動ロールバックする。アニメの発火はネットワーク完了に依存させず、押下即で再生する。

落とし穴。width/height/box-shadow はアニメしない（レイアウト／ペイントが頻発する）。粒子角度を Math.random() でレンダー時に決めるとハイドレーション不一致になるので、等間隔で決定的に算出するかクリック時に決める。prefers-reduced-motion では弾み・バーストを止め、塗りの切替だけ残す——「動きを減らす」であって「機能を消す」ではない。ひとこと。本物のボタン＋transform/opacity＋楽観的更新。この3点で"軽くて気持ちいい"いいねになる。
