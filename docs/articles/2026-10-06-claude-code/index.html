Claude Code

Claude Code v2.1.292 — 承認なしartifact公開とeffort、そして“フックで制御”の設計指針

日次更新は地固め回。運用に効く細かな改善＋セキュリティ修正と、Steeringの2軸。

📅 2026年10月6日 ⏱ 約3分 🔗 出典 3 件

Claude Code本体はこのところほぼ日次でリリースが進み、本日時点の最新はv2.1.292（10/6）。派手な新機能というより「毎日の運用で効く細かな改善＋セキュリティ修正」が束で入った回だ。地味だが、自分のように多数のスケジュールタスクを無人で回す運用には直接響く。

何が入ったか。v2.1.292ではclaude plugin installに--marketplace <source>が付き、どのマーケットプレイスから入れるかを明示できるように。Agentツールにはサブエージェントの思考量を指定するeffortパラメータが追加された。Artifact一覧の取得上限が50→200件に拡大し、スケジュール/ルーティン実行ではartifactを承認なしで公開するよう変更（無人実行で承認待ちに詰まらないための変更で、まさにこの読み物タスクのような自動運用に効く）。mod/フック向けにはプロンプトキャッシュやturn.stepフックのserverToolUsesなどメタデータが拡張。直前のv2.1.290（10/5）はマネージドエージェントのオンボーディングや権限粒度（tool.checkのagentId、組織必須承認のceiling）を追加し、v2.1.291（10/6）は緊急パッチでクラウドセッションの権限応答取りこぼしと終了時メッセージ喪失のリグレッションを修正している。

今日いちばん読むべきは“制御の設計指針”。Anthropic公式『Steering Claude Code』が、Claudeの挙動を操る手段を「文脈コスト」×「指示の強制力」の2軸で整理した。要点は、(1) CLAUDE.mdは200行以内に抑えてビルドコマンドや構成・規約の“概観”だけに使う（何でも詰め込む置き場にしない）、(2) 具体的な制約は.claude/rules/へ置きpaths:でスコープして無関係作業でのトークン浪費を防ぐ、(3) デプロイ等の手続きはスキル（名前と説明だけ常時読み込み、本体は起動時のみ）、(4) 調査・レビューなど要約だけ戻せばよい副作業はサブエージェントに隔離、(5) 「絶対こうしろ/するな」はプロンプト頼みにせず、ハーネスが実行するフック（PreToolUse等）で確定的に強制する、というもの。別記事の上級ベストプラクティス11選も同じ思想で、「プロンプトで縛る→仕組み（アーキテクチャ）で制御する」への転換、同じ指摘が2回続いたら/clear、仕様と実装・執筆とレビューのセッション分離、を勧める。

自分が試すなら。まず各スケジュールタスクのCLAUDE.mdを「消したらClaudeが間違えるか?」で棚卸しして最小化し、絶対要件（例：特定フォルダ外への書き込み禁止）はPreToolUseフックへ移す。effortはサブエージェントの重さ調整に使えるので、軽い整形系はlow・設計レビューはhighと振り分けると無駄打ちが減る。注意点：今回はUNCパス経由のフック承認迂回や改ざんキャッシュのポリシー回避などセキュリティ修正が多い回なので、更新は後回しにしないこと。

まとめ：v2.1.292は“地固め”回だが、承認なしartifact公開とeffortは自動運用に、Steeringの2軸は日々の設定整理に効く。制御はプロンプトでなく「ルール＋スキル＋フック」の構造へ寄せるのが2026の定石。
