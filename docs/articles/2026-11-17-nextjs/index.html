マウス追従スポットライト／グロー・ホバーカード — Bentoグリッドの“光る枠”を依存ゼロ・純CSSで。鍵は「再レンダーを経由しない座標渡し」

Linear/Vercel系ランディングやBentoグリッドで定番の、カーソル位置に淡い光が灯り枠が光る演出。本質は(1)座標をReact再レンダーなしでCSSへ渡す(2)光を背景グローと枠グローの2層に分ける(3)グリッド全体で1リスナに集約、の3点。使う技術はすべてBaseline。

📅 2026年11月17日 ⏱ 約5分 🔗 出典 4 件

Linear / Vercel / shadcn 系ランディングや Bento グリッドで定番化した「カードにカーソルを乗せると、ポインタ位置に淡い光が灯り、枠が光る」演出。見た目はリッチだが、本質は3点だけ——(1) ポインタ座標を React を再レンダーせず CSS へ渡す、(2) 光を『背景グロー』と『ボーダーグロー』の2層に分ける、(3) グリッド全体で1つのリスナに集約する。派手さの割に依存ゼロ・純CSS+小さなJSで組め、'use client' 境界も最小化できる。

なぜ注目か：珍しく“枯れた”演出テーマ

使う技術（CSS カスタムプロパティ、radial-gradient、mask + mask-composite、Pointer Events）はすべて Baseline。機能検出もフォールバックも要らず、「対応状況の但し書き」がない珍しいテーマで、難しさは対応ではなく設計（再レンダー回避・レイアウトスラッシング回避・a11y）に寄る。Aceternity UI の CardSpotlight、Magic UI の MagicCard、motion-primitives の Spotlight 等が軒並み標準採用しているが、中身は数十行の素のCSS+JSで、ライブラリ無しで十分再現できる。

仕組み：座標は state でなく CSS 変数へ直書き

グリッド全体を1ラッパーで囲み、1つの mousemove リスナが全カードの --mouse-x/--mouse-y を一括更新する。カスタムプロパティは擬似要素へ継承されるので、カード要素に setProperty するだけで ::before（枠グロー）と ::after（背景グロー）の両方へ効く。枠グローは radial-gradient を padding＋mask-composite: exclude で内側をくり抜き、枠（リング）だけを光らせる定石を使う。重要なのは座標を useState に持たせないこと——毎フレーム state 更新すると INP が悪化するので、useRef＋el.style.setProperty で再レンダーゼロ、座標は DOM へ直書きして React を経由しない。

/* 枠だけを光らせる mask-composite 版 */
.card::before {
  content: ""; position: absolute; inset: 0; border-radius: inherit;
  padding: 1.5px;                 /* 枠の太さ */
  background: radial-gradient(240px circle at var(--x) var(--y),
             hsl(220 90% 65%), transparent 60%);
  -webkit-mask: linear-gradient(#000 0 0) content-box, linear-gradient(#000 0 0);
  -webkit-mask-composite: xor; mask-composite: exclude;  /* 枠部分だけ残す */
  opacity: 0; transition: opacity .4s; pointer-events: none;
}
.card:hover::before { opacity: 1; }

Next.js（App Router）での組み込み

'use client' は『座標を書く島』だけに閉じ込める。mousemove を張るラッパーをクライアント化し、中身のカードは children で流す。グループ型の SpotlightCard はフック無し（クラスと擬似要素CSSだけ）なのでServer Component のまま使え、データ取得・一覧 map は RSC に残せる。初期HTMLは座標未設定・グロー opacity:0 なのでハイドレーション mismatch が無く、光はポインタ移動後に初めて出る純プログレッシブエンハンスメント。revalidate/use cache/PPR とも無干渉だ。

落とし穴・性能

最大の事故はレイアウトスラッシング。ハンドラ内で各カードの getBoundingClientRect()（読み）と setProperty（書き）を交互にやると強制同期レイアウトになるので、読みを全カード分先に済ませてから書き、requestAnimationFrame で1フレーム1回に間引く（リスナは {passive:true}）。動かすのは translate/opacity だけに留めてコンポジタ合成に乗せ、left/top やグローの寸法を毎フレーム変えない。タッチでは無意味なので @media (hover:hover) and (pointer:fine) でラップし、端末では演出もリスナも付けない。a11y はグローを純装飾として aria-hidden・pointer-events:none にし、キーボード等価として :focus-visible で枠グローを点灯、prefers-reduced-motion では追従 transition を切る。

ひとことまとめ

“光る枠”はサーバーに残したカード＋クライアントの座標島＋純CSSで、依存ゼロ・再レンダーゼロで組める。自分で試すなら、まず mask-composite の枠グロー1層から入れて、スポットライト（背景グロー）を足すのが堅い。
