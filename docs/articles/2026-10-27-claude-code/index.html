10/27のClaude Code — 新規版は止まっても「自動モード×コンテキスト管理」が静かに成熟している

v2.1.310で止まった週。だが直近1ヶ月の更新を並べると、auto modeの既定化と長い会話の自動圧縮という“放っておいても安全に走り続ける”方向がはっきり見える。

📅 2026年10月27日 ⏱ 約4分 🔗 出典 5 件

10/27(JST)時点で公式changelogの最新はv2.1.310（10/23）のまま。10/24〜27の新規リリースは確認できない。だが「新しい版が無い日」こそ、直近1ヶ月で何が積み上がったかを読み直す好機だ。キーワードはauto mode（自動モード）とコンテキスト管理の2本で、どちらも「人が張り付かなくても安全に長く走る」方向を向いている。

何が積み上がったか

直近の目立つ更新はこう並ぶ。v2.1.299（10/14）で200Kトークン超の会話を約54分アイドルで自動圧縮（idleCompaction:falseで無効化可）。v2.1.302（10/16）で圧縮に使うモデルを選ぶCLAUDE_CODE_AUTO_MODE_MODELと/configのアイドル圧縮設定が入り、フォーク・サブエージェントがターミナル外でも既定ONに。v2.1.304（10/19）で/auto-mode-setupというガイド付きセットアップが追加。v2.1.305（10/20）でLinuxサンドボックス向けにsandbox.allowNestedUserNamespaces（ファイル保護を弱めうるので慎重に）。そしてv2.1.310（10/23）はVS Codeの計画レビューで「フィードバックを送って計画を続行」ボタンが計画を誤承認する問題の修正や、prompt-too-long後の圧縮が密なテキスト（base64/SVG）を残しすぎる挙動の緩和を含む。

「操縦」の設計図 — 強制はフックへ

公式ブログ「Steering Claude Code」は、挙動を形づくる手段を「いつ読み込むか・コンテキストを食うか・強制力」の3軸で整理する。要点は、CLAUDE.mdは毎ターン読まれコンテキストを消費するので“常に知るべき事実”だけ（200行以内推奨）に絞ること。長い手順はスキル（名前と説明だけ先読み、呼び出し時に全文）、脇作業はサブエージェント（独自コンテキストで要約だけ返す）。そしてハードな禁止は指示文ではなくフック・権限・管理設定で行う——指示はプレッシャーやプロンプトインジェクションで破られうるからだ。この「強制はフックへ」という線引きは、auto modeが既定化していく今こそ効いてくる。

実務での使いどころ・自分が試すなら

auto modeはPro/Max/Teamで既に既定（2026/8）で、1,053名テストでは有害操作の89%を検知（手動レビューは13.6%）という数字も出ている。自分が試すなら、まず/auto-mode-setupで入口を作り、絶対にやらせたくない操作（本番DBへの破壊的コマンド等）はCLAUDE.mdに書くのではなくdeny/フックで固める。長い会話は54分の自動圧縮に任せつつ、base64やSVGを貼る作業では圧縮が効きすぎないか様子を見る。

注意点・落とし穴

sandbox.allowNestedUserNamespacesはサンドボックスの保護を弱めうるので、必要な環境だけで。市場シェアの「34.4%」「企業導入4倍」などはAnthropic全体の指標でClaude Code単体の寄与は切り分けられておらず、二次引用も多い——話のマクラにはいいが、根拠として引くのは控えめに。

ひとことまとめ

版が出ない日こそ、設計思想が見える。「長い会話は自動で畳む」「禁止はフックで固める」——放任と制御の線引きが、auto mode既定時代のClaude Codeの背骨だ。
