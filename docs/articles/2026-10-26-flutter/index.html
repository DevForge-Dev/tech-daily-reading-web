Flutterデスクトップの到達点 — Impeller既定化・experimental multi-window・Widget Previews stable

stable 3.47.8時点で、デスクトップはImpellerが既定（macOS=Metal／Win・Linux=Vulkan）になり、experimental multi-windowとWin/Linux flavor、Widget Previews stableが揃った。11月の3.50（Web WasmGC既定）前の“足場固め”の全体像。

📅 2026年10月26日 ⏱ 約3分 🔗 出典 5 件

現況のstableは 3.47.8（eMudhra中間CA失効に対応するsecurity update・勧告 GHSA-frr6-h895-5pxp）。betaは 3.50.0-0.1.pre / Dart 3.14.0 据え置きで、11月stableの3.50（Web WasmGC既定・Android Impeller一本化）という見通しは変わらない。本番は 3.47.8をpin＋別ジョブでbeta を追う運用が無難だ。この日の主役は、ここ数リリースで揃ったデスクトップ基盤である。

何が新しいか：デスクトップImpeller既定化

デスクトップのImpeller既定化が完了し、macOSはMetal、Windows・LinuxはVulkan（3.47〜）で描画する。macOSは Wide Gamut Color が既定になり、文字は SDF（Signed Distance Function）レンダリング（macOS/Linux/Windows）に。暫定的なopt-outはプラットフォーム別に用意されるが、いずれ撤去される前提だ。

experimental multi-window と flavor

実験的だが Linux/Windowsでpopup window に対応し、新 sized-to-content API が内容にフィットする通常/ダイアログwindowを生成する。各コントローラの windowHandle がネイティブの HWND/NSWindow/GtkWindow を公開し、Windowsプラグインは FlutterEngine::PostPlatformThreadTask で処理をプラットフォームスレッドへ逃がせる。加えて Windows/Linuxのflavor対応（flutter build windows --flavor flavor_a）で、pubspec.yaml にflavor別アセットを書けるようになった。macOSは flutter config --enable-macos-arm64-only でARM64-onlyビルド、SwiftPMは上位100プラグイン中92が移行済み。

Widget Previews stable と、この日の技法

Widget Previews stable は .widget_preview/ のプロジェクトキャッシュで起動を速くし、PreviewThemeData で階層的なテーマテストができる（要 iOS15/macOS12・Java17・compileSdk36）。実装面の小ネタも押さえておきたい。段階（stagger）アニメーションは controller1つ＋各Tweenの Interval(begin,end) で“ずらし”を作るのが正体で、専用のdelayプロパティは無い——区間の隙間が遅延、接する区間が連続、同一区間の共有が同時進行になる。状態管理のRiverpodは @riverpod コード生成で、戻り型（T/Future<T>/Notifier）がprovider種別を自動決定し、family は引数を足すだけに置き換わる。アプリサイズは --analyze-size＋App Size toolのtreemapで 可視化してから削る。

ひとことまとめ

Flutterデスクトップは「動く」から「本番で整う」段階へ。Impeller既定・multi-window・flavor・Widget Previewsが出揃った今、3.47.8をpinしつつ11月の3.50を試すのが現実解だ。
