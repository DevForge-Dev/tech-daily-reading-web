クロスセッションメッセージングがWindows対応で全OS横断——ListAgents/SendMessageで別セッション連携、/claude-apiでSDK移行、受信ソケットは30秒で切断

新モデルではなく「セッション間連携」と「移行・信頼性」を固める一日。ListAgentsで到達可能な別セッションを発見しSendMessageで届ける仕組みがWindowsでも揃い、受信側は作業を止めずツール呼び出しの合間で読む。受信ソケットは30秒無入力で切断、名前空間での無効化バグも修正。/claude-apiはanthropic 0.x→1.xのPython移行を自動化し、フルスクリーンレンダラーはBedrock/Vertex/Foundryへ拡張。

📅 2026年9月1日 ⏱ 約3分 🔗 出典 6 件

今日のClaude Codeは新モデルではなく「セッション間連携」と「移行・信頼性」を固める一日だった。目玉はクロスセッションメッセージングのWindows対応で、これまでmacOS/Linux先行だった機能が全OSで揃った。到達可能な別セッションを探すListAgentsと、名前を指定してメッセージを届けるSendMessageの2ツールが噛み合い、複数マシンで走るClaude Code同士が作業を止めずに連携できる。

何が新しいか

受信側は実行中のタスクを止めず、ツール呼び出しの合間でメッセージを読むため、並列作業や役割分担を遠隔ウィンドウ間でも自然につなげられる。あわせて信頼性の調整も入り、受信インボックス用ソケットは30秒以内に完全な1行が来ない接続を切断するようになった（投稿スクリプトはデータが揃ってから接続する運用が推奨）。v2.1.232のソケットディレクトリ強化以降、ユーザー名前空間やrootlessコンテナでメッセージングが黙って無効化されていたバグも修正された。移行支援では、Pythonプロジェクトをanthropic 0.x系から1.x系へ移す/claude-apiアップグレードコマンドが新設され、フルスクリーンレンダラーの利用提案がBedrock/Vertex/Foundry構成にも拡張された。

仕組みのポイント

連携の勘所は「受信は非同期・非ブロッキング」という設計だ。SendMessageは相手の実行を割り込まず、相手がツール呼び出しの区切りに達したときに読ませる。だからA→B→Aのピンポンで役割分担しても、双方の長い処理を止めずに済む。/claude-apiは破壊的変更への追従を自動化し、旧SDK（0.x）のクライアント初期化やメソッド名の差分を1.x系へ機械的に書き換える。SendFeedbackツールや組織向けTips表示のローテーションなど、運用の使い勝手を高める小改善も続いている。

実務での使いどころ・自分が試すなら

1人×Claude Code×多PJの横断運用では、「探索担当セッション」と「実装担当セッション」を分け、ListAgents/SendMessageで橋渡しするとメインの文脈を膨らませずに済む。関連して今日はサブエージェント実践ガイド2026（独自コンテキスト・専用プロンプト・絞ったツールと権限で並列探索や重コンテキスト作業を委譲）と、Skills vs Hooksの使い分け（スキル＝判断を委ねる知識追加／フック＝判断に関わらず100%発火して確実に実行）も話題だった。まずスキルから始め、確実に効かせたい処理だけフックへ、が公式推奨だ。

注意点・落とし穴

クロスセッション連携は便利だが、受信ソケットの30秒タイムアウトを踏むと取りこぼす。投稿側は「1行を揃えてから接続」を守る。事例面では、Microsoftの企業規模実地調査が導入者のマージPR約24%増（4か月持続）を報告し、NRIはテスト工程で最大85%・開発工程40%の効率化を挙げる一方、トークン支出の管理が現実的な論点になる。5万スターのTips集も本質は「文脈を絞る」「処理を強制する」の2つ——CLAUDE.mdは消せる行を消し200行以下に保つ。

ひとこと

派手な新機能ではないが、複数セッションを束ねて「安全に・止めずに・移行しながら」使い倒すための足回りが着実に厚くなった一日だった。
