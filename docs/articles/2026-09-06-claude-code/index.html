Claude Code v2.1.261 — インライン出力上限を128Kへ、/skill-doctor で未使用Skillのコンテキスト費用を可視化、/status に組織ポリシー行

9/4のv2.1.261は67件のCLI変更を含む更新。bashOutputMaxChars/taskOutputMaxCharsでコマンドやバックグラウンドタスクのインライン出力を最大128K文字まで受け取れるようになり、長いビルドログのファイル退避が減る。/skill-doctorはロード済みなのに未使用のSkillとそのコンテキスト費用を一覧化し、トークン効率の棚卸しに効く。/statusには組織ポリシー未読込の理由行も追加。

📅 2026年9月6日 ⏱ 約3分 🔗 出典 3 件

9月4日リリースの v2.1.261 は67件のCLI変更を含む更新で、テーマは「長い出力の扱い」と「肥大化したコンテキスト」という日々のつまずきを片付けることにある。派手な新機能というより、毎日の効率を底上げする回だ。

何が新しいか

最大の追加は bashOutputMaxChars と taskOutputMaxChars の2設定で、コマンドやバックグラウンドタスクの出力をClaudeがインラインで受け取れる量を最大128K文字まで引き上げられる。これまで長いビルドログはファイルへ退避され、読み直す手間が発生していたが、その往復が減る。あわせて未使用Skillを棚卸しする /skill-doctor が追加され、ロード済みなのに使われていないSkillと、それが消費しているコンテキスト費用を一覧表示する。/status と claude doctor には組織ポリシー(Organization policy)行が加わり、プロキシがエンドポイントを通していないなど、ポリシーが読み込めなかった理由が分かる。少し前の v2.1.257 では既定Fableモデルが Claude Fable 5.1(1Mコンテキスト・入力$10/出力$50 per M)へ更新されている。

仕組みのポイント

Skillは description が現在のタスクに一致すると自動ロードされる長期知識だが、ロードされた瞬間からトークンを消費する。使わないSkillが常駐するとコンテキストが圧迫され、応答のコストと質に響く。/skill-doctor はこの「見えない出費」を可視化し、剪定の判断材料をくれる。

使いどころ・自分が試すなら

10PJを1人で横断する運用では、まず /skill-doctor で常駐Skillを棚卸しし、定期タスクごとに本当に要るSkillだけ残す。CI的な長時間ビルドを回すプロジェクトでは taskOutputMaxChars を引き上げ、失敗ログを会話内でそのまま追えるようにしたい。

注意点

出力上限を上げるほど1リクエストのトークンとコストは増えるので、128Kは常用ではなく「ログが長い時だけ」に留めるのが賢い。Skill棚卸しも一度きりでなく、構成を変えたら再実行する運用にすると効く。

ひとことまとめ：可視化(skill費用・組織ポリシー)と容量調整(128K出力)で、毎日のトークン効率と再現性を底上げする堅実な回。
