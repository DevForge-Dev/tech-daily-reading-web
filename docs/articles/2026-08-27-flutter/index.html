Swift Package Managerが既定に・Android 10+はpure Impeller — Flutter 3.47/Dart 3.13とRive・Riverpod 3.3の実務線

iOS/macOSの依存管理がCocoaPodsからSPMへ、Android 10+はlegacy Skiaを撤去してpure Impeller Vulkanが既定、Webは描画最適化で約40%高速化。現行は3.47/Dart 3.13。あわせてRiveの事前ロード原則、Riverpod 3.3.1＋codegen、GPUスレッド時間で詰めるパフォーマンス設計を再確認する。

📅 2026年8月27日 ⏱ 約3分 🔗 出典 4 件

今日のFlutterは基盤（描画・依存管理）の世代交代が主役だ。iOS/macOSの既定依存管理が Swift Package Manager (SPM) に移り、CocoaPods時代が終わりに向かう。flutter コマンドが既存Podfileを検出して段階的にSwiftPMへ移行し、パッケージ解決が高速化・native Xcodeプロジェクトとの統合が向上する。最低要件はiOS 15・macOS 12、Xcode 27パイプライン。描画側は Android 10+（API 29+）でlegacy Skia backendを撤去してpure Impeller Vulkanが既定になり、Webターゲットは描画パイプライン最適化で約40%高速化。現行安定版は Flutter 3.47 / Dart 3.13で、Dart 3.13では primary constructors が正式化された（利用時は language version を ^3.13.0 に）。

アニメーションと状態管理の実務線

アニメーションの今日の主役はRiveの実装ベストプラクティス。.rivは必ず initState か FutureBuilder で事前ロードし build() 内でロードしない（毎フレーム再読込とjankを回避）、同一アニメを複数表示するならRiveFileインスタンスを再利用、Rive widgetは RepaintBoundary で包んで周囲から repaint を隔離する。StateMachineController＋SMITrigger でアニメロジックを描画から分離すればreactive・data-drivenになり、デザイナーはFlutterコードに触れず反復できる。黄金律は「まずimplicit（AnimatedContainer等・150〜500ms）」で、explicitはloop/physics/gesture限定＋dispose必須。状態管理は新規の既定をRiverpod 3.3.1＋codegenに。@riverpodアノテーションでcompile-time safetyを確保し、async providerは失敗時にautomatic retryでネットワークグリッチを吸収、ref.watch(provider.select(...)) で最小スライス購読しリビルドを抑える。監査証跡が要る大規模・規制業界(fintech/healthcare)はBloc 9.0で events/states/logic を厳格分離。

パフォーマンスの詰め方・注意点

詰め筋はGPUスレッド時間：目標は60fpsで4ms未満・120fpsで8.3ms未満。CustomPainterでは Paint をbuild毎に生成せずキャッシュし shouldRepaint を適切に実装、アニメ領域を RepaintBoundary で隔離する。最も多い問題は不要なwidget rebuildで、プロパティ不変なら const で再ビルドを完全スキップ、大きな build() を分割、Selector/select で局所再描画にする。計測は必ずprofileモードでDevToolsのPerformanceタブから（debug VMは遅く数値が当てにならない）。注意点はSPM移行の過渡期で、CocoaPods前提のCI・依存やプラグインの対応状況を確認しながら段階移行すること。

ひとこと

描画（Impeller）・依存管理（SPM）・状態管理（Riverpod codegen）が2026年の既定線として固まった。新規はこの3点を初期設定にし、パフォーマンスは「予算内に収める」を合言葉に測って詰めるのが近道だ。
