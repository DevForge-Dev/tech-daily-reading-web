11月安定版へ降りる三本柱 — WasmGC・Impeller一本化・build hooks、そしてHero/MVVM/jank診断

beta 3.48 / Dart 3.14 が確定させた11月の破壊的変更と、Hero・App Architecture・DevTools 診断の実務勘所。

📅 2026年9月26日 ⏱ 約4分 🔗 出典 5 件

この日の主役は beta 3.48 / Dart 3.14 が 11 月安定版へ降ろす機能の確定だ。現行安定版は Flutter 3.47.4 / Dart 3.13.3、beta の最新 pre-release は 3.48.0-0.5.pre。年4回（2/5/8/11月）サイクルで次の安定機能リリースは 2026 年 11 月見込みで、beta の三本柱がそのまま 11 月の破壊的変更になる。

三本柱は ① Web の WasmGC 既定化（flutter build web --wasm。dart:html→package:web ＋ dart:js_interop 移行が前提）、② Android の Impeller 一本化（legacy Skia backend の opt-out を deprecate し Vulkan へ集約）、③ build hooks stable（native asset を pub build で扱う仕組みの正式化）。さらに analyzer plugin system でカスタム lint をパッケージ配布可能になる。デザインシステムは material_ui / cupertino_ui 1.0 が SDK から独立済みだが、SDK 同梱版の正式 deprecation は 11 月 stable から。3.47.x の間は既存コードが動くので「11 月までに移行」が現実解で、dart fix --apply --code=migrate_design_widgets で差分適用できる。

アニメーションの話題は Hero（共有要素）トランジション。2画面に同じ tag の Hero を置くと push/pop に連動して要素が「飛ぶ」（標準 300–600ms）。カスタマイズの要は flightShuttleBuilder（飛行中だけ見た目を差し替え）・createRectTween（MaterialRectArcTween で弧を描かせる）・HeroMode。飛ばすのは最小要素にし、画像は前後で同じ ImageProvider／解像度に揃えてちらつきを防ぐ。設計面では公式 App Architecture guide の MVVM が土台で、UI 層は View↔ViewModel が 1:1、Data 層は Repository が single source of truth（caching/retry/変換を担当）、Service は state を持たない最下層。Riverpod 3.3 / Bloc 9.2 はこの MVVM に載る「ViewModel の実装詳細」と位置づけられる。

パフォーマンスは DevTools を使った jank 診断が実務的だ。鉄則は必ず profile モード（debug の VM は数値が代表しない）。Performance overlay の上下2グラフ（UI thread / raster thread）で赤バーの出る側を見て「build が重い」か「描画が重い」かを切り分け、Rebuild counts で過剰 rebuild を、CPU profiler でホットな関数を特定する。対処は const 徹底・ref.watch(provider.select(...))/BlocSelector で最小購読・アニメ領域を RepaintBoundary で隔離・重い同期処理を Isolate.run() へ・長リストは ListView.builder＋cacheExtent（固定高なら itemExtent）。ひとことまとめ：Impeller が全既定で shader jank は 30–50% 減。本番は 3.47 系を維持しつつ、11 月の Wasm・Impeller・design widget 分離を beta で前倒し検証しておくのが吉。
