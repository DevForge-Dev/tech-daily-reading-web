Claude Code v2.1.329 が latest 昇格 — /tasks がスケジュール・loop再開・会話フォークまで可視化し、無人運用の「見える化」が進む

昨日の v2.1.327 から二段飛びで v2.1.329 が latest へ（JST 11/20 03:40 公開・stable=v2.1.311）。目玉は /tasks がスケジュールタスク・/loop の再開予定・ゴール・会話フォークを一覧表示し x で止められること。無人で走らせるセッションの状態が、ようやく画面から読めるようになった。

📅 2026年11月20日 ⏱ 約3分 🔗 出典 3 件

Claude Code の版番号が、昨日まで latest だった v2.1.327 から一気に v2.1.329 へ進んだ（JST 11/20 早朝公開、stable は v2.1.311 据え置き）。npm の dist-tags を一次確認した更新で、間の v2.1.328（11/18 公開）とあわせて読むと、この数日のテーマが「無人・自律で動くセッションを、安全に・見えるようにする」ことに寄っているのが分かる。

何が新しいか — /tasks が「走っている自分」を映す

v2.1.329 の主役は /tasks の拡張だ。これまで現在のタスクくらいしか見えなかったのが、(1) このセッションに紐づくスケジュールタスク、(2) /loop の再開予定（wakeup）、(3) ゴール、(4) この会話から派生したフォーク——までを一覧し、x で確認のうえ停止できる。定期タスクや自己ループを多用する運用ほど「今なにが仕掛かっているか」が掴めず不安だったが、その可視化が進んだ格好だ。あわせて /mcp には、リモート HTTP MCP が接続を拒否したときの JSON-RPC エラーを示す「Server message」行、/status には自動更新されない管理マーケットプレイスを示す「Marketplace auto-update」行が増えた。OpenTelemetry のイベント/メトリクスを有効にしたまま Code Mode が使える点も地味に効く。

堅牢化の本体は修正側・一つ前の v2.1.328

修正も実務直撃だ。ネットワーク停止やファイルロックで ~/.claude.json が読めず既定値へリセットされる不具合、macOS で Keychain を読めるが書けないときの繰り返しサインアウト、そして /code-review <pr番号> が PR ではなくチェックアウト中ブランチをレビューしていた問題（gh pr diff で PR を読むよう変更）が直った。一つ前の v2.1.328 では、Bedrock・Agent Platform・Foundry 等で Opus 4.6／Sonnet 4.6 の auto モードに対応し（権限モード未指定の対話は auto で開始）、mcp_tool フックに "onFailure":"block"、保留ツール呼び出しの復元を止める CLAUDE_CODE_DISABLE_DEFERRED_TOOL_RESUME も入った。DevelopersIO（石川覚）は、公式『Choose a permission mode』に 4.6 系がまだ載らず CHANGELOG と食い違う点を指摘している。

試すなら・落とし穴

自分の運用で効くのは、まず /tasks を開いて「知らないうちに走っている定期タスク／ループ」を棚卸しすること。無人実行を増やすほど、この一覧と /status の自動更新行が効いてくる。注意点は v2.1.329 は latest であって stable（v2.1.311）ではないこと——安定重視の環境は stable を pin したまま、新 /tasks だけ検証機で触るのが安全だ。事例面では楽天（市場投入 24→5 営業日、1,250万行 vLLM を7時間自律リファクタ）や Stripe（1,370人展開・Scala→Java を4日移行）が公式/自社事例として出ているが、いずれも自己申告の数値で方法論の記載はない点は割り引いて読みたい。

ひとこと：この数日の Claude Code は「速く賢く」より「無人で安全に・状態を見せる」方向。定期タスクと自己ループを回す人ほど、v2.1.329 の /tasks は今日入れる価値がある。
