Claude Code Projects ベータ始動 — 閉じても走り続けるクラウド並列スレッド＋共有メモリ

9/17発表のProjectsが各所で詳報。作業単位を『個別セッションの集合』から『永続プロジェクト』へ。各スレッドは独立クラウドセッション＋専用ブランチで、ラップトップを閉じても走り続け、共有メモリで文脈を再利用する。あわせてv2.1.278のauto modeサーバサイド分類器（分類オーバーヘッド非課金）も整理する。

📅 2026年9月21日 ⏱ 約2分 🔗 出典 4 件

背景から。ここ数週のClaude Codeは派手な新API追加より運用の足回りを固める方向が続いていたが、9/17発表の Projects（ベータ） は久々に作業モデルそのものを変える一手だ。MarkTechPostやVentureBeatが揃って詳報し、注目を集めている。

何が新しいか

従来は開発者が個別セッションを手動で立て、閉じれば止まっていた。Projectsは作業単位を永続的なプロジェクトに置き換える。開発者が高レベルの目標と対象リポジトリを渡すと、Claudeが『chief of staff（参謀長）』のようにスコープ設定→スレッド作成→タスク委譲→レビュー→依存関係の調整まで一貫して担う。各スレッドは独立したクラウドセッションとして動き、対象リポジトリの独立コピーと専用ブランチが割り当てられる。ラップトップを閉じてもクラウド側で走り続け、スレッド間で共有メモリとファイル/成果物の共通ライブラリを再利用できる。ベータはまず一部Pro/Maxから提供開始。

もう一つの軸：auto modeのサーバサイド分類器（v2.1.278）

コスト面では v2.1.278 でauto mode（モデル自動選択）の分類がサーバサイドの分類器ルーティング既定に。Claude API/Enterpriseでは分類オーバーヘッドが非課金になり、Bedrock/Vertex/Foundry・各種ゲートウェイでも既定化された。CLAUDE_CODE_AUTO_MODE_SERVER=0 でオプトアウトでき、課金される旧経路にフォールバックする際は警告が表示される。

使いどころ・自分が試すなら

Projectsは『長時間・複数リポジトリにまたがる開発の自動化』に効く。試すなら、まず依存の少ない独立タスク（小さなリファクタや調査）を1プロジェクトに切り出し、共有メモリに何が蓄積されるかを観察するとよい。上級運用の定石——文脈は量より『必要なものを必要なときに』、定義→文脈読込→計画提示→小変更→証拠のレビュー可能な流れ、Hooksで決定論的強制・Subagentsで並列/文脈分離——はProjects時代でも有効だ。

注意点・落とし穴

クラウドで走り続ける以上、権限・監査・コストの管理が要る。auto modeを多用する組織は /status で分類経路と課金挙動を確認しておきたい。ベータゆえ提供対象は限定的で、挙動も今後変わりうる点は織り込んでおく。

ひとことまとめ

『あとはよろしく』でスコープ設定〜委譲〜統合まで走り続ける——Claude Codeがセッション管理からプロジェクト運営へ一段上がった回だ。
