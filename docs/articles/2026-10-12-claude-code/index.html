Claude Code

Claude Code を"仕組みで縛る" — onFailure:"block"・Mods・Hooks上級運用の棚卸し（v2.1.296据え置き週）

新バージョンが止まった週だからこそ、CLAUDE.mdの「助言」とHooks/Modsの「強制・拡張」の使い分けを整理する。

📅 2026年10月12日 ⏱ 約3分 🔗 出典 4 件

10/12（月）時点で公式changelogは10/9のv2.1.296が最新のまま。週末を挟んで更新は途切れ、新機能待ちの谷間だ。だからこそ、直近に入った制御系の機能を「どの層に置くか」という観点で棚卸ししておきたい。Claude Code を安全に動かす鍵は、派手な新機能より、ルールをどの仕組みで効かせるかの設計にある。

何が新しく・重要か。先週のv2.1.295で入った onFailure:"block" は、コマンド/HTTPフックが起動失敗・タイムアウト・終了コード0/2以外で終わったとき、ツール呼び出し自体をブロックできる仕組み。公式Hooksリファレンスにはまだ未記載で、async や Stop/SessionStart系のフックは対象外、値の綴り間違いは設定ファイルごと黙ってスキップされる点に注意が要る。v2.1.292のAgentツール effort は、環境変数 CLAUDE_CODE_EFFORT_LEVEL ＞ 呼び出し時指定 ＞ サブエージェントのフロントマター ＞ セッション設定、の優先順で効く。

仕組みを噛み砕くと、3層で考えると整理しやすい。CLAUDE.md はあくまでClaudeの判断に委ねる"助言"で、短く保つのが鉄則。確実に効かせたいルールは Hooks で"強制"する——例えばPreToolUseフックで .env/.key/.pem への書き込みを exit code 2 で機械的にブロックする。さらに画面やプロンプトに踏み込む"拡張"が Mods（v2.1.287以降で既定オン）で、プロンプト書き換え・ツール呼び出しの保留/拒否/置換・UIパネル追加ができ、Hooksと違いClaude Code内部で動くため状態保持とUI描画が可能だ。

自分が試すなら、機微ファイル保護はCLAUDE.mdに書くだけで満足せず必ずPreToolUseフックに落とす。レビューを挟みたい危険コマンドは公式サンプルMod「Blast Radius」を雛形に保留させ、コンテキスト使用量は「Token Weather」で可視化する。注意点。Modsはユーザー権限かつサンドボックス外で動くので、配布元を信頼できるものに限定し claude plugin validate で中身を確認。組織運用では allowManagedModsOnly でユーザー導入Modを禁止するのが安全だ。

ひとこと。「助言＝CLAUDE.md／強制＝Hooks／拡張＝Mods」の三分法で、効かせたいルールの性質に応じて置き場所を決める——新版が乏しい週の収穫はこの運用の型だった。
