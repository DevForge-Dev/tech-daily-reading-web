Claude Code

Claude Code v2.1.296 — MCP説明の上限を4,096字へ、Sonnet 5.5キャッシュ読取を半額、サブエージェントに`autoCompactWindow`

新機能より"運用の目盛り"を整える版。上限倍増・キャッシュ半額・サブエージェントの自動コンパクトで、大量・長時間のエージェント運用がそのまま安く・安定する。

📅 2026年10月9日 ⏱ 約3分 🔗 出典 3 件

背景。Claude Codeは「フックやスキルを自然言語で書く」運用が定着し、長いMCP説明文やサーバ指示をツール検索経由で読む構成が当たり前になってきた。そこで効いてくるのが説明文の文字数上限とキャッシュ読取のコストだ。本日10/9公開の最新v2.1.296は、まさにこの2点に手を入れた「大量運用の最適化」版で、改善9件・バグ修正56件を含む。

何が新しいか。第一に、ツール検索経由で読むMCPツール説明・サーバ指示の既定上限を2,048→4,096文字へ倍増（前日の2.1.295では個別上限を16,384文字へ拡張済み）。第二に、/cost・ステータスライン・--max-budget-usd・SDKのコスト計算が参照するSonnet 5.5のキャッシュ読取単価を$0.20→$0.10/Mtokへ半減。第三に、サブエージェントに本体より早く自動コンパクトを掛けるautoCompactWindow、Readに巨大テキストを一括読みするallow_large、過負荷(529)リトライの最大待ちを延ばすCLAUDE_CODE_OVERLOADED_RETRY_MAX_DELAY_MSが加わった。

仕組みのポイント。autoCompactWindowはサブエージェント側の文脈を本体とは独立のタイミングで畳めるようにするもので、長時間走る監査・レビュー系サブエージェントが文脈あふれで失速するのを防ぐ。全ワークフローエージェントを一つのモデルで走らせるCLAUDE_CODE_WORKFLOW_SUBAGENT_MODELと併用すれば、重い並列処理の挙動とコストが読みやすくなる。

自分が試すなら。多数のMCPを束ねたプロジェクトで、まず説明上限4,096字を前提に各サーバの指示文を書き直す。そのうえでSonnet 5.5を"長い定型プロンプトを使い回す"キャッシュ多用の設計に寄せ、/costで半額化の効き目を測る。あわせて10/7公開の新モデルClaude Haiku 5.5（Haiku 4.5比で実行コスト約75%減、API既定Haiku、1Mコンテキスト・$0.10/$0.50 per Mtok）を、要約・分類・コンパクトなどのサブエージェントに割り当てる。

落とし穴。上限引き上げは"書いてよい量"が増えるだけで、冗長な指示はかえって文脈を圧迫する。キャッシュ半額もキャッシュが当たる設計でなければ効かない。ポリシー面では10/8の利用規約改定（選挙妨害・偽報道の禁止、モデルへの執拗な虐待の明文禁止。通常の反論・創作・研究/テストは対象外）がClaude全体に及ぶ点も要確認。ひとことまとめ：派手さはないが、上限4,096字・キャッシュ半額・自動コンパクトで"大量運用のコスト最適化"を静かに進めた版だ。
