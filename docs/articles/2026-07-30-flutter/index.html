Flutter が LG スマートTVへ — webOS 公式SDK と、Riverpod 3.0 の Mutations

Google×LG の公式 Flutter on webOS SDK が2026上期リリース目標で、配信先が大画面TVへ拡大。状態管理は Riverpod 3.0 の Mutations がアクションのライフサイクル（Idle/Pending/Success/Error）を自動でUIに公開し、失敗時は自動リトライする。

📅 2026年7月30日 ⏱ 約2分 🔗 出典 4 件

今日の主役は配信先の拡大だ。GoogleとLGが提携し、FlutterアプリをLG webOS スマートTVで動かす公式 webOS SDKを2026年上半期リリース目標で開発中。モバイル／デスクトップ／Webに加え大画面TVが正式な配信先に加わる。安定版は Flutter 3.44.6 / Dart 3.12.2（7/9のパッチ）、次の機能リリースは2026年8月だ。描画は Impeller がiOS＋モダンAndroid（API 29+）の既定で、TVのような常時描画UIでも滑らかさを稼ぎやすい。

もう一つの深掘りは Riverpod 3.0 の Mutations。「Login」「Post Comment」などのアクションを定義すると、そのライフサイクル状態（Idle／Pending／Success／Error）を自動でUIに公開してくれる。従来は自前で isLoading や error フラグを握っていた定型が、Mutationに集約される。さらにプロバイダはネットワーク失敗時に自動リトライし、一時的な通信障害が恒久的なエラー画面に化けない。compile-time safety・組込みオフライン永続化・最小ボイラープレートを備え、テストは平均で30〜40%行数が少ない。

使い分け：新規プロジェクトは Riverpod 3.3.x＋code generation が既定線。監査証跡が要る規制業界（fintech／healthcare）や複雑な並行ワークフローは、event/state/業務ロジックを厳格分離する Bloc 9.0 が向く。上に feature単位のClean Architecture＋go_router を敷く。自分が試すなら：まず既存の「Login」画面をMutationへ置き換え、ローディング／エラー表示の定型がどれだけ減るかを測る。注意点：webOS SDKはリリース目標段階（未GA）で、TVはリモコン主体のフォーカス移動・大画面レイアウト・10フィートUIの作法という別物の設計が要る（ここはナレッジ外なので実機検証で詰める）。まとめ：配信先はTVへ広がり、状態管理はMutationで定型が縮む。書く量を減らして体験の作り込みに時間を回すのが今の正解だ。
