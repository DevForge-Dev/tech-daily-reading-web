9/22の話題リポジトリ — 非自己回帰の意思決定エンジン・harness競争・Anthropic公式の金融エージェント

エージェント／harness一色の上位に、超低遅延の「System 1」意思決定モデル(laya)が割り込んだ一日。自社harnessのOSS化(ZCode)とAnthropic公式の金融エージェント配布(financial-services)が並んだ。

📅 2026年9月22日 ⏱ 約3分 🔗 出典 3 件

エージェント／コーディングharness一色だった上位に、この日は超低遅延の「意思決定モデル」が割り込んだ。純粋な増加率で突出したのは非自己回帰の laya。そこに自社harnessをOSS化する動き（Z.aiのZCode）と、Anthropic公式のドメイン別エージェント配布（financial-services）が並び、「モデル／harness／業務エージェント」の三層がそれぞれ話題を作った一日だった。各リポジトリを「解決したい課題」と「提供する機能」で読み解く。

NandhaKishorM/laya（Python・⭐約10k）

解決したい課題：LLMのツール選択・分類・ルーティングは、本来「決めるだけ」なのに自己回帰生成を通すため遅く高価。この「意思決定に逐次生成は要らない」という不便を突く。提供する機能：100+言語のタイプ付き意思決定を単一フォワードパス・約33msで返す非自己回帰の「System 1」エンジン。厳密妥当スコアリング規則への強化学習（RLCD）で学習し、リクエストごとに最適チェックポイントを選ぶルータを備える。公開わずか4日で約10kスターに達し、派生の laya-mlx / kev も同時急伸——「フロンティアラボが後追いした」という文脈で急拡散し、本日のモメンタム筆頭となった。

zai-org/ZCode（TypeScript・⭐5.5k）

解決したい課題：コーディング・エージェントのharness（探索・編集・実行の足回り）を、他社CLIに頼らず自社モデル（GLM系）前提で持ちたいという需要。提供する機能：Z.ai（智譜）公式の拡張可能なコーディングharnessで、コード探索・編集・実行をエージェントに委ねる「Claude Code系」の対抗実装。TypeScript・Apache-2.0で、公開2日で約5.5k。各社harness競争（Claude Code / Codex / 各社実装）が新章に入ったことを示す一本で、既存CLIエージェントの設計比較対象として関心を集めた。

anthropics/financial-services（Python・⭐35.8k）

解決したい課題：投資銀行・エクイティリサーチ・PE・ウェルスマネジメントの定型ワークフローを、汎用チャットではなく業務特化の形で効率化したい。提供する機能：Anthropic公式「Claude for Financial Services」。Pitch Agent / Market Researcher / Earnings Reviewer / Model Builder（ExcelでのDCF・LBO・3表・comps）/ GL Reconciler / Month-End Closer など、名前付き業務エージェント・スキル・データコネクタを、Cowork プラグインまたはManaged Agents APIの両形態で配布する（全出力は人手承認前提）。約35.8kで公式リファレンスとして注目。自分の用途なら、Coworkプラグインとして最短で試せるのが効く。

まとめ

三層のうち、まず試すなら業務直結の financial-services（Cowork導入が最短）、設計の観察としては laya の「決定は非自己回帰でよい」という主張が中期的に効きそう。ZCodeはharness設計の比較材料として眺める価値がある。
