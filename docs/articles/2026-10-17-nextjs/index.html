Flags SDK v4 — App Routerのフィーチャーフラグを「decideでサーバー評価＋precomputeで静的維持」

flag()一つでプロバイダ非依存・型安全・RSCネイティブ。『フラグで分岐＝ページが動的化』の罠を、precomputeで畳み込んで回避する。

📅 2026年10月17日 ⏱ 約4分 🔗 出典 5 件

フィーチャーフラグ（機能のオン/オフ・A/B・段階ロールアウト・権限ゲート）をApp Routerでどう実装するか。その現行の標準解が、Vercel製OSSのFlags SDK（npm flags、最新v4.0.0）だ。process.env.FEATURE_Xを散らす運用や、クライアント判定でちらつき・秘密露出を招く実装からの移行先になる。

何が新しい/重要か

核はflag()一つ。flags/nextからflag({ key, decide, defaultValue })を呼ぶと「呼ぶと値に解決されるasync関数」が返り、ページではawait myFlag()で読むだけ。特徴は3つ。(1) RSCネイティブ＝評価はdecide()内でサーバー実行され、判定ロジックやプロバイダのシークレットがバンドルに乗らない。(2) 型安全＝flag<T>()で戻り値型が推論。(3) プロバイダ非依存＝自前decideでも、LaunchDarkly/Statsig/ConfigCat等のアダプタでも書き味が同じ（“flags as code”）。defaultValueはdecideが例外/undefinedのときの安全弁で、プロバイダ障害時も本番を落とさない。

// flags.ts （'use client' 不要・サーバーで評価される）
import { flag } from 'flags/next';
export const showNewDashboard = flag<boolean>({
  key: 'new-dashboard',
  defaultValue: false,        // decide失敗時のフォールバック
  async decide() {            // ここはサーバー実行
    return false;
  },
});

最重要の罠と、その回避＝precompute

素朴にページ内でawait flag()すると、リクエスト文脈を読むため動的レンダリングに倒れる。マーケ/LPのように静的で出したいページではこれが致命的だ。回避策がprecomputeパターン——フラグ値を署名付きでURLセグメントに畳み込み、ISR/CDNに載せる。

手順は、(1)フラグをas constでグループ化、(2) proxy.ts（Next.js 16でmiddleware.tsから改名）でconst code = await precompute(marketingFlags)→rewriteで/[code]/...へ内部リライト（URL表示は元のまま）、(3) app/[code]/page.tsxでawait showFlag(code, marketingFlags)とcodeを渡して読む。静的化はgenerateStaticParamsが空配列ならISR、generatePermutationsなら全組み合わせをビルド時プリレンダ。

評価コンテキストの共有と観測性

ユーザー識別はidentifyで{ user: { id } }を作りdecide({ entities })に渡す。これをdedupe()で包むと、多数のフラグが同じDB/セッション照会をリクエストにつき1回に重複排除できる（※App Router専用、Pages Router不可）。複数フラグはevaluate()で一括評価すればheaders/cookiesを一度だけ読む。app/.well-known/vercel/flags/route.tsにdiscoveryエンドポイントを置けば、Vercel ToolbarのFlags Explorerから自分のセッションだけオーバーライドして確認でき、reportValue()でRuntime Logs/Web Analyticsにフラグ値がタグ付けされる。

自分が試すなら・注意点

まずnpm install flagsとFLAGS_SECRET（32バイトのランダムをbase64url、環境ごとに別値）を用意。単純なゲートはページ直読み、静的に保ちたいLP系だけprecompute、という使い分けが現実的だ。落とし穴は、FLAGS_SECRET未設定でprecomputeが機能しない／proxy.tsのconfig.matcherを広げ忘れてrewriteが走らない／serializeの値はフラグと同順で渡す、の3点。常時最新が要るゲートはprecomputeせず動的評価にする。

ひとこと：「サーバーで決める」を徹底したのがFlags SDKの肝。precomputeという一手間で“フラグ＝動的化”の常識を崩し、静的配信と機能分岐を両立させられる。
