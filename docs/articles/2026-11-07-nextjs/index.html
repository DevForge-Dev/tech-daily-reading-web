並列ルート×インターセプトルートで“URL付きモーダル”を作る — (.)/(..)規約とdefault.tsxの罠

クリックはモーダル、直URL/リロードは実ページ。クライアント状態なしで共有・SEO・リロード耐性を満たすApp Routerの定番と3大落とし穴。

📅 2026年11月7日 ⏱ 約3分 🔗 出典 3 件

App Router の並列ルート（@folder スロット）とインターセプトルート（(.)/(..) 規約）を組み合わせると、「一覧でサムネをクリック→詳細がモーダルで被さる。でも URL は /photo/123 に変わり、直接開く/リロードすると“フルページ”で開く」という Instagram/Dribbble 風の挙動を、クライアント状態管理なしで作れる。useState で開閉するだけのモーダルと違い、URL で共有・ブックマーク・SEO 可能／リロードで文脈を失わない／ブラウザ戻るで閉じ進むで再度開く、を標準で満たす。Next.js 13.3 から安定し、16 系でも挙動変更はない。

仕組み：到達経路で描き分ける

肝は「どう到達したか」で出し分ける点。リンククリック（ソフトナビゲーション）なら URL をマスクして現在のレイアウト内にモーダルを被せる。直接 URL・リロード・外部リンク（ハード遷移）なら、インターセプトせず本来のフルページ（app/photo/[id]/page.tsx）を描く。これは仕様であり正しい設計で、クローラやリンクプレビュー Bot も実ページを取得できる＝共有性と SEO を両立する。

フォルダ構成と“3大落とし穴”

@modal スロットを用意し、親レイアウトで {children} の隣に {modal} を置く。忘れがちな3点：(1) @modal/default.tsx を置かないとページ全体が404になる（スロット1つの欠落が全体を落とす）。(2) (..) の段数はファイル階層ではなく“ルートセグメント”基準で数え、@slot フォルダはセグメントに数えない——公式 nextgram 例では @modal/(.)photo のように (.) を使う。(3) 直接 /photo/123 を開いた訪問者は履歴がなく router.back() が効かないので、実 href を持つ閉じるリンクと @modal/page.tsx（return null）を併設する。

RSC を汚さないコツ

'use client' が要るのは useRouter と onClick を持つモーダルの殻だけ。詳細コンテンツ（PhotoDetail）は Server Component のまま children として渡せ、データ取得もサーバーで完結する。インターセプト側とフルページで同じ PhotoDetail を使い回し、React.cache で二重フェッチを避ける。なお「スロットを role で出し分ける」のは認可ではない——両スロットともサーバーで実行され出力はレスポンスに含まれるので、認可は各 page か DAL で必ず行う。

いつ使う / 使わない

コンテンツが固有 URL に値する（商品・写真・投稿・ログイン）で、共有・SEO・リロード耐性が要るなら使う。確認ダイアログや設定パネルのような“使い捨て UI”で URL 不要なら、スロット+インターセプト+default.tsx のコストに見合わず、useState の boolean モーダルの方が簡単。自分が試すなら公式 nextgram を clone して (.) の段数感覚を手で掴むのが最短だ。
