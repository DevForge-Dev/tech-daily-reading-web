Claude Code v2.1.295 — フック/HTTPフックに onFailure:"block"、OSC 7501、MCP説明16Kへ

改善13件・バグ修正97件の大型版。自然言語フックの"取りこぼし"を塞ぐ安全性パッチ v2.1.294 も同日。

📅 2026年10月8日 ⏱ 約3分 🔗 出典 3 件

この日の中心は公式リリース。最新はv2.1.295（10/8）で、改善13件・バグ修正97件を含む大型版だ。同日には小さな安全性パッチv2.1.294も出ており、「フックを自然言語の指示文で書く」運用がじわじわ普及したいま、その信頼性を補強する内容になっている。

何が新しいか。フック／HTTPフックに onFailure:"block" が加わり、起動失敗・タイムアウト・想定外の終了コードのときに対象アクションを通さずブロックできるようになった。これまで「失敗したら素通り」だった検証フックが、初めて"ゲート"として機能する。端末向けには Program Status Protocol（OSC 7501）対応が入り、対応端末が稼働中／入力待ち／完了を表示できる。地味だが効くのがMCPツール説明の読み込み上限を 2,048→16,384 文字へ拡張した点と、サブエージェントが skills から最大32スキルを各1回だけ事前ロードできるようになった点。mod向けには通知 $.ui.notify や Button の子要素対応も追加された。

仕組みのポイント。onFailure:"block" は、CLAUDE.md の指示が「依頼」にすぎないのに対し、フックが「強制」を担うという設計思想の延長にある。10/8更新の『Agentic Workflows 2026 Playbook』も、検証ループを PostToolUseフックでlint・Stopフックでテスト通過までブロックする型として挙げており、今回の onFailure:"block" は「フック自身が落ちたときの穴」を塞ぐ最後のピースと言える。

自分が試すなら。まず既存の検証フック（lint/test）に onFailure:"block" を付けて、フックのクラッシュが"緑扱い"になっていないか確認する。次にMCP説明上限が上がったので、要点が削られて渡っていたツール（長い説明のMCP）を見直す。サブエージェントのスキル事前ロードは、読解をfan-outする運用（本体には要約だけ残す型）と相性が良い。

注意点。modはサンドボックスされずユーザー権限で動く（mod実践ガイドが強調）。サードパーティ製は導入前に claude plugin validate/test で検証し、チームは allowManagedModsOnly で統制する。onFailure:"block" はブロックが"厳しすぎ"ると開発を止めるので、まずは重要フックだけに限定したい。

ひとこと。新機能より「フックを信頼できるゲートにする」補強が主役の日。自然言語フック時代の地固めとして要チェック。
