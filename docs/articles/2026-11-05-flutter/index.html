11/5のFlutter — Widget Previewer（'flutter widget-preview start'＋@Preview）が stable 3.47 で正式化：実機ビルドなしのUI反復

アプリ全体を実機/エミュで起動せず、widget をブラウザ上に並べて即確認。デザイン反復を高速化する公式プレビュー環境が安定版に。使い方と制約、そして足踏み中の3.50事情まで。

📅 2026年11月5日 ⏱ 約4分 🔗 出典 4 件

背景・なぜ今これか。 Flutter 3.47 で stable 入りしたのが Widget Previewer。狙いは明快で、アプリ全体を実機/エミュで起動せず、widget をブラウザ上の専用環境に並べて即確認し、デザインの反復を高速化することだ（DCM によれば 3.35 で experimental 初登場、3.38 で IDE 連携）。SwiftUI の Preview や Storybook に近い発想が、ついに公式で安定提供された。

使い方。 import 'package:flutter/widget_previews.dart'; して @Preview(...) を付ける。対象は①トップレベル関数（Widget/WidgetBuilderを返す）②クラスの static メソッド③必須引数なしの public な Widget コンストラクタ/factory。最小例は @Preview(name: 'My Sample') Widget sample() => const Text('Hello');。起動はプロジェクト直下で flutter widget-preview start（ローカルサーバ＋ブラウザのリアルタイム環境・保存で自動更新）、AndroidStudio/VSCode は「Flutter Widget Preview」タブで自動起動する。

カスタマイズ。 引数で name/group（UIでグルーピング）/size（疑似サイズ、例 Size(375,667)）/textScaleFactor/wrapper（ScaffoldやInheritedWidgetを注入）/theme/brightness（light/dark）/localizations を渡せる。1関数に複数 @Preview 可——同じ widget を light/dark の2枚並べる、といった使い方ができる。

制約（落とし穴）。 annotation に渡すコールバックはpublic かつ const（インラインのクロージャ不可→トップレベル関数か static メソッドに）。previewer は Flutter Web でビルドされるため ネイティブプラグイン・dart:io・dart:ffi は不可（呼ぶと throw）。アセットは packages/<pkg>/assets/... のパッケージ相対。ビルドキャッシュはプロジェクト直下 .widget_preview/。IDE は同時1プロジェクトのみ。

現況（3.50 は足踏み）。 stable は依然 3.47.9 / Dart 3.13.7（10/29）、beta 3.50.0-0.3.pre で据え置き。11月 stable 3.50 は 11/5 時点も未公開で、release-tracker #195830 は 11/2 起票のまま open・チェックリスト全未完（cherry-pick マージや Archive 反映が未着手）＝最終ゲートで止まっている。来週あたりの 3.50 を見据えつつ、Previewer は 3.47 で今すぐ試せる。

あわせて（本日の実務メモ）。 素材には他に、Hero のカスタム（flightShuttleBuilder で両ルートの見た目ジャンプを吸収、createRectTween に MaterialRectArcTween で弧を描く軌道）、go_router 17.x（context.go/push・global redirect+refreshListenable・StatefulShellRoute.indexedStack・型安全ルート）、ListView 性能（shrinkWrap:true の罠＝遅延生成が死ぬので CustomScrollView+SliverList.builder で平坦化、固定高は itemExtent/prototypeItem）も。いずれも「今日の仕事ですぐ効く」定番。

ひとことまとめ。 UIの試行錯誤を「実機ビルド待ち」から解放する一手。@Preview を1つ書いて flutter widget-preview start——まずこの往復を体に入れると反復速度が変わる。
