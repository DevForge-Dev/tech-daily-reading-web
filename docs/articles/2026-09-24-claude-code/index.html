v2.1.281はBedrock/MCPを強化しつつ「autoの再帰rm無確認」を修正 — 助言(CLAUDE.md)と強制(Hook)の設計思想

9/23のv2.1.281はBedrockのassume_role/ガードレールとMCP URLモードのelicitationを足しつつ、プロンプトキャッシュ喪失・resumeの二重実行、そしてautoモードでの再帰rm無確認実行を修正した。

📅 2026年9月24日 ⏱ 約3分 🔗 出典 3 件

Claude Code は毎週のように小刻みなリリースを重ねているが、9/23 公開の v2.1.281 は「エンタープライズ対応の前進」と「安全性の地固め」が同居した回だ。単なる新機能追加ではなく、危うい既定挙動をひとつ潰した点にこそ今日の学びがある。

何が変わったか（v2.1.281）

エンタープライズ向けには Amazon Bedrock upstream で assume_role（開発者ごとのセッションは任意）と guardrail:{id,version} 指定に対応。Claude Desktop 連携に blockReadsOutsideWorkingDirectories / disableBypassPermissionsMode などのキーと telemetry.resource_attributes が入った。MCP は URL モードの elicitation とサーバー検証を強化。安定性では、MCP 切断やプロキシのストリームイベントでプロンプトキャッシュが失われる問題、セッション再開(resume)で旧ターンが変形して再送・巨大セッションが末尾のみ復元・ツールが二重実行される不具合を修正した。

核心：autoモードの「再帰rm無確認実行」修正

今回いちばん重いのは、autoモードで再帰的な rm が無確認で実行されていた挙動を明示許可制に改めた点だ（ファイルパスの null バイト処理も是正）。自動承認は「安全な操作は通し、危険な操作は内部の安全分類器で止める」思想で、手動承認の負担と危険な権限バイパスの中間を埋める。だが分類の穴は破壊的操作に直結する。自動化の価値は、境界（何を通し何を止めるか）の精度で決まる——今回の修正はそれを地で示した。

合わせて読みたい：助言と強制の使い分け

今週のチュートリアル群が示す原則は明快だ。CLAUDE.md は助言にすぎず（しかも 200 行を超えると遵守率が落ちる）、絶対に守らせたいことは 100% 実行される Hook（破壊的 git のブロック、編集後の自動 lint、環境準備など）に落とす。繰り返し作業はクリーンな別コンテキストで並列実行できる Subagent へ委譲する。週まとめでは v2.1.277 から CLAUDE.md 無しでも AGENTS.md を直接読めるようになった点も押さえたい（既定 claude-md-or-agents-md）。

自分が試すなら

(1) 破壊的コマンドを止める PreToolUse Hook を一つ書き、「分類器頼み」を一段減らす。(2) CLAUDE.md を 200 行以内に刈り込み、反復して貼る文脈は「8〜12 個の厳選スキル」＋ .agents/skills/ 同梱へ寄せる。(3) resume の二重実行が直ったので、長いセッションの再開を安心して使う。

注意点

autoモードは「危険を分類器が止める」前提でも過信しない。今回の件が示す通り分類は完璧ではないので、破壊的操作は Hook か手動承認で二重化するのが堅い。Bedrock の assume_role/guardrail はエンタープライズ設定前提の機能で、個人利用ではまず influence しない。

ひとことまとめ

新機能より「無確認 rm を潰した」ことが今日の主役。自動化は速さではなく境界設計の信頼で価値が決まる、と再確認できる回だった。
