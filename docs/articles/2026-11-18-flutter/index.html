Flutter Hero アニメ — tag が一致する2ルート間で子を“飛ばす”。経路は MaterialRectArcTween の弧、飛行中は flightShuttleBuilder で差し替え

stable は 3.50.0 据え置き（公開約1週間・3.50.1 hotfix はまだ未登場＝初動は安定）。今日の技法は Hero——同一 tag を持つ2画面の要素を画面遷移中に飛ばす専用ウィジェット。サムネ→詳細の拡大遷移が典型で、tag を両ルートに1つずつ・新ページ初フレームに存在させるのが肝。

📅 2026年11月18日 ⏱ 約4分 🔗 出典 3 件

リリース状況から。stable は 3.50.0 / Dart 3.14.0（11/11）が現在も最新で、公開から約1週間たっても hotfix 3.50.1 は未登場——公式ポリシー『最新版だけ hotfix する』の下、過去例（3.47.1 が約1週間後）に照らせばまだ出得るが、昇格直後の回帰 hotfix 連発は起きておらず初動は安定している。beta は 3.51.0-0.1.pre（Dart 3.15.0）のまま静かだ。本番は 3.50.0 を pin 基準に、別ジョブで 3.51 beta を緑化しておくのが定石。その上で今日は、画面遷移アニメの定番 Hero を読み物として再構成する。

何が新しい/重要か：2画面間で同一要素を飛ばす専用ウィジェット

公式定義は『子を hero animation の候補としてマークするウィジェット』。これまで扱った明示トランジション（SlideTransition 等）や同一ルート内差し替えの AnimatedSwitcher と違い、Hero は2画面間で同一要素を飛ばす専用だ。発火条件はただ一つ——push/pop 先ルートの Hero と tag が一致すること。const 構築でき、child は『Navigator の push/pop 遷移中に一方のルートからもう一方へ "fly" する』。

仕組み：tag ルールと飛行の制御点

tag ルールが最重要だ。公式いわく『同じ tag を持つ Hero のペアごとに hero animation が発火』『各ルートは tag ごとに Hero を1つより多く含んではならない』『Hero は新ページのアニメの最初のフレームに存在していなければならない』。つまり同一 tag は両ルートに1つずつ、新ページ初フレームに存在が必須で、tag は通常『基になるデータを表すオブジェクト』（≒一覧の各アイテム ID）を使う。飛行の見た目は2つの override で制御する——flightShuttleBuilder は飛行中に表示するウィジェットを差し替える（source/destination 両方が与えたら destination 優先、無ければ destination の Hero child が既定で飛ぶ）。createRectTween は飛行経路（bounds の変化）を定義し、null なら MaterialApp の HeroController が使う MaterialRectArcTween＝直線でなく弧を描く経路になる。

// 一覧・詳細の両方に同じ tag の Hero を置く
Hero(
  tag: 'photo-${item.id}',          // ← 両ルートで一致させる
  child: Image.network(item.thumb),  // 詳細側は拡大画像
)
// iOS バックスワイプ等でも飛ばすなら transitionOnUserGestures: true

実務での使いどころ・自分が試すなら

典型は画像サムネ→詳細の拡大遷移。一覧の各カードと詳細画面の両方に Hero(tag: アイテムID) を置くだけで、タップすると画像が弧を描いて拡大しながら遷移する。曲線は curve（既定 Curves.fastOutSlowIn）/reverseCurve で調整。円⇄矩形の変形を伴う『radial hero』や、飛行中にプレースホルダを置く placeholderBuilder（GlobalKey 衝突回避に空 SizedBox を併用）まで踏み込むと表現の幅が広がる。自分で試すなら、まず standard hero（別位置/サイズへ単純に飛ばす）を1組だけ組み、動いたら flightShuttleBuilder で飛行中の角丸やラベルを足すのが段階的で安全だ。

注意点

最大の罠は tag の重複と初フレーム不在。同一ルートに同じ tag の Hero が2つあると実行時エラー、新ページ初フレームに Hero が無いと飛ばない。tag はアイテム ID のような一意値を使い、リストでインデックスを使い回さないこと。あわせて今日の素材では、再描画を subtree に封じ込める RepaintBoundary（貼りすぎは raster cache 構築コスト＋GPU メモリで逆効果）と、状態管理の定番 flutter_bloc（buildWhen/context.select で不要 rebuild 抑止）も挙がっており、遷移の派手さと描画コストのバランスを取る視点で併読すると効く。

ひとこと

Hero は『同じ tag を両ルートに1つずつ・新ページ初フレームに存在』さえ守れば、数行でサムネ→詳細の拡大遷移が手に入る。経路が既定で弧（MaterialRectArcTween）になるのが Material らしい所で、まずは画像1枚の standard hero から入るのが入り口として手頃だ。
