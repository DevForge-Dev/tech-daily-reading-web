Claude Code

11/2のClaude Code — サンドボックス機構 sandbox-runtime を Apache 2.0 で OSS化（CLI `srt`）、VM/コンテナ無しでOSレベルのファイル/ネットワーク制限

公式changelogは v2.1.316(10/31) から進まず。代わりに直近で表に出た地固め——sandbox-runtime のOSS化(10/24)、デスクトップ v3.6556.1 の sshHostCommands/権限モード端末別保存、プラグイン公式化とMods、そして『3語ステータス行がトークンの15〜20%を食う』という隠れコスト分析を束ねて読む。

📅 2026年11月2日 ⏱ 約3分 🔗 出典 4 件

背景・なぜ今これか。11/2(JST)時点で公式changelogの最新は依然 v2.1.316(10/31) で、新バージョンは出ていない。そこで本日は『無人で長く走らせる自分の運用』に効く、直近に表へ出た地固めを束ねて読む。筆頭は、Claude Code のサンドボックス実装 sandbox-runtime が10/24に Apache-2.0 で公開された件だ。

何が新しい/重要か。@anthropic-ai/sandbox-runtime(CLI名 srt、npm install -g で導入) は、VMやコンテナを立てずにローカルプロセスへOSの標準機能だけでファイル/ネットワーク制限をかける。macOSは Seatbelt、Linuxはroot不要の bubblewrap＋ネット名前空間、Windowsはalpha(WFP送信制御・制限付きトークン・NTFS ACL＋srt-win.exe)。送信は許可リスト方式(ワイルドカードドメイン)で、環境変数・認証ファイルのマスキング、AWS SigV4署名、Unixソケット許可、実験的TLS終端まで備える。.mcp.json の command を srt に差し替えればMCPサーバもそのまま包めるのが実務的に効く。

仕組みのポイント。肝は『隔離＝重い仮想化』という前提を外し、各OSが元から持つサンドボックス機構を薄く叩くこと。だからVM起動のオーバーヘッド無しで、無人エージェントが暴れても作業ディレクトリ外や許可外ホストに手が届かない。位置づけは research preview で API/スキーマは変わり得る、とAnthropicは明言している。

周辺の地固め。デスクトップ v3.6556.1(10/22) は、自前コマンドの出力から接続先を得る sshHostCommands、iOSシミュレータのキー操作、そして権限モードを『この端末・各SSHホスト・各WSL』別に保存する変更を入れた。プラグインは公式化(v2.1.302)し、キュレーション集 claude-plugins-official と、JS/TSでエージェント挙動に割り込む「Mods」(破壊的シェルの遮断・PRタグ付け等を実行経路内で実装)が登場。クラウドセッションもPro/Maxへ広がった。

自分が試すなら・落とし穴。無人定期タスクを回す自分の運用では、まず srt で各スケジュールタスクを許可ドメイン＋作業ディレクトリに封じ込めるのが現実的な一手だ。ただしWindowsは curl.exe/Invoke-WebRequest/.NET HttpClient/winget 等のSchannel系が送信制御を回避できる既知の穴があり、現状alpha。macOS/Linuxから先に導入するのが無難。併せて第三者分析(10/28)が指摘した『3語ステータス行(エージェント要約)の生成がトークンの15〜20%を食う』という隠れコストも頭に置き、進捗表示・自動圧縮・サブエージェント運用を見直すと効く(※個人検証ベースで数値は変動)。

ひとことまとめ。本日は『安全に・安く・手元で縛って走らせる』の地固め。srt でサンドボックス、権限モードは端末別に固定、Modsで危険操作に割り込み、ステータス行の隠れコストを意識——この4点が無人運用者の今日の収穫だ。
