setStateで全部作り直さない — ValueListenableBuilderで変わる1点だけrebuild

カウンタ1個の更新でScaffoldごと作り直すのを止める。ValueNotifierの“==通知”とchild:退避を押さえ、変わる最小の部分木だけを外科的にrebuildする。

📅 2026年11月9日 ⏱ 約3分 🔗 出典 3 件

Flutter の State で setState を呼ぶと、その build() 全体が再実行される。カウンタ1個の更新でも Scaffold ごと作り直す——これが積もるとジャンクになる。狙いは「変わる最小の部分木だけ」rebuild することだ。道具は、値付きなら ValueListenableBuilder<T>、任意の Listenable なら ListenableBuilder。（なお stable 3.50 は 11/9 時点でも未公開＝昇格ゲートで足踏み継続。本番は 3.47.9 pin が無難。）

ValueListenableBuilder：値が来るビルダー

valueListenable に ValueNotifier<T> を渡すと、値が変わった時に builder サブツリーだけが再実行される（周囲は不変）。builder は (context, value, child) で value を受け取るので、Text('$value') をここだけで組む。公式サンプルも「Scaffold 全体に setState する代わりに」この形を使う。

ValueNotifier の“通知は == 比較”という肝

ValueNotifier は単一の値を持つ ChangeNotifier で、新値が旧値と == なら通知しない。だから List/Map を中身だけ in-place で変更しても参照が同じで通知されない——value = [...old, x] のように新しい参照を代入する。可変データは ValueNotifier でなく ChangeNotifier を継承して手動 notifyListeners()。どちらも dispose() 必須だ。

ListenableBuilder と child: 退避

値が要らず notify だけ受けたいなら ListenableBuilder（builder に value は渡らない）。Animation を聴くなら可読性で AnimatedBuilder が推奨（実装は同一）。両者とも child: に「値に依存しない重い静的サブツリー」を一度だけ構築して渡し、rebuild のたびに作り直さないのが定石。共有モデルを「アスペクト」で分割し必要な依存だけ rebuild したいなら InheritedModel<T>（MediaQuery がこの実装）も手だ。

ひとことまとめ

局所の1値は ValueNotifier＋ValueListenableBuilder、複数値・派生は ChangeNotifier＋ListenableBuilder。== 通知と child: 退避を押さえれば、setState の無駄 rebuild はかなり削れる。
