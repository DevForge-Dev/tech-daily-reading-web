JSゼロで作るスクロール・スタッキングカード — position:sticky ＋ scroll-driven でRSCのまま重ねる

スクロールでカードが上部に貼り付き次のカードが重なる定番演出を、JavaScript 1行なしで実装する話。土台は position: sticky だけ、縮小の加点演出も CSS Scroll-driven Animations で完結し、App Router では server component のまま use client 不要・hydrationゼロでINP/CLSに有利。

📅 2026年8月17日 ⏱ 約3分 🔗 出典 3 件

今日のNext.jsの主役はスクロール・スタッキングカード——スクロールにつれてカードが画面上部に貼り付き、次のカードが上に重なって下のカードが少し縮んで奥へ引っ込む、Apple/Stripe系のプロダクトサイトで定番のあの演出だ。注目点はJavaScriptを1行も書かずに実装できること。土台は position: sticky だけ、「奥のカードを縮める」加点演出もCSS Scroll-driven Animations（animation-timeline）で完結する。

なぜ嬉しいか。scrollリスナもIntersectionObserverも不要なので、App Routerではserver componentのまま 'use client' 不要・hydrationゼロ・メインスレッドを塞がずINP/CLSに有利だ。JS必須でSSR注意が要ったGSAP ScrollTriggerのピン留めを、素のCSSで置き換えられる。

最重要のコツは「内側にstickyを掛ける」。カード外枠 .card は通常フローのまま高さを持たせ、内側の .card__content にだけ position: sticky; top: ヘッダー分 を付ける。こうするとラッパの高さ＝スクロール量が変わらず、スクロール距離が安定する。縮小は各カードに --index/--numcards を渡してレンジを 100%/N ずつ分割し、scale(calc(1.1 - 0.1 * var(--reverse-index))) で奥ほど小さくする。animation-fill-mode: forwards を忘れると区間通過後に元サイズへ戻るので注意。

対応状況（2026年8月）。Chrome/Edge 115+とSafari 26はscroll-driven対応済み、Firefoxは部分対応が入り始めた段階でまだBaseline未到達。未対応でもsticky部分は全モダンブラウザで動くので、縮小演出が外れるだけの自然フォールバック（プログレッシブエンハンスメント）になる。

落とし穴。祖先に overflow: hidden/auto/scroll があるとstickyが効かない（動かない時はまずこれを疑う）。top は固定ヘッダー高さに合わせないと隠れる。scroll連動は動きに敏感な人に強い違和感を与えるため、scale部分は必ず @media (prefers-reduced-motion: no-preference) で囲む（WCAG 2.3.3 に沿う）。

ひとことまとめ：stickyを土台に、加点だけscroll-drivenで足す二層設計。RSCのままJSゼロで重厚な演出が出せて、パフォーマンスにも優しい。
