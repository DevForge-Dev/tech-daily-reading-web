Flutter 3.48 / Dart 3.14 が beta 入り — 安定版 3.47 の到達点と、状態管理は“benchmark でなく team expertise で選ぶ”

3.48.0-0.3.pre（Dart 3.14 同梱）が 8/26 に pre-release。安定版は 3.47.2。土台は Impeller デスクトップ既定・Widget Previews stable・WasmGC。状態管理は新規=Riverpod 3.3、規制業界=Bloc 9 を基本線に、最後はチームの流暢さで決める。

📅 2026年9月9日 ⏱ 約3分 🔗 出典 4 件

今日の主役は Flutter 3.48 / Dart 3.14 の beta 入りだ。3.48.0-0.3.pre（Dart 3.14.0 同梱）が 2026-08-26 に pre-release となり、安定版に降りてくるのは年 4 回（2/5/8/11 月）サイクルで 2026 年 11 月の見込み。現行の安定版は 3.47.2 / Dart 3.13.x で、beta を試すなら flutter channel beta && flutter upgrade、戻すなら flutter channel stable。

土台は 3.47 系の到達点

Impeller が macOS/Windows/Linux のデスクトップでも既定になり、Widget Previews が stable、Dart 3.13 の primary constructors が正式化された。3.48 系はこの延長で WebAssembly（WasmGC）を Flutter Web の既定に近づける取り組みとビルド時間最適化を継続する。Web は --wasm で opt-in（dart:html → package:web 移行が前提）、macOS では Wide Gamut Color が既定だ。Impeller は iOS＋モダン Android（API 29+）で全 shader を build 時に AOT precompile し、shader compilation jank を排除して複雑アニメでも 120fps を維持する。

状態管理は benchmark でなく team expertise で選ぶ

今日の指針で刺さるのは「ライブラリの優劣より、チームの流暢さ・データフローの形・欲しい保証で決める」という考え方だ。BLoC に習熟したチームは、理論上クリーンでも Riverpod へ途中移行するより BLoC を継続した方が速く出荷できる。その上で基本線は——新規は Riverpod 3.0（3.3.x）を既定（compile-time safety・BuildContext 非依存の読み取り・最小 boilerplate・unified Ref・automatic retry）、監査証跡が要る規制業界（fintech/healthcare）や複雑並行は Bloc 9.0（on<Event> で typed event を処理し event-driven な audit trail を生成）。GetX は 12 ヶ月超で回避、Provider は既存アプリの保守が 2026 の共通見解だ。

パフォーマンス: フレーム予算と再ビルド削減

最も多い性能問題は不要な widget rebuild。プロパティ不変なら const で再ビルドを完全スキップ、大きな build() は分割、ref.watch(provider.select(...)) や BlocSelector で局所購読する。アニメする領域は RepaintBoundary で囲んで partial repaint に閉じ、重い計算は Isolate.run()/compute() で背景へ逃がす。計測は必ず profile モード（debug は JIT/assert で歪む）で DevTools を使う。フレーム予算は 60fps=16 / 90fps=11 / 120fps=8.3ms。

ひとことまとめ

beta の 3.48 は「大転換」より「Web の Wasm 化とビルド最適化を着実に進める」リリース。今すぐ動くべきは安定版 3.47 の土台活用で、状態管理はチームの現在地から選ぶのが最短だ。
