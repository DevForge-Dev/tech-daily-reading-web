11/5のNext.js — Cache Componentsと'use cache'（Next 16）：『デフォルト動的・明示キャッシュ』への反転とPPR統合

Next 16 で安定化した新レンダリングモデル。暗黙キャッシュをやめ、キャッシュしたいものだけ use cache でオプトインする。cacheComponents 一発で PPR/useCache/dynamicIO を束ねる設計を押さえる。

📅 2026年11月5日 ⏱ 約4分 🔗 出典 5 件

背景・なぜ今これか。 Next.js 16 で Cache Components が安定版になり（experimental.cacheComponents → トップレベル cacheComponents: true）、App Router のレンダリング/キャッシュの新しい既定路線になった。create-next-app の新規アプリでは既に有効。Next 16 を触るなら遅かれ早かれ向き合う土台なので、正しいメンタルモデルを持つ価値が高い。

何が新しいか：発想の反転。 〜15 は「デフォルトでキャッシュ/静的、動的APIに触れたらルート全体が動的」という暗黙のキャッシュだった（なぜ静的にならない/なぜ古いデータ、が分かりづらい）。16 は 「データ取得はデフォルト動的。キャッシュしたいものだけ use cache で明示オプトイン」に反転。粒度はページ/コンポーネント/関数で選べる。そして cacheComponents: true が ppr / useCache / dynamicIO を一括制御する統合フラグとなり、旧 experimental.ppr と experimental_ppr は撤廃された。

仕組み。 Next は静的HTMLの外殻（App Shell）をプリレンダして即配信し、動的コンテンツは準備でき次第ストリーミングする。use cache（対象は async 必須）を付けた結果はシェルに取り込まれ、毎回フレッシュが要るデータは use cache を付けず <Suspense fallback> で包む。最大の違いは、cookies() を読んでもルート全体は動的に落ちないこと。ランタイムAPIは Suspense 境界の内側に置くのが作法。

// next.config.ts
export default { cacheComponents: true, partialPrefetching: true }

// データ関数をキャッシュ可能に（必ず cacheLife を明示）
export async function getProducts() {
  'use cache'
  cacheLife('hours'); cacheTag('products')
  return (await fetch('https://api.example.com/products')).json()
}

落とし穴（重要）。 use cache スコープ内で cookies()/headers()/searchParams を読めない（next-request-in-use-cache）。制約は呼び出しスタックを辿って効くため、next build は通っても next start で落ちることがある——定石はキャッシュ外で読んで引数として渡す。未解決のリクエスト時Promiseをキャッシュに渡すと「プリレンダ中のキャッシュ充填がタイムアウト（約50秒）」。明示 cacheLife の無い外側キャッシュに短寿命キャッシュをネストするとビルド失敗。Node.jsランタイム必須（runtime='edge' は削除）、output:'export' は非対応。

再検証の使い分け。 updateTag(tag) は Server Actions 専用でタグを即時失効——次アクセスは古い値を返さずフレッシュ取得を待つ（フォーム送信→updateTag→redirect のように「書いた本人に最新を見せたい」場面）。revalidateTag(tag, profile) は Server Functions / Route Handlers 用で、再検証中は stale-while-revalidate で古い内容を配信（profile='max' 推奨、1年窓）。引数1個の revalidateTag(tag) は非推奨。

実務での型。 安定・共有可能なデータ（記事一覧・商品・ナビ）は use cache+cacheLife+cacheTag で静的シェルへ。ユーザー固有・毎回フレッシュな値は Suspense でストリーミング。ミューテーションは Server Action+updateTag、Webhookは Route Handler+revalidateTag(tag,'max')。すべての use cache に明示 cacheLife を付けるのが事故予防になる。

ひとことまとめ。 「キャッシュは引き算（暗黙に効く）から足し算（明示オプトイン）へ」。この一文を腹落ちさせれば、静的シェル＋Suspense と use cache の配置は自然に決まる。
