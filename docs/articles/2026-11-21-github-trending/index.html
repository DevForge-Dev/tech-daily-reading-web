今日のモメンタム3本は、Rust のコード移行ツール／Kotlin の Android プライバシーツール／Python のルールベース実証と、言語もジャンルも見事に割れている。共通点は、AI エージェント・スキル束に偏った当日トレンドに対し、いずれも「解きたい課題」と「提供する機能」が明快な多様性枠として増加率で突き抜けたこと。各リポジトリを課題と機能に分けて読む（★数・forks は実行時の api.github.com 実測）。

erkamyaman/rust-anything（Rust・⭐約6.6k）

解決したい課題：既存アプリを Rust へ書き換えるとき、「翻訳できたか」ではなく「書き換えが元と同じ挙動か」を保証するのが難しい。提供する機能：自分のアプリを一片ずつ Rust 化し、元の挙動を記録して各片をそれと照合しながら移行するツール。「コードを翻訳する」のではなく「同じ挙動であることを証明する」設計だ。CLI/HTTPサーバ/ライブラリを TS/Python/Go/Java 等から移行でき、Claude Code プラグイン・MCP Registry にも対応。なぜ今急上昇：created 2026-11-16＝作成約5日で⭐約6.6k（日平均約1,317★＝当日最速級）。「Rewrite in Rust」ミームに乗りつつ、録画した元挙動とバイト単位で照合する検証付き移行という新規性で急伸——v2.0 では Prettier を自前 Rust へ移植し19x高速・全runバイト一致というデモが拡散した。forks518・MIT。※open issues 1 は要確認だが整備状況から実体あり。

Eynnzerr/TelemetryCleaner（Kotlin・⭐約2.2k）

解決したい課題：国内向け Android 固件にプリインされたキャリア系テレメトリ（SystemHelper/RegService 等）はデスクトップ入口が無く、通常手段では静かな定時データ収集を止められない。提供する機能：これらのコンポーネントの導入状態・権限を検出し、免Root（Shizuku）でアンインストール・復元、クラウドソースで対応メーカー/パッケージ名を拡充する非AIプライバシーツール。なぜ今急上昇：created 2026-11-11＝約10日で⭐約2.2k（日平均約219★）。可視化・管理できる実用性が支持され、エージェント一色のトレンドで希少な Kotlin × 非AI システム/プライバシーの多様性枠。forks165・MIT（商用可）。

huggingface/pybot（Python・⭐約1.0k）

解決したい課題：重みも学習も使わない「LLM 以前」のルールベース・チャットボットを、エージェントでどこまで伸ばせるかは実証されていなかった。提供する機能：純 Python（if-else/正規表現/ルックアップ表）だけの bot を、1,000体超のエージェントが5,000版以上自作・評価して磨く HuggingFace 公式の実験プロジェクト。なぜ今急上昇：created 2026-11-12＝約9日で⭐約1.0k（日平均約114★）。SmolTalkBench の勝率を 0%→26%（SmolLM-360M-Instruct 級）まで押し上げ、約64万行のコード＋エージェント自作の55万行テストから成る規模と、インストール不要（Python 3.8+）で即実行できる手軽さが話題に。Apache-2.0。

まとめ：自分が試すなら

無人リサーチ運用の視点で一番効くのは rust-anything の“録画→照合”設計——「生成物が元と同じ挙動か」を自動検証する発想は、移行に限らず自動化パイプラインの回帰防止に応用が利く。pybot は「役割分担したエージェント群に大量の版を自作・評価させる」運用の生きた事例として、TelemetryCleaner は Shizuku で免Root に権限操作を行う Android 実装例として読む価値がある。3本とも許容的ライセンス（MIT / Apache-2.0）で手に取りやすい。
