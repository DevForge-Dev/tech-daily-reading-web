Code Review GA と v2.1.304 — PR自動レビューに「深度」と「組織一括」、判定の可観測性まで

レビューを速く、そして選べるように。Code ReviewのGA化、深度選択（Quick/Standard/Deep）、OTelによる判定の区別、mod権限の強化を一本で読む。

📅 2026年10月20日 ⏱ 約3分 🔗 出典 3 件

AIによるコードレビューが「試す機能」から「本番インフラ」へ移った週だった。Anthropicは2026年10月15日にClaude CodeのCode Reviewを一般提供(GA)に移行し、続く10/19のchangelog v2.1.304、10/15の v2.1.301 で、速度・深度・組織規模・可観測性の各軸が一気に埋まった。単発のアップデートというより、PR自動レビューを「どう運用するか」を設計できる段階に来た、と読むのが正しい。

何が新しいか

GA化の対象はClaude TeamとEnterprise。管理者がGitHubアプリを入れて対象リポジトリを選べば、以後は新規プルリクエストに対し開発者側の設定なしで自動レビューが走る。プレビュー期比で所要時間が約20分→6〜10分へ約3倍高速化し、指摘は「問題・発生条件・修正案」を数文で簡潔に示す形に改善された。

v2.1.304 では、そのレビューに深度(Quick / Standard(既定) / Deep)をリポジトリ単位で選ぶ設定と、GitHub組織内の全リポジトリを一括対象にするオプションが加わった。mods APIではツール承認の tool.check に decider:"person"(権限ダイアログかホストのコールバックだけがaskを承認できる)と e.isReadOnly が追加。/auto-mode-setup がBedrock/Vertex/Foundryなど非既定構成でも動くようになり、約43件の不具合(claude --worktree の未確認ブランチ削除、headlessの --max-turns 超過など)も修正された。

判定の「出所」が追えるようになった

地味だが効くのが v2.1.301 の可観測性。OpenTelemetryの tool_decision イベントに classifier_verdict / permission_mode / classifier_category が加わり、ツールの許可・拒否が「auto mode分類器の判定由来」なのか「権限ルール由来」なのかを分けて集計・監査できる(OTEL_LOG_TOOL_DETAILS=1 でマッチした組込ルール名も記録)。無人運用のリトライ制御用に CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS も追加された。

実務での使いどころ・注意点

Enterpriseなら、まず組織全リポにStandardを一括適用して底上げし、認証やインフラに触る重要リポだけDeepに引き上げる運用が素直。無人CIで危険な書き込み系ツールを走らせるなら decider:"person" で人の承認を必須にできる。止まった理由はOTelダッシュボードで分類器/ルールのどちらかまで追える。注意点として、GAはTeam/Enterprise限定、Deepは当然遅くなる、そしてEnterprise対象組織は2027/1/15までに最低1万ドル分のクレジットを請求でき(請求後30日で失効)る点は見落としやすい。

ひとこと：Code Reviewは「速度 × 深度 × 組織規模」の三軸で調整できる本番機能になった。まずStandardで全体を回し、Deepは絞って使うのが費用対効果の勘所。
