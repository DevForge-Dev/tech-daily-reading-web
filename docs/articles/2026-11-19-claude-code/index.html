Claude Code

Claude Code v2.1.327 が latest 昇格・CHANGELOG 正式掲載 — 自動実行の allow を締め、トークンと設定ファイルを守る堅牢化

昨日まで next 先行で中身が読めなかった v2.1.327 が本日 latest へ昇格し、CHANGELOG にも変更一覧が掲載（stable=v2.1.311）。mcp add-json のstdin読込、/status の壊れた設定一覧などの新機能に加え、PowerShell allow 無視・.mcp.json 他キー削除・WebFetch 長大URL拒否など、無人実行を安全側へ締める修正が本体。

📅 2026年11月19日 ⏱ 約4分 🔗 出典 4 件

Claude Code の版番号は、昨日まで『next 先行で中身が読めない』もどかしい状態だった。本日 11/19、その v2.1.327 が npm の latest へ昇格し、一次ソースである GitHub の CHANGELOG.md 先頭にも変更一覧がそろって載った（stable は v2.1.311）。つまり『版はあるが変更点が不明』の宙ぶらりんが解消し、ようやく内容を確定して読める日になったということだ。

何が新しいか

大半は修正だが、実務に効く追加がいくつかある。/install-github-app がリポジトリを変更する前に確認を挟むようになり、うっかり設定を書き換える事故を防ぐ。地味だが重要なのが claude mcp add-json <name> - ——server 定義の JSON を 標準入力（stdin）から読めるようになり、トークンをコマンドライン引数（＝シェル履歴）に残さずに登録できる。ほかに /status が『壊れた agent / skill / command / output style、効かないキーバインド、使えないサンドボックス、無視された権限、噛み合わない hook matcher』を一覧化、attributionProject で課金グループに名前を付与、非フルスクリーン描画に /tui classic の別名追加、など。

仕組みと落とし穴

安全系の修正が今回の肝だ。auto モードが .\scripts\build.ps1 * のような『.\ 始まりの PowerShell ワイルドカード allow ルール』を無視していた不具合が直り、意図した許可がきちんと効く。逆に claude mcp add / remove を project scope で使うと .mcp.json の $schema など他ツールのトップレベルキーを巻き添えで削除していたのも修正。さらに WebFetch は権限プロンプトの前に 2,000字超の URL を拒否、Remote Control の worktree モードはサーバ停止時に稼働中セッションの .env 等 git-ignored を消す不具合も直った。DevelopersIO（石川覚）の検証では、少し前の v2.1.325 で『サンドボックス内 Bash が既定で通常の権限フローに従う（＝確認が入る）』変更も入っており、従来のノープロンプト挙動に戻すには sandbox.autoAllowBashIfSandboxed: true が要る点に注意。

自分が試すなら

まず mcp add-json - での登録に切り替えてトークンを履歴から外す。次に /status を一度走らせ、積み上がった壊れた skill / hook matcher を棚卸しする——このスケジューラ群のように定期タスクが多い環境ほど効く。無人実行の allow ルールは PowerShell / 複合コマンドの挙動が変わっているので、v2.1.311（stable）運用なら更新後に一度 allow が意図通り効くか確認したい。

注意点

事例側は温度差を押さえておく。GoDaddy は約2,000人規模へ Bedrock 経由で展開しスプリントを約半減（ただし二次ニュース・AWS 事例の未確認引用）、一方 Uber は2026年 AI 予算が4か月で枯渇し主因は Claude Code と報じられた（半年前・The Information 由来の未確認値）。どちらも消費ベース課金のコスト管理が論点で、ツールの否定ではなく『予算設計の作り直し』として読むのが妥当だ。

ひとこと：今日の v2.1.327 は派手な新機能より『自動実行の allow を厳密化し、トークンと設定ファイルを守る』地味な堅牢化が本体。無人・定期運用の土台づくりに効く更新だ。
