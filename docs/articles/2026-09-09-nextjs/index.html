同一ドキュメント View Transitions でリスト変化を自動アニメ — FLIP 不要で追加/削除/並び替え/フィルタを補間

カード一覧・テーブル行・カンバン列の追加/削除/並び替え/フィルタを、DOM を更新するだけでネイティブに補間。FLIP の手測りも Motion 等のライブラリも要らない。鍵は view-transition-name の一意性と、React 側の flushSync。

📅 2026年9月9日 ⏱ 約4分 🔗 出典 4 件

リスト（カード一覧・テーブル行・タグ・カンバン列）の追加/削除/並び替え/フィルタを滑らかに見せる仕事は、これまで FLIP（getBoundingClientRect() で前後位置を測って transform で差分を打ち消す）や Motion / AutoAnimate といったライブラリの担当だった。ブラウザ標準の View Transitions API は、DOM を更新するだけで要素が旧位置から新位置へネイティブに補間され、消える要素はフェードアウト、現れる要素はフェードインする。手測りも transform 計算もライブラリも要らない。

仕組み: startViewTransition の 4 段階

document.startViewTransition(callback) は、(1) 呼ばれた瞬間に view-transition-name を持つ全要素の旧スナップショットを撮り、(2) callback 内で DOM を新状態へ更新し、(3) 新スナップショットを撮り、(4) 名前ごとに ::view-transition-group が旧→新の位置/サイズを補間し、その中で -old（フェードアウト）と -new（フェードイン）がクロスフェードする。旧新両方にある名前＝移動/モーフ、旧のみ＝退場、新のみ＝入場、という対応だ。

絶対条件: view-transition-name はスナップショット内で一意

旧または新のスナップショット内で同じ名前が 2 つ以上あると、ブラウザはどれを補間すべきか決められず、トランジション全体を黙ってスキップして warning を出す（部分失敗ではなく全無効）。リスト項目には必ずアイテム ID を含む一意名を付ける——style={{ viewTransitionName: 'row-' + item.id }} のように名前空間プレフィックス＋一意 ID が定石で、使い回しは最頻出の破損原因だ。

Next.js（App Router）での組み込み

トリガーはクライアント state 変化なので、リスト UI は 'use client' の島に隔離し、データ取得は RSC のまま props で流し込む。View Transitions はブラウザ上の更新時のみ発火するため SSR に無影響で hydration mismatch も起きない。React は DOM 更新が非同期なので、callback 内で flushSync(() => setState(next)) を使い、同期的に新状態を反映してから新スナップショットを撮らせる（これを怠ると「更新前の DOM」が撮られアニメが壊れる）。

function withViewTransition(update) {
  if (!document.startViewTransition) return update();   // Firefox 等はフォールバック
  document.startViewTransition(() => flushSync(update));
}

注意点・落とし穴

名前は動くものだけに絞る——名前付き要素が多いほど合成コストが増え、100 行同時アニメは jank になる（仮想化リストは画面内のみ名前付け）。アニメ中の旧/新画像は置換画像なのでホバー等が一瞬効かない。prefers-reduced-motion はワイルドカード ::view-transition-group(*) 等で animation:none にし、状態変化自体は残す。Level 2 の types と view-transition-class を使えば「並び替えの時だけ」の演出や一群への共通アニメも書ける。

ひとことまとめ

リストの動きは、もうライブラリの独占領域ではない。一意名と flushSync さえ押さえれば、依存ゼロで「並び替えて滑る／フィルタで詰めて動く」が既定の挙動として無料で手に入る。
