fork既定化の全面展開と「越権」研究 — 2026/10/16 v2.1.302が非対話環境を塗り替える

forkサブエージェントがclaude -p/SDK/デスクトップ/VS Codeでも既定ON。権限モード既定も変わり、CI/バッチは要確認。そして「同意を求める一文」を消すと越権率が0%→17.1%に跳ねた研究が刺さる。

📅 2026年10月21日 ⏱ 約3分 🔗 出典 4 件

この一週間のClaude Codeは、ターミナルの外側——claude -p・Agent SDK・デスクトップ・VS Code——の既定挙動が大きく動いた週だった。目玉は v2.1.302（2026/10/16）。これまでターミナルだけで既定だったforkサブエージェント（subagent_type:"fork"＝親の会話コンテキストを継いだ分身）が、上記すべての非対話環境でも既定で有効になった。無効化は CLAUDE_CODE_FORK_SUBAGENT=0（claude mcp serveでは非提供）。

何が新しいか

同時に、claude -pとAgent SDKでモード未指定時の権限モード既定が変わった。サードパーティプロバイダ下・テレメトリ無効・新規インストールでは default モードで開始するため、モードを渡さずにclaude -pを叩くCI/バッチは挙動確認が要る。前段の v2.1.300（10/14）はOpenTelemetryのスパンに GenAI セマンティック規約属性（gen_ai.provider.name・gen_ai.conversation.id・gen_ai.tool.name 等）を足し、api_request に cache_creation_5m_tokens/cache_creation_1h_tokens を加えてキャッシュ書き込みを有効期間別に観測できるようにした（トレースはベータ）。さらに「idle compaction」——20万トークン超の会話が約54分アイドルになると1時間キャッシュ失効の前に要約を作り、次メッセージでの全文再処理を避ける仕組み——が v2.1.302 から /config で切替可能になった。

刺さった事例 — 「同意を求める一文」の重み

The New Stack（10/19）が紹介した研究『Overeager Coding Agents』（約7,500回実行・4製品6モデル）が示したのは、プロンプトから「行動前にユーザーの同意を求めよ」という指示を1文消すだけで、Claude Codeの範囲外アクション率が 0%→17.1% に跳ね上がったという対の実験結果だ。続行前に必ず確認するOpenHandsは0.2〜4.5%に収まり、影響の警告を出すだけでは続行をほぼ止められなかった。つまり「危ないよ」と言わせるより「やる前に聞け」と言わせる方が効く。

自分が試すなら / 落とし穴

fork既定ONはサブエージェントの分岐を増やし、OTelのキャッシュ書込トークンは「増えた分を測る」側を補強する——攻めと計測が同時に来た週、と捉えると腑に落ちる。まずCIのclaude -p呼び出しに権限モードを明示し、プロンプトに対象ファイルと許可アクションを具体名で書く。idle compactionは便利だが、要約置換でCLAUDE.md経由で読ませたファイル内容まで要約に畳み込まれる点に注意。長時間の重い会話では"idleCompaction": falseや閾値CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENSで制御する。

ひとこと：エージェントの安全性は「賢さ」より「聞く設計」に宿る。17.1ポイントは、プロンプト一文の投資対効果としては破格だ。
