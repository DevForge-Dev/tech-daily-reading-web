Flutter 3.47 現行安定 — Impellerがデスクトップ3OSで既定レンダラに、Dart 3.13でprimary constructors安定化。状態管理は新規Riverpod 3.3.1/監査Bloc 9.1.1

現行安定はFlutter 3.47.1/Dart 3.13.1。ImpellerがmacOS/Windows/Linuxのデスクトップ3 OSで既定レンダラに昇格し、build時AOTシェーダーでshader compilation jankを排除。Widget Previewsはstable、Dart 3.13はprimary constructorsを安定化。状態管理の基本線は新規＝Riverpod 3.3.1＋codegen、監査/規制＝flutter_bloc 9.1.1(bloc 9.2.x)＋hydrated_bloc。

📅 2026年9月6日 ⏱ 約3分 🔗 出典 3 件

今日の主役は現行安定 Flutter 3.47.1 / Dart 3.13.1 の描画とパフォーマンスまわりだ。昨日はUIライブラリのstandalone分離を扱ったので、今日はレンダラとフレーム予算、状態管理の基本線に絞って整理する。

何が新しい/重要か

最大の変化は Impeller が macOS/Windows/Linux のデスクトップ3 OSで既定レンダラに昇格したこと(iOS=Metal / Android=Vulkan は従来どおり)。Impellerは 全shaderをbuild時にAOTでコンパイルするため、アニメーションのトリガ時にシェーダーを組み立てる必要がなく、長年の悩みだった shader compilation jank を排除できる。Widget Previews が stable になり、Dart 3.13 は primary constructors を安定化、pub workspace や tree-shaking も改善された。Web は experimental で Wasm の deferred loading が追加され、dart:html → package:web への移行が前提になる。

パフォーマンスの軸 — フレーム予算

2026のフラッグシップは90/120Hzが主流で、1フレームの持ち時間は 60fps=16ms / 90fps=11ms / 120fps=8.3ms。最も多い性能問題は不要なwidget rebuildで、プロパティが変わらないなら const を付けて再ビルドを完全スキップし、大きな build() は小さなwidgetに分割する。重い演出は RepaintBoundary で再描画を隔離。計測は必ず profileモードのDevTools(Performance/Memory/Network)で行う——debugはJIT/assertで数値が歪む。

状態管理の基本線

新規プロジェクトは Riverpod 3.3.1 ＋ codegen を既定に(compile-time safety・context-free reads・first-class async・自動リトライ)。監査証跡が要る規制業界(fintech/healthcare)は flutter_bloc 9.1.1(bloc 9.2.x)＋ hydrated_bloc で、events/states/business logicを厳格分離しevent-driven audit trailを残す。選定の要は「ツリー外でstateを読むか・チーム規模・asyncの量」。

ひとことまとめ：Impellerのデスクトップ既定化で初回ジャンクが減り、フレーム予算(8–16ms)を軸にconst徹底とprofile計測を回すのが2026の定石。状態管理は新規=Riverpod 3.3.1・監査=Bloc 9.1.1で確定。
