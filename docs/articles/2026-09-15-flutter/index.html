Flutter 3.48 / Dart 3.14 beta — Web の WasmGC 既定化が11月安定版の目玉、状態は Freezed 3.x × sealed で網羅

現行安定は3.47.x/Dart 3.13.x、いまは3.48/Dart 3.14がbeta。目玉はWebのWasmGCを既定コンパイルターゲットへ前進させ（flutter build web --wasm、dart:html→package:web移行が前提）初期ロードを短縮する点。状態はFreezed 3.x×sealed classesでswitch網羅、新規はRiverpod 3.3.1・監査はBloc 9.0が定番。

📅 2026年9月15日 ⏱ 約4分 🔗 出典 3 件

Flutter は年4回（2/5/8/11月）の機能リリースサイクルで、次の安定版は2026年11月見込み。現行安定は Flutter 3.47.x / Dart 3.13.x（3.47.0 は 2026-08-12）で、いまは Flutter 3.48 / Dart 3.14 が beta。11月に何が降りてくるかは、この beta の中身を見ると輪郭がつかめる。今日の主役はその Web の大転換だ。

何が新しい/重要か — WasmGC が Web の既定へ

beta の目玉は Web ターゲット。WebAssembly（WasmGC）を既定のコンパイルターゲットへ前進させ、flutter build web --wasm で opt-in できる。狙いは初期ロード短縮と JS ブリッジの縮小で、前提として dart:html → package:web への移行が必要になる。あわせて不要な SwiftPM スキームの早期除外などでビルド時間も最適化。3.47 系の到達点だった material_ui / cupertino_ui 1.0 の standalone 化、Impeller の全デスクトップ既定、Widget Previews stable の上に積み上がる格好だ。試すなら flutter channel beta && flutter upgrade、戻すなら flutter channel stable。

仕組み — 状態は Freezed 3.x × sealed で網羅

設計面の2026の定番は Freezed 3.x × sealed classes。状態を Loading/Data/Error のような代数的データ型（ADT）で表すと、copyWith・==/hashCode が自動生成され、UI 側は Dart 3 の switch で分岐漏れを compile-time に検出できる。新しい variant を足すと未処理をコンパイラが指摘してくれるのが効く。

状態管理の既定線は、新規は Riverpod 3.3.1＋@riverpod codegen（compile-time safety・context-free reads・first-class async）、監査/規制が絡む大規模は Bloc 9.0（on<Event> の event-driven audit trail、永続化は hydrated_bloc）。どちらも Freezed の sealed state と自然に組み合う。アニメーションは差し替えに AnimatedSwitcher、画面遷移に PageRouteBuilder の transitionsBuilder を宣言的に。

実務での使いどころ・注意点

まずは新規画面の状態を Freezed の sealed で切り、switch 網羅で握る型を作りたい。AnimatedSwitcher は切り替え対象に一意な Key を付けないと Flutter が同一 widget とみなし遷移が起きないのが定番の落とし穴。パフォーマンスは画像を cacheWidth/cacheHeight（内部は ResizeImage）で表示サイズにデコードし、写真は WebP、計測は必ず profile モードで（debug は JIT/assert で歪む）。フレーム予算は 60fps=16／90fps=11／120fps=8.3ms。

ひとことまとめ

11月安定版へ向けた「Web の作り替え」回。WasmGC 既定化で初期ロードを削り、状態は Freezed sealed＋switch で堅く、画像デコードとフレーム予算で 120fps を守る——beta のうちに --wasm を素振りしておきたい。
