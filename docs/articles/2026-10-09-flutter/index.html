Material/Cupertino が SDK から独立 — material_ui / cupertino_ui 1.0 移行が本番化

変わるのは import 元だけ。3.50（11月）の旧ライブラリ deprecation 前に dart fix で済ませたい。

📅 2026年10月9日 ⏱ 約3分 🔗 出典 3 件

DevCon 2026 最終日（10/9）に、長く予告されてきた大きな構造変更が本番化した。Material / Cupertino が SDK から独立し、material_ui / cupertino_ui 1.0 への移行が実運用フェーズに入る。import 'package:flutter/material.dart'; が import 'package:material_ui/material_ui.dart'; に変わる——が、シンボル名・クラス名は不変で、変わるのは import 元だけというのが最大の要点だ。

なぜ分離するのか。両パッケージ1.0は Flutter 3.47 に同梱され、中身は3.44で凍結されたフレームワークコードに一致する。SDK本体から切り離すことで、デザインライブラリを SDK と独立したペースでリリースできるようになる。SDK内蔵の旧 Material/Cupertino は次期stable（3.50・2026年11月）で正式 deprecation 予定なので、移行は"いつか"ではなく今期の宿題だ。

互換ブリッジと落とし穴。旧 import のままの3rd-party依存があるときは MaterialApp.builder で MaterialUiCompatibilityBridge(child: child!) を噛ませる。ただしこれは Theme/Localization を注入するだけで型不一致は直さない——ColorScheme や FloatingActionButtonLocation などを旧 package:flutter/material の値のまま新パッケージ型の引数に渡すことはできず、その依存は先に移行が必要だ。ローカライズは flutter_localizations のデザイン部が分離され、localizationsDelegates は GlobalMaterialLocalizations.delegates 1行で済むようになった。

同じ日のもう一つの主役＝デスクトップの Impeller 既定化。3.47 で macOS（Metal）/ Windows・Linux（Vulkan）でも Impeller が既定レンダラに昇格した。シェーダをビルド時に事前コンパイルするため、初回アニメ時の shader compilation jank が構造的に消える。アニメーションも AnimationController 不要の TweenAnimationBuilder（任意値の1回遷移）や AnimatedSwitcher（widget入替のクロスフェード）で軽く書ける。

現行バージョンと今後。安定は Flutter 3.47.5 / Dart 3.13.4、beta は 3.49系。3.50（11月）では Web の WasmGC 既定化・Android の Impeller 一本化も入る。ひとこと：import を書き換えるだけの"痛くない破壊的変更"。3.50で旧ライブラリが deprecation になる前に、dart fix で一気に済ませておきたい。
