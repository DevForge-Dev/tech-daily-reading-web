11/1のFlutter — Flutter 3.50 Web WasmGC既定を実測。skwasm/CanvasKit自動選択・対応ブラウザ行列・cross-origin isolationの罠

stable 3.47.9 / beta 3.50.0-0.3.pre(10/29)。--wasmはdart2wasm+skwasmとdart2js+CanvasKitを同時出力し全ブラウザで動く。Chromium=既定Wasm、Safari/FirefoxはallowList明示。COOP/COEP未設定だと速くならない。

📅 2026年11月1日 ⏱ 約3分 🔗 出典 3 件

背景・なぜ今これか。現況は stable 3.47.9 / Dart 3.13.7、beta 3.50.0-0.3.pre / Dart 3.14.0(ともに 10/29)。11月 stable の 3.50 はまだ未公開だが、目玉の Web WasmGC 既定を昇格前に beta で実測できる段階だ。今回は概念でなくビルド/配信の具体手順を押さえる。

何が重要か——二系統の同時出力。flutter build web --wasm は dart2wasm＋skwasm を出すが、フォールバックの dart2js＋CanvasKit も同じ build/web に同時出力するので全ブラウザで動く。起動時に flutter_bootstrap.js が WasmGC・JS String Builtins・例外ハンドリング Phase4 の3機能を判定し、wasmAllowList を見て Wasm 版を選ぶ(下図)。実行版の判定は const bool.fromEnvironment('dart.tool.dart2wasm')。

対応ブラウザ行列(3.50)。Chromium 137+(Chrome/Edge/Opera/Brave)は --wasm で既定 Wasm、WebKit(Safari)26.2+ と Gecko(Firefox)147+ は既定フォールバックで wasmAllowList:{webkit:true}／{gecko:true} を明示指定して有効化する。遅延ロードは既定オフ＝--enable-wasm-deferred-loading、レガシー web ライブラリ(dart:html/dart:js 等)は Wasm 非対応で --no-deprecated-js-interop によりコンパイル時に検出できる(無指定でも dry-run で非致命警告)。

実務での落とし穴。最大の罠はマルチスレッド描画に cross-origin isolation が必須な点。Cross-Origin-Opener-Policy: same-origin＋Cross-Origin-Embedder-Policy: credentialless(または require-corp)を配信側で設定しないと複数スレッドで動かず、「skwasm にしたのに速くならない」の典型原因になる。本番デバッグには --source-maps でシンボル化、--no-strip-wasm は関数名を残せるがバイナリ約47%肥大するので常用は避ける。

ひとことまとめ。3.50 Web Wasm は「--wasm は Wasm と CanvasKit を両方吐くので安全」「Safari/Firefox は allowList 明示で有効化」「COOP/COEP 未設定だと速くならない」の3点が実務の核。昇格前に beta でこの3点を配信環境ごと検証しておけば、stable 昇格日に慌てずに済む。
