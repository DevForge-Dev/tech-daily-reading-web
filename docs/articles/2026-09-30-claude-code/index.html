Claude Code v2.1.286/285 — 権限UIの可視化と設定ガバナンス、7層スタックで捉える運用

派手な新機能より“運用の地固め”。件数表示・拡張思考の保持・WebFetch無効化・allowedProviders で、長時間・無人・組織規模の運用に耐える足場を固める2連続リリース。

📅 2026年9月30日 ⏱ 約4分 🔗 出典 5 件

9月末のClaude Codeは、派手な新機能より「運用の地固め」に寄った2連続リリースだった。無人のスケジュール実行や組織導入が当たり前になった今、効いてくるのは“安全に回り続ける”ための細部だ。

2連続リリースの中身

v2.1.286（9/30）はUIと安定性が主役。権限リクエストが溜まると「5件中2件」のように件数を表示し、フルスクリーン一覧の「他N件」行をマウス操作できるようになった。拡張思考（extended thinking）ブロックがモデル切替や再開セッションをまたいでも保持され、artifact公開はデザイン計画を返信ではなくページ本体へ書き込む。修正も厚く、gcp/awsの認証リフレッシュが重複ログインを開く不具合、--resume/--continueがバッチ並列ツール後にターンを落とす不具合、そしてMCPサインイン資格情報がエラーメッセージに露出する不具合などが潰れた。

v2.1.285（9/29）は設定・運用系の拡充。環境変数CLAUDE_CODE_DISABLE_WEB_FETCHでWebFetchを無効化、claude --desktopで現ディレクトリをデスクトップ版で開き、claude plugin configureと.mcpbの<server>.<key>=<value>構文でインストール時に設定値を渡せる。管理設定allowedProvidersでマシンが使えるAPIプロバイダを制限できる。SDKの遅延ツール喪失やstdio MCPの残留、クラウドセッション再起動後のartifact更新拒否も修正された。

スタックとして捉え直す

個々の機能を点で覚えるより、MCP（外部接続）/CLAUDE.md（記憶）/Skills（統合拡張）/サブエージェント（並列専門家）/Hooks（自動化）/Plugins（配布）/スケジュールタスクの7層スタックで捉えると使い分けが早い。静的知識はCLAUDE.md、再利用ワークフローはSkills、文脈分離が要る深掘りはサブエージェント、規則の強制はHooks（exit code 2でブロック）、定期処理はスケジュールタスク、という割り当てだ。

自分の運用にどう効くか

無人運用ではallowedProvidersとCLAUDE_CODE_DISABLE_WEB_FETCHで“暴走の芽”を事前に閉じ、SubagentStopの品質ゲート（型チェック・テスト）で成果物を担保するのが現実解。CLAUDE.mdは「消しても困らない指示は削る」で簡潔に保ち、知識はSkillsへ逃がす——30人組織の導入事例では800行超でSkill起動率が40%低下し、「400行上限」をPRレビューで強制していた（90日で監査19→41、生産性+35%）。

注意点

件数表示やマウス操作は便利だが、無人実行では結局--allowedToolsと--output-format jsonの併用が安全弁になる。資格情報露出の修正が入った点からも、ログやエラー出力を外部へ流す運用は最新版への追従を前提にしたい。なお「本番コードの80%はClaude」「企業採用でAnthropicがOpenAIを初逆転」といったニュースは勢いを示すが、検証ガードレール（CIのAIレビュー層が本番バグの約1/3を捕捉）とセットで語られている点を忘れずに。

ひとこと：機能ラッシュ後の“締め”の回。可視化・保持・ガバナンスで、長時間・無人・組織規模の運用に耐える足場が整った。
