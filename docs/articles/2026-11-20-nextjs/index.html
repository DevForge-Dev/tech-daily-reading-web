動的OG画像は next/og の ImageResponse で焼く — Satori は「ブラウザではない」ことだけ先に飲み込む（Next.js 16 の params/ランタイム作法つき）

リンクを貼ったとき出る大きなOGカードを、ページ単位で自動生成する標準解が opengraph-image.tsx × next/og の ImageResponse。レンダラは Satori で、HTML/CSS→SVG→PNG に変換する別エンジン。grid は効かず flexbox 前提、という一点を知らないと「黙って崩れる」。

📅 2026年11月20日 ⏱ 約4分 🔗 出典 3 件

SNS や Slack にリンクを貼ると出る大きなカード画像（Open Graph 画像）は、クリック率に直結する「もう一つの UI」だ。ブログ記事や商品ページのようにページごとに中身が変わるサイトでは、全ページ共通の静的 PNG では足りず、タイトルや著者を焼き込んだ1枚をページ単位で生成したい。App Router はこれをファイル規約 opengraph-image.tsx ＋ next/og の ImageResponseで標準提供する。JSX をそのままサーバーで画像化できるのが最大の利点だが、Next.js 16 で params が Promise 化し、既定ランタイムが Node.js に寄ったことで、旧 @vercel/og 時代の Edge 前提サンプルとは書き方がずれてきた。

核心：レンダラは Satori＝ブラウザではない

ImageResponse の中身は Satori で、HTML/CSS → SVG → PNG に変換する専用エンジンだ。headless Chrome でもブラウザでもないので、CSS の一部しか解釈しない。公式が明言するとおり「flexbox と CSS の一部のみ対応、display:grid のような高度なレイアウトは効かない」。さらに calc()・CSS 変数・transform・アニメーションはエラーも出さず黙って無視され、「なんか違う絵」が出る。要素は基本 display:flex 前提で、子が2つ以上あるのに親に flex が無いと崩れる。ここを知らずに普段の CSS 感覚で書くのが一番の落とし穴だ。

Next.js 16 の作法 — params は await、ランタイムは書かない

動的ルートでは params が Promise になったので const { slug } = await params が必須（型は params: Promise<{ slug: string }>）。既定はビルド時生成＋キャッシュ（static optimization）で、cookies()/headers()/未キャッシュ fetch を使うと静的最適化が外れて都度生成になる。既知スラッグは generateStaticParams で全部焼けば実行時生成ゼロだ。ランタイムは Next.js 16 で runtime='edge' が非推奨になり、既定の Node.js で問題なく動く。これに伴いフォント読み込みも変わり、現行サンプルは node:fs/promises の readFile をモジュールスコープで一度だけ読む（リクエストに依存しない予測可能値だから）。Edge 時代の「関数内で毎回 fetch(new URL(...))」は不要になった。

export const size = { width: 1200, height: 630 }
const font = await readFile(join(process.cwd(),'assets/NotoSansJP-Bold.ttf'))
export default async function Image({ params }:{ params: Promise<{slug:string}> }) {
  const { slug } = await params
  const post = await getPost(slug)
  return new ImageResponse(
    <div style={{ width:'100%', height:'100%', display:'flex', flexDirection:'column' }}>{post.title}</div>,
    { ...size, fonts:[{ name:'Noto', data:font, weight:700 }] })
}

試すなら・注意

制限も押さえておく。バンドルは合計 500KB 上限（JSX・CSS・フォント・画像の総和）、フォントは ttf/otf/woff のみでパース速度優先なら ttf/otf。ページの generateMetadata に openGraph.images を書くとファイル規約の画像を上書きしてしまうので、「ファイル画像が出ない」ときはまず実際の og:image タグを疑う。確認は /blog/<slug>/opengraph-image を直接開けば PNG が見え、debug:true で要素境界を可視化できる。ユーザー入力をそのまま焼く用途では、過去に RCE 修正（16.3.6）も入っているため Next を最新に追従しておくこと。出力は静的 PNG なので prefers-reduced-motion 対応は対象外——動くものではない。

ひとこと：「ブラウザだと思って CSS を書かない」。flexbox だけで組み、grid と calc を捨て、og-playground で先に絵を固める——これだけで OG 画像生成の八割は安定する。
