Lottie / dotLottie を App Router で — Rust+WASM の新ランタイムと 'use client' 島の作法

デザイナー発アニメの標準 Lottie の土台が総入れ替え。@lottiefiles/dotlottie-react はコアが Rust→WASM・描画は ThorVG（WebGPU可）で、State Machine・テーマ・Web Worker を獲得。.lottie コンテナは JSON より最大80%小さい。完全クライアント専用ゆえ 'use client'＋ssr:false の島に隔離し、寸法固定と prefers-reduced-motion 対応をセットにするのが要点。

📅 2026年8月10日 ⏱ 約4分 🔗 出典 4 件

デザイナー発アニメの事実上の標準 Lottie を、Next.js App Router で今どう載せるか。土台が総入れ替えされた点が今回の肝だ。旧世代は Airbnb の lottie-web（純JS・SVG/Canvas）だがメンテはほぼ停滞し prefers-reduced-motion も長年未対応。新世代は LottieFiles の @lottiefiles/dotlottie-webで、コアが Rust → WASM、描画は ThorVG で Software/WebGL2/WebGPU バックエンドを持つ。React ラッパは @lottiefiles/dotlottie-react。

何が新しいか — .lottie コンテナと新ランタイム

dotLottie（.lottie）は Lottie を包むオープンなコンテナ（実体は Deflate 圧縮の ZIP）。1ファイルに複数アニメ・画像/フォント・State Machine・テーマ（slot）を同梱でき、JSON より最大80%小さい。新規は基本これを選ぶ。同一 Rust コアが Kotlin/Swift/WASM へ展開され iOS/Android/Web で挙動が揃うのも強み。旧新いずれもブラウザAPI（WASM/Canvas/window）依存＝SSR 不可な点は変わらない。

App Router での組み込み — 'use client' 島に隔離

Lottie は完全クライアント専用。Server Component に next/dynamic の ssr:false を直書きするとビルドエラー（ssr: false is not allowed with next/dynamic in Server Components）になる。定石は 'use client' ラッパを1枚挟むこと。ページ本体とデータ取得は RSC のままで、この島だけがクライアントになる。

// components/lottie-hero.tsx（クライアント島）
'use client';
import dynamic from 'next/dynamic';
const DotLottieReact = dynamic(
  () => import('@lottiefiles/dotlottie-react').then(m => m.DotLottieReact),
  { ssr:false, loading: () => <div aria-hidden style={{width:360,height:360}} /> }
);

性能・落とし穴・a11y

複数同時/多レイヤ/モバイルでは DotLottieWorkerReact（OffscreenCanvas）でレンダリングをワーカーに逃がす。既定でオフスクリーン自動フリーズ、DPR は実値の75%（網膜級が要る時だけ上げる）、IntersectionObserver で可視時のみロード。落とし穴はコンテナに幅・高さが必須（無いと何も出ない＝CLS 対策に寸法固定）、WASM の初回フェッチが初期表示コスト、.json より .lottie 優先。そして最重要の a11y——Lottie は既定 autoplay かつ SR に何も伝わらないので、装飾は親を aria-hidden、意味を持つなら role="img"＋aria-label、prefers-reduced-motion: reduce では autoplay せず静止フレーム表示にする。

ひとことまとめ：新規は .lottie＋@lottiefiles/dotlottie-react を 'use client'＋ssr:false の島に隔離。寸法固定と reduced-motion 対応をセットで。
