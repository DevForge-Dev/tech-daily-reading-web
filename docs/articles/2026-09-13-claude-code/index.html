Claude Code

v2.1.269でclaude plugin eval — プラグインを採点しリリースゲートに、v2.1.270が最新

プラグインを『測れる』ようにする回。claude plugin evalが再現可能なスコアをJSON+HTMLで出し、Static/LLM Judge/Monte Carloの3層評価と併せて導入前に採点できる。Agent TeamsとSubagentsの棲み分けも整理する。

📅 2026年9月13日 ⏱ 約3分 🔗 出典 5 件

9月のClaude Codeは新機能の派手さより「品質を計測して運用に組み込む」方向に効く更新が続く。9/11の v2.1.269 でプラグイン評価が公式機能になり、9/12公開の v2.1.270 が9/13時点の最新版だ。あわせて出てきた3層評価フレームワークやAgent Teams/Subagentsの実践知と束ねて、いま押さえておきたい点を整理する。

何が新しい/重要か

v2.1.269 の目玉は新コマンド claude plugin eval。プラグインの eval スイートをClaude Codeに対して実行し、再現可能なスコア付き結果をJSONとHTMLレポートで出す。プラグイン無しのベースラインと挙動を比較できるので、そのままリリースゲートに使える。あわせて /output-style [name] で出力スタイルの一覧・切替ができ（Remote Control/ヘッドレス対応）、Bashツールがファイルを編集した場合は変更ファイルの差分がツール結果に併記されるようになった。v2.1.270 はその流れを汲む累積リリースで、CLI/VS Code/Web/Slackにまたがる信頼性・プロンプトキャッシュ・セッション周りの修正が積み上がっている。

仕組みと使い分け（Agent Teams vs Subagents）

評価と並んで実務で効くのが並列化の設計だ。Subagentsは独自のコンテキスト窓・システムプロンプト・限定ツール権限を持つ専用インスタンスで、最大の利点は文脈の保全。二度と見返さない検索結果やログを逃がせばノイズはその窓に留まり、本会話には結論だけが戻る。万能1体より範囲を絞った5〜7体のロースターが有効とされる。一方Agent Teams（CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1で有効化・実験的）は、共有タスクリストとteammate同士の直接メッセージで協働する点が違う。並列トラックを持つ大型機能やQAのスウォーム、対立仮説の検証に向く。

実務での使いどころ・注意点

自作プラグインがあるなら、まず claude plugin eval でベースライン比較を回し、CIのリリースゲートに載せたい。価値が高いのは自環境固有の知識（DBスキーマ・テスト規約・デプロイ手順・コーディング規約）をClaudeに与えるプラグインだと指摘されている。3層評価はStaticを常時、LLM JudgeをPR時、Monte Carloをリリース前、と段階配置すると費用対効果がよい。Agent Teamsは実験的なので、まずSubagentsで文脈保全の型を作ってから広げるのが安全。30人規模の組織では共有Skill22＋Hook11で4か月35%の生産性向上を維持した事例もあり、単発利用でなくワークフロー化が定着の鍵だ。

ひとことまとめ

「測って締める」回。eval でプラグインを採点し、3層で導入前に見極め、Subagents/Agent Teams で並列を設計する。毎日回すエージェント運用の品質保証が一段固くなった。
