TweenSequence：1本の Controller で複数 Tween を時系列に直列連結

公式定義は「複数の Tween の列で値が定まる Animation を作る」。11/7 に見た Staggered（1つの controller を Interval で並行分割）と対をなし、TweenSequence は同一プロパティを区間ごとに別 Tween で“直列”に動かす（例＝膨らむ→一拍止まる→縮む）。構成は TweenSequence<T>(List<TweenSequenceItem<T>>) で、各要素 TweenSequenceItem(tween:, weight:) の weight がその区間の長さを決める。weight は任意スケールの相対値で、合計が100である必要はなく比率だけが効く。

final seq = TweenSequence<double>([
  TweenSequenceItem(
    tween: Tween(begin: 5.0, end: 10.0).chain(CurveTween(curve: Curves.ease)),
    weight: 40.0),
  TweenSequenceItem(tween: ConstantTween(10.0), weight: 20.0),  // 止める
  TweenSequenceItem(
    tween: Tween(begin: 10.0, end: 5.0).chain(CurveTween(curve: Curves.ease)),
    weight: 40.0),
]).animate(controller);   // controller.drive(seq) でも可

生成は .animate(controller) で Animation<T> 化し、表示は AnimatedBuilder 内で .value を読む。使い分けは——同一プロパティを順番に多段変化→TweenSequence、別プロパティを時差で並行→Staggered（Interval）、2値のクロスフェード→AnimatedCrossFade。先頭↔末尾を反転した逆向きが要るなら FlippedTweenSequence がある。

実務でもう一本：画像メモリ最適化（握りすぎが jank/OOM の主因）

画像は原寸でデコードすると巨大で、表示が小さくても原寸ビットマップが ImageCache に乗る。Image(cacheWidth:/cacheHeight:) は公式いわく「指定サイズでデコードさせる」指示で、目的は「主に ImageCache のメモリ使用量を減らすこと」（画面表示サイズ自体は layout/width/height が決め、cacheWidth とは独立）。cacheWidth を直書きできない provider（FileImage/NetworkImage 等）は ResizeImage(provider, width:, height:) で明示的に包んでデコード寸法を制御する。

あわせて precacheImage(provider, context) で遷移先ヒーロー画像など数枚を先読みすると初回のちらつきを抑えられるが、公式警告どおり大量に pin するとメモリ枯渇で OS に kill され得るので数枚に留める。DI 周りでは今日の素材に get_it（service locator）＋injectable（アノテーションから登録コードを codegen）も挙がっており、“何を注入するか=get_it、状態をどう監視するか=Riverpod/Bloc”で併用するのが自然だ。

ひとことまとめ

アニメは「同一プロパティを直列に動かすなら TweenSequence、並行なら Staggered」で棚卸し。画像は「表示相当にデコードして ImageCache を削る」が握りすぎ対策の一丁目一番地。どちらも “速くする前に無駄を生まない” 側の定石だ。※版は pub.dev/公式ドキュメント現行表示で、採用前に最新を確認。
