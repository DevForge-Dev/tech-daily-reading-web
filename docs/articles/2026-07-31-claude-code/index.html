Claude Code

Opus 5 が既定Opusモデルに — 1Mコンテキスト・128K出力で価格据え置き、MCPはステートレス・コアへ

claude-opus-5 が Claude Code の既定Opusに。1Mコンテキスト/128K出力/thinking既定オンで価格は据え置き。MCP 2026-07-28 はステートフルからrequest/responseのステートレス・コアへ移行し、リモートMCPのデプロイが容易になった。

📅 2026年7月31日 ⏱ 約2分 🔗 出典 4 件

Opus 5 が Claude Code の既定Opusモデルに組み込まれ、エージェント的コーディングとコンピュータ操作の性能を底上げした。関心はモデル選定よりも「1Mコンテキストと effort をどう運用に落とすか」へ移っている。

何が新しいか：Opus 5（claude-opus-5）はコンテキスト1Mトークン（既定かつ最大で小型版なし）・最大出力128Kトークン・thinking既定オン。価格は入力$5／出力$25（100万トークンあたり）と Opus 4.8 から据え置きで、性能だけが上がった。ただし既定の解決先はプランで割れる：Max/Team Premium/Enterprise従量/API は Opus 5、Pro/Team Standard は引き続き Sonnet 5。もう一つの目玉が MCP 2026-07-28 で、双方向ステートフルからrequest/responseのステートレス・コアへ移行し、サーバレスやエッジ基盤に載せやすくなってリモートMCPサーバのデプロイ・スケールが大幅に容易になった。認可も Entra/Okta 等の企業ID基盤と整合する形に整理された。

仕組みの噛み砕き：effort レベルは思考の深さ＝コスト/レイテンシと品質のトレードオフを握る。難しい設計・デバッグは高effort、定型作業は控えめ、が定石だ。運用面の後押しとして7月のチェンジログでは sandbox.network.strictAllowlist（許可リスト外ホストを無プロンプトで拒否）、スクリーンリーダー対応、--forward-subagent-text（サブエージェントの出力を stream-json に含める）が入った。

実務での使いどころ：1Mコンテキストを活かし、大規模リポジトリを丸ごと文脈に載せた設計レビューや横断リファクタが現実的になる。Microsoft の数万人規模フィールド研究では CLI エージェント採用者が約24%多くPRをマージし、普及は社内ソーシャル経由——チーム導入は「隣の席のデモ」が効く裏づけだ。注意点：Pro/Team Standard は既定が Sonnet 5 なので、Opus 前提の手順書をそのまま配ると挙動が変わる。thinking 既定オンでトークン消費が増えるため、定型作業は effort を絞る。ひとことまとめ：モデルは速く賢くなった。差がつくのは effort とコンテキスト設計の運用側だ。
