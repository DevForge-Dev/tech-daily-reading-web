11/28も新バージョンなし — v2.1.330『easel』チャートと定期タスク/loop 30日化、第三者クラウドの auto モード拡大を振り返る

npm dist-tags 一次確認で latest=next=v2.1.332 据え置き（stable=v2.1.326）。本体の新リリースは11/24以降ない日なので、直近リリースの“見落としがち”を復習する。v2.1.330 は内蔵チャートモッド『easel』を足し、定期タスクと /loop の最長稼働を7日→30日へ延長。v2.1.328 は Bedrock/GCP/Foundry など第三者プロバイダへ auto モードを拡大し、v2.1.327 は標準入力からサーバを登録する claude mcp add-json <name> - を追加した。

📅 2026年11月28日 ⏱ 約4分 🔗 出典 4 件

本日（JST 11/28・土）も Claude Code 本体の新バージョンは無い。npm レジストリの dist-tags を一次確認すると latest＝next＝v2.1.332（2026-11-24 公開）、stable＝v2.1.326 で、いずれも前日から変化なし。直近の公開履歴は v2.1.330(11/20)→v2.1.331(11/23)→v2.1.332(11/24) で、11/24 以降は本体の新リリースが止まっている。リリース面の新事実が乏しい日なので、ここでは直近リリース（v2.1.327〜330）の見落とされがちな要点を棚卸しする。

何が新しいか：直近リリースの“効いてくる”3点

第一に v2.1.330 の内蔵チャートモッド『easel』。要求時や MCP メトリクスの結果に応じてチャートを描く機能で、Pro/Max および対象の Team/Enterprise、macOS/Linux で使える（自動チャートは /config で無効化可）。第二に、定期タスク（recurring tasks）と /loop のウェイクアップが、セッション稼働中に最長30日まで延長された（従来は7日。記事時点でドキュメントは7日表記のまま、との指摘あり）。第三に v2.1.327 の claude mcp add-json <name> -——標準入力からサーバ JSON を読み込み、トークンをコマンド履歴に残さず登録できる（ただし Claude Code セッション内からは実行不可）。※リリース要点の一部は二次情報（aiparabellum／dev.to）に基づく。

仕組み・セキュリティ：auto モードが“自前契約”を離れた

運用に最も効くのは v2.1.328 の auto モード拡大だ。これまで実質 Anthropic 直 API 前提だった auto モード（危険度の低い操作を自動承認）が、Amazon Bedrock・Google Cloud Agent Platform・Microsoft Foundry・Claude apps ゲートウェイ上の Opus 4.6／Sonnet 4.6 でも使えるようになり、権限モード未指定の対話セッションは auto で開始する。裏を返せば“今まで都度確認だった環境が黙って自動承認に変わり得る”ので、確認を残したいなら permissions.defaultMode を明示設定する。あわせて v2.1.330 ではセキュリティも強化され、root/ホーム/作業フォルダを狙う rm の多くが承認を要求し、応答者がいなければ拒否、ファイルツールは .credentials.json への書き込みを拒否するようになった（※二次情報）。

事例：Anthropic『Working with AI』企業導入調査

事例面では、Anthropic の定性研究『Working with AI』（2026-11-23）が目を引く。法務〜物流の58社・66インタビューを対象に、生成AI／コーディングエージェントの実務導入を聞き取った調査（労働力センサスではない）。報告によると、AI 主因の国内レイオフはごく少数にとどまる一方、約3分の2の企業が採用を抑制し、一部は外注（多くはオフショア）を削減。非技術者が作った「ソフトウェア成果物」100件を分類すると、約8割が手作業（表計算・議事録・運用トラッカー等）の自動化、約2割が購入 SaaS の置換だった。最大の壁は「レビューしきれない AI 出力量」で、価値はツール導入そのものより業務の再設計（reorganization）から生まれる、と結論づける。※数値は二次報道の紹介に基づき一次（anthropic.com）で要確認。

実務での使いどころ・落とし穴・ひとこと

自分の定期タスク運用に引きつけると、効くのは2点。ひとつは 定期タスク/loop の30日化で、長く回すスケジュール運用の設計余地が広がること。もうひとつは auto モードの既定化——第三者クラウド経由なら permissions.defaultMode を一度棚卸しし、「確認が出ると思っていた操作が自動承認されていた」を防ぐ。落とし穴は、本稿のリリース要点が一部二次情報に拠ること——版数・挙動は公式 CHANGELOG を正とする。新バージョンが無い日の学びは「機能より“承認と稼働時間の既定”が変わった」ことだ。
