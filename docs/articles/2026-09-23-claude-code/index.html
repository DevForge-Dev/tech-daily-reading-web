v2.1.280でOpus 5.5が既定Opusに — 1Mコンテキスト＆$4/$20、Pro/Team Standardの既定もSonnet→Opusへ

9/22公開のv2.1.280は新モデルClaude Opus 5.5を既定Opusに据え、Pro/Team Standardの既定もOpusへ統一。キャッシュ・セキュリティ・MCP周りの修正も入った大型リリース。

📅 2026年9月23日 ⏱ 約4分 🔗 出典 4 件

Claude Code の日次追跡で、9/22 公開の v2.1.280 は久々の大型リリースとなった。目玉はモデルそのもので、新世代の Claude Opus 5.5（claude-opus-5-5）が「既定の Opus」に昇格し、あわせて Pro・Team Standard プランの既定モデルまで Sonnet から Opus へ引き上げられた。ここ数日「カスタマイズ手段の整理（CLAUDE.md/Skills/Subagents…）」といったソフトな話題が続いていたので、モデル世代とプラン既定が同時に動いたのは節目として大きい。

何が新しいか — Opus 5.5 が既定、Pro/Team Standard も Opus へ

Opus 5.5 は 100万トークン（1M）のコンテキストを備え、価格は 入力 $4 / 出力 $20 per MTok（キャッシュ読み出しは $0.20/MTok と割安）。従来は上位（Max・Team Premium・Enterprise）だけが既定 Opus だったが、今回 Pro と Team Standard の既定も Sonnet→Opus に統一され、既定でより賢いモデルが走る構図になった。UI 面でもフルスクリーン時の /skills 一覧のホイールスクロールなどマウス操作が拡充され、ダイアログのキー処理（Ctrl+C/D の二度押し、y/n 誤爆）も直っている。

安定性・セキュリティ・MCP 周りの修正

地味だが実務に効く修正も多い。ホストアプリからのモデル切替で次プロンプトのプロンプトキャッシュが外れる問題、シンボリックリンク経由でファイル書き込みが誤って許可されるセキュリティ問題を是正。MCP ツール説明・サーバー指示の 2,048 文字上限を CLAUDE_CODE_MAX_MCP_DESCRIPTION_LENGTH で変更できるようになった。加えて ~/.claude/skills/ のスキルが manifest.json の記載でゴミ箱に移動されるバグや、自動モードが無回答時に無限リトライする挙動も直っている。

あわせて読みたい：4プリミティブの使い分け

同日の技術記事では、Skills / Subagents / Hooks / Workflows を「現行モデルが単独で苦手な部分を補うもの」と捉え、症状で選ぶ指針が整理されていた。指示の反復は Rule、貼り付け手順は Skill（/deploy 等の動詞）、出力で文脈が溢れるなら Subagent へ委譲、必ず起きてほしい処理は Hook（exit code 2 でブロック）、多段検証は Workflow、という対応だ。

実務での使いどころ・自分が試すなら

まず既定 Opus 化のコスト影響を見たい。1M コンテキストは大きいリポジトリ横断で効く一方、$4/$20 は Sonnet より高いので、定期タスク側は必要な所だけ Opusに寄せ、軽い整形は下位モデルへ振り分けるのが現実的。MCP 説明の上限緩和は、説明が長い自作サーバーが切り詰められていた場合に効くので、CLAUDE_CODE_MAX_MCP_DESCRIPTION_LENGTH を上げて挙動を確認したい。

注意点・落とし穴

既定モデルが上がると1タスクあたりのトークン単価が上がる。多数の定期タスクを回している運用ほど請求に効くので、明示的にモデルを固定するタスクは意図通りか点検を。シンボリックリンク書き込みの修正はセキュリティ更新なので、できるだけ早く v2.1.280 へ上げるのが安全。

ひとことまとめ

「既定でより賢いモデルが走る」時代の節目。恩恵とコストは表裏なので、既定 Opus 化を歓迎しつつ、タスク単位でのモデル選択とコスト観測をセットで運用したい。
