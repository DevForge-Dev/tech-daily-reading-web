11/6のClaude Code — 静かな日こそ操縦系の整備：7レイヤーの層分けと、fast mode廃止まで残り約3週間

新リリースの乏しい日に、CLAUDE.md・hooks・skillsの役割分離を見直す。7時間自律の楽天事例が裏付ける。

📅 2026年11月6日 ⏱ 約3分 🔗 出典 4 件

11/6は公式に動きが乏しく、最新は11/3の v2.1.318 のまま（11/4〜11/6の新規リリースは未確認・公式docsはv2.1.311止まりで集計サイトが先行）。こういう"静かな日"こそ、ツールの操縦系を見直す好機だ。BestHubが公式ガイダンスを「挙動を制御する7つの仕組み」として整理した（11/4更新・公式資料の二次要約）。

核心は、7つを「いつ読み込まれるか」「トークンコスト」の軸で層分けすること。常時読まれる CLAUDE.md は短く（200行未満、モノレポは claudeMdExcludes で無関係ファイルを除外）、"絶対に守らせたい"制御は hooks／権限へ、手順は skills へ逃がす——という役割分離が勘所になる。

SmartScopeの文脈管理Tips（10/13更新）も同じ思想だ。検証可能な受け入れ基準（テスト・期待出力）を先に渡す、subagentには明確な戻り条件を与える、/compactは保持指示付きで、/clearの前に未解決事項を書き出す。文脈を"縮める前に守る"のがコツ。

実務での使いどころははっきりしている。10プロジェクト横断のような運用なら、各リポジトリの CLAUDE.md を棚卸しして200行へ圧縮し、共通手順はskill化、"本番ブランチへ直pushしない"のような不変則はhookで物理的に遮断する——これだけで取りこぼしと事故が減る。

あわせて期限の実務注意：Opus 4.8の"fast mode"は10/30非推奨・11/30廃止予定で、本日時点で残り約3週間（24日）。fast mode依存のCI/スクリプトは速度維持のため Opus 5.5 への移行確認を急ぎたい。

なぜ今これが効くのか、という裏付けも出ている。Anthropic公式の楽天事例は、約7時間の自律セッションで1,250万行のvLLMコードベースに活性ベクトル抽出を実装し参照実装と数値精度99.9%一致、新機能のTime-to-Marketを24営業日→5日（79%短縮）、さらに1タスクを24並列に分割する"アンビエントエージェント"を構築中、と報告する。長時間の自律運用は、上の層分けされた制御があってこそ破綻しない。

注意点：BestHubは公式資料の二次要約で一部未照合、Goldman Sachsがトレーダーから Claude Code を撤収したとの報道（11/2）は集約見出しベースで一次ソース未確認。鵜呑みにせず一次情報で確認したい。

ひとことまとめ：静かな日は操縦系のメンテ日。CLAUDE.mdを短く、hookで不変則を固め、skillへ手順を逃がす——この三手が自律運用の土台になる。
