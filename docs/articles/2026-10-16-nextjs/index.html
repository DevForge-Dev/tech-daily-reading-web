共有要素トランジション — view-transition-name を揃えるだけでサムネが詳細へ拡大する

一覧のサムネイルが詳細のヒーロー画像へ連続的にモーフ。JS計測が要らなくなった仕組みと、Next.js App Routerでの組み込み、サイレント失敗の落とし穴。

📅 2026年10月16日 ⏱ 約4分 🔗 出典 5 件

写真一覧のサムネイルをタップすると、その画像がそのまま詳細画面のヒーロー画像へ連続的に拡大していく——iOSの写真アプリ、ECのカード→商品ページ、ポートフォリオのギャラリー→作品ページで誰もが見たことのある「共有要素（shared element / hero）トランジション」。従来これはFramer MotionのlayoutIdや自前FLIPで「旧位置を測り→新位置へtransformで寄せる」JS計算が必須だった。それが2025〜2026でほぼCSSとブラウザ任せになる。

何が新しいか

核はView Transitions API。一覧側サムネイルと詳細側ヒーローに同じ view-transition-name を両方付けると、ブラウザが旧スナップショットと新スナップショットを撮り、同名ペアの位置(transform)・サイズ(width/height)を自動で補間してくれる。同一ドキュメントView Transitionsは2025-10にFirefox 144で揃いBaseline Newly available入りし（Chrome/Edge 111+・Safari 18+）、Reactも<ViewTransition>をcanaryに載せ、Next.js App Routerはexperimental.viewTransitionフラグでこれをラップした。「ページ遷移そのもののアニメ化」とは別で、本題は2画面間で“同一要素が生き続けて移動・拡大する”一点に絞る。

仕組みは3ステップ

①旧状態で主役要素に view-transition-name を付与 → ②document.startViewTransition(() => { DOMを新状態へ }) → ③ブラウザがold / new のスナップショットを撮り、同名ペアを ::view-transition-group(名前) でくくって位置・サイズを補間し、中身はold→newをクロスフェード。view-transition-name: match-element（Chrome 137・Safari 18.4・Firefox 144）を使えば100枚のカードに手で名前を振らずに済むが、これは同一ドキュメント専用。

Next.js（App Router）での組み込み

推奨は公式のReact <ViewTransition>。ルートナビゲーションは内部でReact Transitionとして走るため自動発火する。next.config.tsでexperimental: { viewTransition: true }を立て、一覧・詳細の両方で同じ name（例 photo-${id}）を付けるだけ。多くはServer Componentのままでよく、'use client'は原則不要。素のDOM制御がしたい時だけdocument.startViewTransitionを島化して使う。

// next.config.ts
export default { experimental: { viewTransition: true } }

// 一覧・詳細の両方で name を一致させる
<ViewTransition name={`photo-${id}`}>
  <Image src={photo.src} alt={photo.title} fill />
</ViewTransition>

落とし穴

最大の罠は重複名のサイレント失敗。同じview-transition-nameが同時に2つ存在するとマッチに失敗し、全画面が既定クロスフェードへフォールバック＝「ちらつき／点滅」になる。一覧は複数カードがあるので全カードに固定で名前を付けてはいけない。正解は「クリックされた1枚にだけ遷移直前に動的付与し、transition.finishedで外す」。もう一つはアスペクト比が変わる画像の歪み（正方サムネ→横長ヒーロー）で、実務解は::view-transition-old/new { object-fit: cover }。そしてprefers-reduced-motionでは動きだけ消して遷移自体は残す（animation: noneで一括ゲート）。

ひとことまとめ

「両方に同じ名前を付けるだけ」でサムネ↔ヒーローが繋がる時代。鍵はname一致、罠は重複名・付与タイミング・アスペクト比。Next.jsならexperimental.viewTransition＋<ViewTransition>でRSCのまま発火できる。
