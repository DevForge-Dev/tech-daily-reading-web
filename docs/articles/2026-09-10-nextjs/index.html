Prisma ORM v7 を App Router で使う — Rust-free・driver adapter 必須・生成コードのプロジェクト内出力

2025-11-19 の Prisma 7.0.0 で土台が総入れ替え。Rust エンジン廃止で TS 実装化、driver adapter が全 DB で必須に。App Router で RSC 直クエリを安全に回す作法を掴み直す。

📅 2026年9月10日 ⏱ 約4分 🔗 出典 3 件

09-03 の Drizzle に対する「もう一方の巨頭」＝ Prisma を App Router 前提で押さえ直す回。ただし 2025-11-19 の Prisma 7.0.0 で土台が総入れ替えされ、旧来の「schema.prisma に provider = "prisma-client-js" と書いて @prisma/client を import」という 6.x の記憶はそのままだと通用しない。まずは何が変わったかを掴む。

v7 の 3 大変更

①Rust クエリエンジンを廃止し TypeScript 実装へ（Rust-free がデフォルト）。②driver adapter が全 DB で必須。③生成コードが node_modules を出てプロジェクト内へ＋設定は prisma.config.ts に集約。効果はバンドル約90%減（例 ~14MB→~1.6MB）・クエリ最大3倍速・Edge/Workers デプロイが容易。TS 製 query compiler が SQL にコンパイルし、DB 接続は素の JS ドライバ（driver adapter）へ委譲する構図になった。

App Router での作法

土台は Drizzle 09-03 と同じsingleton。RSC はリクエスト毎に走り dev では HMR で PrismaClient が量産され『Too many connections』になるため globalThis にキャッシュする。v7 はインスタンス化時に adapter を渡す点が 6.x と違う。

// schema.prisma
generator client {
  provider     = "prisma-client"   // prisma-client-js から変更
  output       = "../src/generated/prisma" // 必須
  moduleFormat = "esm"
}

// lib/prisma.ts
import 'server-only'
import { PrismaClient } from '@/generated/prisma/client'
import { PrismaPg } from '@prisma/adapter-pg'
const adapter = new PrismaPg({ connectionString: process.env.DATABASE_URL })
export const prisma = globalForPrisma.prisma ?? new PrismaClient({ adapter })

RSC / Route Handler / Server Action からは await prisma.x で HTTP を介さず DB 直行できる。edge では生 TCP Pool が使えないので HTTP ベースの adapter（Neon serverless / Prisma Accelerate）を選ぶのが定石。書込は Server Actions で行い revalidateTag と連動させる。

落とし穴

new PrismaClient() には adapter か accelerateUrl のどちらか必須（URL だけ渡す旧形は不可）。$use() の client middleware は削除 → $extends() へ移行。MongoDB は v7 未対応（使うなら v6 に留まる）。node-pg 採用でSSL 証明書の扱いが変化し、従来黙って無視していた無効証明書が通らなくなる。queryCompiler/driverAdapters/metrics の preview フラグは不要（外す）。

選定メモ・まとめ

Prisma 向き＝スキーマ駆動 DX・自動生成の型/クエリビルダ・Migrate/Studio/Accelerate の一体感・チーム標準化。v7 でバンドル/性能の弱みが大きく縮小。Drizzle 向き＝最小バンドル・SQL に近い制御・edge 第一級。どちらも「RSC 直クエリ・singleton・書込は Server Actions＋revalidateTag・認可は DAL」という App Router の型は共通だ。
