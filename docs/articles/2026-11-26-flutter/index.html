CocoaPods trunk が 12/2 read-only 化 — SwiftPM が iOS/macOS の既定依存マネージャへ

CocoaPods 中央Specsが12/2にread-only。Flutter 3.44からSwiftPMが既定で、CLIが移行を自動化。あと約1週間、依存プラグインの棚卸しが今週の最優先。

📅 2026年11月26日 ⏱ 約3分 🔗 出典 3 件

iOS/macOS 開発者にとって今週の最優先タスクは棚卸しだ。CocoaPods の中央 Specs リポジトリ（trunk）が公式に「2026年12月2日に read-only 化」＝あと約1週間。CocoaPods は「officially in maintenance mode」で、既存ビルドは動き続ける（existing builds will still work）が、この日以降は「no new versions or pods will be added to the trunk」＝新規 pod の公開・追加が止まる。

何が変わるか — SwiftPM が既定へ

公式は「next stable Flutter release, 3.44」から Swift Package Manager を iOS/macOS の既定依存マネージャに昇格させる。ありがたいのは Flutter CLI が移行を自動化する点だ——build/run で Xcode プロジェクトを SwiftPM 向けに更新し、未対応プラグインは警告表示する。未移行プラグインには一時的に CocoaPods へフォールバックするが「CocoaPods support will eventually be removed entirely」＝恒久策ではない。無効化は enable コマンドではなく pubspec.yaml の flutter: > config: > enable-swift-package-manager: false で行う。

プラグイン作者と進捗

プラグイン作者は Package.swift 追加＋標準 Swift package レイアウトへの移行が必須で、未対応パッケージは pub.dev スコアが下がる。公式いわく top 100 iOS プラグインの 61% が移行済み。残り4割が自分の依存ツリーにいないかが分かれ目になる。

実務での動き方

12/2 前に、依存プラグインの SwiftPM 対応状況を確認し、未対応なら作者へ依頼するか代替を採用する。既存ビルドは当面動くので慌てて全面移行する必要はないが、新規 pod が trunk に増えなくなる以上、放置した依存は将来の更新で詰む。なお今日のダイジェストでは AnimatedIcon（Material 標準の2状態トグル図像）、StreamBuilder（build 内で stream を作らない＝親 rebuild で購読が貼り直される罠）、flutter build --analyze-size（DevTools App size tool で版間 diff）も扱われたが、今週は依存移行が最優先。版は stable 3.50.1／beta 3.51.0-0.2.pre で6日連続据え置きだ。

ひとことまとめ

「12/2 に trunk が凍る・3.44 で SwiftPM 既定・CLI が自動移行」。今やるのは依存プラグインの SwiftPM 対応チェック1本に尽きる。
