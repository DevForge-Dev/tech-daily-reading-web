Claude Code v2.1.319 — autoの静かな調整と“聞かずに拒否する”新設定

v2.1.319でauto挙動・ターミナルMCPタスク・denyInsteadOfPrompting・フラグ無効化を追加。直近317/318の実務変更も整理。

📅 2026年11月8日 ⏱ 約3分 🔗 出典 3 件

Claude Code の最新は 11/6 公開の v2.1.319 に更新された（前日まで最新だった 11/3 の v2.1.318 の次）。相変わらず公式 docs の変更履歴は遅延気味で、集計サイト gradually.ai が 11/7 に公式ソース（GitHub の CHANGELOG.md）と照合済みと表示して先行している状態だ。一次（GitHub リリースタグ）はこの digest では未照合なので、断定ではなく「集計サイト先行の確度」で読むのがよい。

v2.1.319 で入った4点

目立つのは、テレメトリやフィーチャーフラグが無効な環境での auto モードの挙動調整、ターミナルからの MCP タスク、そしてプロンプトを出さずに拒否する新設定 permissions.denyInsteadOfPrompting、フィーチャーフラグ全体を殺す CLAUDE_CODE_DISABLE_FEATURE_FLAGS の追加。特に後半2つは CI やエンタープライズのロックダウン運用に効く。確認ダイアログを出さず問答無用で deny に倒せるので、無人実行で「許可待ちで止まる／うっかり許可される」の両方を潰せる。フラグ無効化は、環境ごとの挙動差を消して再現性を上げたいときの逃げ道になる。

直近317/318も運用に効く

手前の2バージョン（いずれも11/3）も地味に重要だ。v2.1.318 は claude auth status にログイン有効期限 loginExpiresAt が出るようになり、gateway の mantle upstream で assume_role に対応、--continue が会話履歴を取り落とす不具合が直った。v2.1.317 は /schedule がユーザーの要求していないコネクタを警告し、web・shell 系ツールがアカウントのメールアドレスを外部送信する前に確認を挟むようになり、Agent SDK のフックで onFailure:block（失敗時にブロック）が使えるようになった。

自分が試すなら

まず claude auth status で loginExpiresAt を確認して、無人スケジュール実行の最中にトークンが切れないか見ておく。次に無人系のプロファイルだけ permissions.denyInsteadOfPrompting を有効化し、危険操作は確認ではなく拒否に倒す。フックは onFailure:block で検証フックを1つ入れ、許可1件・拒否1件を確認してから広げる——今日の技術記事（SmartScope）の勘所とも一致する。

注意点

新リリースの確認が単一の集計サイト依拠で、公式 docs も一次のリリースタグも未照合という点は割り引いて読む。バージョン番号を手で追うよりチャネル追従で差分を取り込む方が事故が少ない。

ひとことまとめ

319 は派手さより「無人・企業運用の締め付け」を一段進めた回。denyInsteadOfPrompting とフラグ無効化は、スケジュール実行で止まらず・暴れない運用の実弾になる。
