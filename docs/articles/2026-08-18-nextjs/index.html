Next.js

ポインタ追従スポットライト & ボーダーグロー・カード — 座標だけJS・見た目は全部CSSで大量カードでも軽い

Vercel/Linear系で定番の「カーソルに光がついてくる」カード。JSは--x/--yのCSS変数を更新するだけ、描画はコンポジタ任せ。スポットライト塗り（radial-gradient）と、mask 2枚のexcludeで枠だけ光らせるボーダーグローの2系統。親1リスナーのグロー・グリッドやApp Routerでの薄いclient境界まで。

📅 2026年8月18日 ⏱ 約3分 🔗 出典 4 件

ヒーローや料金カード、ダッシュボードのタイルで定番化した「カーソルに光がついてくる」インタラクション。Aceternity UI / Magic UIのMagic Cardやibelick / Cruipのチュートリアルで広まった。実装の本質は驚くほど単純で、JSはCSSカスタムプロパティ（--x/--y）を更新するだけ。重いグラデーション描画はブラウザのコンポジタに任せるので、カードが何十枚あっても軽い。

効果は大きく2系統。(A) スポットライト塗りはカーソル位置を中心にした淡いradial-gradientを面に敷いてhoverでフェードイン。(B) マスク・ボーダーグローは明るいグラデーションをmaskで1pxの枠だけに切り抜き、枠が発光しているように見せる。併用すると「枠=くっきり／面=ふんわり」で質感が出る。

枠だけに絞る定石（Josh Comeau / Cruip系）は2枚マスクの合成だ。

mask:
  linear-gradient(#000 0 0) content-box,  /* 中身を隠す */
  linear-gradient(#000 0 0);              /* 全面 */
mask-composite: exclude;                  /* 差 = 枠(padding)分だけ残る */

padding:1pxの分がボーダー幅になる。Safari向けに-webkit-mask-composite: xorも併記すると安全。グロー・グリッドにするなら、親.cardsに1つだけpointermoveを張り、各カードの相対座標を計算して--x/--yを更新する。カード毎にリスナーを張るとイベント過多になるので親1つに集約するのがコツ。

Next.js（App Router）では、ポインタ座標の取得はクライアント処理なのでハンドラを持つラッパに'use client'が必要。ただし中身のテキスト/画像はServer Componentのままchildrenとして流し込めるので、クライアント境界を薄いラッパに閉じ込められる（RSCのままデータ取得できる）。初期--x/--yを50%で描いておけばハイドレーション前でもレイアウトが崩れない。

落とし穴：タッチ端末はhoverが無くpointermoveが電池を食うので@media (hover: hover) and (pointer: fine)の中だけで有効化。--x/--yにtransitionを掛けると追従が遅れて不自然になるので、フェードはopacity側だけに。多数カードは親1リスナー + rAFで1フレーム1回に間引く。ライトテーマでは加算的な光が映えにくいので色は濃いめ＆低不透明度に。

まとめ：ライブラリ不要。「座標だけJS、見た目は全部CSS」を守れば、大量カードでも60fpsを保ったまま高級感のある光が出せる。
