Next.js 16 の型安全ルーティング — typedRoutes と PageProps/LayoutProps/RouteContext

文字列でルートを指すAPIの“型検査の空白地帯”をNext.js 16が塞ぐ。存在しないパスやparamsのタイポがコンパイル時に赤くなり、フォルダ名変更＝ルート変更のリンク切れも検出できる。

📅 2026年9月30日 ⏱ 約5分 🔗 出典 4 件

App Routerで文字列でルートを指すAPI——<Link href>・router.push・redirect・params/searchParams——は、長らく型検査の空白地帯だった。/abootのようなタイポや動的セグメント名の間違いはビルドを通ってしまい、実行時404で初めて気づく。Next.js 16はこの穴を2つの機能でまとめて塞いだ。ORM（Drizzle/Prisma）でデータ層の型安全は取れても、ルーティング層はこれまで手動だった部分だ。

何が新しいか

一つはtypedRoutes（Statically Typed Links）。v13.2でベータ導入されたものが16系でexperimental.typedRoutesからトップレベルのtypedRoutesへ昇格し、“stable”扱いになった。<Link>のhrefとnext/navigationのpush/replace/prefetchを、アプリに実在するルートだけに制限する。もう一つはPageProps / LayoutProps / RouteContextという3つのグローバルヘルパー型（import不要）。ルートリテラル（例 '/blog/[slug]'）を渡すだけで、params・searchParams・名前付きスロットが自動で型付く。手書きのparams: Promise<{ slug: string }>を廃せる。

仕組み

next dev / next build / next typegen 実行時に、Next.jsが.next/types配下へ隠し.d.tsを生成し、アプリ内の全ルートを列挙してLinkのhref型やnavigationメソッドの引数型に流し込む。リテラル文字列は検証される（テンプレートリテラル /blog/${slug} も可）。実行時に組み立てる非リテラル文字列はas Routeキャストが要る。ヘルパー型のparams/searchParamsはPromiseなのでawait必須（Next.js 15+の非同期params）、静的ルートではparamsは{}に解決される。LayoutPropsは並列ルートの名前付きスロット（app/dashboard/@analytics→props.analytics）をディレクトリ構造から推論する。

実務での組み込み

手順はシンプル。(1) next.config.tsにtypedRoutes: true、(2) tsconfigのincludeに.next/types/**/*.tsがあるか確認、(3) 一度next devかnext typegenで型を生成、(4) ページ/レイアウト/Route HandlerのpropsをPageProps<...>等へ置換し手書きのPromise注釈を削除。typedRoutesもヘルパー型もビルド時/型レベルの機能でランタイムに干渉しないため、<Link>やredirectを使うページはRSCのままでよく、クライアントJSは増えない。

// next.config.ts
const nextConfig = { typedRoutes: true }

// app/blog/[slug]/page.tsx — params が自動で型付く（要 await）
export default async function Page(props: PageProps<'/blog/[slug]'>) {
  const { slug } = await props.params   // slug: string（キー厳格）
  return <h1>Blog: {slug}</h1>
}

落とし穴

as Routeは安全弁ではなく“逃げ道”で、間違った文字列もTSに飲ませられる＝実行時404を握り潰す。動的リンクは可能な限りテンプレートリテラルで書き、キャストはproxy.tsのリダイレクト先など静的解析できないケースに限定する。CIではnext typegen → tsc --noEmit の順にしないと、型生成前の実行でPagePropsが「Cannot find name」になって落ちる。.next/typesのinclude漏れ、params/searchParamsの未await（searchParamsアクセスは動的レンダリングを誘発）も頻出バグだ。

ひとこと：フォルダ名変更＝ルート変更でリンク切れがコンパイル時に赤くなるのは効く。フロント〜ルート〜データ取得まで型が繋がる“最後のピース”が実用レベルに来た。
