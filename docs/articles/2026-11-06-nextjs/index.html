11/6のNext.js — Material リップルをApp Routerで正しく：座標起点・被覆半径・確実な破棄・RSC島化

波紋は見た目でなく実装の正しさ。CSS-onlyとJSの島の使い分け、落とし穴とprefers-reduced-motionまで。

📅 2026年11月6日 ⏱ 約4分 🔗 出典 4 件

ボタンを押した"その場所"から円が広がって消えるMaterial Designのリップル（波紋）は、どこを押したかを身体的に確認させる定番のタッチフィードバックだ。:activeの色変化だけより「触れた感」が段違いで、ボタン/リスト/カード/FABなど"押せる面"全般に効き、モバイル〜PWAの体感品質に直結する。

ポイントは見た目ではなく実装の正しさに集約される。(1)起点をポインタ座標に合わせる、(2)要素全体を必ず覆う半径にする、(3)連打で重なる複数リップルを確実に破棄する、(4) transform/opacity だけでアニメする、(5)本物の <button> に乗せ prefers-reduced-motion で無効化できる——この5点だ。

仕組みの核は半径計算にある。クリック点から4隅への最大距離を半径にすれば、隅をタップしても反対隅まで確実に届く。

size = Math.max(
  hypot(x, y), hypot(w-x, y),
  hypot(x, h-y), hypot(w-x, h-y)
) * 2;  // Math.max(w,h) の中央固定だと隅タップで"欠けた波紋"になる

方式Bのライフサイクルはこうだ。onPointerDown で座標とサイズを算出し、絶対配置の span を state に積む。@keyframes で scale(0)→scale(1) ＋ opacity を落とし、onAnimationEnd でその波紋を state から除去する——これでDOMリークしない。

App Routerでの組み込みは素直だ。方式Bはボタンの殻だけ 'use client' の小島に隔離し、ページ本体・データ取得・一覧の map はRSCのまま children を流し込むだけ。ripples の初期値を空配列にすればSSRは波紋ゼロのボタンを描画しクライアント初回と完全一致＝hydration mismatch無し。波紋はJS到達後のクリックで初めて現れる純粋なプログレッシブエンハンスメントで、JS前でもボタンはPOSTでき、Server Actions / useFormStatus とも同居する。

落とし穴：onClick（離した時に発火＝遅い／キーボード擬似clickは座標無しで左上に出る）ではなく onPointerDown（押下即時）＋キーボードは中央起点に分岐する。overflow:hidden / border-radius:inherit 忘れで角丸からはみ出す。ripple層の pointer-events:none 忘れで次のクリックを食う。width/height をアニメすると毎フレームreflow＝初期サイズ固定で transform:scale() だけ動かす。<div> でなく必ず <button>。

アクセシビリティ：リップルは装飾（意味はラベル/状態が担う）なので prefers-reduced-motion: reduce では波紋を出さず（WCAG 2.3.3）、代わりに :active/:focus-visible の色変化でフィードバックは残す。JS側でも matchMedia を見て波紋のstate追加自体をスキップすれば無駄なDOMも作らない。

試すなら：まずCSS-onlyを"軽い触感"の既定に入れ、座標起点が要る主要CTAだけ方式Bの島に。デザインシステムにMUIを使っているなら Button が内部でrippleを持つのでそれで足りる。

ひとことまとめ：座標起点・被覆半径・確実な破棄・transform限定の4点を外さなければリップルは軽い。RSCは殻だけ島化し、本体はServerのまま。
