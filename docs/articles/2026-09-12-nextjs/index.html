サードパーティスクリプトを性能を落とさず積む — next/scriptの4戦略と@next/third-parties

GA/GTM・チャット・地図・動画はCore Web Vitalsの主要な悪化要因。素の<script>はメインスレッドを塞ぎINP/LCP/TBTを一気に悪化させる。next/scriptの読み込み戦略を用途で選び、GA/GTM/YouTube/Mapsは@next/third-partiesに任せる、App Router前提の正しい積み方を整理する。

📅 2026年9月12日 ⏱ 約4分 🔗 出典 3 件

アナリティクス・タグマネージャ・チャットサポート・SNS埋め込み・地図・動画といったサードパーティスクリプトは、Core Web Vitals（CWV）の最大級の悪化要因だ。素の <script> をそのまま置くとメインスレッドを塞ぎ、INP（旧FID）・LCP・TBTを一気に悪化させる。Next.jsは①読み込みタイミングを制御する組み込みの next/script、②GA/GTM/YouTube/Mapsを最適化済みで包む @next/third-parties を用意している。App Router前提の正しい置き場所と戦略、'use client' 要否の落とし穴を押さえる。

4つのloading strategy

next/script（Next.js 16.3系で確認）の strategy は4種類。beforeInteractive はNext.jsコードより前・ハイドレーション前に読み、必ずルートレイアウトに置く必要があり、常に <head> に注入されドキュメント読み込み時に1回だけ実行される。用途はボット検知・Cookie同意などサイト全体で最速に要るものだけ。afterInteractive は既定値で、ハイドレーション後にクライアント側で読み、タグマネージャ・アナリティクス向け。lazyOnload はアイドル時に全リソース取得後読み、チャット・SNSウィジェットなど低優先向け。worker は実験的でApp Routerでは未対応（pages/ のみ）。

落とし穴：イベントハンドラは Client Component 限定

onLoad / onReady / onError はServer Componentでは動かないため、使うファイルに 'use client' が必要。さらに onLoad・onError は beforeInteractive と併用不可で、代わりに onReady を使う。onReady はロード完了時＋マウントのたび（ルート遷移で再マウントされる度）に走るので、Google Maps のように毎回インスタンス化し直す用途に向く。GA/GTMのイベント送信ヘルパ（sendGAEvent/sendGTMEvent）もClient Componentから呼ぶ。スクリプトURLに秘密キーを含めない（クライアントに露出する）。

// @next/third-parties：GA はルートレイアウトに1回
// app/layout.tsx
import { GoogleAnalytics } from '@next/third-parties/google'
export default function RootLayout({ children }) {
  return (<html lang="ja"><body>{children}
    <GoogleAnalytics gaId="G-XXXXXXXXXX" />
  </body></html>)
}

実務での判断・まとめ

迷ったらafterInteractive（既定）。beforeInteractive は「全体最速が本当に要るもの」だけ・ルートレイアウトのみに限定する。分析タグをbeforeInteractiveからafterInteractiveへ落とすだけでTBTが大きく改善することが多い。チャット/SNSは lazyOnload。GA/GTM/YouTube/Mapsは @next/third-parties（現状experimentalなので @latest 固定推奨）に任せると、内部で適切な戦略とファサード（YouTubeはlite-youtube-embed）を使い手書きより安全にCWVを守れる。Lighthouse/WebPageTestで before/after を必ず測る。
