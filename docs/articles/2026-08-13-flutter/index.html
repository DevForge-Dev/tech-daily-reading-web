Dart 3.12のprivate named parameters — コンストラクタ定型を3方向から削る、8月リリース窓の主役

先頭_の名前付き引数がprivateフィールドを直接初期化。primary constructors・dot shorthandsと合わせ定型を3方向から削減。土台はFlutter 3.44／Impeller Android既定、状態管理はRiverpod 3.3が既定線。

📅 2026年8月13日 ⏱ 約3分 🔗 出典 4 件

Flutterは年4回（2/5/8/11月）の機能リリースで、いまは8月のリリース窓に入っている。現行安定版は Flutter 3.44 / Dart 3.12（3.44.0 は Google I/O 2026 で公開）。2026ロードマップは最低4回のstableをコミットしており、今回の主役はDart 3.12のprivate named parameters——コンストラクタの定型コードを大きく削る言語機能だ。

何が新しいか。Dart 3.12はprivate named parametersを初期化仮引数（initializing formals）とprimary constructor引数に拡張した。先頭 _ の名前付き引数がprivateフィールドを直接初期化し、公開名は _ を除いた名前を自動採用。カプセル化を保ったまま「フィールド宣言→コンストラクタ引数→代入」の三重定型が消える。あわせて primary constructors（experimental・クラスヘッダでinstance変数を直接宣言）と dot shorthands（型が自明なら .value）で、定型を3方向から削減する。

// 従来
class User {
  final String _name;
  User({required String name}) : _name = name;
}
// Dart 3.12：private named parameter
class User {
  final String _name;
  User({required this._name}); // 呼び出しは User(name: 'a')
}

土台の状況。Material／Cupertinoはコアから material_ui／cupertino_ui へ切り出され（3.44でコア内は凍結）、独立バージョニングでM3更新がSDKを待たず届き、未使用UIはbinaryから外れapp size削減に効く。描画は Impeller が Android 既定・Skia 撤去（Android=Vulkan／iOS=Metal）、iOS/macOSはSwift Package Managerが新規既定。状態管理の既定線は新規=Riverpod 3.3.1＋codegen（@riverpod・compile-time safety・最小ボイラープレート）、監査/規制業界や複雑並行はBloc 9.x。

自分が試すなら、既存モデル層のコンストラクタをprivate named paramsで書き換え、dart fix／flutter analyze で警告を潰しながら移行する。移行前は flutter upgrade で3.44系最新パッチへ上げ、Impellerを実機検証（差が出たら --no-enable-impeller で切り分け）。注意点：primary constructorsはexperimentalなので本番投入は段階的に。Impeller既定化で描画差異が出る箇所は必ずprofileモードで確認する。ひとことまとめ：今回は言語（定型削減）と土台（Impeller/パッケージ分離）が同時に前進した回。まずコンストラクタの書き換えから恩恵を取りにいける。
