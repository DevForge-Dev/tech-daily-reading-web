Claude Code

Claude Codeがオートモードを既定化 — 承認クリックを卒業し「不可逆・破壊的・環境外」だけ止める

8/14よりPro/Max/Teamでオートモードが既定オン。分類器が有害操作の89%を検知（人間は13.6%）という実測を根拠に、権限プロンプトの大半を廃し危険操作のみ確認へ。あわせてGitLab MR対応・Ultraplan廃止・VS Code Focus view・資格情報 mode:"mask" など足回りも更新した回。

📅 2026年8月16日 ⏱ 約2分 🔗 出典 3 件

ここ数日のClaude Codeは「いちいち承認しない」方向へ大きく舵を切った。Anthropicは8月14日から Pro・Max・Team の各プランでオートモードを既定で有効化。各ステップで人間の承認を求めず、操作が「不可逆・破壊的・環境外を対象」と判定されたときだけ停止して確認を挟む設計だ。

なぜ今か。背景には反射的クリックの実測がある。社内テストでは分類器が有害操作の89%を検知したのに対し人間は13.6%にとどまり、しかも従来の権限プロンプトは97%が承認されていた。つまり「毎回聞く」体験はほぼ素通りされ、安全性より摩擦を生むだけになっていた——これを機械判定へ寄せる判断である。

足回りも同時に更新。公式What's newでは claude-code-action がGitLabのマージリクエスト連携に対応し、GitHubに続きGitLabでも自動レビュー・変更提案が可能に。一方で研究プレビューだったUltraplan（/ultraplan）は削除され、プランモードやWeb版Claude Codeへ誘導される。VS Code拡張にはFocus viewが加わりツール実行ログを折りたたんで会話を見通しよくでき、v2.1.221ではサンドボックス資格情報に mode:"mask" が追加され、Linux/WSLで実値を渡さず外部APIを呼べる。使用量警告もゲートウェイの上限名・リセット時刻・運用者メッセージを明示するよう改善された。

自分が試すなら、オートモードで定型作業（テスト生成・整形・ログ集計）を回し、停止が入るのは本当に「不可逆・破壊的・環境外」だけかをHookログで観察したい。破壊的操作の歯止めは PreToolUse フックで二重化しておくと安心だ。GitLab派はMRレビュー連携を早めに試す価値がある。

注意点。既定化は当面 Pro/Max/Team のみで、Enterprise・API・Bedrock/Vertex はオプション扱い（順次拡大）。「自動＝無制限」ではなく、環境外・破壊的判定では必ず止まる設計を理解して使う。Ultraplan依存のワークフローは手動起動やSubagentへ組み替えが要る。

ひとことまとめ：承認クリックという形骸化した儀式を捨て、危険操作の判定を機械に寄せた回。摩擦を減らしつつ「止めるべき所で止める」を分類器で担保する。
