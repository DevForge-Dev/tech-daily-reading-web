Flutter 3.47.7 と Impeller の次段階 — WebGPUプレビュー、公式MVVM＋Command、AOTシェーダ

3.50（11月）前は3.47.7にpin。WebはWebGPUプレビュー、設計は公式アーキテクチャガイドのMVVM＋Command、描画はImpellerのAOT＋テッセレーション。

📅 2026年10月15日 ⏱ 約4分 🔗 出典 6 件

現行安定はFlutter 3.47.7 / Dart 3.13.5(2026-10-08 patch)、betaは3.49.0-0.2.pre。次stable3.50は11月で、WebのWasmGC既定化・Android Impeller一本化・Material/Cupertinoのcore分離が出揃う見込み。レンダリングとアーキテクチャの両面で節目なので、今日は「バージョン固定の指針」「公式アーキテクチャガイド」「Impellerの内部」をまとめる。

何が新しいか — Webレンダリングの次段階

ImpellerのWebバックエンドが WebGPU ベースでプレビュー段階に入った。未対応ブラウザは従来のCanvasKit/Skia系へフォールバック、flutter build web --wasmはWasmGC対応ブラウザで有効になる。レンダラのバックエンドは用途別に整理され、iOS/macOS=Metal、Android=Vulkan(非対応端末はOpenGLフォールバック)、Web=WebGPU(preview)。Androidのlegacy Skiaは3.50でAndroid10+から正式引退予定だ。

移行の実務としては、3.50前は安定ラインを3.47.7にpinし、betaでCIを1本持っておく。material_ui/cupertino_ui分離はdart fix --apply --code=migrate_design_widgetsで前倒しできる。

アーキテクチャ — 公式ガイドのMVVM＋Command

公式アーキテクチャガイドはUI層とデータ層の2分割を大原則に置く。MVVM対応はView=widget合成／ViewModel／Model=repository+serviceで、各featureはViewとViewModelが1:1。ロジックはViewModelに集約し、ユーザー操作はCommand(ViewModelのメンバ関数)として公開する。Viewに置いてよいのは表示出し分け・アニメ・デバイス別レイアウト・単純ルーティングのみ。データ層ではrepositoryが信頼できる唯一の情報源でStream/Futureを公開し、repository同士は依存しない。serviceは最下層・状態を持たず、データ源1つにつき1クラス。不変モデル(freezed/built_value)・単方向データフロー・DIはprovider・ナビはgo_routerが推奨で、domain層(use-case)は複数repositoryの結合など条件付きで足す。

パフォーマンス — Impellerの内部

Impellerはビルド時にシェーダを事前コンパイル(AOT)するので、SkiaのJITで起きる「初回だけカクつく」shader jankが消える。代償はバイナリがわずかに増えること。描画は複雑なベクターパスを三角形にテッセレーションしてGPUへ渡しCPU負荷を下げ、blur/shadow/クリップは事前計算パイプラインで処理する。非公式の実測では複雑シーンでラスタ時間が約50%減、ドロップフレーム約90%減との報告もある。計測はflutter run --profile+DevTools(Draw Call Batching／Texture Memory View)が基本。

自分が試すなら / 注意点

頻繁に再描画する領域はRepaintBoundaryで隔離し、スクロール上のBackdropFilterは避ける。60Hz機で無理に120fpsを狙わない。カスタムGLSL fragment shaderは多くが自動変換されるがビジュアル回帰テストを推奨、Android9以下はドライバ差で挙動が不安定になりうる点に注意。アーキテクチャは「Viewにロジックを置かない／repository同士を繋がない」の2点を守るだけでテスト(fake前提設計)がぐっと楽になる。

ひとことまとめ

3.50前は3.47.7にpin。レンダリングはImpeller/WebGPUで前進、設計は公式MVVM＋Commandが実務の軸。
