Flutter 3.47 の“デザインシステム分離” — material_ui / cupertino_ui が SDK から独立、M3更新が四半期を待たず届く（SDK同梱は2026/11に非推奨予定）

今日の主役は Flutter 3.47 のデザインシステム分離。material_ui / cupertino_ui が SDK から切り出され独自リリースサイクルを持つことで、Material 3 の更新が年4回の SDK リリースを待たず届く。当面 opt-in、SDK同梱版は 2026年11月に deprecation 予定。安定版は 3.47.1 / Dart 3.13.1、Impeller はデスクトップでも既定に。

今日の主役は Flutter 3.47 のデザインシステム分離だ。これまで SDK に同梱されていた material_ui / cupertino_ui が standalone パッケージとして独立し、独自のリリースサイクルを持つ。狙いは明確で、Material 3（M3）の更新が年4回の SDK リリースを待たずに届くようにすること。デザイン仕様の変化に UI ライブラリだけ先行して追随できる。

何が新しい/重要か

移行は当面 opt-inで、いきなり壊れることはない。ただし SDK-bundled 版は 2026年11月に deprecation 予定なので、新規プロジェクトは早めに standalone パッケージ側へ寄せておくのが安全だ。現行安定版は Flutter 3.47.1 / Dart 3.13.1（3.47.0 は 2026-08-12 リリース）、機能リリースは 2/5/8/11月の年4回サイクルで、次は 2026年11月。レンダラの Impeller はデスクトップでも既定に昇格し、Web は experimental で Wasm の deferred loading を追加（dart:html → package:web への移行が必要）。Widget Previews が stable になり、Dart 3.13 は primary constructors を stable 化、pub workspace や tree-shaking も改善された。

実務での使いどころ・注意点

自分が試すなら、まず既存の中規模アプリで standalone パッケージへ opt-in し、テーマ・コンポーネントの差分と回帰を CI で確認したい。2026年11月の非推奨に向け、pubspec.yaml の依存を段階的に切り替える計画を今から引いておくと移行が滑らかだ。落とし穴として、分離によりパッケージのバージョン整合を自分で管理する必要が出る（SDK が面倒を見てくれない）。Web を触るなら dart:html → package:web の移行が前提になる点、Impeller 既定化で古い描画前提のワークアラウンドが不要になる点も合わせて確認しておきたい。

まとめ：UI ライブラリの独立で M3 追随が速くなる一方、バージョン整合は自己管理に。opt-in の今のうちに移行検証を進め、11月の非推奨に備えるのが得策だ。
