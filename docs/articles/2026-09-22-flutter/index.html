Wasm前進とMaterial 3 Expressiveのspringモーション — 描画はsaveLayer回避が効く

DevToolsがWASMを既定レンダラ化しWasm移行が前進。UIはMaterial 3 Expressiveのspring駆動モーションが主流化。性能の要はsaveLayer回避と不要rebuild削減で、90/120Hz時代のフレーム予算に直接効く。現行はFlutter 3.47.4 / Dart 3.13.3。

📅 2026年9月22日 ⏱ 約4分 🔗 出典 4 件

この日のFlutterは、基盤（Wasm）・見た目（Material 3 Expressive）・性能（描画）の三面が同時に動いた。現行安定版は Flutter 3.47.4 / Dart 3.13.3（2026-09-11 patch）で、3.47系はImpellerが全デスクトップ既定・Widget Previews stableに到達している。

何が新しいか

主役は WebAssembly（Wasm）の前進。DevTools が WASM を既定レンダラとして同梱し、ロード高速化と大きなwidget treeのスムーズなスクロールを実現した。Flutter web本体もWasm既定化へ進み、3.47は experimental deferred loading でバンドル分割を可能にする。移行の前提は dart:html からの脱却——package:web ＋ dart:js_interop へ移す（WasmGC前提のためChrome/Firefox/Safariの新しめの版が対象）。Dart 3.13では primary constructors がstable、dot shorthands で .start のように先頭ドット省略も入った。

アニメーション：spring駆動へ

UIは Material 3 Expressive のモーションが主流化。material_3_expressive パッケージは M3E* クラスで45 widgetsを収録し、motor のspring physics・material_new_shapes のmorph・状態レイヤを統一トークンで扱う。springは duration ではなく stiffness/damping で「物理的に自然な」動きを作り、割り込みにも滑らかに追従する。使い分けの目安は、micro=implicit（AnimatedOpacity 等・50〜200ms）→ 多段=flutter_animate → component=explicit（AnimationController・200〜400ms・dispose必須）→ 共有要素=Hero。

性能：saveLayerを避ける

描画コスト増の典型は saveLayerを誘発する操作——ネストした Opacity、複雑なclipping path、複数の重なるshadow、offscreen bufferへの反復描画。単色の透過は色のalphaに畳み込み、角丸は BoxDecoration で表現して ClipRRect を減らす。もう一つの定番は不要なrebuild：const で完全スキップ・大きな build() を分割・ref.watch(select) / BlocSelector で最小購読・アニメ領域を RepaintBoundary で隔離し、重い計算は Isolate.run() / compute() で背景へ。計測は必ず profileモードで DevTools Performance の flame chart から。

状態管理：派生値をmemo化

性能は「どのライブラリか」より stateをどう構造化し derived値をmemo化するかで決まる。派生値は都度計算せず、Riverpodの computed provider（ref.watch で依存宣言）やBlocの BlocSelector にキャッシュさせる。新規既定は Riverpod 3.3.1 ＋ @riverpod codegen（compile-time safety・unified Ref・最小boilerplate）、監査/規制や大規模チームは Bloc 9.0。要は「一つ選んで一貫させ、テストを書く」。

ひとことまとめ

Wasmで土台が速くなり、M3Eで見た目がspringになった今こそ、saveLayerとrebuildという“昔ながらの2大コスト”を潰すのが費用対効果が高い。
