Dart 3.13 の書き味 — primary constructors / dot shorthands と、UIを詰まらせないIsolate設計

primary constructorsとdot shorthandsがstable化しボイラープレートを一掃。あわせてフレーム予算とIsolateでUIスレッドを空ける定石、Rive/Blocの勘所まで。

📅 2026年9月25日 ⏱ 約4分 🔗 出典 5 件

Flutterの今日はDart 3.13の言語エルゴノミクスが主役。安定版はFlutter 3.47.4 / Dart 3.13.3、betaが3.48/3.14で、次の安定機能リリースは2026年11月見込み。年4回（2/5/8/11月）サイクルの、"言語が地味に効いてくる"回だ。

primary constructors と dot shorthands が stable

primary constructors（3.12でexperimental→3.13でstable）はクラスヘッダに直接コンストラクタ引数を宣言でき、フィールド名/型の重複記述とinitializer listのボイラープレートを一掃する。あわせてprivate named parameters（先頭_の名前付き引数）でprivateフィールドの初期化が簡潔になり、state/modelクラスの定義量が目に見えて減る。

// before
class Point {
  final int x, y;
  Point({required this.x, required this.y});
}
// after — primary constructor
class Point({required int x, required int y});

dot shorthandsはenum/静的メンバの型名を省略でき（MainAxisAlignment.start → .start）、switchの網羅分岐やThemeData構築の冗長さを削る。Freezed 3.xのsealed class＋pattern matchingと組むとstate定義が一段とスリムに。移行はdart fix --dry-runで差分を見てからdart fix --applyで当てるのが安全だ。

UIを詰まらせない：フレーム予算とIsolate

パフォーマンスの主役は重い処理をIsolateへ逃がしてUIスレッドを空けること。フレーム予算は下図の通りで、JSON parse・画像処理・暗号化のようなCPU重い同期処理をbuild/initStateに置くと即座に溢れる。

Dart 3のIsolate.run()（旧compute()より簡潔）で単発の重い計算を背景isolateへ投げ、結果だけ受け取る。描画側はconst徹底・build()分割・ref.watch(provider.select(...))/BlocSelectorでの最小スライス購読・アニメ領域をRepaintBoundaryで隔離が定番。土台のImpellerは全プラットフォーム既定になり、移行報告ではjankフレーム30–50%減。計測は必ずprofileモードでDevTools Performanceを使う。

その他の勘所（Rive / Bloc）

アニメはRive state machine × data bindingで、複雑なauthored artをコードで手組みせずオフロードし、StateMachineController＋SMITrigger/SMIBool/SMINumberで入力にリアルタイム応答。Riveのプロパティ（テキスト・色・数値）をFlutterのstateへ直結できるdata bindingが定石化した。状態管理はBloc 9.2のbloc_concurrencyで、検索連打はrestartable()、送信ボタンの二度押しはdroppable()、順序が要る処理はsequential()——並行性のバグを設計で断つのが要点。永続化はhydrated_blocでstateを自動シリアライズ/復元する。

ひとことまとめ

新規の既定はRiverpod 3.x、監査/規制・大規模チームはBloc 9.xという選定線は不変。今回の目玉はコードの書き味を下げるDart 3.13で、まずdart fixでprimary constructor移行を1クラス試し、重い初期化をIsolate.run()へ逃がすところから手を付けたい。
