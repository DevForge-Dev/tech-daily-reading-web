claude plugin eval で『効くか』を数値化 — あり3回/なし3回の採点、effort上限とAgent Teamsでコスト制御も前進

9/12公開のv2.1.269でclaude plugin evalが追加。プラグインをあり3回/なし3回実行してスコア比較し、JSON+HTMLレポートで効果を再現可能に検証できる。v2.1.268/267の統一料金・effort上限でコストを締め、実験的Agent Teamsは共有タスク+メールボックスでセッションを分隊協働させる。

📅 2026年9月15日 ⏱ 約3分 🔗 出典 4 件

9月のClaude Codeは派手な新機能というより「プラグインが本当に効くかを測る」「コストとリソースを締める」という、運用の地味だが効く更新が軸だ。9/12公開の v2.1.269 で追加された claude plugin eval は、勘で語られがちだったプラグインの効果を数値で検証できるようにした転換点。あわせて v2.1.268/267 で料金と推論コストの制御が前進し、実験的な Agent Teams も姿を見せている。

何が新しい/重要か

claude plugin eval は、プラグインの eval suite を Claude Code 本体に対して実行し、スコア付きで再現可能な結果を JSON＋HTMLレポートで出力する。肝は各ケースをプラグインを読み込んだ状態で3回・読み込まない状態で3回走らせ、両者を突き合わせる点。「プラグインありのときだけ振る舞いが変わるか」を定量比較できるので、効果の有無を主観でなくスコアで判断できる。同版では /output-style [name] が Remote Control やクラウド等の headless セッションでも一覧・切替でき、Bash がファイルを編集した場合はその diff がツール結果に添付されるようになった。

仕組み — Agent Teams は「委譲」から「分隊の協働」へ

もう一つの見どころが実験的な Agent Teams。従来の subagent が親に結果を返すだけの「指示された作業者」なのに対し、teammate は独立したコンテキストを持つ別セッションで、共有タスクリストとメールボックス（相互メッセージ）を介して peer-to-peer に会話する。team lead が全体をオーケストレーションし、pending/in-progress/completed を共有する。既定では無効で、環境変数 CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1 で有効化する。コスト側は v2.1.268 が統一料金＋レート自動整合を、v2.1.267 が全プロバイダ横断の effort level（推論の労力）上限をもたらし、危険な rm の安全確認も強化された。

実務での使いどころ・自分が試すなら

自作プラグイン（skill/hook 束）に eval を用意して CI に組み込めば、「新しい指示を足したら本当にスコアが上がったか」を回帰テストのように担保できる。effort 上限はコスト暴走の歯止めとして各プロバイダに設定しておきたい。数字も追い風で、Pragmatic Engineer の1.5万人調査では 「最も愛されるツール」46%、AIエージェント常用者の 71% が主力採用。Copilot を売る Microsoft が社内で Claude Code を広く採用、Google 技術者は「1年分の設計を1時間で再現」と証言し、ラン率は $2.5B超に達する。

注意点

eval は1ケースにつき計6回実行するため、ケース数×6のトークン/時間コストがかかる。まずは代表ケースを絞って回すのが現実的。Agent Teams は実験的機能で挙動が変わりうるため、本番ワークフローに常用するのは時期尚早。

ひとことまとめ

「効くかを測り、コストを締める」回。プラグインの価値をスコアで検証し、effort 上限で支出を抑え、Agent Teams で協働の芽を試す——エージェント運用の再現性と経済性が一段進んだ。
