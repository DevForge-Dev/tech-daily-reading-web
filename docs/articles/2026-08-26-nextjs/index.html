Before/After画像比較スライダー — 「自前実装しない」native range × clip-path が推奨解に

加工前↔後を仕切りドラッグで見比べる定番UI。既製ライブラリは重い/依存過多/キーボード・SR非対応になりがち。核心は pointer/touch/keyboard を自作しないこと——標準の input type=range に操作を任せ、その値を CSS clip-path に流すだけで全入力手段がタダで揃う。

📅 2026年8月26日 ⏱ 約3分 🔗 出典 4 件

「Before↔After」を仕切りのドラッグで見比べるインタラクションは、ランディング・エディタ・写真/不動産/医療系で定番だ。だが既製ライブラリは「重い」「React・jQuery依存」「キーボードやスクリーンリーダーで操作不能」のどれかを抱えがち。2025〜26の記事群が推す解は明快で、自前でpointer/touch/keyboardを実装しない——ブラウザ標準の <input type="range"> に操作を全部任せ、その値を CSS clip-path に流すだけで、マウス・タッチ・矢印/Home/End・スクリーンリーダー・フォーカスがタダで揃う（Cloud Fourの実装で1.5KB・依存ゼロ）。

仕組みのポイント

同寸の画像を2枚重ね、下層をAFTER（全面）、上層のBEFOREを position:absolute; inset:0 で重ねて右からクリップする：clip-path: inset(0 calc(100% - var(--pos)) 0 0)。操作は range を画像上に全面オーバーレイし、value を CSS変数 --pos に流し込むだけ。width/left を毎フレーム変えるとレイアウト/ペイントが走るが、clip-path はコンポジタ処理で軽く、ドラッグ中のカクつきを避けられる。仕切り線は上層wrapperに filter: drop-shadow(2px 0 0 #fff) を掛けるだけで要素を増やさず出せる。

Next.js（App Router）での組み込み

値→CSS変数の反映に input リスナと style.setProperty を使うため、スライダー本体は 'use client' の薄い島に隔離し、画像URLの取得（DB/CMS/fetch）はRSCのまま行って src/alt を props で渡す。画像は next/image を2枚とも fill＋親 aspect-ratio で最適化し、LCP候補のAFTER側に priority。初期 value=50 ならサーバーHTMLも中央分割でhydration mismatchなし＝JS到達前も「50%で静止」した比較が見えるプログレッシブエンハンスメント。

const onInput = (e) => {
  const v = e.target.value;
  cancelAnimationFrame(raf.current);
  raf.current = requestAnimationFrame(() =>
    box.current.style.setProperty('--pos', v + '%'));
};

落とし穴

2枚は完全同寸・同トリミング（object-fit:cover＋同 aspect-ratio）でないとズレる。コンテナに寸法を与えCLS=0を確保。毎入力で React state を回すと再レンダー多発でINPが悪化するので ref＋CSS変数直書き＋rAF で間引く。純CSS(JSゼロ)版はキーボード/タッチ/SRが弱いので本番はnative range併用が無難。

ひとこと

「操作系はブラウザに、見た目はCSSに」任せるほど、軽く・アクセシブルで・壊れにくい。自作の誘惑を捨てるのが最短ルートだ。
