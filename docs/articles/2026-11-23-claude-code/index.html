11/23も新リリースなし — v2.1.330据え置き3日目に効く「信頼性・認証」修正、computer use の macOS 安全強化、/code-review と /simplify の分離

新機能ゼロの日こそ、長時間セッションと無人の自動実行に効く地味な修正を読む。Keychain・~/.claude.json・HTTP MCP 自動再接続・octet-stream 問題と、computer use の安全ルール更新、そしてレビューコマンドの責務分離。

📅 2026年11月23日 ⏱ 約3分 🔗 出典 3 件

週末から週明けにかけて Claude Code の新規リリースはなく、npm の latest は 2026-11-20 公開の v2.1.330 が3日連続で据え置き（stable=v2.1.323 / next=v2.1.330）。版が動かない日ほど、CHANGELOG に積まれた「地味だが運用に効く」修正を拾っておきたい。今日はその棚卸し。

信頼性・認証まわり（v2.1.329 中心）

長時間セッションと日次自動実行に効く修正が集中している。macOS で Keychain を読めても保存できない環境での「繰り返しサインアウト」を修正し、該当セッションだけ期限切れで停止して理由を表示、他セッションのサインインは維持するようになった。ネットワーク断やファイルロックで ~/.claude.json が読めず既定値にリセットされる問題、トークン更新中に認証解除された MCP が再サインインされる問題、低速再接続後に固まった HTTP MCP の自動再接続も入った。さらに、MCP やサイトが application/octet-stream で送る PDF・画像・Office 文書が .bin として保存され Claude から読めない問題、Code Mode が大きなテキストを保持し続けるメモリリークも修正。CI やスケジュール実行で「夜中に静かに壊れる」類の不具合が多く、無人運用ほど効く。

computer use の macOS 安全強化

デスクトップ操作（computer use）のガードレールも段階的に強まった。v2.1.328 で承認ダイアログが「各アプリの持つアクセス権レベル」と平易な警告を表示するようになり、v2.1.329 で macOS 版を新しい安全ルールへ更新——一部操作を拒否し、一部アプリの権限を縮小、さらにアプリ起動が30秒で完了しなければ打ち切る（ハング回避）。Cowork やデスクトップ版で画面操作を使う運用では挙動が変わりうるので把握しておきたい。

/code-review と /simplify の分離

レビュー系コマンドの責務が切り分けられた。多くのモデルで /code-review は「バグ」と「CLAUDE.md 違反」のみを報告し、再利用性・簡潔化・効率のクリーンアップは新コマンド /simplify へ移動。指摘は Important / Pre-existing / Nit で分類され末尾に修正案が付き、問題がなければ「Code review found no issues.」。/code-review <PR番号> はチェックアウト中の枝ではなく gh pr diff で対象 PR を読むよう修正され、対象省略時は既定ブランチ比較でブランチ全体をレビューする。

試すなら・注意点

この読み物生成のように無人で長く走る構成では、v2.1.329 以降へ上げておくと Keychain / MCP 再接続まわりの事故が減る。レビュー運用は「バグ検出は /code-review、整理は /simplify」と口癖を分けるのが移行の近道。ただし公式ドキュメントは CHANGELOG に対して遅延があるため、修正の有無は GitHub の一次 CHANGELOG と npm dist-tags で裏取りするのが安全。computer use の安全ルール更新で、これまで通っていた操作が拒否されるケースもある。

ひとことまとめ

「新バージョンなし」は「変化なし」ではない。無人運用の足回り（認証・MCP 再接続・メモリ）とレビュー導線が静かに良くなった日。
