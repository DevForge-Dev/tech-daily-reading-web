11月の3.50へ逆算するFlutter — branch cutoffの読み方と、Android Impeller一本化でシェーダjankを構造的に消す

2026は年最低4本のstable。cutoffから次stableを逆算する。11月の3.50はWeb WasmGC既定・Android Impeller一本化が確定。あわせてflutter_hooksで消すアニメ定型と公式MVVMも押さえる。

📅 2026年10月30日 ⏱ 約3分 🔗 出典 4 件

背景。2026のFlutter/Dartロードマップは年「最低4本」のstableと「12本」のbeta(ほぼ月1)を掲げる。これは床であって天井ではなく、四半期ごとにminorが+3進む(3.41→3.44→3.47→3.50)のが長年の運用だ。計画の肝はbranch cutoff——3.50は10/6にbranch済みで、cutoffを過ぎてマージされたfixはその四半期stableに載らず次(約3か月後)待ちになる。自分のPRやアップグレードを「次のstableに間に合わせる」逆算に使える。現況はstable 3.47.8 / Dart 3.13.7(10/23)、beta 3.50.0-0.2.pre / Dart 3.14.0。

何が重要か。11月のstable 3.50の確定事項は不変で、Web WasmGC既定・Android Impeller一本化・Wasm遅延ロードstable・Android17 day-zero、そしてmaterial_ui/cupertino_uiの正式deprecationだ。中でも効くのがImpeller。Impellerはシェーダをビルド時(AOT)にコンパイルして同梱するため、Skiaが実行時(JIT)にコンパイルして起こしていた「初めて出る要素で初回フレームが固まる shader jank」を構造的に解消する。

代償と注意。シェーダを前もって同梱するぶんバイナリが微増し、カスタム.fragとgoldenテストは移行時に視覚回帰テストが要る(Impeller/Skiaで描画差が出得る)。Android 9以下はドライバ問題でGLESフォールバックなので、対象端末は性能低下を前提に--profile＋実機で計測する。逆に、Skia向けの--cache-sksl/--bundle-sksl-pathウォームアップはImpellerでは不要=削除してよい。

この日の他の収穫も実務的だ。アニメーションはflutter_hooksのuseAnimationControllerがStatefulWidget＋SingleTickerProviderStateMixin＋initState/disposeの定型をbuild内の数行に畳む(vsyncはhookが供給、手動disposeは禁物)。開始はuseEffect(() { c.repeat(); return null; }, const []);が定石。アーキテクチャは公式App ArchitectureガイドのMVVM——View/ViewModel/Repository/Serviceの4層で、Viewはロジックを持たず、Repositoryがある型の単一情報源、Serviceは状態を持たない最下層、と責務が明快だ。自分が試すなら本番を3.47.8にpinしつつ別CIでflutter build web --wasmとappbundleを今のうちに緑化しておく。
