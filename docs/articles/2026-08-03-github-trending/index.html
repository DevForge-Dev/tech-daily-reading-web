8/3の話題リポジトリ — PDFを撮る前に仕分けるRust、AIが解いた数学10問のLean証明、CRMを裏返した『エージェントが本体』

本日のモメンタム枠3本は、ドキュメント処理・形式検証・営業支援とジャンルはバラバラだが、どれも『重い処理やDBを主役から外す』発想で急上昇している。無駄なOCRを避ける、証明を機械検証で担保する、CRMを作業メモに格下げする——共通するのは主役の置き換えだ。

📅 2026年8月3日 ⏱ 約3分 🔗 出典 3 件

今日のTrendshift日次で上位に並んだ3本は、扱う領域こそ違えど「これまで主役だったもの（OCR・人手の証明・DB）を脇役に落とす」という共通の運動を見せている。以下、各リポジトリについて解決したい課題と提供する機能を分けて読む。

firecrawl/pdf-inspector（Rust・⭐— / Trendshift日次1位）

解決したい課題：PDFは中身がテキスト型か、スキャン画像か、混在かがまちまちで、全ページに一律OCRをかけると時間もコストも精度も無駄になる。提供する機能：ページをレンダリングせずPDF内部（フォント符号化・テキスト演算子・画像被覆率）を解析し、約10〜50msで「テキスト/スキャン/画像/混在」に分類してOCR要否をページ単位でルーティングする。位置情報付き抽出と見出し/表/リスト検出でMarkdown変換まで行い、MLモデル不要の純Rust（単一依存lopdf）でPython/Node/WebAssemblyバインディングも同梱。OCRの前段として「撮る前に仕分ける」発想が支持され、複数ソース言及のトップ新星になった。

openai/ten-proofs（Lean・⭐— / Trendshift日次24位）

解決したい課題：AIが「未解決問題を解いた」と主張しても、人間がその証明を独立に検証するのは難しい。提供する機能：OpenAIが次世代モデル「Astra」で得た、10年以上未解決だった数学・理論計算機科学の10問の証明を Lean 4 の機械検証可能な証明書として公開した。高次元球充填の上界改善、27年ぶりの非ソフィック群の構成、Connesの剛性予想の反例などを含み、Lean compiler さえあれば誰でも真偽を独立検証できる（Apache 2.0）。8/1に249ページの原稿とともに公開され一斉報道。エージェント一色のトレンドの中で希少な「形式検証・数学」ジャンルとして急上昇した。

trycompai/crm（TypeScript・⭐— / Trendshift日次3位）

解決したい課題：既存CRMはエージェントを「機能として後付け」する程度で、依然として人手入力の台帳から抜け出せていない。提供する機能：発想を裏返し、永続的なリサーチ・エージェントを本体、DBをその作業メモの置き場と位置づけたオープンソースのエージェント・ファーストCRM。エージェントは自前のスケジュール・作業キュー・リサーチ予算で動き、ブラウザを閉じても走り続ける。外部連携はすべて任意で、APIキー無しでも会話/会議/署名から動く。この逆転設計がHacker News等で話題になり急上昇した。

自分が試すなら：一番すぐ効くのは pdf-inspector だ。ドキュメント処理パイプラインの前段に挟めば、OCRに回すページを絞ってコストと時間を素直に削れる。ten-proofs はLean環境があれば主張を自分で検証でき、AI生成物を「信じる」から「確かめる」へ動かす好例。trycompai/crm は設計思想の参照先として、既存プロダクトに「エージェントを本体に据えたら何が変わるか」を考える叩き台になる。まとめ：今日の3本は、重い処理・人手・DBという“当たり前の主役”を疑うと新しいプロダクトが立ち上がる、を別々の分野で同時に示した。
