縦スクロールで横に流れるギャラリーをCSSだけで — sticky × Scroll-driven Animations（view-timeline）

JSライブラリ定番だったpinned horizontal scrollを、Scroll-driven Animations（animation-timeline）でJSゼロ・'use client'不要のServer Componentのまま実装する。2025-09のSafari 26追随で実用ラインに。ただしFirefox未対応でBaseline未達、フォールバック必須。

📅 2026年9月21日 ⏱ 約3分 🔗 出典 4 件

エージェンシー系サイトの定番演出——「ページを縦にスクロールすると、あるセクションだけ横に流れる」pinned horizontal scroll。従来は GSAP ScrollTrigger の pin などJSライブラリで、scroll イベントごとに transform を書き換えて実装していた。これを Scroll-driven Animations（animation-timeline） で、JSゼロ・コンポジタスレッド駆動・'use client' 不要のServer Componentのまま書けるのが今回の主題だ。

なぜ今か

Chrome/Edge 115（2023-07）に続き、2025-09のSafari 26 / iOS 26 が追随したことで実用ラインに乗った。App Router的にはハイドレーション不要・バンドル増ゼロ・RSC/SSR/キャッシュに無干渉で、相性は最上級。ただしFirefoxは未対応（フラグ止まり）で Baseline未達のため、フォールバック前提で入れる。

仕組み（3層構造）

背の高いラッパーで「横移動に使う縦距離」を稼ぎ、その中のstickyなピンが画面に貼り付いて“止まって見える”領域を作り、トラック（flexのパネル列）がタイムラインに連動して translateX する。速度はラッパーの height で調整する（高いほどゆっくり）。

肝は calc(-100% + 100vw)。100% がトラック自身の総幅なので、パネル枚数や各幅に依らず「最後のパネルまで見せて止まる」終端が自動で決まる。タイムラインはセクション完結なら view-timeline + animation-range: contain 0% contain 100% が扱いやすい。

.wrap  { height: 380vh; view-timeline: --h block; }
.pin   { position: sticky; top: 0; height: 100vh; overflow: hidden; }
.track { display:flex; height:100%;
  animation: slide linear both;
  animation-timeline: --h;
  animation-range: contain 0% contain 100%; }
@keyframes slide { to { transform: translateX(calc(-100% + 100vw)); } }

注意点・落とし穴

フォールバックは必須。@supports not (animation-timeline: view()) で、ラッパーを height:auto・ピンを position:static・トラックを overflow-x:auto（+ scroll-snap）にしてネイティブ横スクロールへ退避する。prefers-reduced-motion: reduce でも同じ形に落とす（スクロールジャックは乗り物酔いの原因）。animation-range の指定漏れは全ビュー区間にマップされてパネルが画面外でも動くので contain を明示。縦スクロールバー幅で 100vw がわずかに過剰移動する場合は 100dvw へ切替える。

ひとことまとめ

「JSで毎フレーム書き換えていた演出」が、CSSだけ・Server Componentのままに置き換わる好例。フォールバックさえ書けば、Firefoxでも“横に見られる”状態は保てる。
