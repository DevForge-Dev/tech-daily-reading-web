依存ゼロの3Dチルト・ホバーカード — CSS 3D transform × Pointer Events で60fps

perspective・座標正規化・preserve-3d・CSSグレアの4点と、App Router でのサーバー境界の切り方。rAFスロットルと prefers-reduced-motion まで。

📅 2026年10月2日 ⏱ 約4分 🔗 出典 6 件

製品カードやプロフィール、ヒーロー要素に「触れる」質感を与える定番が、ポインタに追従して傾く3Dチルト／パララックス・ホバーカードだ。カーソル位置に応じて rotateX／rotateY で立体的に傾き、表面に光沢（グレア）が走り、内部レイヤーが奥行き違いで視差移動する——という表現を、ライブラリ無し・CSS 3D transform ＋ Pointer Events だけで実装できる。2026年も react-parallax-tilt／vanilla-tilt は使われ続ける一方、「軽量・SSR安全・prefers-reduced-motion 対応しやすい」として CSS変数駆動の自前実装が好まれている。

仕組みの要点

肝は4つ。(1) perspective は親に置く（perspective: 900px・600〜1200px が目安）と複数カードで遠近が共有され並べても破綻しない。(2) ポインタ座標を要素中心基準で -0.5〜0.5 に正規化し、rotateY = px*MAX／rotateX = -py*MAX（MAX は 8〜15deg）で角度を出す。(3) カードに transform-style: preserve-3d を付け、内部要素を translateZ() で浮かせると視差とグレアが本物の奥行きに見える（見出し translateZ(48px)、背景 translateZ(0) など）。(4) グレアはポインタ位置を --mx／--my に書き込み、radial-gradient のオーバーレイ＋mix-blend-mode: overlay で下地と馴染ませる。JS 側は transform 文字列を組み立てず、カスタムプロパティだけ更新して CSS で組むのがシンプルで速い。

Next.js（App Router）への組み込み

Pointer Events・useRef・requestAnimationFrame・DOM計測を使うため、Tilt ラッパーは 'use client' 必須で RSC では実装できない。賢いのはサーバー境界の切り方——カードの中身（画像・見出し・本文）はサーバーコンポーネントのまま children としてクライアントの <Tilt> に渡す。こうするとインタラクションのロジックだけがクライアントバンドルに入り、コンテンツは RSC／ストリーミングの恩恵を受ける。初期描画は --rx:0;--ry:0 の傾き0で SSR し、ハイドレーション後に pointerenter でイベントを足せば不整合も起きない。PPR や loading.tsx のスケルトンとも共存できる。

落とし穴

pointermove は高頻度なので毎イベントで DOM を触るとジャンクする——rAF で最新イベントのみを次フレームに適用する。getBoundingClientRect() は pointerenter で一度だけ計測してキャッシュ（毎回呼ぶと強制リフロー）。will-change: transform は常時付けるとレイヤー肥大で逆効果——カードが多ければ enter で付与・leave で外す。タッチでは縦スクロールを奪わないよう touch-action: pan-y を。そして初期HTMLに乱数や「マウント後の値」を入れないこと（ハイドレーション不整合）。

prefers-reduced-motion と自分が試すなら

matchMedia('(prefers-reduced-motion: reduce)').matches が true なら pointerenter で早期 return し傾き・グレアを一切付けない。CSS 側でも @media (prefers-reduced-motion: reduce) で transform:none の保険をかける。自分なら、まず依存ゼロの自前実装（数十行）で製品カードに入れ、慣性が欲しくなった要素だけ Motion の useSpring に差し替える段階導入が良さそう。

ひとこと：「ライブラリで一発」より、CSS変数＋rAF＋サーバー境界の3点を押さえた自前実装のほうが、軽くて SSR に強く長持ちする。
