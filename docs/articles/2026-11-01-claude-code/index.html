Claude Code

11/1のClaude Code — サブエージェントの効率を一括指定するCLAUDE_CODE_SUBAGENT_EFFORT、Opus 4.8 Fast Modeを11/30廃止、v2.1.316のセキュリティ修正

最新はv2.1.316(10/31)。サブエージェントのeffortをセッションから継承せず一括指定する新環境変数、Opus 4.8 Fast Modeの11/30削除(Opus 5.5へ移行推奨)、--restrictedの作業ディレクトリ外アップロードの穴修正まで。

📅 2026年11月1日 ⏱ 約3分 🔗 出典 4 件

背景・なぜ今これか。11/1(JST)時点のClaude Code最新は v2.1.316(10/31公開。v2.1.315は10/30にnpm公開のみでCHANGELOG記載なし)。派手な新機能より『無人で長く走らせる運用を、効率とコストの両面で締める』方向の地固めが続く局面で、毎日定期タスクを回す自分の運用にこそ効く更新だ。

何が新しい/重要か。目玉は新環境変数 CLAUDE_CODE_SUBAGENT_EFFORT。より具体的な指定が無いとき、サブエージェントがセッションの effort を継承せずこの値で動く——メインは高 effort・サブは低 effortという使い分けができる。効率の優先順位は上図の通り（CLAUDE_CODE_EFFORT_LEVEL ＞ 呼び出し時 effort ＞ 定義内 effort ＞ CLAUDE_CODE_SUBAGENT_EFFORT ＞ セッション effort）。もう一つの重要点は Opus 4.8 Fast Mode の廃止で、10/30付で非推奨・11/30に削除。以後 Fast Mode リクエストはエラーを返し、通常 Opus 4.8 へのフォールバックも無い——速度を保ちたいなら Opus 5.5 への移行が推奨される。

仕組み・そのほかの追加。ultrathink キーワードを無効化する CLAUDE_CODE_DISABLE_ULTRATHINK、相互認証のクロス証明書を保持する CLAUDE_CODE_DISABLE_LOOPED_CROSS_CERT_DROP、Claude apps ゲートウェイのプール予算 pooled_budget・全一致ポリシーを重ねる managed.policy_mode: layered・Bedrock 向け guardrail.input_tagging を追加。セキュリティ面では --restricted セッションで Read 許可が及ぶと作業ディレクトリ外のファイルをアップロードできた穴を修正し、ゲートウェイがリクエスト内の全モデルを検査、PowerShell フックのブロック漏れも塞いだ。

実務での使いどころ・落とし穴。自分の無人運用なら CLAUDE_CODE_SUBAGENT_EFFORT=low を既定に置き、重い判断を要するメインだけ高 effort にすればトークンコストを素直に削れる。破壊的変更として、Team/Enterprise ではサーバ管理設定が承認プロンプト無しで適用されるようになった(検証失敗の保存済みコピーは拒否)点は要注意——管理者が設定を変えると自分の端末にも黙って反映される。Vertex/Bedrock では最新モデル未提供時にセッション途中でエラーにせず旧モデルへフォールバックするようになり、長時間バッチが途中で死ににくくなった。

ひとことまとめ。v2.1.316 は「サブエージェントの effort を個別に絞ってコスト最適化」「Fast Mode は 11/30 で終わり、速度は Opus 5.5 へ」「restricted の穴塞ぎ」の3点を押さえれば十分。無人運用者ほど CLAUDE_CODE_SUBAGENT_EFFORT と管理設定の無確認適用は今すぐ把握しておきたい。
