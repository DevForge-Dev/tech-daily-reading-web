更新の空白日に描く Claude Code 拡張の地図 — Hooks / Skills / Subagents / worktree の棲み分け

9/7以降の新規リリースは無く最新は v2.1.263（9/6）のまま。空白日は拡張3本柱（Hooks=強制・Skills=知識・Subagents=委譲）と worktree 並列の整理が効く。普及は ARR $2.5B・日次29Mインストールへ。

📅 2026年9月8日 ⏱ 約3分 🔗 出典 5 件

9月8日時点で公式 changelog の最新は v2.1.263（9/6）のままで、9/7 以降の新規リリースは確認できなかった。機能追加の無い「空白日」は、増えすぎた拡張機構を頭の中で整理し直す好機だ。今日は複数の解説記事が口を揃える拡張3本柱の棲み分けと、並列運用の要である git worktree を地図にまとめる。

何が新しい/重要か

直近で見落とされがちな実務更新も振り返る価値がある。v2.1.260（9/3）はフルスクリーン時に会話の横で未コミット差分を表示し /diff で開閉できる差分パネル、headless（-p/Agent SDK）セッションでも使える /reload-plugins と /advisor のテキスト版を追加。v2.1.257（9/1）は claude-fable-5-1 を既定 Fable モデルに（1M コンテキスト・$10/$50 per Mtok、キャッシュ読取 $0.25/Mtok）し、auto mode に「Containment Escape」ルール（クラウドのメタデータ認証取得・egress 回避・テナント越えを既定で自動承認しない）を導入した。

実務での使いどころ

ノイズの多いリサーチは Subagent に隔離し、実装は別エージェントで検証する「二重化」が幻覚対策の要。並列は git worktree で各エージェントに独立ディレクトリを与え（Git 履歴は共有）、計画→共有コントラクト定義→所有境界で分割→worktree に隔離→ワーカー単位でテスト→統合後に最終検証という型が定石。開発者あたり 4〜8 個の同時 worktree を安定運用する事例も紹介されている。自分なら、まず PostToolUse フックで prettier、on-Stop でテストを回す最小構成から始める。

注意点

3本柱は役割が重なって見えるが、混ぜると破綻する。「守らせたい規則」をプロンプト（Skills/CLAUDE.md）に書いても確実には効かない——強制は必ず Hooks／権限で。逆に決定論不要の知識を Hooks に埋めると硬直する。並列 worktree は共有コントラクトを先に固めないと統合で衝突する。

ひとことまとめ

普及は日次インストール 29M・ARR $2.5B（8か月で Copilot/Cursor を抜き最多）と規模を増すが、効かせ方の本質は「強制・知識・委譲」を混同しないこと。空白日はその地図を引き直すのに向く。
