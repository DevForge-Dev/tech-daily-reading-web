Flutter 3.50 ブランチカット — Wasm遅延ロードGAとImpeller一本化、Riverpod 3の状態標準化

11月の安定版へ向け3.50が確定。配信とレンダリングの刷新に、Riverpod 3のMutations/永続化/自動リトライを添える。

📅 2026年10月13日 ⏱ 約3分 🔗 出典 4 件

安定チャンネルは Flutter 3.47.7 / Dart 3.13.5（10/8のpatch）。そして10/6に 3.50のブランチカットが実行され、master に入ったPRがこの時点で3.50に確定した。beta は数日内、stable は11月の見込みだ。節目の大きい更新なので、何が変わるかを押さえておきたい。

何が新しく・重要か。3.50の目玉は3つ。(1) Webの Wasm遅延ロード（deferred/lazy loading）が experimental → stable GA に昇格し、分割配信で初回バンドルを削減。(2) Androidで legacy Skia バックエンドが API29+ で正式に引退し、Impeller 一本化が完了。(3) Webの WasmGC 既定化も前進。言語側は Dart 3.14 で Augmentations（外部コードから既存クラスへメンバーを追加）が入る見込みで、macros は引き続きポーズ——コード生成は当面 build_runner ＋ source_gen が主軸のままだ。

状態管理の要点——Riverpod 3.4系。実験的に Mutations が入った。final addTodo = Mutation<void>(); を宣言し addTodo.run(ref, () async {...}) で副作用を実行、ref.watch で MutationIdle / Pending / Error / Success を switch 分岐でき、「送信中スピナー・成功トースト・失敗再試行」の状態管理が標準化される。オフライン永続化は build 冒頭で persist(...) を呼ぶだけ（JsonSqFliteStorage、既定キャッシュ2日、AsyncValue.isFromCache で由来判定）。失敗した provider は指数バックオフ（200ms→最大6.4秒）で自動リトライし、null を返すと停止する。

UIとアニメーション。Material 3 Expressive は spring（物理ベース）モーションが核で、押下での形状モーフや選択ピルの拡大が spring 駆動になる。flutter_animate は Text('Hi').animate().fadeIn().slide().scale() と effect をチェーンでき、.then() が前 effect の delay＋duration から次の開始を自動計算してくれる。注意点。spring/morph は毎フレーム再描画なので必ず --profile で計測し（debug は3〜5倍遅い）、重い画面は RepaintBoundary で隔離する。ひとこと。3.50は「配信を軽く・描画をImpellerに統一」、状態は Riverpod 3 で非同期の定型を言語化する年だ。まず beta でCIを1本回し、11月の切替コストを前倒しで潰しておきたい。
