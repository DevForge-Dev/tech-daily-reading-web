Riverpod 3.3.1×codegen を新規既定に — 自動リトライ・オフライン永続化と、Design System Modularization の始動

現行安定はFlutter 3.44/Dart 3.12、8月は次期リリース窓。新規アプリはRiverpod 3.3.1＋codegenを既定に、指数バックオフ自動リトライ(200ms→6.4s)・オフライン永続化・Mutationsを低ボイラープレートで得る。ImpellerがAndroid既定でSkia撤去、Material/Cupertinoのコア分離でapp size削減も進む。

📅 2026年8月9日 ⏱ 約3分 🔗 出典 3 件

現行安定版は Flutter 3.44 / Dart 3.12（3.44.0 は 2026-05-18・Google I/O 2026 公開）。Flutterは年4回（2/5/8/11月）リリースで、いままさに8月のリリース窓に入っている。今日の主役は状態管理の既定線と、コア構成の作り替えだ。

何が新しいか — 新規はRiverpod 3.3.1＋codegen

ほとんどの新規アプリは Riverpod 3.3.1＋codegen を既定にしてよい。compile-time safety・context-free reads・first-class async に加え、3.0系のresilience機能を、codegenによってProvider並みまで下げたボイラープレートで得られる。目玉の自動リトライは、providerが初期化で失敗すると指数バックオフ（200msから倍々で最大6.4s）で自動再試行し、一時的な通信障害を恒久エラーにしない。さらにunified RefでAPIを刷新、experimental offline persistence（再起動でキャッシュから復元）、Mutationsで副作用の Idle/Pending/Success/Error を UI に公開する。監査証跡が要る規制業界（fintech/healthcare）は on<Event> 構文に統一された Bloc 9.0 が適材で、選定の基本線は『新規＝Riverpod 3.3.1、監査/大規模＝Bloc 9.0』。両者は ProviderScope と MultiBlocProvider で共存できる。

土台の変化 — Modularization と Impeller

Design System Modularization が本格始動。Material と Cupertino を Flutter コアから切り出し、pub.dev の standalone・独立バージョニングのパッケージにする。M3更新が四半期SDKを待たず届き、未使用UIはbinaryに含めないので app size 削減につながる。描画基盤の Impeller は Android で既定・Skia を撤去（Vulkan／iOS=Metal）。ビルド時AOTシェーダーで shader compilation jank を排除する。

実務での使いどころ・注意点

自分が新規で始めるなら Riverpod 3.3.1＋codegen で、まず自動リトライとMutationsをフォーム送信・API初期化に入れる。offline persistenceはまだexperimentalなので本番データの信頼源にはせず、UX改善の付加程度に留めるのが安全。パフォーマンスは const 徹底＋RepaintBoundary でアニメ領域を隔離し、必ずprofileモードでDevTools（Inspector 2.0）を使い、UIスレッドをフレームあたり8ms未満（60fps=16ms/90fps=11ms/120fps=8.3ms）に保つ。

ひとことまとめ：状態管理は『新規=Riverpod 3.3.1＋codegen』で確定。土台はModularization＋Impellerでサイズと初回ジャンクが同時に改善していく局面。
