Flutter 2026-10-02 — AIが開発ループに入り込み、signalsが第3の状態管理に

dart mcp-server と Agentic Hot Reload で AI が開発の“一部”へ。signals の台頭、leak_tracker の CI 統合まで、3.50（11月）へ降りる足場を読む。

📅 2026年10月2日 ⏱ 約4分 🔗 出典 3 件

現行の安定版は Flutter 3.47.5 / Dart 3.13.4、beta は 3.49.0 / Dart 3.14、次の安定機能リリースは 3.50（2026年11月）。この日の“主役”は、AI がフレームワーク周辺のツールではなく開発ループそのものの一部になり始めた、という潮目の変化だ。

何が新しいか — AIネイティブな開発ループ

Dart & Flutter MCP Server（dart mcp-server）が起動中のアプリを自動検出し、AI エージェントのコード変更を Agentic Hot Reload で即反映する。さらに dart analyze / format / test の結果も MCP 経由で AI が読み取り、修正ループを自動で回す。UI 生成側では GenUI が A2UI プロトコル上で LLM 応答から実ウィジェットをランタイム合成し、サーバ側の生成フローは Genkit for Dart が担う。

Dart 3.14（beta）では dot shorthands が定着（MainAxisAlignment.start → .start）、build hooks（hook/build.dart）でネイティブアセット同梱と link hooks の tree-shaking（未使用ネイティブシンボル除去）が入る。macros は無期限ポーズのままで、生成は build_runner＋source_gen が主軸だ。

状態管理 — signals が第3の選択肢に

signal() / computed() / effect() の細粒度リアクティビティを持つ signals が浮上した。依存を自動追跡し、変化した computed だけを再評価する SolidJS/Preact 系の設計で、UI は Watch((){...}) か SignalsMixin で購読する。ボイラープレートが少なく学習コストも低い。一方で大規模のガバナンス・監査・一貫性は Riverpod 3.3 / Bloc 9.2 が依然優位という住み分けだ。

パフォーマンス — leak_tracker が CI の番人に

leak_tracker が flutter_test に統合され、testWidgets 実行中に AnimationController・StreamSubscription・TextEditingController・FocusNode などの dispose 忘れを自動検出する。CI に組み込めば回帰を防げる。DevTools の Memory view で snapshot を diff、Allocation Tracing で割当元を辿る定石も健在だ。

自分が試すなら・注意点

まず dart mcp-server を Claude Code 等に繋いで Agentic Hot Reload の往復を体感し、小さな画面で signals を試す。11月の 3.50 では Android が Impeller 一本化（legacy Skia 撤去・API29+）、Web は WasmGC 既定（dart:html→package:web）になるため、移行の下準備（dart fix --apply --code=migrate_design_widgets は --code 無しだと無変更の罠）は早めに。macros 前提の設計は当面見送りが無難だ。

ひとこと

AI が「開発ループの中」に入った年。手触りの signals と、番人の leak_tracker を両輪に、3.50 へ向けて足場を固めたい。
