可変フォントを純CSSでアニメ — font-variation-settings × @property × next/font

1つのフォントファイルに太さ・幅・傾きを連続値の「軸」で持つ可変フォント。next/fontの推奨形態で、演出は純CSSだから Server Component のまま use client 不要・hydrationゼロ。最大の落とし穴は font-variation-settings が「非加算」で全軸を上書きすること。1軸だけ滑らかに動かす定石は @property で型を宣言したCSS変数。

📅 2026年7月26日 ⏱ 約3分 🔗 出典 3 件

背景から。可変フォントは太さ(wght)や幅(wdth)などを連続レンジで持つので、CSSの transition/@keyframes に乗せるだけで「文字が太る・幅が伸びる・傾く」演出が純CSS・ゼロ依存で作れる。Next.js 文脈で効くのは、可変フォントが next/font の推奨形態で、1ファイルに全軸が入りリクエスト1本＋size-adjust でCLS0、しかも演出が純CSSなのでServer Component のまま hydration ゼロで出せる点だ。

何が新しい／落とし穴

軸は4文字タグで、登録軸は小文字・カスタム軸は大文字。登録軸には高レベルCSSプロパティが対応する。最大の落とし穴が font-variation-settings は「非加算」で指定宣言が全軸を一括上書きし、継承もされないこと。親に "wght" 700、子に "opsz" 14 と書くと子の wght は既定へリセットされる。対策は二つ、(1)登録軸は font-weight 等の高レベルプロパティを使う、(2)1宣言で必要な全軸を書く。

1軸だけ滑らかに — CSS変数 ＋ @property

1軸だけ動かしたいのに全軸を書き直すのは辛い。定石は各軸をCSS変数へ逃がすことだが、素のカスタムプロパティは既定で離散補間でパッと切り替わる。ここで @property で型を宣言すると数値として滑らかに補間できる（Baseline 2024）。

@property --wght { syntax: "<number>"; inherits: false; initial-value: 400; }
h1 { --wght: 400; font-variation-settings: "wght" var(--wght);
     transition: --wght .3s ease; }
h1:hover { --wght: 850; }

next/font 実装と注意点

可変フォントは next/font で weight を渡さず（レンジ全体が使える）、opsz 等の非既定軸は axes で opt-in、宣言は必ず module スコープで layout に適用する（'use client' 不要）。ポインタ追従など JS が要る演出だけ Client 島に閉じ込め、毎フレーム setState せず useRef＋style.setProperty('--wght', v) で直書きする。パフォの落とし穴は font-variation-settings のアニメがGPUコンポジット対象外で再ラスタライズ＋再レイアウトを誘発すること。見出し・短いラベル・単発トリガーに限定し、prefers-reduced-motion では動きを止めて到達状態(太字など)だけ残す。まとめると「純CSSで軽やかに、ただし動かすのは見出しだけ」。
