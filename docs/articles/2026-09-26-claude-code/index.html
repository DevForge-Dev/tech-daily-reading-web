Claude Code 週次総まとめ — /doctor prompt-auditとOpus 5.5既定化、AGENTS.md対応まで

changelog v2.1.283の自己監査コマンドから、クラウドセッション正式提供・Opus 5.5既定化・Hooks強制ゲートまで、この週の実務インパクトを整理する。

📅 2026年9月26日 ⏱ 約4分 🔗 出典 4 件

この一週間の Claude Code は、派手な新機能よりも「毎日の運用が事故りにくくなる」地味な改善がまとまって入った週だった。changelog の刻みと週次まとめを合わせて読むと、狙いは恒久メモリ（CLAUDE.md）の品質管理・モデル制御・クラウド運用の安定化に集約されている。

何が新しいか

最新版は v2.1.283（9/25 公開）。目玉は CLAUDE.md やプロンプト記法を自己監査する新コマンド /doctor prompt-audit で、肥大した指示や曖昧な書き方を点検できる。管理設定には availableModelsMatch / deniedModels が加わり、組織で使えるモデルの許可・拒否を細かく制御できるようになった。加えてヒントヘッダに x-claude-code-prompt-id を付けてリクエストをグルーピングし、MCP ツール出力を OpenTelemetry の span イベントへ記録。バグ修正では SDK セッションで deferred ツール呼び出しや完了済みツール結果が失われる問題、長時間実行中に MCP 進捗通知が破棄される問題、セッション終了後に stdio MCP サーバーが残る問題を一掃した。

週次（9/18〜24）では運用面のインパクトが大きい。v2.1.277 で CLAUDE.md が無いとき AGENTS.md をプロジェクト指示として読むようになり、Codex や Cursor と指示ファイルを重複なく共有できる。9/23 にクラウドセッションが Pro/Max/Team 向けへ正式提供となり、Anthropic のクラウド上でセッションが永続化して端末をまたいで作業を続けられる。Auto Mode の安全分類器はサーバー側へ移り、対象プランでは分類のための課金が発生しない。そして v2.1.280 で Opus 5.5 が既定モデルになった。

実務での使いどころ

上級ベストプラクティスの勘所は4つ。第一に、安全要件は CLAUDE.md の「お願い」ではなく PreToolUse Hook で確定ブロックする——bash スクリプトを終了コード2で終わらせれば、Claude の記憶に依存せず毎回操作を止められる。第二に、調査や検証はメインセッションでやらず Subagent へ隔離し、失敗手法が後続を汚す「コンテキスト汚染」を防ぐ。第三に、同じ問題で2回つまずいたら /clear で失敗パターンを一掃して再スタート。第四に、lint やテスト等の安全な反復操作は permissions.allow で自動許可し、承認過多→無確認クリック→安全性低下という悪循環を断つ（機密ファイルは deny で隠す）。自分が回している定期タスク群なら、まず各 CLAUDE.md を /doctor prompt-audit にかけ、rm や force push に Hook ゲートを1本差すのが即効性がある。

Skill の配布3方式

作った Skill を配る手段は用途で分かれる。自前の Plugin Marketplace（GitHub リポジトリ＋設定ファイル）はチーム共有向き、公式 Plugin Store は審査つきの一般公開向き、vercel-labs の Skills CLI は Cursor / Copilot など40超のエージェント横断向き。Plugin 経由は /plugin:skill とプレフィックスが付く一方、Skills CLI は環境をまたいで名前が一貫するのが実務上の分かれ目だ。

注意点とまとめ

Opus 5.5 の既定化で Pro/Team Standard は Sonnet から切り替わり、トークン消費とレイテンシの体感が変わる点は定期タスク運用者ほど効いてくる。モデル制御は組織設定なので、個人環境では availableModels 系は無関係。総じて「壊れにくく、指示を点検でき、モデルを選べる」方向に一歩進んだ週で、まずは自分の CLAUDE.md 監査と Hook ゲート1本から取り込むのがコスパが良い。
